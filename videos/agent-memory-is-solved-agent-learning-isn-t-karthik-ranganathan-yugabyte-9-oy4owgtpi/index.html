Summary

Overview

  • Speaker: Karthik Ranganathan
  • Channel: AI Engineer
  • Main topic: Agentic data infrastructure, multi-agent memory sharing, and collective agent learning
  • Purpose: Explain the architectural gaps in multi-agent learning systems and introduce Miko as a persistence and context-sharing layer that solves multi-agent handoffs. Karthik Ranganathan, co-founder and CEO of Yugabyte, argues that while individual agent memory is largely solved, collective agent learning remains an unsolved infrastructural problem. Drawing on internal company experience running multiple agents (Hagen, Growth Vector, Perf Advisor, Voyager), he highlights why multi-agent handoffs fail (loss of context, reasoning, and dead-ends), debunks five common misconceptions in agent engineering, and introduces Miko as an agent-native data persistence layer designed to enable context sharing, supervised promotion, and decision traces.

Topic Map

The State of Agent Memory vs Agent Learning

  • Explanation: Agent memory works well on a per-agent basis (vector stores, episodic recall), but learning is collective across agents and requires new architectural primitives.
  • Key claims:
    • Agent memory is a solved problem.
    • Agent learning is collective, not isolated.
    • Infrastructure built for a single agent does not support multi-agent learning.
  • Examples:
    • Running internal agents like Hagen for customer support and Growth Vector for go-to-market.
  • Terminology:
    • agent memory
    • agent learning
    • vector stores
    • episodic recall
  • Why it matters: Understanding that memory and learning require different infrastructure prevents engineering teams from hitting architectural dead-ends.

Why Multi-Agent Systems Fail on Handoffs

  • Explanation: When agent A hands off work to agent B, the reasoning, dead-ends, and context are lost, forcing agent B to re-derive decisions from scratch.
  • Key claims:
    • Multi-agent systems fail on handoffs, not reasoning.
    • Receiving agents only get final outputs (like an MD file or PDF), losing reasoning and dead-ends.
    • Re-deriving context burns tokens and wastes resources similar to onboarding a new human team member.
  • Examples:
    • Agent A doing work and handing off the final output to Heather's agent without reasoning traces.
  • Terminology:
    • handoff
    • context loss
    • reasoning traces
    • dead-ends
  • Why it matters: Handoff inefficiencies are the primary source of token burn and repeated errors in multi-agent workflows.

Five Misconceptions in Agent Architecture

  • Explanation: Builders make five common assumptions about scaling agent intelligence that actually represent architectural gaps.
  • Key claims:
    • More memory is not learning; it is just more expensive storage.
    • Shared state is not shared knowledge.
    • RAG over transcripts (ragging everything) increases noise and burns tokens.
    • Fine-tuning is not scalable for persistent lessons.
    • A bigger context window is the surest way to quick failure and rotting context.
  • Examples:
    • Building distributed RAG pipelines that only worsened accuracy benchmarks.
  • Terminology:
    • RAG transcripts
    • fine-tuning
    • context window
    • shared state
  • Why it matters: Identifying these misconceptions steers engineers away from dead-end architectures.

Three Missing Primitives for Agent Handoffs

  • Explanation: Closing the handoff gap requires three core primitives: context sharing, supervised promotion, and decision traces.
  • Key claims:
    • Context sharing closes lost context by letting agents work on the same shared context.
    • Supervised promotion closes the durability gap by promoting private per-agent memory to shared knowledge via human or agent supervision.
    • Decision traces close the reasoning gap by tracking why decisions were made and dead-ends encountered.
  • Examples:
    • Promoting private agent memory to a shared knowledge datapack after human review.
  • Terminology:
    • context sharing
    • supervised promotion
    • decision traces
    • datapack
  • Why it matters: These primitives form the blueprint for robust multi-agent coordination.

Key Points

Agent memory is solved, but agent learning is collective

  • Explanation: Individual agents can recall past conversations and use vector stores, but groups of agents cannot easily share or learn from each other's work without new infrastructure.
  • Evidence: Internal failures scaling four different agents (Hagen, Growth Vector, Perf Advisor, Voyager) before realizing data infrastructure was missing.
  • Practical implication: Do not treat single-agent memory stores as sufficient for multi-agent collaboration.

Multi-agent failures stem from handoffs, not reasoning

  • Explanation: When agent A hands off results to agent B without reasoning traces or dead-ends, agent B loses context and must re-derive solutions.
  • Evidence: Analogy to onboarding a human employee: making a new hire re-derive three months of decisions wastes time.
  • Practical implication: Design multi-agent frameworks to pass reasoning and context alongside final outputs.

Human promotions are training signals for self-improving orchestration

  • Explanation: When humans validate that a piece of agent memory or output is 'worth keeping', it serves as a high-quality training signal for future orchestration.
  • Evidence: Demonstrated via Miko's promote-to-knowledge feature in the live demo.
  • Practical implication: Stop optimizing what agents remember; start optimizing what they learn together.

Core insights

6
[!]Failure Modehigh noveltymoderate evidence

Multi-agent systems fail primarily at handoff boundaries, not at reasoning. The receiving agent gets only the final artifact (an MD file or PDF) and loses the reasoning path and the dead-ends the sender already explored, so it re-derives everything from scratch.

Why it matters

This relocates the engineering problem from 'make each agent smarter' to 'make the boundary between agents lossless'. Teams instrumenting per-agent reasoning quality while ignoring handoff payloads are optimizing the wrong surface, and the cost shows up as repeated token burn and re-litigated decisions.

Generalization

Any pipeline that composes specialized workers (agents, services, or humans) needs to carry negative results and rationale alongside outputs; artifact-only interfaces force redundant recomputation downstream.

[A]Architecturehigh noveltymoderate evidence

Three primitives are proposed as the missing abstraction layer for multi-agent coordination: context sharing (agents operate on one shared context rather than message-passing snapshots), supervised promotion (private per-agent memory is promoted to shared knowledge under human or agent supervision), and decision traces (records of why a decision was made and which dead-ends were hit).

Why it matters

Each primitive maps to a distinct named gap — lost context, durability, and reasoning — which gives a concrete checklist for designing a handoff protocol instead of hand-rolling one. Notably, promotion introduces a gated write path into shared knowledge rather than letting every agent write freely.

Generalization

Shared knowledge stores need a promotion gate (review, confidence threshold, or curator agent); without it the shared store degrades into an append-only dump of unevaluated agent output.

[O]Mental Modelmedium noveltyweak evidence

Human approval of a memory item ('worth keeping') is reframed as a training signal for orchestration rather than as a manual curation chore. The target of optimization shifts from what a single agent remembers to what a group of agents learns jointly.

Why it matters

If promotion decisions are logged, they become a labeled dataset of what the system should retain — usable for evaluating and improving retrieval ranking or orchestrator routing, not just for cleaning storage. That makes review effort dual-purpose instead of pure overhead.

Generalization

In any human-in-the-loop curation flow, treat the accept/reject decision as a label and persist it; the review queue is a free preference dataset for ranking and routing.

[~]Tradeoffmedium noveltymoderate evidence

Five named anti-patterns are asserted: more memory is not learning but more expensive storage; shared state is not shared knowledge; RAG over transcripts increases noise and burns tokens; fine-tuning does not scale for persistent lessons; a bigger context window is the fastest route to rotting context.

Why it matters

These cut against the default escalation path (bigger window, dump more transcripts into a vector store, fine-tune on lessons). Each is a substitution that looks like learning but adds cost or noise without adding durable, transferable knowledge — specifically the distinction between raw shared state and curated shared knowledge.

Generalization

Scaling context or storage is a capacity move, not a learning move; durable improvement requires a distillation step that removes information, not one that accumulates it.

[M]Mechanismmedium noveltyweak evidence

The proposed persistence layer treats memory, knowledge, and conversations as first-class primitives exposed over MCP, and answers a single query with hybrid retrieval across vector, semantic, and graph indexes rather than requiring the caller to pick one index.

Why it matters

Two concrete design choices: a protocol boundary (MCP) that makes the store usable by heterogeneous agent clients without custom SDKs per agent, and fused multi-index retrieval that avoids forcing the agent to choose a retrieval strategy — the graph leg captures relationships that pure vector similarity misses.

Generalization

Memory infrastructure exposed as a protocol rather than a library makes cross-vendor and cross-agent context sharing feasible; hybrid retrieval behind one call reduces the burden of retrieval-strategy selection at the agent layer.

Deep dives

Handoff tax: measuring re-derivation cost at agent boundaries

Research question

In a controlled multi-agent task suite, how much redundant token spend and repeated dead-end exploration occurs when agent B receives artifact-only versus artifact-plus-decision-trace from agent A, and does the delta change task success?

Why

The talk's central claim relocates the engineering problem from per-agent reasoning quality to the losslessness of the boundary, but supplies no number. Without a measured handoff tax, teams cannot decide whether decision traces are worth the extra write volume and payload size, and 'handoff failures' stays an anecdote rather than a budget line.

Source video ↗

Decision-trace schema under a context-rot budget

Research question

Which decision-trace representation (structured rationale plus explicitly ruled-out options, versus raw transcript excerpts) maximizes downstream agent accuracy per token consumed, and what expiry or compression policy keeps traces from accumulating into a rotting context dump?

Why

Decision traces are the proposed fix for lost reasoning, but the same talk warns that accumulating raw context degrades quality. The two claims are in direct tension unless traces are a lossy, bounded distillation — a design constraint that nobody has specified, schema-wise or budget-wise.

Source video ↗

Promotion gates: the criterion that turns private memory into shared knowledge

Research question

Does a learned promotion classifier over candidate memory items beat human-only and agent-only gates on downstream task success for consuming agents, and does the accept/reject log itself improve retrieval ranking or orchestrator routing when used as labels?

Why

Supervised promotion introduces a gated write path with review latency and a propagation risk: one bad agent promotion spreads a wrong lesson to every consumer at once. Whether the gate is worth its latency, and whether agent-supervised promotion is safe at all, is the load-bearing unresolved question of the whole architecture.

Source video ↗

Operationalizing 'shared state is not shared knowledge' as convergence

Research question

With identical shared state but differing levels of curation and promotion, do receiving agents converge on the same decisions — and is decision convergence per token a usable metric that separates state access from knowledge sharing?

Why

The claim is asserted without a definition and sits in tension with the proposed fix of context sharing. Treating convergence as the operational definition converts a slogan into a measurable property, which is the only way to know whether a shared-context layer is actually delivering knowledge rather than a bigger inbox.

Article ideas

4

The Handoff Is the Bug: Why Multi-Agent Failures Live at the Interface

Teams instrument per-agent reasoning quality while the real defect is an artifact-only interface between agents; handoff payloads must carry rationale and ruled-out options, because an interface that transmits only outputs forces every downstream agent to pay an onboarding tax that no amount of model improvement removes.

Angle

Reframe the debugging surface: for each agent boundary in a system, write down exactly what crosses it, then show that the missing fields are negative results and rationale — not more context.

Source video ↗

Capacity Is Not Learning: Why Bigger Windows, More Memory, and Transcript RAG All Fail the Same Way

Bigger context windows, larger memory stores, transcript-level RAG, and fine-tuning are all accumulation moves dressed up as learning moves; durable improvement requires a step that removes information — a promotion gate and a distillation contract — which is why teams that escalate capacity keep reporting degraded accuracy benchmarks.

Angle

Line up the four escalation paths against the same criterion (does it delete anything?) and show each fails for the same structural reason.

Source video ↗

Your Review Queue Is a Labeled Dataset

Human approval of what an agent should remember is usually treated as curation overhead; if those accept/reject decisions are persisted, they become a free preference dataset for retrieval ranking and orchestrator routing — making review effort dual-purpose instead of pure cost.

Angle

Turn the chore into a signal: instrument the promotion gate as a labeling pipeline and argue that the review latency buys routing quality, not just storage hygiene.

Source video ↗

Memory Should Be a Protocol, Not an SDK

Exposing memory, knowledge, and conversations over a protocol boundary lets heterogeneous agent clients share context without per-vendor integrations, and pushing hybrid retrieval behind a single call removes a retrieval-strategy decision the agent layer was never good at making — at the cost of a new, silent place where rank fusion can degrade quality.

Angle

Architecture argument: what changes when memory is a service with its own access semantics versus a library each agent embeds, including the observability debt you take on.

Project ideas

4

HandoffTax

beyond-evals

On a fixed multi-step task suite, passing artifact-plus-decision-trace instead of artifact-only reduces redundant token spend and repeated dead-end exploration by a measurable margin without lowering task success.

Proof of concept

Build a two-agent pipeline (sender, receiver) over a fixed suite of research-and-produce tasks. Instrument every boundary crossing to log tokens spent after handoff, which already-explored options the receiver re-explores, and whether it re-derives a decision the sender already made. Run three arms: artifact-only, artifact-plus-rationale, artifact-plus-rationale-and-dead-ends.

Measurement

Redundant tokens per handoff, dead-end repetition rate (fraction of ruled-out options re-explored), task success, and tokens per successful task, compared across the three arms.

Source video ↗

PromotionGate

gatehouse

A promotion gate that scores candidate memory items and logs every accept/reject decision produces both a cleaner shared store and a labeled dataset that improves retrieval ranking or orchestrator routing over unsupervised heuristics.

Proof of concept

Stand up a shared knowledge store with three write policies: free write, human-only gate, and mixed gate (agent proposes with confidence, human escalates a sampled fraction). Log accept/reject with context features. Train a ranker on the logged decisions and A/B it against a similarity-only baseline for consuming agents.

Measurement

Downstream task success and retrieval precision for consumers of promoted versus unpromoted knowledge; ranker lift over baseline on held-out promotion decisions; review latency per promoted item.

Source video ↗

TraceBudget

new

A structured, lossy decision trace (decision, rationale, ruled-out options, expiry) outperforms raw transcript excerpts on downstream agent accuracy per token consumed, and unbounded traces degrade accuracy over a long session.

Proof of concept

Define two trace representations for the same agent sessions — structured schema versus verbatim transcript slice — and replay each into a receiving agent across short and long sessions. Add a third arm with no trace. Vary the token budget per trace and the expiry window.

Measurement

Accuracy per token consumed, receiver re-derivation rate, and accuracy decay as accumulated trace volume grows within a session.

Source video ↗

ConvergenceCheck

movement-lab

Agents given identical shared state but differing curation produce divergent decisions; decision convergence under identical state is therefore a usable operational test for shared knowledge rather than mere state access.

Proof of concept

Construct paired settings with the same underlying shared state: one raw, one curated and promoted. Give multiple independent receiving agents the same tasks and compare their decisions. Swap the order of retrieval results to test whether convergence is driven by curation or by retrieval position.

Measurement

Inter-agent decision agreement rate per setting, agreement after retrieval-order perturbation, and token cost to reach a decision.

Architectural implications

4

Where the shared context and knowledge boundary lives

Before

Each agent owns a private memory store; collaboration happens by passing final artifacts between agents.

After

A separate persistence layer owns memory, knowledge, and conversation as first-class primitives, accessed over MCP by all agents.

Consequence

Memory becomes a shared service with its own retrieval, versioning, and access semantics; agents become stateless-ish clients, and the handoff protocol is defined by the store's data model rather than by ad-hoc message formats.

Source video ↗

Who is allowed to write to shared knowledge

Before

Any agent that has a lesson writes it wherever it can, or the team dumps transcripts into a shared index.

After

Private memory is promoted to shared knowledge only through supervised promotion, by a human or a supervising agent.

Consequence

Adds a gated write path and review latency, but prevents the shared store from filling with unvalidated, noisy agent output — which the speaker claims is exactly what degrades RAG accuracy.

Source video ↗

What the handoff payload contains

Before

Output artifact only — the final document or result.

After

Artifact plus decision trace: why decisions were made and which dead-ends were already ruled out.

Consequence

Downstream agents stop re-exploring known dead-ends; token cost per handoff drops, at the price of higher write volume and larger payloads on the sending side.

Source video ↗

How retrieval strategy is chosen

Before

The agent or its prompt selects an index type (usually vector-only) per query.

After

Hybrid retrieval across vector, semantic, and graph returns fused results in one call.

Consequence

Fewer agent-level retrieval decisions to get wrong, but the store now owns rank fusion and its tuning — a new place where quality can silently degrade.

Source video ↗

Tradeoffs and failure modes

5

Supervised promotion of memory to shared knowledge

Benefit

Keeps the shared store curated and turns human judgment into a durable signal for what is worth retaining.

Cost or risk

Introduces a human or supervising-agent bottleneck and review latency; if the supervisor is itself an agent, a bad promotion can propagate a wrong lesson to every agent at once.

Source video ↗

RAG over raw transcripts

Benefit

Zero curation effort, trivially captures everything that was said, fast to stand up.

Cost or risk

Increases noise and token spend; the speaker reports distributed RAG pipelines that worsened accuracy benchmarks rather than improving them.

Source video ↗

Enlarging the context window

Benefit

Defers the design work of deciding what to retrieve and what to drop.

Cost or risk

Called the surest route to quick failure, with degraded 'rotting' context and higher per-call cost.

Source video ↗

Fine-tuning as the persistence mechanism for lessons

Benefit

Makes lessons part of the model rather than part of the prompt or retrieval layer.

Cost or risk

Does not scale as the mechanism for continuously accruing persistent lessons across agents; the speaker dismisses it as a general answer.

Source video ↗

Hybrid multi-index retrieval in a single query

Benefit

Captures relational structure via graph alongside semantic and vector similarity, and offloads strategy choice from the agent.

Cost or risk

More indexing surface to maintain and more parameters to tune; rank fusion can hide which retriever actually contributed to a result.
