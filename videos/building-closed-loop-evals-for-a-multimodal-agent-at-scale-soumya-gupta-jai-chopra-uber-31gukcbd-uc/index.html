Summary

Overview

  • Speaker: Soumya Gupta, Jai Chopra
  • Channel: AI Engineer
  • Main topic: Building closed-loop evaluations for multimodal agents at Uber scale
  • Purpose: To share production-grade engineering practices for building, evaluating, and self-tuning multimodal AI agents at scale using closed-loop eval pipelines. Soumya Gupta and Jai Chopra from Uber explain how they designed real-world production evaluations and closed-loop feedback systems for multimodal agents handling food photography enhancement on Uber Eats. They cover agent architecture (image understanding, routing, generation, QA), offline human alignment, routing and generation evaluations, failure modes, and three feedback loops (model loop, dogfooding loop, marketplace loop) to maintain high agent performance at scale.

Generation Evals & Pairwise Comparison

  • Explanation: Evaluating image generation and enhancement using prompt generation, multi-dimensional QA gates, pass@k metrics, and pairwise comparisons.
  • Key claims:
    • Generation pipeline uses a 3-step process: generate prompt, enhance image, and pass through QA gate.
    • QA gate checks faithfulness, portion size, natural plating, colors/textures, and sharpness.
    • Pairwise comparison (pass@k) assesses whether the generated image is a better version of the original.

Key Points

End-to-end logging must be established first

  • Explanation: Without comprehensive, flat JSON logging across all agent steps from the start, it is impossible to optimize or build self-learning loops.
  • Evidence: Mentioned during agent orchestration discussion and code overview using Arize.
  • Practical implication: Engineers should prioritize telemetry and structured logging before building complex agent feedback mechanisms.

Human labels as the golden source of truth

  • Explanation: Using objective guidelines for human labelers removes subjective bias and provides a reliable baseline for offline alignment.
  • Evidence: Offline human alignment workflow for routing and generation evals.
  • Practical implication: Invest in clean, unbiased human-labeled evaluation datasets before training or tuning agent prompts.

Config-driven automated tuning pipelines

  • Explanation: Using a diagnoser agent to analyze production drift, rewrite agent configurations, and trigger auto-tuning pipelines keeps systems sharp over time.
  • Evidence: Detailed explanation of online tuning focused on drift without human-in-the-loop.
  • Practical implication: Automate closed-loop tuning to reduce maintenance overhead for production AI agents.

[~]Tradeoffmedium noveltystrong evidence

The routing guardrail metric is deliberately asymmetric: recall is the optimization target so bad images cannot slip into the system, accepting over-enhancement (precision loss) as the cheaper error.

Why it matters

Picking recall over precision is a value judgment encoded as a metric, and it directly determines which failure examples the team treats as bugs.

Generalization

In gated pipelines, choose the guardrail metric by the asymmetry of downstream cost, not by generic F1-style balance.

[M]Mechanismmedium noveltystrong evidence

Why it matters

Pairwise-vs-original framing directly targets regressions (edits that are worse than the input), which absolute quality scores cannot detect; the multi-dimension gate separately catches specific hallucination classes like added ingredients.

For enhancement/edit agents, evaluate each output against its own input as a pairwise baseline, not only against an absolute quality rubric.

Guardrails for agents that rewrite production configuration

Research question

What validation, canary, and rollback envelope is required before an LLM diagnoser's rewritten agent configuration is promoted to production, and does shadow evaluation on held-out human-labeled data reduce blast radius?

Why

The talk places an LLM in the tuning layer, not just the inference layer. That creates a new class of production change whose blast radius spans every routed item, yet no promotion gate is described. Without a promotion contract, drift remediation and drift causation become indistinguishable.

Source video ↗

Quantifying 'avoid sameness' as a marketplace-level eval metric

Research question

Which distributional diversity metrics over generated image sets (embedding spread, prompt/style entropy, pairwise perceptual distance) correlate with marketplace conversion, and can a per-item eval harness detect a collapse toward sameness?

Why

The objective triple explicitly includes a cross-item constraint that no per-item quality gate can observe. If sameness is not measured, a locally improving agent can monotonically degrade the shared marketplace surface while every item-level metric stays green.

Source video ↗

Representativeness and staleness control in production sampling for drift detection

Research question

How should production samples be stratified (by geography, device type, dish type, merchant tier) so that label-distribution drift is detected before it moves marketplace metrics, and what sampling cadence bounds detection latency?

Why

The entire closed loop is only as good as the sample it diagnoses. If sampling is unstratified or silently stale, the diagnoser rewrites configs in response to a distribution that no longer exists, and auto-tuning becomes a drift amplifier rather than a corrector.

Source video ↗

Cost-weighted evaluation of the router as a compute valve

Research question

Does optimizing the router's recall-first guardrail on a cost-weighted confusion matrix rather than on F1 change the routing threshold enough to materially alter generation spend per thousand items at constant quality?

Why

The router is simultaneously the quality gate and the spend control for the whole pipeline, so its threshold is an economic parameter. A precision miss documented in the talk (a good cheeseburger flagged as low quality) is not a quality bug but a budget line item, and should be evaluated as one.

Source video ↗

Calibrating pairwise pass@k against human pairwise judgment

Research question

How much do automated pairwise-vs-original pass@k judgments agree with human pairwise labels, and does agreement hold across dish types where portion size and plating expectations differ?

Why

The QA stack combines a multi-dimension rubric, pairwise comparison, and human labels, but if pass@k diverges from human judgment per segment it will silently validate edits that the golden source rejects, making the two layers of the eval stack contradictory rather than layered.

Article ideas

4

Your Trace Schema Is the Real Agent Interface

Teams that build agents and then bolt on observability cannot build self-learning loops; the flat per-step record contract must be designed first because it is the substrate that every tuning loop consumes, and it therefore deserves versioning discipline like any other public interface.

Angle

Invert the standard build order using a single production case: show which tuning capabilities became possible only because the logging contract existed up front, and what breaks when the schema drifts.

Source video ↗

Recall Is a Budget Decision, Not a Quality Preference

Choosing recall for a gating classifier is not a generic best practice but a statement about asymmetric downstream cost; teams should derive the guardrail metric from the price of each error and evaluate the router on a cost-weighted confusion matrix instead of F1.

Angle

Walk through the recall-first routing decision and show how the accepted precision loss (routing high-quality images needlessly) is a compute line item, not a quality bug.

Source video ↗

Putting an LLM in the Tuning Layer Changes Who Owns Drift

Moving drift remediation from a human reading dashboards to a diagnoser agent that rewrites configuration relocates responsibility for correctness: the config becomes generated output, so it needs its own canary, shadow evaluation, and rollback path before any loop closes automatically.

Angle

Reframe the sample, compare, diagnose, rewrite, redeploy loop as a code-generation pipeline and apply the same release engineering rigor to it.

Source video ↗

Per-Item Gates Cannot Measure Marketplace Sameness

When an agent acts across many items on a shared surface, per-item quality gates miss the failure mode that matters most: the gradual collapse of diversity; distributional constraints must be promoted to first-class objectives with their own metrics and owners.

Angle

Use the uniform-prompt collapse as the concrete illustration of a metric that is invisible to item-level evaluation but decisive for marketplace trust.

Project ideas

4

Config-Diff Shadow Gate

beyond-evals

A diagnoser-generated configuration change that is shadow-evaluated against a held-out human-labeled set before promotion will show lower regression rates on production metrics than direct promotion of the same rewrite, at a bounded evaluation cost.

Proof of concept

Wrap the diagnoser's rewritten configs in a promotion service that replays both old and new configs against a frozen stratified human-labeled sample, computes per-dimension deltas on the existing QA rubric, and requires a positive pairwise delta before canarying to a small traffic slice with automatic rollback.

Measurement

Regression rate of promoted configs (fraction that must be rolled back), per-dimension QA delta between shadow and production outcome, and added evaluation cost per promotion.

Source video ↗

Sameness Meter

movement-lab

Embedding spread and prompt/style entropy computed over a generated image batch will detect a diversity collapse at least one tuning cycle earlier than marketplace conversion metrics, and will correlate with conversion when conversion eventually moves.

Proof of concept

Compute per-batch distributional diversity metrics over generated images for a fixed menu cohort, replay historical batches where a prompt change occurred, and compare the metric trajectory against the corresponding A/B conversion series.

Measurement

Lead time in days between diversity-metric deviation and conversion deviation, plus rank correlation between the two series across cohorts.

Source video ↗

Cost-Weighted Router Bench

gatehouse

Tuning the routing threshold on a cost-weighted confusion matrix (where a precision miss is priced as wasted generation spend) will find a threshold that reduces generation spend per thousand items with no measurable drop in downstream QA pass rates, compared to a recall-only threshold.

Proof of concept

Build an offline replay harness over logged routing decisions with known downstream labels, sweep the threshold, and plot spend per thousand items against QA pass rate and faithfulness-gate failure rate to locate the Pareto frontier.

Measurement

Generation spend per thousand items at matched QA pass rate; change in false-positive routing rate; faithfulness failure rate at the chosen threshold.

Source video ↗

Drift Sampling Simulator

new

Stratified production sampling by geography, device type, and dish type detects injected label-distribution drift earlier than uniform random sampling at equal sample volume, and the detection advantage grows as drift concentrates in one segment.

Proof of concept

Simulate a production stream with synthetic segment-level drift injections, run stratified versus uniform samplers at matched budget, and measure detection latency and false-alarm rate for each sampling policy as drift concentration varies.

Measurement

Detection latency in sample cycles at fixed false-alarm rate; segment-level recall of drift detection; samples required per true drift event.

Architectural implications

3

Observability is a prerequisite layer that the tuning loop depends on, rather than a downstream add-on.

Before

Build agent, then add logging/dashboards when something breaks.

After

Define a flat per-step JSON record schema consumed by both debugging and automated tuning before agent behavior is finalized.

Consequence

The trace schema becomes a versioned interface; changing agent steps requires changing the record contract, and tuning pipelines break if it drifts.

Source video ↗

An agent (the diagnoser) now sits in the tuning/configuration layer, not only in the inference path.

Before

Humans read eval dashboards and edit prompts/configs manually.

After

A diagnoser agent analyzes drift, rewrites configurations, and triggers auto-tuning pipelines without human-in-the-loop.

Consequence

New safety surface: config-rewriting agents need their own eval and rollback, since their output changes production behavior broadly.

Source video ↗

Evaluation is stratified into three loops with distinct signal types (human labels, internal feedback, business A/B metrics).

Before

One offline eval suite used as the proxy for all quality questions.

After

Separate loops per signal scope, with the marketplace loop sliced by geography, device type, and dish type.

Consequence

Teams must reconcile conflicting signals across loops and decide which layer owns a given regression.

Tradeoffs and failure modes

5

Routing guardrail metric selection

Benefit

Optimizing recall ensures bad images do not slip into the enhancement system.

Cost or risk

Loses precision, e.g., a high-quality image is flagged as low quality and unnecessarily routed, spending generation cost.

Agency vs determinism in an image agent

Benefit

Agents balance deterministic rules with creative agency, avoiding uniform outputs across the marketplace.

Cost or risk

Higher agency raises the risk of unfaithful or hallucinated edits that break consumer trust.

Automated generation QA gates

Benefit

Prevents hallucinated food items, reward hacking, and unrealistic edits from reaching production menus.

Cost or risk

Multi-dimension QA plus pairwise pass@k adds evaluation cost and can still be gamed structurally (reward hacking).

AI-generated food photography

Benefit

Cost or risk

Benefit
