Summary

Overview

  • Speaker: Sam
  • Channel: AI Engineer
  • Main topic: AI Agent Governance, API Gateways, and Security Architecture
  • Purpose: To demonstrate why AI agent governance must move from agent-level prompts and policies to gateway-level infrastructure enforcement for improved security, scalability, and cost control. The speaker, Sam, CTO at Gravitee, argues that relying on user prompts, markdown files, or agent-level permissions to enforce AI policy and security does not scale and fails in production. Instead, AI governance, identity management, cost control, semantic caching, and rate limiting must be shifted upstream to the infrastructure layer using an API gateway. Through live architectural comparisons, Sam demonstrates how gateway-level control blocks unauthorized API calls, prevents PII leaks, and manages LLM costs efficiently.

Key Points

Prompts are not security boundaries

  • Explanation: Relying on prompt instructions or markdown policies to restrict AI agent behavior fails because LLMs prioritize user helpfulness and can be jailbroken or bypassed.
  • Evidence: Demonstrated live where prompt-governed agents executed unauthorized deletions, while gateway-governed agents were blocked.
  • Practical implication: Security and governance must be enforced in infrastructure, not in natural language prompts.

Decoupling front-end agents from back-end services

  • Explanation: Agents should be decoupled from MCP servers, databases, and LLMs using an API gateway to manage permissions, routing, and caching.
  • Evidence: Gateway intercepting tool calls and evaluating JWT claims and runtime permissions.
  • Practical implication: Enables scalable multi-agent architectures without exploding infrastructure complexity.

Gateway-level cost and rate controls

  • Explanation: Enforcing token limits and rate limits at the gateway prevents runaway loops from draining budgets.
  • Evidence: Comparison of ungoverned multi-call loops versus gateway rate-limited calls.
  • Practical implication: Protects organizations from unpredictable financial exposure in production AI systems.

Deep dives

Falsifying prompt-based agent governance: repeatability and boundary conditions of runtime policy bypass

Research question

Under what conditions does prompt/markdown-level agent governance reliably fail to block unauthorized tool calls, and what is the bypass rate as a function of prompt-injection pressure, context length, and tool surface size?

Why

The entire case for moving governance to the gateway rests on the empirical claim that prompt-level policy is bypassed at execution time. If bypass is rare or model-version-dependent, the infrastructure argument weakens; if it is pervasive, every agent-with-tools deployment needs an enforcement chokepoint on the invocation path.

Source video ↗

Task-scoped agent identity: deriving and propagating per-tool-call claims for gateway authorization

Research question

How does a gateway derive an agent's task-scoped identity and authorized claim set for each individual tool call, and can a token-exchange flow issue narrower credentials per invocation without breaking multi-step agent plans?

Why

Per-call authorization is the mechanism that makes gateway enforcement more than a coarse allow/deny list. Without a concrete scheme for mapping task intent to scoped credentials, the gateway either over-grants (agent identity reused across all tools) or breaks legitimate multi-step workflows.

Source video ↗

Semantic cache correctness: false-hit rate, staleness, and invalidation for gateway-level LLM response caching

Research question

On a skewed real-world query distribution, what is the semantic-cache false-hit rate (similar but not equivalent intents), and how much answer correctness degrades versus the cost and latency saved?

Why

The claimed benefit is zero cost and zero latency, but the unaddressed liability is serving semantically adjacent but wrong answers. Quantifying hit precision and invalidation cost determines whether semantic caching is a net win or a correctness hazard at the shared-infrastructure layer.

Source video ↗

Gateway rate limiting as a deterministic cost circuit breaker for runaway agent loops

Research question

Does per-minute rate limiting on the tool-call surface contain runaway agent loops more effectively than loop detection inside the agent, and at what threshold does it begin to throttle legitimate high-volume agent workloads?

Why

One agent turn can fan out into many backend calls, so the cost chokepoint is the tool-call surface, not the model call. Determining the operating threshold separates a cost circuit breaker from a throughput tax that masks underlying loop bugs.

Your Agent's System Prompt Is Not a Security Boundary

Natural-language policy is a suggestion to a component optimized to be helpful; the only governance that survives prompt injection and model drift is enforcement on the invocation path, which means the trust boundary for agents belongs at the gateway, not in the markdown file.

Angle

Treat agent governance as the client-side-validation fallacy of the LLM era: we already know not to trust the caller, yet we keep shipping policy as prose and calling it control.

Per-Call Authorization for Agents: Why 'Authenticated Agent' Is Not Enough

Authenticating the agent once and granting it a broad token reintroduces the very privilege-escalation risk governance was supposed to remove; agent authorization must be evaluated at each tool invocation against task-scoped claims.

Angle

Borrow the workload-identity and token-exchange patterns from service meshes and apply them to agent-to-tool traffic, with concrete guidance on scoping claims to a task rather than a session.

BypassBench: Prompt-Policy Evasion Harness for Tool-Using Agents

gatehouse

A tool-using agent governed only by system-prompt or markdown policy will execute unauthorized mutating tool calls in a measurable fraction of trials, and that fraction is materially reduced (approaching zero) when the same calls are authorized at a gateway using runtime claims.

Proof of concept

Build a pair of identical agent configurations against the same MCP-style tool set: one governed by prompt policy, one behind a gateway that evaluates JWT claims per call. Run a fixed adversarial and benign task suite (including destructive and PII-retrieval tasks) against both and record executed vs. blocked calls.

Measurement

Unauthorized-call execution rate per configuration, blocking latency added by the gateway, and false-block rate on legitimate tasks.

Source video ↗

Task-Scoped Agent Credential Broker

gatehouse

A token-exchange service that mints narrow, short-lived credentials per tool call from a task descriptor can authorize multi-step agent plans without over-granting, keeping the over-grant window bounded by a single invocation.

Proof of concept

Intercept agent tool calls, map each call's intent plus agent identity to a scoped claim set, issue a short-TTL token, and have the gateway validate it. Test on a multi-step plan requiring different privilege levels across steps.

Measurement

Privilege breadth per issued token (count of authorized verbs/resources), plan success rate without manual re-scoping, and number of denied calls caused by scope mismatch.

Source video ↗

Semantic Cache Hit-Precision Audit

beyond-evals

Semantic caching at the gateway reaches high cost savings on skewed query distributions but exhibits a non-trivial false-hit rate on near-miss intents, and the correctness loss is not uniform across query categories.

Proof of concept

Instrument a gateway semantic cache in front of an LLM endpoint, replay a skewed intent distribution (including deliberately near-miss pairs such as variants of 'list my bookings'), and grade cached responses against fresh-model responses.

Measurement

Hit rate, false-hit rate by intent category, answer-equivalence score for cache-served vs. fresh responses, and tokens/latency saved per correct answer.

Source video ↗

Loop-Breaker Threshold Study

new

Per-minute rate limiting at the gateway caps runaway-loop cost with negligible impact on legitimate agent workloads, provided the threshold is set from observed fan-out-per-turn rather than a uniform default.

Proof of concept

Run a deliberately looping agent and a legitimate high-fan-out agent through the same gateway with configurable per-minute limits; sweep thresholds and record cost, completion, and throttling outcomes for each.

Measurement

Tokens/backend calls consumed before and after the cap, legitimate-task completion rate at each threshold, and throttled-request count attributable to true loops vs. valid work.

Tradeoffs and failure modes

3

Centralizing agent governance in a gateway

Benefit

Deterministic, prompt-injection-resistant enforcement of security, rate limits, and caching across all agents.

Cost or risk

Introduces a gateway as a critical path dependency and single point of enforcement/failure; all agent traffic must be routed through it to be governed.

Semantic caching of LLM responses at the gateway

Benefit

Zero cost and zero latency for repeated or similar intents.

Cost or risk

Serving 'similar' prompts from cache can return responses that are semantically close but wrong for the specific request; correctness risk is not addressed in the summary.

Gateway rate limiting as cost control

Benefit

Stops runaway agent loops from draining budgets without burdening the downstream LLM or MCP server.

Cost or risk

A blanket per-minute limit can throttle legitimate high-volume agent workloads or mask underlying loop bugs rather than fixing them.
