Overview

  • Speaker: Felippe Felisola Caso & Francesco Galletta
  • Channel: AI Engineer
  • Main topic: Monzo's in-house AI coding agent (Agent Chip) built using LLMs and internal platform capabilities
  • Purpose: To share Monzo's architectural approach, internal tooling investments, and business outcomes achieved by deploying an in-house agentic platform powered by LLMs. Felippe Felisola Caso and Francesco Galletta from Monzo present how they built an in-house AI coding and agentic assistant called Agent Chip. Operating at a bank with over 3,000 backend services and thousands of data warehouse models, Monzo leveraged an existing strong internal platform—including an MCP (Model Context Protocol) gateway and an agent orchestration system running in isolated sandboxes—to enable Agent Chip to author over 10% of merged PRs, execute 1,800+ tasks daily, and assist both technical and non-technical business users.

For any agent touching production systems, the tool-access gateway (authn/authz, capability scoping, deterministic response shaping) is the load-bearing component; the agent runtime is a replaceable shell around it.

[A]Architecturemedium noveltystrong evidence

Ablating the agent platform: which layer actually produces the uplift

Research question

Of the MCP gateway (auth/authz + determinism-shaping), sandbox isolation with egress proxy, the orchestration layer, and the Slack front-end, which component contributes what fraction of task success rate, tool-call error rate, and escalation-to-human rate?

Why

The 'Lots of Little Multipliers' framing bundles four distinct investments with no ablation. Without it, teams copy the whole stack or none of it, and cannot tell whether the gateway's determinism-shaping is a capability enabler or a capability ceiling for ambiguous tasks.

Source video ↗

Post-merge quality accounting for agent-authored changes

Research question

What is the revert rate, 7-day follow-on fix-commit rate, and review-comment density of agent-authored merged PRs compared with human-authored PRs in the same repositories?

Why

'Over 10% of merged PRs' is an authorship metric, not an outcome metric. If agent PRs carry a higher follow-on fix rate, the 10% number is a rework transfer rather than a capacity gain, and the review gate is weaker than it appears.

Review and verification as the relocated bottleneck

Research question

When both agent-authored changes and non-specialist-authored changes enter the same review queue, does end-to-end delivery time improve, or does cycle time move into review and staging verification?

Why

Expanding the author base without expanding review capacity just moves the queue. This determines whether review tooling, intent-capture in PR descriptions, and staging-test coverage are the next infrastructure investments or an afterthought.

Ownership and escalation protocol for always-on agents with write access

Research question

For event-triggered agent actions (dbt alert failure triage, data-quality alerts), what escalation threshold, ownership assignment, and failure-attribution model keeps a wrong draft PR from becoming a silent no-op?

Why

A draft PR is only a trust boundary if someone is accountable for reviewing it. Without explicit escalation and ownership, always-on agents generate reviewable artifacts that nobody is routed to, converting proactive triage into backlog generation.

Invocation cost as the real adoption variable

Research question

Is internal agent adoption driven by interface placement and near-zero invocation cost, or by model capability — testable by holding the model and tool surface fixed while moving the invocation surface?

Why

If interface dominates, agent distribution strategy is an architectural decision, not a UX afterthought. The same evidence also flags the cost: emoji-reaction prompts carry no natural metadata for scoping or intent, which is exactly what later review needs.

Your Agent Is a Shell; the Gateway Is the Product

The load-bearing engineering in a production agent is the tool-access gateway — centralized authn/authz, capability scoping, and deterministic response shaping — not the agent loop or the model. Teams that build the agent first and retrofit the gateway hit the security and reliability wall that Monzo pre-empted by treating the platform as the primary multiplier.

Angle

Reframe 'LLM' as 'Lots of Little Multipliers' and walk the concrete consequence: swapping the model provider or adding a second agent re-exposes no credentials, because tool onboarding happened once at the gateway.

Source video ↗

10% of Merged PRs Is Not a Quality Metric

Agent-contribution share is an activity metric masquerading as an outcome metric. Until agent-authored PRs are instrumented for revert rate, follow-on fix commits, and review-comment density — and until agent review verdicts are separated from human review verdicts — an agent-authored PR share tells you about volume, not about whether the human gate is still doing work.

Angle

Propose a standard agent-contribution scorecard and use the 'Looks good to me' review anecdote as the warning shot: agents reviewing agent-authored code is where review becomes ceremonial.

Source video ↗

The Emoji Is the Architecture

Distribution is part of the system design. Placing the agent where work already happens, at near-zero invocation cost, is what converted a novelty into a teammate executing more than 1,800 tasks daily — and the same frictionlessness is why scoping and intent metadata must be designed back in at the interface rather than the prompt.

Angle

Argue that the front-end choice determines both adoption curve and volume control, then show what the emoji interface structurally cannot capture.

Gateway Ablation Harness

gatehouse

Disabling gateway determinism-shaping for a cohort degrades tool-call error rate on ambiguous tasks while improving success rate on narrow tasks, proving the gateway trades capability breadth for reproducibility and that the tradeoff is measurable per task class rather than global.

Proof of concept

Wrap an MCP gateway behind a feature flag with two modes (deterministic-shaped responses vs raw tool responses); route a fixed task corpus across both cohorts against the same sandboxed agent and tool ledger; log tool-call error rate, task success, and escalation-to-human.

Measurement

Per-task-class delta in tool-call error rate, task success rate, and human escalation rate between gateway modes, with task-class split by ambiguity.

Agent Contribution Scorecard

beyond-evals

Agent-authored merged PRs exhibit a measurably higher 7-day follow-on fix-commit rate than human-authored PRs in the same repositories and change-size band, meaning PR-count share overstates net capacity gain.

Proof of concept

Instrument a PR feed to tag authorship (agent vs human vs non-specialist-via-agent), then auto-compute revert rate, follow-on fix commits within N days, and review-comment density per PR; join against files and change size to control for repository.

Measurement

Revert rate and 7-day follow-on fix rate per authorship class, matched by repo and diff size; plus review-comment density as a proxy for review depth.

Containment Red-Team Bench

gatehouse

With sandbox isolation plus an egress proxy as the only external path, hallucinated or adversarial tool sequences cannot reach systems outside the declared tool ledger, and the residual failure modes are confined to legitimate-tool misuse rather than exfiltration or lateral movement.

Proof of concept

Build a sandbox mirroring the isolated-namespace / agent-image / proxy topology; run a red-team corpus of prompt-injection and over-broad tool-use attempts; record every blocked egress attempt and every action that succeeded within permitted tools.

Measurement

Escape rate (actions outside declared tools or past the proxy), blocked-egress attempt count, and blast-radius score per attack class.

Zero-Friction Invocation Experiment

movement-lab

Holding model and tool surface fixed, embedding the agent in the existing collaboration surface at near-zero invocation cost drives higher weekly active requesters and higher cross-functional (non-engineer) share than a standalone agent UI.

Proof of concept

Deploy the same agent behind two front-ends — an in-channel reaction-triggered interface and a separate web console — with randomized opt-in cohorts; log requesters, requests, and requester job function, and sample intent clarity of resulting artifacts.

Measurement

Weekly active requesters, requests per requester, and non-engineer share of requests per front-end; secondary: fraction of requests lacking usable scope/intent metadata.

Architectural implications

3

Auth and authorization were moved out of individual tools and into a shared MCP gateway sitting between the agent and internal services.

Before

Each internal service or tool exposes its own credentials and permission checks to whatever calls it, including an agent.

After

A single MCP server owns auth/authz and determinism-shaping for all agent-accessible tools and knowledge sources.

Consequence

Agent permissions become centrally auditable and revocable; a new tool is onboarded once, and adding a second agent or swapping the model provider does not re-expose credentials.

Source video ↗

Agents are confined to an isolated namespace with a dedicated agent image and an egress proxy.

Before

An agent runs with ambient network access and broad filesystem/credential reach on the host.

After

The agent has explicit, bounded tools plus a proxy as the only path to external systems such as GitHub.

Consequence

Compromise or hallucinated actions are contained to the sandbox; egress becomes the choke point for logging, rate limiting, and policy on what the agent can reach.

Source video ↗

The agent's write output is deliberately capped at reviewable artifacts (draft PRs, drafted Slack replies) rather than merged changes or direct production actions.

Before

Automation either does nothing or performs the final action end-to-end.

After

Agent produces a candidate change; a human or staging pipeline performs the commit/merge step.

Consequence

The human review surface becomes the system's real safety boundary and its throughput bottleneck — making review tooling and reviewer load the next infrastructure investment.

Tradeoffs and failure modes

4

Viral low-friction invocation

Benefit

Emoji-reaction prompting removed all activation energy, driving adoption from engineers to business users.

Cost or risk

Low invocation cost also lowers the deliberateness of each request; volume (1,800+ tasks/day) and unbounded scope creep across domains become the operational load, and the interface gives no natural place to attach scoping or intent metadata.

Source video ↗

Agent-authored PRs entering human review

Benefit

More than 10% of merged PRs are agent-authored, absorbing routine change work.

Cost or risk

Review quality can degrade toward rubber-stamping; the summary itself cites senior engineers receiving agent code reviews that conclude 'Looks good to me,' which cuts both ways if agents review agents.

Source video ↗

Democratizing contribution for non-specialists

Benefit

Business users can query data and initiate staging-tested PRs without deep coding expertise, relieving engineering bottlenecks.

Cost or risk

Expanded author base raises the fraction of changes whose intent is not legible to reviewers, shifting risk into staging-test coverage and review, which must now catch semantics rather than syntax.

Source video ↗

Determinism enforced at the gateway

Benefit

Constraining tool behavior at the MCP layer makes agent actions reproducible and auditable despite non-deterministic LLM reasoning.

Cost or risk

Determinism-shaping tool responses can strip nuance the model needs, creating a ceiling on capability for ambiguous tasks — the agent is safe precisely where the gateway has predefined the semantics.
