[O]Mental Modelmedium noveltymoderate evidence

Agentic AI is positioned not as a replacement abstraction for automation and generative AI, but as a layer stacked on top of both: the LLM supplies open-ended reasoning while orchestration supplies goal direction, so the agent is a goal-directed composite rather than a smarter model.

Why it matters

Framing the agent as an orchestration-plus-LLM composite (rather than a model property) determines where engineers put the goal state, planner, and control loop; it implies the hard engineering work lives in orchestration and goal specification, not in the model itself.

Generalization

Any agentic system can be decomposed into a reasoning substrate plus an orchestration layer that owns goals; evaluating one without the other is an incomplete evaluation.

[A]Architecturemedium noveltymoderate evidence

Risk monitoring shifts from a periodic, post-collection batch review (analyze data after it lands in the system) to a continuous 24/7 scan of upstream source systems (EDC, labs) that emits real-time risk scores plus recommended mitigation actions routed to specific owners such as site owners and CROs.

Why it matters

This changes the integration boundary: agents must hook into live operational systems of record and produce not just alerts but ranked scores and action recommendations addressed to accountable humans. That requires event/stream ingestion, anomaly scoring, action-recommendation generation, and a routing/escalation surface — a materially different subsystem than a reporting pipeline.

Generalization

Monitoring agents are most valuable when they read directly from the systems where work happens and emit an action plus an owner, rather than emitting a report after the fact.

A per-task autonomy policy control plane for agents

Research question

What minimal policy specification (thresholds, escalation triggers, approval gates, handback state) lets one agent runtime switch between autonomous execution and human collaboration per task, and how does it change review burden vs. throughput?

Why

The talk treats human-in-the-loop as configurable flexibility, not a fixed gate. That means autonomy has to be a runtime property with explicit escalation and handback semantics — a control plane — otherwise teams either over-gate (reintroducing the human latency they were removing) or under-gate (removing oversight a regulated domain requires). Without a specified policy format, the claim is unfalsifiable.

Alert quality and calibration for continuous upstream risk monitoring

Research question

What precision/recall and false-positive rate must a 24/7 anomaly-scanning agent hold before the sustained alert stream costs less in review effort than the periodic post-collection review it replaces?

Why

Continuous scanning is only an improvement if alert quality stays above the point where human reviewers can absorb the stream. The talk asserts real-time scoring and recommended mitigations but gives no accuracy, alert-volume, or calibration evidence, so the net-benefit claim is currently an argument, not a result. This is the single number that determines whether the architecture change pays off.

Verification harness for regulated-domain agents

Research question

What verification procedure — correctness tests, guardrail-compliance checks, auditability artifacts — should precede deployment of an agent that can act on trial data, and at what residual failure rate is it acceptable?

Why

The platform is described as offering 'verified agents,' but the verification procedure is unspecified. In a regulated domain, verification is the deployment gate, so 'verified' must decompose into measurable test classes and acceptance thresholds. This also determines whether guardrails plus context grounding actually reduce errors enough at the decision boundary.

Digitizing a Workflow Doesn't Fix Eroom's Law — Replacing Reactive Decisions Does

The paper-to-electronic transition failed to change trial cost curves because it moved data capture without changing the decision model; agentic AI only produces productivity gains where it removes or augments reactive decision steps, and the honest metric is throughput per human capacity, not modernization.

Angle

Treat the historical electronic-systems shift as a controlled natural experiment in technology substitution without workflow redesign, and derive the design rule for agent deployments from what it failed to change.

Your Monitoring Agent Is a Report Generator Until It Emits an Owner

Monitoring agents only become decision support when they read directly from the systems where work happens and emit a ranked action addressed to an accountable human, which forces ingestion, scoring, recommendation, and routing/escalation to be built as one subsystem rather than added as a reporting pipeline.

Angle

Architecture teardown of the boundary change from post-collection batch review to live source-system scanning, with the integration contract as the deliverable.

Autonomy Is a Configuration, Not a Mode

Framing agentic systems as either autonomous or human-in-the-loop is the wrong axis; autonomy belongs in a per-task policy layer with defined escalation and handback semantics, and the design question is what that policy must specify to be auditable.

Angle

Argue against the fully-autonomous myth by showing what a runtime needs when humans are intervenable at variable points instead of a mandatory gate.

Reuse Rate Is the Only Agent-Platform KPI That Prevents Pilot Purgatory

The pilot-to-production failure mode is not weak model accuracy but treating each pilot as a one-off demo; if capabilities are not built once as platform assets and composed through existing APIs, small-and-fast scaling is impossible, so reuse rate should be instrumented as a first-class metric alongside accuracy.

Project ideas

4

Autonomy Policy Layer Prototype

gatehouse

Making autonomy level an explicit per-task policy with escalation triggers and handback state reduces human review minutes per completed task without increasing error-escape rate, compared with a single system-wide approval gate.

Proof of concept

Wrap a small set of trial-operations agent tasks (e.g., anomaly triage, data transformation) in a policy layer that declares autonomy level, escalation conditions, and handback state transfer; route low-risk tasks autonomously and gate high-risk tasks to a reviewer with transferred context.

Measurement

Review minutes per task, task throughput, and error-escape rate (agent actions later reversed) with the policy layer on vs. a fixed approval gate off.

Source video ↗

Anomaly Injection Benchmark for Continuous Trial Monitoring

beyond-evals

Continuous scanning of source-system data detects injected anomalies faster than periodic post-collection review, but only above an alert-rate ceiling where reviewer capacity absorbs the stream.

Proof of concept

Build trial-like data with known injected anomalies, run both a continuous 24/7 scanning loop and a periodic post-collection review, and sweep the scoring threshold to trace the sensitivity/alert-volume curve.

Measurement

Detection sensitivity and time-to-detection vs. alerts per reviewer-day (alert fatigue cost), with the threshold at which continuous scanning stops paying off.

Source video ↗

Regulated-Domain Agent Verification Harness

gatehouse

A verification harness that separates correctness, guardrail-compliance, and auditability test classes yields a reproducible residual failure rate per agent capability, and context grounding plus enforced constraints lowers it more than model capability increases do.

Proof of concept

Define acceptance test classes for a set of trial-operations agent capabilities, run them against (a) a base model with guardrails and business context and (b) a larger model without domain grounding, and compare failure modes by class.

Measurement

Residual failure rate per test class, share of failures attributable to guardrail violations vs. capability gaps, and reproducibility of results across repeated runs.

Source video ↗

Reuse-Rate Instrumentation for an Agent Platform

movement-lab

Tracking capability reuse across use cases and geographies predicts which pilots reach production, and governing data cleanliness raises agent task success more than adding raw data volume.

Proof of concept

Instrument an agent platform so each capability records which use cases consume it, then correlate reuse patterns with pilot outcomes while holding model and task constant across a clean-data vs. large-data comparison.

Measurement

Reuse rate per capability, correlation between reuse rate and pilot-to-production promotion, and delta in task success from clean data vs. additional raw data volume.
