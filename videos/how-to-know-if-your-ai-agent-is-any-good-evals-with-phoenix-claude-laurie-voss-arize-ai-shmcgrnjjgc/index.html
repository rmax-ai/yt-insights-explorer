  • Purpose: To guide AI engineers on moving past 'vibes-based' agent development to systematic, automated evaluation using Phoenix and CI/CD pipelines. Laurie Voss, Head of Developer Relations at Arize AI, presents a comprehensive workshop on how to evaluate AI agents using Phoenix and the Claude Agent SDK in TypeScript. He introduces a 7-step process starting from tracing agent steps, reading and organizing data, writing code and LLM-as-a-judge evals, testing the judge against human labels, running experiments, and locking them into CI/CD pipelines.

Key Points

Looks good to me is not a test suite

  • Explanation: Relying on manual spot-checking of a few agent runs leads to unexpected production failures when users use the agent in novel ways.
  • Evidence: Shipping agent features based on 3 manual test runs.
  • Practical implication: Establish automated evaluation suites before shipping AI agents.

Code evals are fast, free, and brittle

  • Explanation: Deterministic functions check formatting and exact matches in milliseconds without API costs.
  • Evidence: String matching and JSON parsing checks.
  • Practical implication: Use code evals for structure and format; use LLM judges for meaning.

LLM judges understand meaning but make mistakes

  • Explanation: Using a second LLM to grade outputs against a rubric handles semantics but can be non-deterministic and costly.
  • Evidence: LLM judge evaluating grounding and tone.
  • Practical implication: Validate LLM judges against human-labeled golden datasets.

Human labels form the golden dataset

  • Explanation: Humans remain the gold standard for quality judgment.
  • Evidence: Annotating 16 traces with actionability labels in Phoenix.
  • Practical implication: Build a golden dataset of 20-100 human-labeled examples to test your judges.

Core insights

6
[!]Failure Modehigh noveltymoderate evidence

An LLM judge is itself an untested model: it must be validated against a human-labeled golden set before its scores are trusted, and its failure mode can be silent and degenerate. In the workshop, adding XML delimiters around few-shot examples flipped an evaluator's classifications from uniformly negative to correct — meaning the judge had been systematically wrong, not merely noisy.

Why it matters

Judges sit in the trust path of every automated quality metric and CI gate. A judge that emits a constant label (all pass or all fail) looks stable and low-variance, so it evades detection by the usual 'the numbers look consistent' heuristic, while silently invalidating every downstream decision. This makes judge calibration a prerequisite, not an optimization.

Generalization

Any LLM used as a grader, router, or classifier in an automated pipeline needs its own labeled test set and per-class agreement metrics; delimiter/formatting sensitivity is a first-class regression surface, and metric stability is not evidence of correctness.

[M]Mechanismhigh noveltyweak evidence

The human bottleneck in observability is not collecting traces but reading them, and the proposed substitute is a coding agent reading traces on your behalf rather than a human skimming transcripts.

Why it matters

This reframes 'manual trace review' from a human ritual into an automated analysis stage that can operate over hundreds of spans, keeping qualitative inspection in the loop without it becoming the scaling limit. It also implies the trace format must be machine-readable and complete enough for an agent to reason over — a constraint on instrumentation design, not just tooling choice.

Generalization

As agent systems generate more telemetry than humans can review, the analysis layer itself becomes an agentic workload; observability infrastructure should be optimized for machine consumers (structured spans, stable schemas) as much as for human dashboards.

Source video ↗
[~]Tradeoffmedium noveltystrong evidence

Eval type should be selected by the property being tested, not by preference: deterministic code checks own format/structure/required content in milliseconds at zero cost, LLM judges own semantics (correctness, faithfulness, tone, actionability) at a cost in money and determinism, and humans own ground truth at a cost in scale.

Why it matters

Teams routinely pay LLM-judge latency and cost for checks that a string match would settle (e.g., 'does the output mention the requested ticker'), or conversely rely on brittle exact matching for semantic qualities. Routing each assertion to the cheapest sufficient mechanism changes eval suite cost and runtime by orders of magnitude.

Generalization

In any verification system, partition assertions by whether they are decidable and cheap versus semantic and expensive; layer the cheap layer first so the expensive layer only runs on outputs that already pass structural checks.

Source video ↗
[P]Practicemedium noveltymoderate evidence

Eval prompts are treated as production code and their acceptance metrics become build gates: experiments run against a golden dataset, and CI/CD fails when scores fall below acceptance criteria rather than when a human feels the diff is fine.

Why it matters

This converts prompt/model/agent changes from an unreviewable diff into a measurable regression surface with a pass/fail boundary. It also introduces a new maintenance burden — the eval suite and golden dataset must be versioned alongside the agent — and forces a decision about how to threshold non-deterministic scores.

Generalization

Any system with non-deterministic outputs needs a statistical acceptance gate in CI rather than a deterministic test suite; the gate's threshold policy becomes an architectural decision, not a tooling detail.

Source video ↗
[A]Architecturemedium noveltymoderate evidence

Tracing is treated as an auto-instrumentation concern (~5 lines registering an SDK module) emitting OpenInference/OpenTelemetry spans, rather than manual logging statements scattered through agent code.

Why it matters

Putting trace emission at the SDK/module boundary keeps observability out of business logic and produces uniform span structure across agent steps, which is what makes traces reusable as eval inputs and dataset material. Manual logging couples instrumentation to code churn and yields inconsistent schemas.

Generalization

Observability for agent runtimes should be a middleware/instrumentation layer conforming to a shared semantic convention, so that traces are a stable substrate consumable by debuggers, eval harnesses, and dataset builders alike.

Source video ↗
[O]Mental Modelmedium noveltyweak evidence

Quality is engineered as stacked imperfect layers — automated evals, manual transcript review, production monitoring and A/B testing — on the assumption that each layer misses different failures, so no single eval is expected to be sufficient.

Why it matters

This shifts the design question from 'how do we write a good eval' to 'what does each layer catch that the others don't,' which justifies paying for redundant coverage (e.g., an LLM judge plus sampled human review plus live monitoring) instead of optimizing one metric to exhaustion.

Generalization

For systems with open-ended failure surfaces, coverage comes from heterogeneous detectors with uncorrelated blind spots, not from maximizing the accuracy of a single detector.

Deep dives

5

Meta-evaluation: certifying an LLM judge before it gates anything

Research question

How many human-labeled examples, and which agreement statistics, are required before an LLM judge's labels can be trusted as a build gate — and how do we detect a degenerate constant predictor that reports stable but uniformly wrong labels?

Why

Judges sit in the trust path of every automated quality metric. A judge that always emits the same label looks low-variance and therefore 'stable', so the usual consistency heuristic cannot catch it; only a human-labeled golden set with per-class agreement can. Without this, CI gates certify nothing.

Source video ↗

Judge prompt sensitivity and drift as a regression surface

Research question

How sensitive are LLM judge classifications to non-semantic prompt perturbations — delimiter placement, few-shot ordering and count, whitespace — and what re-validation cadence detects judge degradation after an underlying model update?

Why

The XML-delimiter flip is a single anecdote showing a silent, total classification inversion. If a formatting change can flip an evaluator from uniformly wrong to correct, the reverse can happen in production with no signal. This makes judge prompts a versioned artifact needing perturbation tests, not a one-time authoring task.

Source video ↗

Statistical release gates for non-deterministic agent outputs

Research question

For the same agent and golden set, how do single-run score thresholds, pass@k, and pass^k compare on false-alarm rate and real-regression escape rate per CI dollar spent?

Why

Gating on non-deterministic scores with a small golden set forces a choice between flaky builds and thresholds loose enough to miss regressions. The gate policy is an architectural decision — it determines CI runtime, API spend, and what class of regression can never be caught before merge.

Source video ↗

Agent-driven trace triage as a replacement for human transcript reading

Research question

Does a coding agent reading structured spans detect known-bad traces at a rate comparable to human reviewers, and at what rate does it produce confidently wrong diagnoses?

Why

The claim that coding agents substitute for human trace reading is asserted without a procedure or validation. If it holds, qualitative inspection stays in the loop without being the scaling limit; if it does not, it reintroduces 'looks good to me' at machine speed and volume. Either outcome constrains how spans must be structured for machine consumers.

Source video ↗

Cost-aware routing of assertions across code evals, judges, and humans

Research question

What is the measured cost and runtime reduction from partitioning an eval suite by decidability — deterministic checks first, judges only on survivors — versus running every assertion through an LLM judge?

Why

Teams pay judge latency and cost for checks a string match would settle, and conversely use brittle exact matching for semantic qualities. Routing assertions to the cheapest sufficient mechanism changes suite cost and runtime by orders of magnitude and is directly actionable, unlike general 'use the right eval type' advice.

Article ideas

4

Your Judge Is a Model, Not an Oracle

An LLM judge is an untested classifier until it has been scored against a human-labeled golden set; because a systematically wrong judge produces stable, low-variance scores, metric consistency is actively misleading evidence of correctness and calibration must precede gating.

Angle

Treat the judge as the system under test: per-class agreement, degenerate-predictor detection, and the XML-delimiter flip as a case study in silent total failure.

Source video ↗

Stop Paying an LLM to Check Your JSON

Most eval suites route assertions to the wrong mechanism; partitioning by decidability — deterministic checks first, judges only on outputs that survive — cuts suite cost and runtime by orders of magnitude while increasing semantic coverage where it actually matters.

Angle

Build the eval suite as a test pyramid with an explicit routing rule per assertion, and show where exact matching silently misgrades semantic quality.

Source video ↗

The Prompt Diff Is the Release Gate

Once eval prompts are versioned like code and acceptance metrics gate CI, the hardest remaining problem is statistical rather than editorial: non-deterministic scores plus a small golden set make every threshold a choice between flaky builds and undetected regressions.

Angle

Frame CI gating as a statistical policy decision — repeated runs, pass@k versus pass^k, threshold selection — and treat golden-dataset refresh as roadmap-critical maintenance.

Source video ↗

Depth in Layers, Not Accuracy in One Metric

For open-ended agent failure surfaces, coverage comes from heterogeneous detectors with uncorrelated blind spots — automated evals, human review, production monitoring — not from optimizing a single eval to exhaustion.

Angle

Reframe the design question from 'how do we write a good eval' to 'what does each layer catch that the others don't', and justify paying for redundant coverage.

Project ideas

4

Judge Certifier

beyond-evals

For a given judge and task, precision/recall estimated from a human-labeled golden set of N examples converges tightly enough at a specific N to support a build gate, and a constant-label judge will be detected by per-class agreement even though its run-to-run variance is near zero.

Proof of concept

Take 100 traces from a real agent, hand-label them, then sweep golden-set size (10, 20, 40, 80) and measure variance in judge precision/recall estimates. Include a deliberately degenerate judge that always returns 'pass' as a control to confirm the variance-based heuristic misses it while per-class agreement flags it.

Measurement

Confidence-interval width on precision/recall versus golden-set size; detection rate of the constant-label control judge; false-certification rate at each set size.

Source video ↗

Judge Perturbation Fuzzer

beyond-evals

Non-semantic perturbations to a judge prompt (delimiter style, few-shot ordering, few-shot count, whitespace) cause classification flips on a labeled golden set at a measurable rate, and that flip rate varies more across perturbations than across repeated runs of a single prompt.

Proof of concept

Generate a matrix of judge-prompt variants around one task, run each against a fixed labeled set, and score agreement with human labels. Report per-perturbation deltas to rank which formatting dimensions are the real regression surface.

Measurement

Per-perturbation accuracy delta and flip rate versus human labels; ratio of perturbation-induced variance to sampling variance across repeated identical runs.

Source video ↗

Gate Policy Bench

gatehouse

For the same agent and golden set, pass^k with a moderate threshold strictly dominates single-run scoring on regression escape rate per CI dollar, and the dominant cost driver is repeated sampling rather than judge pricing.

Proof of concept

Inject a known set of quality regressions into an agent, then run three gate configurations — single-run threshold, pass@k, pass^k — in CI against the same golden dataset and record which regressions each gate catches and which good builds it blocks.

Measurement

False-alarm rate, regression escape rate, CI wall-clock time, and API spend per gate configuration per injected regression.

Source video ↗

Agent Trace Triage

new

A coding agent reading structured OpenInference spans agrees with human reviewers on labeled traces at a rate high enough to substitute for manual transcript reading, but exhibits a measurable rate of confidently wrong diagnoses that must be reported rather than hidden.

Proof of concept

Assemble a labeled trace set containing known-bad and known-good agent runs, have both a human reviewer and an agent-driven triage harness diagnose each trace, and compare diagnoses against the ground-truth labels.

Measurement

Detection rate on known-bad traces, false-positive rate on good traces, confident-but-wrong diagnosis rate, and cost per trace compared to human review time.

Tradeoffs and failure modes

5

Code evals: determinism vs. semantic blindness

Benefit

Millisecond, zero-cost checks for format, structure, and required content.

Cost or risk

Brittle — correct outputs that vary in surface form fail, so exact-match checks are a poor proxy for quality.

Source video ↗

LLM-as-a-judge: semantic coverage vs. trustworthiness

Benefit

Can grade meaning — correctness, faithfulness, tone, actionability — at scale.

Cost or risk

Non-deterministic and paid per call; can be systematically wrong in ways that look like stable metrics, as when every case was labeled negative until delimiters were added.

Source video ↗

Human evaluation: ground truth vs. throughput

Benefit

The gold standard for quality judgment and the source of golden-set labels.

Cost or risk

Does not scale — the documented in-session labeling effort was 16 traces, which is thin evidence for calibrating a classifier.

Source video ↗

Manual spot-checking as a release gate

Benefit

Fast and requires no infrastructure; catches gross breakage.

Cost or risk

Produces confident false confidence — agents pass three ad-hoc runs and then fail on novel user behavior in production.

Source video ↗

CI gating on eval metrics

Benefit

Turns prompt and model changes into measurable regressions caught before merge.

Cost or risk

Non-deterministic scores plus a small golden set make thresholds noisy, inviting either flaky builds or thresholds loose enough to miss real regressions.
