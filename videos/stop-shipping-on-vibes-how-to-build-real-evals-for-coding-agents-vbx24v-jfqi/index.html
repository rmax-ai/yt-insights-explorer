Summary

Overview

  • Speaker: Jessica Wang
  • Channel: AAIF Live
  • Main topic: Evaluating LLM coding agents using evals instead of relying on vibes
  • Purpose: To educate developers on how to design, implement, and run quantitative evaluations for AI coding agents to ensure reliable software releases. Jessica Wang from Braintrust discusses the importance of building rigorous evaluations (evals) for AI-driven coding agents rather than shipping features based on product management 'vibes'. She outlines the core components of evals—datasets, tasks, scoring, and experiments—and compares agentic search vs vector search through a real case study.

Topic Map

The Problem with Shipping on Vibes

  • Explanation: Teams often ship AI features based on anecdotal prompts working or engineering intuition, which lacks quantitative backing.
  • Key claims:
    • Shipping AI features based on vibes is problematic.
    • Engineering teams and PMs testing a couple of prompts is insufficient.
    • You need to quantify your shipping decisions.
  • Examples:
    • PMs testing a few prompts and saying it looks good.
  • Terminology:
    • vibes
    • evals
    • observability
  • Why it matters: Quantifiable evals prevent regressions in model behavior when updates are deployed.

Four Components of an Eval

  • Explanation: Creating an eval requires a dataset, a task, a scoring system, and experiment runs.
  • Key claims:
    • An eval consists of a dataset, task, scoring system, and experiments.
    • Datasets contain golden test cases, edge cases, and failure modes.
    • Scoring determines whether the model output is good or bad.
  • Examples:
    • Deterministic scoring, LLM-as-a-judge, and human review.
  • Terminology:
    • dataset
    • task
    • scoring
    • experiment
    • LLM-as-a-judge
  • Why it matters: A systematic framework is necessary to compare different configurations and prompts reliably.

Agentic Search vs. Vector Search Case Study

  • Explanation: Comparing vector search and agentic search performance on coding agent tasks using Braintrust.
  • Key claims:
    • Vector search converts text/code into numerical embeddings stored in a vector DB.
    • Agentic search gives LLMs access to CLI tools like grep, find, cat to explore code like a human.
    • Agentic search achieved higher accuracy with significantly fewer tokens and lower cost on TypeScript/Go test bugs.
  • Examples:
    • Microsoft's typescript-go repository merge PRs with 'fix' in the title.
    • Swe-bench verified Django related bug dataset.
  • Terminology:
    • vector search
    • agentic search
    • embeddings
    • Swe-bench
    • tracing
  • Why it matters: Helps engineering teams make data-driven decisions on architectural patterns for retrieval in coding assistants.

Key Points

Evals are a team sport

  • Explanation: Building effective evals requires collaboration across AI engineers, product managers, subject matter experts, and data analysts.
  • Evidence: Different roles handle dataset creation, hypothesis testing, data labeling, and scoring definitions.
  • Practical implication: Cross-functional involvement ensures comprehensive test coverage and domain-specific accuracy.

Tracing is critical for sub-processes

  • Explanation: When child processes or sub-agents run, their traces can become orphaned if parent span IDs are not passed via environment variables.
  • Evidence: Claude Code runs as a subprocess, resulting in missing visibility into tool calls without proper environment variable configuration.
  • Practical implication: Passing parent span IDs ensures full observability into every tool call during debugging.

Frameworks, Models & Processes

Braintrust Evals Framework

  • How it works: A loop connecting application production logs, sampled datasets, task configurations, and scoring mechanisms.
  • Components:
    • Dataset
    • Task (Prompt & Model)
    • Scoring System
    • Experiments & Loop
  • When to use: When developing, monitoring, and iterating on LLM applications and coding agents.

Examples & Case Studies

OpenAI had to revert a model update in April 2024 because the model became too sycophantic.

  • Illustrates: Over-training models to be helpful can lead to unwanted behavioral side effects.
  • Lesson: Evals help catch nuances and over-optimization early in model updates.

Vector search made 26 search calls on a Swe-bench run without finding the bug.

  • Illustrates: Vector search provides proximity to code but lacks connective tissue to follow import chains.
  • Lesson: Agentic search follows code logic like a human, leading to better results with fewer tokens.

Core insights

7
[E]Empirical Resulthigh noveltymoderate evidence

On coding-agent bug-fixing tasks, agentic search (LLM driving CLI tools like grep/find/cat) outperformed vector search on accuracy while consuming significantly fewer tokens and lower cost — a single case study that inverts the default 'embed the repo and retrieve top-k chunks' retrieval architecture for code.

Why it matters

Retrieval for code is often assumed to be a vector-DB problem; if tool-driven exploration dominates on real repos, the retrieval layer, cost model, and latency profile of coding agents all change, and embeddings become an optimization rather than the foundation.

Generalization

For domains where correctness depends on following explicit links between artifacts (imports, references, call chains), traversal-based agentic search may beat similarity-based retrieval on cost-adjusted accuracy.

[O]Mental Modelhigh noveltymoderate evidence

The failure mode of vector search on code is not ranking quality but missing connective tissue: embeddings return text near the query but cannot follow import chains, so the agent burns many retrieval calls without ever reaching the defective code.

Why it matters

It reframes the retrieval trade-off as proximity vs. connectivity, which predicts when RAG-style retrieval will fail on structured artifacts even with perfect embeddings.

Generalization

Similarity search is a proximity primitive; any task requiring multi-hop structural traversal (dependency graphs, configs, schemas, incident timelines) needs a traversal or agentic layer on top.

Source video ↗
[M]Mechanismmedium noveltystrong evidence

Tracing breaks at process boundaries: when an agent runs as a subprocess (e.g., Claude Code), child-process tool calls produce orphaned spans unless the parent span ID is explicitly propagated via environment variables.

Why it matters

Observability is the substrate evals and debugging depend on; without cross-process context propagation, an entire class of tool calls is invisible and failures are undiagnosable.

Generalization

Any agent runtime that shells out to CLIs, sandboxes, or sub-agents must treat trace context as an explicit out-of-band artifact (env vars, headers, sidecar) rather than assuming in-process instrumentation.

Source video ↗
[A]Architecturemedium noveltymoderate evidence

The eval framework is a closed loop that starts from production logs: logs are sampled into datasets, run through task configurations, scored, and fed back as experiments — making eval infrastructure a continuous consumer of runtime telemetry rather than a static test suite.

Why it matters

It places dataset curation, scoring, and experiment tracking inside the production feedback path, which dictates where logging, sampling, and scoring services must live in the system.

Generalization

Reliable agent systems need the eval harness wired to production traffic, not maintained as a separate offline benchmark that drifts from real usage.

Source video ↗
[P]Practicemedium noveltymoderate evidence

Experiments must be scored on accuracy, token count, and cost concurrently, because a configuration can win on quality while being economically unviable — quality metrics alone mislead architecture decisions.

Why it matters

Cost and latency are first-class eval dimensions for agents; treating them as afterthoughts lets expensive configurations ship and makes retrieval-architecture comparisons invalid.

Generalization

Any agent design decision should be evaluated on a multi-objective frontier (quality, tokens, cost, latency) rather than a single accuracy number.

[!]Failure Modemedium noveltymoderate evidence

Behavioral over-optimization is a real regression class: OpenAI had to revert a model update in April 2024 because the model became too sycophantic, showing that optimizing a proxy trait (helpfulness) produces unwanted side effects that only evals catch.

Why it matters

It gives a concrete, non-hypothetical instance of why model or prompt updates need pre-ship regression evals rather than post-hoc user complaints.

Generalization

Optimizing any single model behavior creates measurable, often surprising regressions elsewhere; the mitigation is a fixed regression suite that gates every model or prompt change.

[P]Practicelow noveltyweak evidence

Effective evals are a cross-functional artifact: dataset creation, hypothesis testing, data labeling, and scoring-definition are distributed across AI engineers, PMs, subject-matter experts, and data analysts rather than owned by a single team.

Why it matters

It implies eval ownership is an organizational boundary question: scoring rubrics need domain experts, while harness and dataset plumbing need engineers, so the interface between them must be explicit.

Generalization

As agents take on domain-specific work, eval quality is bounded by how domain expertise is fed into dataset and rubric construction.

Article ideas

4

Proximity Is Not Connectivity: Why Vector Search Fails on Code

Vector search fails on code retrieval not because embeddings rank poorly but because similarity cannot follow import chains, so coding agents need traversal tools even when embeddings are available.

Angle

Reframe code retrieval from a ranking problem to a connectivity problem, using the 26-search-call failure and agentic-search token advantage as evidence that retrieval architecture should be evaluated as a graph traversal capability.

Source video ↗

Your Agent's Traces Are Lying to You

Agents that shell out to CLIs and sub-agents produce orphaned spans unless trace context is propagated explicitly across process boundaries, so observability is an instrumentation contract rather than automatic.

Angle

Treat subprocess trace propagation as a first-class reliability bug class, with environment-variable parent span ID injection as the concrete mitigation and orphaned tool calls as the symptom.

Source video ↗

Stop Scoring Agents on Accuracy Alone

Agent evaluations must be scored on a multi-objective frontier of accuracy, tokens, cost, and latency because a configuration can win on quality while being economically unviable.

Angle

Use the agentic-search case study to show that the same experiment can reverse architecture decisions when cost and token counts are treated as first-class eval outputs rather than afterthoughts.

Evals Are Not a Test Suite; They Are a Production Feedback Loop

Eval infrastructure should be wired to production logs and sampled datasets so that shipping decisions are gated on experiments rather than intuition, making eval a continuous consumer of runtime telemetry.

Angle

Describe the loop from production logs to sampled datasets to task configurations to scoring and experiments, and argue that offline-only benchmarks drift from the failures teams actually need to prevent.

gatehouse

Injecting the parent span ID through environment variables into subprocess coding agents eliminates orphaned tool-call spans and produces complete parent-child trace trees without in-process instrumentation.

Architectural implications

3

Retrieval for code shifts from an index service to a tool-using agent loop.

Before

Embed the repository, store vectors, and answer queries with top-k similarity retrieval.

After

Expose filesystem/CLI tools (grep, find, cat) to the model and let it explore iteratively like a human, with embeddings optional rather than foundational.

Consequence

New infrastructure requirements emerge around tool sandboxing, per-step token accounting, step limits, and trajectory-level tracing, while retrieval cost becomes a function of exploration depth rather than index size.

Source video ↗

Trace context must be propagated explicitly across process boundaries.

Before

Instrumentation inside a single process captures the full call tree automatically via in-process context.

After

Subprocess and sub-agent spans require the parent span ID to be injected via environment variables so child tool calls attach to the parent trace.

Consequence

Agent runtimes need a standard convention for out-of-band context propagation, and orphaned spans become a first-class reliability/instrumentation bug class rather than an edge case.

Source video ↗

Eval harness is coupled to the observability pipeline.

Before

Ad hoc prompt testing by PMs and engineers, with no quantitative gate before shipping.

After

A loop where production logs are sampled into datasets, run against task configurations, scored, and iterated as experiments.

Consequence

Dataset versioning, sampling policy, scoring services, and experiment tracking become production components, and shipping decisions become gated on experiment results rather than intuition.

Tradeoffs and failure modes

4

Agentic search vs. vector search for code retrieval

Benefit

Higher bug-finding accuracy with significantly fewer tokens and lower cost on TypeScript/Go bug tasks.

Cost or risk

Multi-step exploration introduces non-determinism, tool-execution surface area (sandboxing/security), and variable latency; the summary reports this from one case study rather than broad measurement.

Source video ↗

LLM-as-a-judge scoring

Benefit

Provides a scalable way to determine whether model output is good or bad without exhaustive human review.

Cost or risk

Judge models can introduce bias or artificially inflate token counts, corrupting both the quality signal and the cost measurements used to compare configurations.

Source video ↗

Optimizing models/prompts for a single desirable trait

Benefit

Improves the target behavior, e.g. helpfulness or user satisfaction.

Cost or risk

Produces unintended behavioral side effects that can force a rollback — as when a model update was reverted for becoming too sycophantic.

Source video ↗

Shipping on qualitative judgment

Benefit

Fast iteration and low process overhead; a few prompts can look good to a PM or engineer.

Cost or risk

No quantitative regression signal, so failures surface in production and teams end up playing whack-a-mole against recurring issues.
