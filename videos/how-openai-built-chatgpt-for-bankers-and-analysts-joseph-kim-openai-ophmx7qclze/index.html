Overview

  • Purpose: To share lessons learned in building vertical-specific AI products in financial services, technical approaches using MCP, and strategic predictions on model progress. Joseph Kim, Head of ChatGPT for Financial Services at OpenAI, discusses the development, motivation, architecture, and future outlook of ChatGPT for Financial Services, a tailored version of ChatGPT Work built for investment banking, equity research, and wealth management. He covers how OpenAI addressed the capability overhang, integrated bundled premium financial data using Model Context Protocol (MCP) tools and connectors, enabled professional-grade artifact generation, and shares predictions on model capabilities toward 2027.

Key Points

The Capability Overhang

  • Explanation: The distance between what AI models are capable of and the value enterprises actually extract from them.
  • Evidence: Internal OpenAI data showing engineering adoption of Codex outpaced finance and legal until dedicated desktop apps were released.
  • Practical implication: Product builders must focus on user experience, domain tools, and workflows to close the gap.

Licensed Data vs. Generic Connectors

  • Explanation: Relying on existing MCP connectors for financial data often introduced latency, errors, and poor search quality.
  • Evidence: OpenAI licensed financial data directly from providers like Crunchbase, Fiscal.ai, PitchBook, and LSEG and indexed it natively.
  • Practical implication: Owning hosting and search infrastructure gives builders greater control over quality, reliability, and fine-tuning.

The Threshold Phenomenon

  • Explanation: Steady model progress results in a sudden perceived leap in usefulness when a task crosses the threshold where human verification time becomes less than manual creation time.
  • Evidence: Historical progress in math benchmarks from high school SAT math to Olympiad gold and research-level proofs.
  • Practical implication: Builders should identify capabilities currently under-appreciated and design interfaces for when those capabilities cross the usefulness threshold.

Scaling vs. Unhobbling

  • Explanation: Scaling increases underlying model intelligence, while unhobbling removes constraints on how models apply intelligence through chat, memory, tool usage, and persistent agents.
  • Evidence: Evolution from basic prompting to tool usage and persistent multi-turn workflows.
  • Practical implication: Combining scaling with persistent agent workflows makes AI more accessible and human-like to work with.

[A]Architecturehigh noveltymoderate evidence

Owning the domain data layer — licensing financial datasets and building custom hosting and search indices — beat delegating retrieval to third-party MCP connectors, which introduced latency, errors, and poor search quality. Data access quality was treated as an infrastructure problem, not a tool-integration problem.

Why it matters

It relocates responsibility: instead of treating retrieval as a thin connector to an external API, the platform takes ownership of ingestion, indexing, and search quality so the model's retrieval surface is deterministic. This is a general pattern for any vertical agent whose value depends on retrieval precision.

Generalization

When retrieval quality is the product, build and own the index rather than composing over someone else's API — connectors are for long-tail sources, not core corpora.

Generalization

Project ideas

4

Index-vs-Connector Retrieval Bakeoff

beyond-evals

For a fixed financial-research query set, an owned and indexed corpus will produce lower p95 retrieval latency, lower tool-error rate, and higher citation-supported answer accuracy than equivalent third-party MCP connectors.

Proof of concept

Build two retrieval paths over the same document corpus: one via external MCP connectors and one via locally hosted search index; expose both through identical tool schemas and compare results on a benchmark of company-overview and filing-based questions.

Measurement

p95 latency, tool error rate, retrieval precision@k, citation validity rate, and human verification time per generated answer.

Source video ↗

Verification Crossover Instrument

beyond-evals

Per-task verification time ratio — human review time divided by manual creation time — predicts whether users will repeatedly use an agent feature better than benchmark accuracy alone.

Proof of concept

Instrument a small artifact-generation workflow to log review duration, edit distance, and acceptance/rejection; compare against a manual baseline for the same task type across model or harness versions.

Measurement

Verification-to-creation time ratio, edit distance, acceptance rate, and feature reuse rate before and after model/harness changes.

Source video ↗

Harness Unhobbling Ablation Rig

movement-lab

Adding persistence and proactivity to a stateless tool-using agent will reduce human verification time on multi-step vertical tasks more than adding memory alone, holding model and tools constant.

Proof of concept

Create a fixed task suite with four harness configurations: stateless, memory-only, persistence-only, and persistent-plus-proactive; run identical domain tasks and capture human review effort.

Measurement

Median verification time delta, task completion rate, intervention count, and unintended-action rate per harness configuration.

Source video ↗

Template Drift Regression Fixtures

gatehouse

Treating firm templates as versioned configuration with regression fixtures will preserve artifact conformance across template updates better than prompt-only formatting instructions.

Proof of concept

Generate PowerPoint and Excel artifacts from a fixed prompt set using skill-based tools; validate outputs against template schemas and visual fixtures before and after a simulated template revision.

Measurement

Template conformance pass rate, human reformatting minutes per artifact, and regression count across template versions.
