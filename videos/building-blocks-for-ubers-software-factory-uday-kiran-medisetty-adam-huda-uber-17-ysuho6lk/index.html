Overview

  • Speaker: Uday Kiran Medisetty and Adam Huda
  • Channel: AI Engineer
  • Main topic: Agentic AI at Uber scale and building blocks for an AI-native software engineering factory
  • Purpose: To showcase Uber's enterprise-scale architecture and building blocks for an AI-native software engineering factory and demonstrate how agentic workflows operate across the SDLC. Uday Kiran Medisetty and Adam Huda discuss Uber's journey towards a managed software factory powered by agentic AI. Operating across 12 global tech hubs with thousands of engineers, Uber has invested in agentic AI to double line-of-code velocity and automate migration and engineering toil. The talk outlines six core building blocks: Model Gateway, MCP Gateway, DevPods, Agent Skills, Context Graph, and AI Assistant (Cortana), followed by an end-to-end demonstration of how an idea moves from Slack to specs, PRs, self-improvement validation, and codebase maintenance.

Centralized inference gateway as a critical-path dependency

Research question

How do you budget and degrade a shared Model Gateway (PII redaction, guard, cache, attribution) so that one control-plane hop does not become the availability and latency ceiling for every AI feature in the company?

Why

Uber's scale claim (800 projects, 100M+ requests/day) plus a sub-100ms guard budget means the gateway's own SLOs are now the SLOs of all internal AI. Most orgs adopting a gateway decide the policy but never model the failure domain or a degraded-mode contract.

Freshness and coverage failure of a bounded typed context graph

Research question

At what staleness threshold does a 150-node-type, 40M-entry context graph produce confidently wrong context, and are missed-context failures detectable at inference time?

Why

The graph is presented as the reliability mechanism replacing unbounded search, but a curated index converts retrieval errors from visible (agent finds nothing) to silent (agent finds plausible stale edges). Coverage gaps need their own observability before the graph can be trusted as a determinism control.

Validator escape rate in pre-review automated validation loops

Research question

What fraction of agent-authored changes pass static analysis, visual-spec validation, and staging integration and still require substantive human correction, and who validates the validators?

Why

Moving the quality gate upstream of human review only reduces review load if the automated loops have measured escape rates. Visual validation against Figma specs in particular has a spec that may itself be wrong or outdated, so the loop can systematically bless incorrect output.

Article ideas

4

Your AI Gateway Is a Production Service, Not a Policy Checklist

Once PII redaction, guardrails, caching, and cost attribution live in a shared model gateway, compliance stops being a code-review concern and becomes an SLO problem: the gateway becomes a shared failure domain whose latency budget caps every feature built on it, and teams that adopt it without a degraded-mode contract have centralized their risk rather than reduced it.

Angle

Treat gateway adoption as a reliability engineering decision: define the hot-path budget, the fail-open/fail-closed matrix per guard, and the blast radius of a gateway incident across all consuming projects.

Source video ↗

Token Efficiency Is a Tool-Interface Problem, Not a Prompt Problem

Fleetwide token consumption is governed primarily by how tools and context are represented to the model, not by prompt phrasing: aggregating tool surfaces or exposing them as code instead of discrete schemas can dominate every other optimization, which means context budget should be owned by the gateway/tooling layer rather than by individual prompt authors.

Angle

Reframe context bloat as an interface design and platform-ownership question, with representation patterns (aggregated tool surfaces, code-mode exposure) as the primary lever and prompt tuning as the residual.

Source video ↗

Your Agentic Velocity Metrics Are Measuring the Wrong Thing

Adoption percentage and lines-of-code velocity are throughput metrics that cannot distinguish faster delivery from faster rework; without pairing them against revert rate, post-merge defect rate, and review time, an org can report doubled LOC while quality silently degrades, and the same blind spot applies to automated migration claims at fleet scale.

Angle

Build the counter-metric set that must ship alongside any agentic adoption dashboard, and treat a single systematic agent mistake propagated across millions of auto-migrated lines as the canonical tail risk.

Source video ↗

Skill Marketplaces Are Package Registries and Should Be Governed Like One

Once agents execute skills at fleet scale, skill quality becomes supply-chain management: lint, review, evals, distribution, and default installation are the minimum controls, and persona-based auto-install is in direct tension with token-optimization goals because it inflates the tool surface for every engineer whether or not the skill is relevant.

Angle

Argue that skill authoring conventions are insufficient and map the required package-management controls onto agent skills, including the cost of defaults.

Project ideas

4

Escape-Rate Harness for Agent-Authored PRs

beyond-evals

A measurable fraction (target: quantify, not assume) of agent-authored changes that pass static analysis, spec/visual validation, and staging integration still require substantive human correction, and that escape rate varies systematically by change type (cross-repo, UI-vs-backend, migration).

Proof of concept

Instrument a pipeline that tags agent-authored PRs with which inner/outer loops they passed, then sample post-merge for substantive human follow-up commits within N days; report escape rate per loop combination and per change category on a fixed task suite.

Measurement

Escape rate (share of loop-passing PRs needing substantive correction), stratified by loop coverage and change type; false-pass rate of visual/spec validation against a known-good reference set.

Source video ↗

Staleness-Conditioned Context Graph Retrieval Benchmark

beyond-evals

Agent answer accuracy degrades measurably with graph staleness, and missed-context failures from a bounded typed index are not detectable at inference time as errors, producing confident wrong answers rather than visible retrieval failures.

Proof of concept

Build a small typed context index over a toy multi-repo/service set, introduce controlled staleness (renamed services, deleted tickets, superseded design docs), and run identical agent tasks with a bounded-index retriever versus unbounded search; score for wrongness and for whether the agent signaled uncertainty.

Measurement

Accuracy and silent-error rate vs staleness level; token burn and latency delta between bounded-index and unbounded-search retrieval; rate at which the agent flags low confidence when the needed edge is missing.

Source video ↗

Lineage-Correlated Gateway Cost Attribution

gatehouse

Per-feature unit economics cannot be reconstructed from gateway telemetry alone unless a trace-correlation ID is propagated across agent hops, so multi-agent fan-out silently misattributes cost to the originating user or project.

Proof of concept

Prototype a gateway shim that stamps a correlation ID at the first request, propagates it through nested agent/sub-agent calls, and attempts to reconstruct per-user-action cost from gateway logs only; compare against an instrumented end-to-end trace as ground truth.

Measurement

Reconstruction error between gateway-only attribution and ground-truth trace cost per user action; fraction of fan-out requests that lose lineage without explicit propagation.

Source video ↗

Context Surface Growth Tracker

movement-lab

Fleetwide token-per-task does not stay reduced as tool and skill counts grow: persona-based auto-install and marketplace expansion re-inflate the effective tool/context surface, eventually outpacing representation-level compression.

Proof of concept

Stand up a synthetic agent fleet with adjustable tool counts and auto-installed skill sets, apply representation-level optimizations (aggregated tool surfaces, code-mode exposure) and then grow the surface, tracking tokens per completed task across both regimes.

Measurement

Tokens per task as a function of installed tool/skill count, with and without representation-level optimization; crossover point where surface growth cancels the compression gain.

Tool integration shifts from hand-written per-tool connectors to auto-projected MCP servers behind a gateway.

Before

Engineers manually authenticate and wire each internal API or SaaS tool into each agent.

After

APIs are crawled and projected into MCPs with standardized auth, discovery, and schema routing.

Consequence

Tool onboarding cost drops, tool supply expands rapidly, and the token/context budget becomes the binding constraint — forcing representation-level optimizations like Omni-MCP and Code Mode.

Context retrieval moves from search-at-inference-time to a maintained typed graph.

Before

Agents issue exploratory queries/searches and assemble context on the fly.

After

Agents read from a bounded graph of typed nodes and edges spanning code, docs, tickets, and data.

Consequence

Lower token burn and latency plus more predictable outputs, at the cost of a new continuously-maintained index whose coverage gaps become a silent source of wrong answers.

Before

After

Consequence

Human review effort can be redirected to design and risk judgment, but validating agents now need their own trust model and can only be as good as the specs (e.g., Figma) they compare against.

Tradeoffs and failure modes

5

Centralized model gateway

Benefit

Uniform PII redaction, guardrails, caching, and per-team cost attribution across 800 projects and 100M+ daily requests.

Cost or risk

Every model call depends on one shared hop; the summary's own guard latency budget (sub-100ms) constrains it, and gateway degradation would stall all internal AI features.

Source video ↗

Bounded context graph instead of unbounded search

Benefit

Reduced token burn, latency, and unpredictable outcomes relative to open-ended search.

Cost or risk

A curated 150-type, 40M-entry graph can miss rare or novel context and requires continuous maintenance; stale edges yield confident but wrong context, and coverage gaps are hard to observe as failures.

Source video ↗

Large-scale automated migration

Benefit

Over 250 migrations and 9 million lines of code changed automatically.

Cost or risk

High-volume automated refactors can propagate a single systematic mistake fleet-wide before humans notice, so migration correctness needs independent verification rather than spot checks.

Source video ↗

Persona-based auto-installed default skills

Benefit

Engineers get default capabilities without discovery or setup effort.

Cost or risk

Auto-installed skills inflate the system prompt/tool surface for everyone, creating context bloat and irrelevant-skill noise that works against the token-optimization goals of the MCP gateway.

Source video ↗

Self-healing CI and autonomous maintenance agents

Benefit

Scheduled cleanups like feature-flag removal and CI repair run without human initiation.

Cost or risk

An agent authorized to repair CI can also relax or rewrite checks to make a build pass, so CI-modifying agents need governance distinct from ordinary code-writing agents (risk inferred from the scope of action, not stated in the summary).
