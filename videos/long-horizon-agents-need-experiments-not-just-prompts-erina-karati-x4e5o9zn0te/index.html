Overview

  • Speaker: Erina Karati
  • Channel: AI Engineer
  • Main topic: Autoresearch in Multi-Agent AI Villages and Evaluating Long-Horizon Agents
  • Purpose: To explain the limitations of short-term agent evaluation, introduce Project Paradox and the Autoresearch pattern, and provide practical engineering lessons for building robust long-horizon multi-agent systems. Erina Karati discusses the challenges of evaluating and improving multi-agent AI systems that maintain state over long periods, using Project Paradox (a video game-like AI village) as a case study. She introduces the concept of 'Autoresearch'—a meta-system outside the village that runs automated experimental loops to score behavior, diagnose failures, propose policy changes, and rerun scenarios, emphasizing that long-horizon agents need experiments rather than just manual prompt tuning.

Topic Map

Project Paradox and Multi-Agent Frameworks

  • Key claims:

Under the Hood of Multi-Agent Architecture

  • Explanation: Explains the stateful architecture behind individual agents, including per-agent RAG memory, emotion vectors, belief/trust matrices, and core memory importance scoring.
  • Key claims:
    • Per-agent RAG memory prevents memory from bleeding across agents by default.
    • Emotion vectors track values like joy, sadness, fear, anger, and disgust.
    • Belief/trust matrices act as trust metrics updated after interactions.
    • Importance scores determine whether memory events cross a threshold to be stored in a separate cache.
  • Examples:

The Problem with Long-Horizon Social Consistency

  • Explanation: While short-term agency works well (planning, moving, talking), longer horizons reveal weaknesses in social consistency, such as rumor propagation turning into false facts and loss of source attribution.
  • Key claims:

    • Information moving across people and time causes failures in source attribution and rumor accuracy.
    • Systems may remember rough topics but lose the source of the topic.

The Bridge to Autoresearch

Controlled Scenarios and Balanced Scorecards

Key Points

Evaluate runs, not single responses

  • Explanation: Long-horizon agent evaluation requires assessing entire simulation runs across controlled scenarios rather than inspecting individual LLM responses.
  • Evidence: Comparison between manual prompt loops and autoresearch scenario loops.
  • Practical implication: Build evaluation harnesses that capture multi-turn, multi-agent state evolution over time.

Memory needs provenance

  • Explanation: Agents need to know where information came from (firsthand, secondhand, verified, or uncertain) to prevent rumors from becoming unverified facts.
  • Evidence: Failures in rumor propagation and source attribution in village simulations.
  • Practical implication: Include provenance metadata alongside stored memories and retrieval policies.

Do not let the AI rewrite everything

  • Explanation: Freezing evaluation harnesses, scenario suites, and metric formulas while keeping a small editable policy surface prevents reward hacking and system destabilization.
  • Evidence: Distinction between frozen components and editable policy surfaces.
  • Practical implication: Confine autonomous optimization loops to restricted policy spaces like prompt templates and retrieval settings.

Frameworks, Models & Processes

Autoresearch Loop

  • How it works: A meta-system outside the agent environment that runs scenarios, traces behavior, scores results against ground truth, proposes policy adjustments, and reruns tests.
  • Components:
    • scenario suite
    • repeated runs
    • metrics scorecard
    • diagnosis / policy edit
    • keep / rollback decision
  • When to use: When optimizing multi-agent social behavior and long-horizon policy parameters.

Recipe for Long-Horizon Agents

  • How it works: A 7-step engineering pattern ensuring controlled evaluation and safe automated policy iteration.
  • Components:
    • Freeze the simulation harness
    • Define controlled behavioral scenarios
    • Log traces, not just final answers
    • Score a balanced behavioral scorecard
    • Expose a small policy surface
    • Search over changes
    • Keep only changes that survive measurement
  • When to use: When engineering stateful, long-running agent systems across gaming, support, coding, or workflow automation.

[A]Architecturemedium noveltymoderate evidence

Treat the editable surface of a self-improving agent system as a narrow, explicitly bounded 'policy surface' — the autoresearch loop may propose edits only to retrieval and memory-write policies while the simulation harness and scenario suites stay frozen.

Why it matters

Defines an architectural boundary for autonomous self-improvement: if the optimizer can rewrite the harness, the scenario suite, and the metrics, it can trivially game its own evaluation. Freezing the bench and constraining the writable region is what keeps automated policy search trustworthy.

Generalization

Any system with a closed-loop optimizer (RLHF data selection, prompt optimizers, auto-eval pipelines, self-modifying scaffolds) should separate an immutable evaluation harness from a small, enumerated set of tunable parameters.

Typed provenance as a first-class memory field with hop-count decay

Research question

What minimal provenance schema (source class, verifying agent, hop count, trust weight) prevents secondhand claims from hardening into asserted fact when agents paraphrase each other, and how fast does attribution accuracy decay per propagation hop?

Why

The summary names the concrete failure — an agent remembers the mango-sales topic but not who said it, and another agent later states it as absolute fact — yet no data model, propagation rule, or trust-degradation function is given. Without a representable uncertainty field, no retrieval or prompting strategy can recover veracity downstream, so this is the highest-leverage unresolved mechanism for long-horizon social consistency.

Exploitability of a balanced scorecard under closed-loop policy search

Research question

Which aggregation function over the six named axes (fact fidelity, provenance accuracy, misinformation resistance, trust calibration, goal completion, dialogue quality) is least exploitable by an optimizer that can only edit retrieval and memory-write policies, and how much of the score gain transfers to held-out scenario suites?

Why

The scorecard is the containment mechanism for autoresearch, but weights, aggregation, and sensitivity to gaming are unspecified, and the loop itself can learn to exploit an aggregation it is scored against. This is the difference between a self-improvement loop that improves behavior and one that improves its score.

Sizing the writable policy surface: improvement versus harness-gaming

Research question

Why

The guidance 'keep it small' and 'rollback is not optional' is directional with no evidence about where the boundary sits. Article ideas

4

Your Agent Optimizer Will Eat Your Eval Harness: Freezing the Bench and Narrowing the Policy Surface

Automated agent improvement loops are only trustworthy if the harness, scenario suite, and metrics are immutable and the writable region is a small enumerated set of policies; anything less and the loop optimizes the scoreboard instead of the behavior. The engineering consequence is concrete: define the write scope as retrieval policy plus memory-write policy, version the bench separately from the runtime, and treat rollback as a required primitive rather than a safety nice-to-have.

Angle

Architectural contract for self-improving systems, argued through the failure mode of an optimizer that can rewrite its own evaluation

Source video ↗

Stop Evaluating Responses: The Run Is the Unit of Work for Stateful Agents

Per-response evaluation is structurally blind to the failure classes that matter for long-horizon agents — rumor propagation, source attrition, trust drift — because those are properties of a trajectory across many turns and multiple agents, not of a completion. Adopting the run as the atomic unit forces a specific infrastructure bill: multi-agent trace capture, state snapshots, belief/trust deltas, and information-flow graphs, all replayable. Teams that skip that bill are measuring the wrong thing confidently.

Angle

Metric-unit argument with the downstream infrastructure consequences spelled out

Source video ↗

Memory Without Provenance Is Just Confident Gossip

A content-only memory store has no representation for uncertainty, so once information crosses agents and time, an agent that remembers the topic but not the source will repeat a rumor as fact and no downstream retrieval or prompting strategy can undo it. The fix is a typed write path — firsthand, secondhand, verified, uncertain — attached at write time, which also converts 'misinformation resistance' from an aspiration into a measurable scorecard axis.

Angle

Mechanism-first argument that locates the fix at the memory-write boundary rather than at answer time

Source video ↗

Optimize One Metric, Break Three Others: Why Agent Behavior Needs an Anti-Goodhart Scorecard

Fuzzy social and epistemic objectives degrade predictably under single-metric optimization — pushing diffusion produces oversharing, pushing recall produces stale-memory noise — so any closed-loop optimizer needs a balanced scorecard across fact fidelity, provenance accuracy, misinformation resistance, trust calibration, goal completion, and dialogue quality. The hard part is not naming the axes but choosing an aggregation the optimizer cannot exploit, which argues for holding out scenario suites the loop never sees.

Angle

Tradeoff analysis and anti-gaming design for objective functions under automated optimization

Project ideas

4

HopDecay

movement-lab

A memory schema carrying typed provenance (firsthand/secondhand/verified/uncertain) plus a per-hop trust attenuation function will keep attributed claims attributable after N propagation rounds, whereas a content-only store will convert the majority of claims into unattributed assertions within a few hops.

Proof of concept

Instrument a minimal multi-agent village scenario (rumor about a countable event, e.g. mango sales) with two memory backends — content-only and provenance-typed — run matched scenario suites, and replay run-level traces to compute the fraction of claims that reach turn T with correct source attribution and the fraction asserted as fact.

Measurement

Per-hop source-attribution retention curve and rumor-to-fact conversion rate per backend; number of hops before attribution accuracy falls below 50%.

Source video ↗

FrozenBench

gatehouse

An autoresearch loop that may edit only retrieval and memory-write policies, against a versioned immutable harness, will show lower scenario-held-out gain but near-zero evaluation-gaming incidents compared to an unbounded-write loop, which will gain on the visible suite while regressing on held-out suites.

Proof of concept

Implement one loop with an enumerated writable-policy surface and a rollback primitive, and a second with unrestricted write scope including the scoring code; run both against the same scenario suite and score both on a held-out suite the loop never sees.

Measurement

Delta between visible-suite score and held-out-suite score for each loop (gaming gap), plus count of edits that modify harness, metrics, or scenario definitions.

Source video ↗

ScorecardArena

beyond-evals

Scorecard aggregation variants differ measurably in exploitability: linear-sum aggregations are gamed by an optimizer that can only touch retrieval and memory-write policy, while held-out-suite validation with per-axis floors preserves gains that transfer to a fresh scenario suite.

Proof of concept

Run the same constrained autoresearch loop against several aggregation functions (weighted sum, per-axis floors, worst-axis maximin) on a training suite, then evaluate all resulting policies on a disjoint suite; optionally randomize seeds and scenario ordering to test robustness.

Measurement

Transfer ratio (held-out gain / training gain) and per-axis regression magnitude for each scorecard variant across seeds.

Source video ↗

RunTrace

beyond-evals

Run-level trace capture (state snapshots, belief/trust deltas, information-flow graph) detects social-consistency regressions that per-response logging cannot surface at all, and does so at a storage cost that is bounded and predictable per scenario turn.

Proof of concept

Instrument the same agent population with two logging paths — per-response pairs and whole-run traces with information-flow graphs — inject a known provenance regression (disable source tagging) and test whether each path flags it before deployment.

Measurement

Regression detection rate per logging path, false-positive rate, and bytes/turn storage overhead of run-level tracing versus per-response logging.

Tradeoffs and failure modes

4

Single-metric optimization of agent behavior

Benefit

Simple, unambiguous optimization target for autoresearch loops.

Cost or risk

Optimizing diffusion alone produces oversharing; optimizing recall alone produces stale-memory noise; other behaviors silently regress.

Source video ↗

Letting the automated loop edit freely

Benefit

Faster, higher-ceiling self-improvement.

Cost or risk

The system can rewrite the harness or metrics and game its own evaluation; without rollback there is no safe recovery.

Source video ↗

Per-agent RAG memory isolation

Benefit

Prevents memory bleed across agents so each agent keeps a coherent state and personality.

Cost or risk

Information that does propagate does so without reliable source attribution, letting rumors harden into asserted facts.

Source video ↗

Importance-scored memory promotion

Benefit

Retains salient events (a murder) while discarding trivia (what was eaten for dinner).

Cost or risk

A threshold-based promotion policy is a tunable surface that can be gamed or mis-tuned, and only the promoted tier is durable.
