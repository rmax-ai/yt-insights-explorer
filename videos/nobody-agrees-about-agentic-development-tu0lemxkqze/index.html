Overview

  • Speaker: Jamie Cwiling, Theo Brown, Jean-Denis Greze, David Cramer
  • Channel: Convex
  • Main topic: Agentic development and software engineering
  • Purpose: To debate and analyze the practical business and technical value, challenges, and future of agentic development in modern software engineering. A panel discussion exploring the impact of AI agents on software development, productivity, code review, architecture, and open-source practices.

Topic Map

Business and Technical Value of Agentic Development

  • Explanation: Panelists discuss the business value and productivity impact of AI agents on software development across AI and non-AI companies.
  • Key claims:
    • Agentic development increases productivity and self-sufficiency.
    • Most value so far has been internal and operational.
    • Non-AI companies see software as a productivity tool, viewing AI as an efficiency improvement.
  • Examples:
    • Spending money on frontier model use for coding.
    • Internal tooling and documentation access.
  • Terminology:
    • agentic development
    • frontier model
    • productivity tool
  • Why it matters: Determines whether AI agents are transformative or merely incremental efficiency boosts for software engineering.

Code Review and the Bar for Code Quality

  • Explanation: Debate on whether AI agents make code review obsolete or more difficult, and how developers set quality thresholds.
  • Key claims:
    • Code review is stressful and agents make it worse if code generation outpaces human comprehension.
    • Developers keep moving the bar for code quality as models improve.
    • Agents help handle high volumes of pull requests.
  • Examples:
    • Reviewing 1,000 pull requests every two weeks with a small team.
    • Cherry-picking useful commits from agent suggestions.
  • Terminology:
    • code review
    • pull request
    • regression
    • tdd
  • Why it matters: Addresses the liability and maintenance risks associated with AI-generated code bases.

Architecture, Abstraction, and Spaghetti Code

  • Explanation: Discussion on how AI agents handle software architecture, maintain context, and whether they promote spaghetti code.
  • Key claims:
    • LLMs love spaghetti code and tend to break abstractions.
    • Junior engineers can introduce complex technical debt much faster with AI.
    • Good architecture means meeting product requirements with minimal human intervention.
  • Examples:
    • Refactoring codebases and dealing with architectural drift.
    • Writing 5,000 lines of code and running performance checks.
  • Terminology:
    • architecture
    • abstraction
    • spaghetti code
    • refactoring
  • Why it matters: Highlights the risk of unmaintainable codebases scaling rapidly due to AI generation speed.

Open Source vs Closed Source in the Age of Agents

  • Explanation: How agentic development impacts open source software, distribution power, and competitive moats.
  • Key claims:
    • Distribution and network effects remain the ultimate moat.
    • Open source benefits from AI because thousands of eyes can review agent-assisted code.
    • Closed-source companies rely on secrecy and proprietary talent moats.
  • Examples:
    • Cloning convex codebases.
    • Open source repositories handling pull requests with AI.
  • Terminology:
    • open source
    • closed source
    • distribution
    • moat
    • fork
  • Why it matters: Explores the shifting dynamics of software ownership, security, and competitive advantage.

Key Points

Productivity vs Architecture Tradeoff

  • Explanation: AI agents speed up code generation significantly, but maintaining architectural integrity requires strict discipline.
  • Evidence: Panelists noted merging 100 PRs in 24 hours without regression due to robust automated systems.
  • Practical implication: Teams must invest in robust CI/CD pipelines and verification systems to catch agent errors early.

The Changing Role of Junior Engineers

  • Explanation: AI lowers the barrier to introducing complex technical complexity, changing how junior and senior engineers collaborate.
  • Evidence: Juniors can iterate faster, but lack systemic architectural context.
  • Practical implication: Mentorship and architectural oversight remain critical to prevent systemic technical debt.

Distribution as the Ultimate Moat

  • Explanation: While AI lowers barriers to writing code, distribution and user trust remain the primary competitive advantages.
  • Evidence: Commercial giants maintain dominance through market reach and ecosystem lock-in rather than proprietary code alone.
  • Practical implication: Businesses should focus on distribution and customer relationships rather than relying on code secrecy.

Frameworks, Models & Processes

Agentic Engineering Verification Framework

  • How it works: Using automated systems and AI agents to pre-screen, test, and vet code changes before human review.
  • Components:
    • Automated CI/CD checks
    • Agent-assisted PR filtering
    • Architectural guardrails
  • When to use: When managing high-volume code generation from AI agents in production environments.

Examples & Case Studies

A two-person team merging 1,000 pull requests every two weeks using AI agents.

  • Illustrates: The extreme velocity enabled by agentic development.
  • Lesson: Automation and robust testing frameworks are necessary to handle agent-generated code volume safely.

Actionable Takeaways

  • Immediate:
    • Implement automated verification for AI-generated code.
    • Use AI to triage pull requests and surface valuable commits.
  • Strategic:
    • Focus on distribution and network effects rather than code secrecy as a moat.
    • Redefine software architecture around LLM capabilities and limitations.
  • Questions to investigate:

Automated architectural guardrails in CI reduce abstraction-eroding changes merged from LLM agents by more than 50% without reducing agent PR throughput.

Proof of concept

Add architecture-as-code checks for dependency direction, module boundaries, and abstraction leaks to a repo receiving LLM agent PRs, then compare against a baseline without guardrails.

Measurement

Abstraction violations per 1,000 agent PRs; PR merge volume; revert rate; reviewer time.

TriageGate

gatehouse

An agent-assisted PR triage layer can let a two-person team merge 1,000 AI-generated PRs every two weeks with equal or lower regression escape rate than manual review.

Proof of concept

Build a bot that clusters agent PRs by intent, summarizes diffs, ranks regression risk, and suggests cherry-picks, then run A/B tests against manual review on the same backlog.

Measurement

PRs merged per two weeks; regression escape rate; reviewer minutes per PR; cherry-pick precision.
