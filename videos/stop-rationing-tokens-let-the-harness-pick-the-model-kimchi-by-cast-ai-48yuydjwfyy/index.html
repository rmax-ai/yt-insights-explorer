Summary

Overview

  • Speaker: Laurent (Co-founder and President of Cast AI) and Zilvinas (Head of Engineering for Kimchi)
  • Channel: AI Engineer
  • Main topic: Dynamic model routing and token optimization in agentic coding environments via Kimchi
  • Purpose: Introduce Kimchi Coding and its architectural capabilities for dynamic multi-model routing, cost reduction, and automated software development life cycle management. Laurent and Zilvinas discuss the challenges of runaway token costs in enterprise AI development, where companies resort to rationing developer token budgets like limiting battery life. They introduce Kimchi, a coding platform utilizing proprietary models for edge cases and open-source for the rest, along with an automated token optimization engine that routes tasks to the right model at the right time. They also introduce /ferment for hands-off execution on complex tasks and Kimchi Teleport/Studio for collaborative agentic workflows.

Key Points

Token caps are the wrong response to high LLM costs

  • Explanation: Treating token budgets like limited laptop batteries makes engineers unproductive.
  • Evidence: Enterprise cases show budgets burning out in months due to uncontrolled agentic loops.
  • Practical implication: Instead of rationing, organizations should implement automated multi-model routing.

Models vary wildly in actual cost per task

  • Explanation: Listed token prices do not reflect the actual cost required to successfully complete a specific engineering task with equivalent quality.
  • Evidence: Academic white paper comparisons show cheaper models sometimes cost more per task due to retries or inefficiencies.
  • Practical implication: Use an automated harness to dynamically select the most cost-effective model per task.

Reading code is no longer enough in agentic engineering

  • Explanation: As generated code volume explodes, reviewing raw lines or diffs becomes unmanageable.
  • Evidence: Engineers and product managers generate massive PRs from agentic workflows.
  • Practical implication: Review intent, specs, and execution contracts rather than raw lines of code.

[E]Empirical Resulthigh noveltymoderate evidence

Listed per-token price is a poor proxy for the actual cost of completing a task: cheaper models can cost more per successful task because of retries and inefficiencies, so routing should be optimized against cost-per-completed-task rather than list price.

Why it matters

It reframes model selection as an outcome-based optimization problem; a routing policy that ranks models by sticker price will systematically pick the wrong model and may cost more than using a single frontier model.

Generalization

Any agent harness that selects among tools/models should benchmark on end-to-end task cost (including retries, loop iterations, and evaluation passes), not on unit price.

[A]Architecturehigh noveltymoderate evidence

Model selection is being moved out of the developer's hands and into the harness layer, which dynamically routes each task to the cheapest capable model instead of defaulting to one expensive frontier model.

Why it matters

It establishes a new abstraction boundary: a routing/optimization layer between the agent loop and the model APIs, making model choice a runtime policy rather than a static configuration choice.

Generalization

Treat model choice as a pluggable routing policy inside the harness, analogous to a scheduler or load balancer, so model substitution and cost policy change without touching agent logic.

[M]Mechanismmedium noveltymoderate evidence

The remediation loop treats failure as the primary driver of work: a task is decomposed into milestones, built, deliberately exercised until it breaks, diagnosed, repaired, and redeployed — repeating passes until output is correct.

Why it matters

It encodes self-healing as an explicit control loop with named phases (Change, Build, Break, Ferment, Complete), rather than relying on a single generation pass plus ad hoc human fixes.

Generalization

For long-running autonomous tasks, model the workflow as a build-break-repair cycle with milestone checkpoints and objective pass/fail evaluation at each step.

Project ideas

3

CostPerTask Bench

beyond-evals

A benchmark that measures end-to-end cost per successful task across models will reveal that routing based on list price is suboptimal, and that a cost-per-task router can achieve >2x savings over a single frontier model on a suite of software engineering tasks.

Proof of concept

Build a harness that runs a set of coding tasks (e.g., from SWE-bench) across multiple models, evaluates success, and computes total tokens and cost per task. Implement a simple router that selects models based on learned cost-per-task and compare against always using a frontier model.

Measurement

Average cost per successful task, success rate, and total cost for the router vs baseline. Hypothesis supported if router achieves >2x cost reduction with no drop in success rate.

Source video ↗

Agent Sandbox Security Scanner

gatehouse

A set of adversarial tests can identify common security misconfigurations in cloud agent sandboxes (e.g., overly permissive credentials, unrestricted network egress), and applying isolation best practices significantly reduces attack surface without hindering agent functionality.

Proof of concept

Create a test suite that attempts to escape sandbox, access unauthorized resources, or exfiltrate data from within a simulated agent environment. Apply hardening measures (e.g., least-privilege credentials, network policies) and re-test.

Measurement

Number of successful exploits before and after hardening; impact on agent task completion time and success rate.

Source video ↗

Remediation Loop Convergence Analyzer

movement-lab

Remediation loops with fixed maximum iteration counts and objective pass/fail gates will converge to correct solutions within a bounded number of passes for most tasks, but a significant fraction will either exceed the limit or oscillate, indicating the need for smarter termination criteria.

Proof of concept

Instrument a build-break-repair agent to log each pass's outcome, cost, and whether the task eventually passes. Run on a set of coding tasks and analyze pass counts and failure modes.

Measurement

Distribution of pass counts, percentage of tasks that converge within N passes, and cases of oscillation or divergence. Success if we can classify tasks into convergent vs non-convergent and identify predictive features.

Architectural implications

3

Model choice moves from a developer/config-time decision to a harness-level runtime routing policy.

Before

Developers pick a single frontier model and accept its cost and behavior for all tasks.

After

The harness evaluates each task (cost, capability, outcome) and dispatches to the most cost-effective capable model.

Consequence

Model selection, cost policy, and fallback behavior become centralized, testable components separate from agent logic — but require per-task evaluation signal to route correctly.

Source video ↗

Agent execution is decoupled from the developer's local machine into cloud containers.

Before

Agent sessions run on the developer's laptop and terminate when the laptop closes.

After

Sessions are offloaded to secure cloud containers that continue running independently of the client.

Consequence

Long-running asynchronous agent jobs become viable, but sandbox isolation, security, and session-state durability become mandatory infrastructure concerns.

Source video ↗

The reviewable unit in agentic engineering shifts from diffs to intent, specs, and execution contracts.

Before

Reviewers read line-by-line diffs and pull requests.

After

Reviewers evaluate intent, specifications, and contracts, treating generated code as an implementation detail.

Consequence

The harness must capture and surface intent/spec artifacts and objective pass/fail evidence, or review degrades into unreviewed bulk merges.

Tradeoffs and failure modes

4

Cost-optimized multi-model routing

Benefit

Reported 2.5x savings over a single frontier model while maintaining task quality.

Cost or risk

Routing decisions depend on accurate per-task cost and quality signals; a mis-calibrated router could silently degrade output quality or increase cost through retries.

Source video ↗

Multi-pass remediation loop

Benefit

Repeated build/break/repair passes can drive output to correctness without human intervention.

Cost or risk

Multiple passes multiply token consumption, so correctness gains trade directly against the token cost the mechanism is meant to reduce.

Cloud-offloaded agent sandboxes

Benefit

Developers can close their laptops and keep working; sessions run asynchronously in the cloud.

Cost or risk

Running automated agents in cloud containers raises unresolved security questions about isolation and access.

Source video ↗

Unconstrained agentic loops

Benefit

Maximizes agent autonomy and throughput without developer throttling.

Cost or risk

Without guardrails or usage limits, loops can burn budgets at an extreme rate.
