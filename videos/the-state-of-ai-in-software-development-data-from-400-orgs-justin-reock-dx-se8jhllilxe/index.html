Summary

Overview

  • Speaker: Justin Reock
  • Channel: AI Engineer
  • Main topic: Impact of AI on developer experience, productivity, delivery velocity, quality, and measurement across 400+ organizations
  • Purpose: To provide empirical data and research-backed insights into how AI adoption actually impacts developer productivity, velocity, code quality, and organizational workflows. Justin Reock, Deputy CTO at DX, shares research analyzing data from over 400 organizations and 200,000 engineers on AI's impact on developer experience and productivity. Contrary to expectations of 5x or 10x productivity gains, data shows modest median PR throughput increases (~7.76% median, 13.1% average). The presentation explores five key trends: velocity impact, quality and delivery impact (showing increased change failure rates and tension between maintainability and change confidence), demographic differences (junior engineers using AI the most, staff+ saving the most time), measurement frameworks (utilization, impact, cost), and SDLC/PDLC agent integrations illustrated through case studies from Morgan Stanley, Zapier, Faire, and Spotify.

Key Points

Productivity gains are more modest than expected

  • Explanation: Longitudinal studies from Nov 2024 to Feb 2026 across 400+ companies show a median PR throughput increase of 7.76% and an average of 13.1%, with no companies hitting 2x, 5x, or 10x.
  • Evidence: Weighted PR throughput increase table (Median 7.76%, Average 13.1%).
  • Practical implication: Executive leadership expecting 10x returns from token spend need to look beyond code generation and address broader workflow bottlenecks.

Code maintainability and change confidence are in tension

  • Explanation: Code maintainability scores increased by 3.8%, but change confidence dropped by 6.1% as developers trust AI-generated code less.
  • Evidence: Bar chart comparing Code Maintainability (+3.8%) and Change Confidence (-6.1%).
  • Practical implication: Organizations must invest in automated testing and review guardrails to maintain engineering confidence when adopting AI.

Foundational DevEx metrics remain paramount

  • Explanation: AI metrics measure what is happening, but core foundational metrics measure whether it is actually working.
  • Evidence: Pyramid diagram showing Core Metrics (measures whether it is working) supporting AI Metrics (measures what is happening).
  • Practical implication: Do not throw away existing DORA and DevEx metrics when adopting AI tools; correlate AI telemetry with foundational metrics.

Find and fix the actual bottleneck

  • Explanation: Applying Eli Goldratt's Theory of Constraints, saving time on tasks that are not the system bottleneck is worthless.
  • Evidence: Manufacturing process diagram showing bottleneck identification and case studies from Morgan Stanley, Zapier, Faire, and Spotify.
  • Practical implication: Target AI agents at administrative tasks, legacy refactoring, code reviews, and incident management rather than just raw code authoring.

Frameworks, Models & Processes

AI Measurement Framework

  • How it works:
  • Components:
    • Utilization (AI tool usage, DAU/WAU, percentage of PRs AI-assisted, percentage of commit code, tasks assigned to agents)
    • Impact (AI-driven time savings, developer satisfaction, DX Core 4 metrics, perceived rate of delivery, change confidence, change failure rate, human-equivalent hours)
    • Cost (AI spend total and per developer, net time gain per developer, agent hourly rate)
  • When to use: When evaluating the return on investment and organizational effectiveness of enterprise AI tooling deployments.

Gauging AI Readiness (DevEx Foundation)

  • How it works: Assesses platform and codebase readiness across Bronze, Silver, and Gold tiers to ensure infrastructure can support AI agents effectively.
  • Components:
    • Clear, accurate, well-structured documentation
    • Data structures with straightforward relations
    • Readable, manageable, modular code
    • Fast, reliable local and CI feedback loops
    • Stable (read: non-flaky) robust test suites
  • When to use: Before rolling out AI agents and coding assistants across an engineering organization.

Examples & Case Studies

Morgan Stanley built 'DevGen.AI', an internal AI agent that reads legacy code (mainframe natural, cobol, perl), gathers context, and creates PRDs for engineers.

  • Illustrates: Automating legacy code refactoring to eliminate reverse engineering.
  • Lesson: Saves the company over 280,000 developer hours annually by targeting a major non-coding bottleneck.

Zapier built an internal automation ecosystem where agents handle daily stand-ups, onboarding steps, internal reporting, and Slack communications.

  • Illustrates: Administrative automation using AI agents across the PDLC.
  • Lesson: Reduced stand-ups from 5x to 2x per week, accelerated onboarding to ~2 weeks, and increased hiring capacity.

Faire developed 'Fairey', an AI agent that automatically reviews PRs for superficial issues and posts comments.

  • Illustrates: Automated code review and quality guardrails.
  • Lesson: Completes roughly 3,000 code reviews per week, freeing senior engineers from routine checks to focus on complex architecture.

Spotify created an incident management agent platform that monitors logs, correlates alerts in real-time, and suggests remediation from runbooks.

  • Illustrates: Incident management and SRE workflow acceleration.
  • Lesson: Handles 90% of incidents at Spotify, dramatically reducing MTTR and freeing SREs for proactive reliability work.

[O]Mental Modelhigh noveltymoderate evidence

Code generation is a small fraction of the value stream (~14-16%), so optimizing it barely moves end-to-end throughput. The largest real-world ROI comes from pointing specialized agents at non-coding bottlenecks (legacy refactoring, code review, incident management, admin workflows), not at the IDE.

Why it matters

It reframes where to invest agent engineering effort: budget and architecture should follow the bottleneck (Theory of Constraints), not the most visible coding task. Teams building coding copilots may be optimizing a step that is not limiting delivery.

Generalization

For any agentic pipeline, measure the value-stream share of the step before automating it; automation of a non-bottleneck step yields sublinear system-level gains.

[E]Empirical Resultmedium noveltystrong evidence

Longitudinal measurement across 400+ orgs shows AI's measured delivery gain is modest and sublinear versus expectations: median PR throughput +7.76%, average +13.1%, with no org reaching even 2x. The gap between token spend growth and throughput growth is the central empirical result.

Aggregate org-level productivity metrics regress heavily toward small effect sizes even when individual-task evaluations show large speedups.

Readability/maintainability proxies can improve while trust and verifiability degrade; evaluation harnesses need separate instruments for generation ease and reviewer confidence.

Seniority changes token efficiency rather than time savings: staff+/senior engineers save roughly the same time as juniors while burning fewer tokens, and juniors adopt AI the most because they have less unlearning to do.

Deep dives

5

Value-stream attribution as the ranking function for agent investment

Research question

How can per-repo and per-org value-stream share be measured stage-by-stage (cycle-time contribution, wait states, handoffs) so that specialized SDLC agents can be ranked and deployed by system-level ROI rather than by visibility?

Why

If code generation is 14-16% of the value stream, then a portfolio decision made on IDE-adjacent intuition systematically over-funds the wrong stage. A reproducible attribution method is the prerequisite for any Theory-of-Constraints-style agent roadmap, and it converts 'where should we build agents?' from an opinion into a measurement.

Source video ↗

The decay of change confidence under AI-assisted delivery

Research question

Is the drop in developer change confidence a fixed property of AI-generated changes, or a function of review capacity being exceeded by larger AI-assisted PRs — and can a review-policy intervention restore confidence without giving back throughput?

Why

Maintainability rising while confidence falls means the standard 'code quality' proxy is actively misleading for AI-assisted code. Combined with median PR size growth, this points at review capacity, not generation capacity, as the binding constraint — which changes what a review agent should be built to do.

Source video ↗

Causal separation of AI gains from confounders in delivery metrics

Research question

What fraction of the observed median PR throughput increase (+7.76%) survives matched-cohort or interrupted time-series comparison against non-adopting teams inside the same organization, once deployment-frequency trends and regional shifts are controlled?

Why

Without causal separation, every downstream ROI model and vendor benchmark inherits an unidentified confounder. This determines whether the low-double-digit effect is the true AI prior or an upper bound that further controls will shrink.

Source video ↗

Feedback-loop determinism as the binding constraint on agent autonomy

Research question

Do organizations meeting explicit thresholds for test determinism and local CI latency show measurably higher AI impact scores than otherwise comparable organizations, and does agent task success rate degrade predictably as local CI latency grows?

Why

Treating AI readiness as an infrastructure property makes flaky tests and slow local CI release-blocking dependencies of agent effectiveness rather than hygiene items. If the correlation holds, readiness tiers become a legitimate gate on agent rollout instead of a slide in a deck.

Source video ↗

Token efficiency as a skill-conditional signal rather than a cost signal

Research question

Which context-selection, task-decomposition, or tool-use behaviors let senior and staff+ engineers achieve comparable time savings at lower token cost, and are those behaviors teachable to juniors or purely experience artifacts?

Why

If token spend is a poor proxy for value delivered, then cost-per-engineer dashboards are actively misleading and token-based ROI attribution will misrank teams and tools. Identifying the mechanism turns a cost number into a leverage point.

Your Coding Copilot Is Optimizing 14% of the Value Stream

Coding assistance sits on a small share of the delivery value stream, so agent investment should be ranked by cycle-time contribution per stage; the visible artifact (code) is not the limiting constraint, and portfolios built around the IDE will keep producing sublinear system-level returns.

Angle

Apply Theory of Constraints to SDLC agent portfolios: instrument the value stream, rank stages, then fund agents in ranked order — with a counterexample set from review, incident, and legacy refactoring work where non-coding agents produced large documented ROI.

Source video ↗

Easier to Modify, Harder to Trust: The Two Quality Signals AI Decoupled

Perceived maintainability and reviewer change confidence have decoupled under AI-assisted delivery, and because PR size grew alongside them, any evaluation harness that reports maintainability alone will pass code that reviewers will not stand behind; review capacity, not generation capacity, is the constraint to engineer against.

Angle

Argue that quality proxies must be split into separate instruments for generation ease and reviewer verifiability, and show what a size-aware AI review policy would have to enforce.

Source video ↗

The 7.76% Reality Check: Why Task-Level Speedups Do Not Survive Aggregation

Longitudinal org-level data showing median PR throughput up 7.76% with no organization reaching 2x is the correct prior for coding-agent ROI; individual-task benchmarks are not projections of organizational throughput, and any 5x or 10x claim is making a claim about measurement, not about delivery.

Angle

Show the gap between task-level speedup evidence and org-level effect size, then specify the matched-cohort and interrupted time-series designs required before attributing any of the gain to AI.

AI Readiness Is an Infrastructure Problem, Not a Model Problem

Project ideas

4

Value-Stream Bottleneck Ranker

new

A specialized agent deployed at the highest cycle-time-contribution non-code stage will reduce end-to-end lead time more than an equal-effort investment in code generation, because code generation is a small share of the value stream.

Proof of concept

Instrument repo, pipeline, review, and incident telemetry to attribute cycle time per stage across a small set of repositories; rank stages by contribution and wait-state share; deploy one narrow agent (e.g., review or incident triage) at the top-ranked stage while holding the coding copilot constant.

Measurement

Per-stage cycle-time share before/after, end-to-end lead time, median PR throughput, and deployment frequency, compared against a control repository set with no new agent.

Source video ↗

Change-Confidence Instrument

beyond-evals

An evaluation harness that measures reviewer change confidence separately from maintainability will flag AI-assisted PRs that pass maintainability scoring but carry low reviewer trust; a PR-size-aware review policy can restore confidence without reducing throughput.

Proof of concept

Ship a paired instrument that captures maintainability and change confidence per PR alongside PR size, then A/B test an AI-specific review checklist applied above a size threshold.

Measurement

Change confidence delta per cohort, PR size distribution, review depth (comments per PR, review latency), escaped defect and change failure rate, with throughput held as a non-regression constraint.

Source video ↗

Agent Readiness Gate

gatehouse

Organizations and repositories meeting explicit test-determinism and local CI latency thresholds show measurably higher AI impact scores and higher agent task success rates than those that do not, so readiness should gate agent rollout.

Proof of concept

Define a readiness scorecard (documentation, data structures, code manageability, local CI latency, flake rate) and wire it as a pre-rollout gate for agent enablement in one org unit; run a second unit ungated as a comparison.

Measurement

Correlation between readiness tier and measured AI impact metrics, agent task success and retry rates, local CI latency and flake rate, with adoption/utilization telemetry joined to DORA/DevEx outcome metrics.

Source video ↗

Matched-Cohort AI Impact Estimator

movement-lab

Within-org matched-cohort and interrupted time-series comparison will shrink the observed AI throughput effect relative to naive org-level trends, because deployment-frequency trends, regional shifts, and general tooling improvements absorb part of the measured gain.

Proof of concept

Build an analysis harness that pairs AI-adopting teams with non-adopting teams inside the same organization on matched baselines, plus an interrupted time-series around adoption dates, and report confidence intervals on the effect.

Measurement

Effect-size difference between naive trend estimates and matched-cohort estimates for PR throughput and perceived rate of delivery, with sensitivity to cohort matching criteria.
