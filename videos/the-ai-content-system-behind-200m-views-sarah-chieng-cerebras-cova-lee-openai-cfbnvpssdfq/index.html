Frameworks, Models & Processes

The Six-Stage Content System

  • How it works: A linear, iterative pipeline taking content from initial idea to published post using specialized AI skills at each step.
  • Components:
    • 01 Idiate (Swipe files, research tools)
    • 02 Script (Voice mode, style analysis)
    • 03 Record (Shot-lists, screen recording capture)
    • 04 Edit (Asset organization, design systems, AI editing)
    • 05 Repurpose (Short clip extraction)
    • 06 Publish (Buffer API, caption generation, monthly learning loops)
  • When to use: When scaling content production as a developer, creator, or tech company.

The Two-Pass Shot-List Framework

  • How it works: Pass 1 annotates the existing script with A-roll, B-roll, and graphic cues without inventing new concepts; Pass 2 deduplicates and structures the recording checklist.
  • Components:
    • Pass 1: Preserve script and annotate execution types
    • Pass 2: Create structured shot list with exact script context
  • When to use: When transitioning from a finalized script to a recording session.

Core insights

6
[A]Architecturemedium noveltymoderate evidence

The reusable unit of capability in this system is a named "skill" (script-writing skill, shot-list skill, caption skill, /coast-cli-skill) that is a versioned prompt artifact rather than a model or an agent. Skills are the thing that gets edited when performance feedback arrives.

Why it matters

It locates the mutable, improvable layer at the prompt/artifact level while the underlying models and tools stay fixed. That makes the system self-modifying without retraining and without touching runtime code, and it gives operators a concrete object to diff, review, and roll back.

Generalization

When a workflow's quality depends on conventions (tone, pacing, structure) rather than raw model capability, extract those conventions into separately versioned skill artifacts so they can be revised independently of the pipeline that invokes them.

Source video ↗
[M]Mechanismmedium noveltymoderate evidence

The loop closes at the artifact layer, not the model layer: post-publish performance data is fed back through a recurring review prompt that rewrites the skill definitions that produced the content. The system's own output metrics are the training signal for its prompts.

Why it matters

It is an eval-driven improvement loop that requires no gradient updates and no model access — just observability of outcomes plus a scheduled prompt that edits the prompt library. This is a cheap, portable pattern for production agents where per-task quality is subjective but per-channel outcomes are measurable.

Generalization

Design agent systems so that production outcome metrics have a defined write path back into the instructions/skills that generated the work; otherwise the system is static regardless of how much telemetry you collect.

Source video ↗
[M]Mechanismmedium noveltyweak evidence

Input modality changes output distribution: text-prompting pulls generation toward generic marketing register, while speaking the raw material out loud preserves the creator's actual phrasing, stories, and examples. Voice-to-text is used as the grounding substrate, and the LLM only restructures it.

Why it matters

It reframes 'authentic voice' as a data-sourcing problem rather than a prompting problem. If the source material is unedited human speech, the model cannot collapse to the modal phrasing of its pretraining; if the source is a typed prompt, it can. This is an architectural choice about where content originates.

Generalization

For any generation task where the failure mode is regression to the mean, supply high-entropy human-origin seed material and constrain the model to restructuring rather than authoring.

Source video ↗
[~]Tradeoffmedium noveltymoderate evidence

Generative steps in a structured pipeline are deliberately split into two constrained passes whose job is annotation, not invention — the shot-list pass maps A-roll, B-roll, and screen recordings onto an existing script without introducing new concepts.

Why it matters

It names a concrete failure mode of multi-step agent pipelines: downstream stages silently invent content that upstream stages never approved, corrupting the artifact chain. Bounding a stage's mandate to annotate-only is a cheap guardrail, paid for with an extra pass (latency and cost).

Generalization

Enforce per-stage generation contracts — declare for each stage whether it may create new content or may only label/transform existing content — so drift cannot propagate through the pipeline unnoticed.

Source video ↗
[P]Practicelow noveltymoderate evidence

Automation extends all the way to publishing but stops short of unapproved external side effects: the agent schedules posts through the Buffer API using platform-specific captions that are pre-approved rather than generated-and-fired.

Why it matters

It draws the human-in-the-loop boundary at the irreversible, externally visible action rather than at content generation. Internally, the agent operates autonomously across five stages; the single gate sits immediately before publication, where mistakes are public and unrecallable.

Generalization

Place approval gates at the irreversibility boundary (publish, send, deploy, pay) and leave everything upstream autonomous — gating early stages buys safety at the cost of the leverage that made automation worth doing.

Source video ↗
[>]Predictionlow noveltyweak evidence

Inference throughput is framed as a workflow-design constraint, not a benchmark number: very fast inference (claimed 750 tokens/sec on Cerebras-served models) is what makes processing large scripts and video-length inputs practical inside an iterative pipeline.

Why it matters

If model latency drops by an order of magnitude, the set of viable patterns shifts from single-shot batch generation toward many-pass, whole-corpus, regenerate-freely loops (two-pass shot-lists, repeated asset sorting, per-platform caption rewrites). Latency budget determines how many agent passes you can afford per artifact.

Generalization

High-throughput inference changes pipeline topology: it makes N-pass refinement and full-context reprocessing economically viable where a single careful pass was previously the only option.

SkillHoldout

beyond-evals

A monthly-review-generated skill promoted only after beating the production skill on a held-out set of recent artifacts will reduce post-promotion quality regressions versus direct promotion.

Proof of concept

Build a skill registry that stores named prompt artifacts and versions; replay recent scripts through candidate and production skills; score against a fixed rubric plus human spot checks; require a margin before promotion.

Measurement

Regression rate on held-out topics, rubric score delta, and number of promotions rejected per quarter.

HandoffContractLinter

gatehouse

Declaring shot-list generation as annotate-only and checking concept overlap at the handoff reduces invented concepts by at least half compared with a single unconstrained pass.

Proof of concept

Instrument a script-to-shot-list pipeline; extract concepts from both artifacts; flag any shot-list concept absent from the script; compare constrained two-pass versus single-pass generation.

Measurement

Invented-concept rate per script, checker false-positive rate, and extra pass latency and cost.

movement-lab

Cliché n-gram rate, distinct-n, coherence ratings, and blind authenticity ratings.

Architectural implications

3

The pipeline is decomposed into six named stages (Ideate, Script, Record, Edit, Repurposing, Publish), each with its own custom tool or skill rather than one end-to-end agent.

Before

A single 'make me a video' agent prompt attempting ideation through publishing in one context window.

After

Stage-scoped skills with explicit typed handoffs (script -> shot-list -> asset folder -> clips -> scheduled posts), each independently debuggable and swappable.

Consequence

Failures localize to a stage and artifacts remain inspectable between stages; the cost is orchestration glue and keeping inter-stage schemas consistent as skills evolve.

Source video ↗

The agent orchestrates deterministic external tools — Codex, Coast CLI, CleanShot X, HyperFrames, HeyGen, Premiere MCP, Buffer API — rather than performing editing or publishing itself.

Before

The LLM is asked to produce final artifacts (edited video, published post) directly.

After

The LLM emits structured instructions/annotations that deterministic tools execute via CLI or API calls.

Consequence

Output quality and reliability become a function of tool interfaces — schemas, CLI contracts, API stability — which are the real integration surface to maintain and monitor.

Source video ↗

Research is front-loaded into a custom retrieval artifact (swipe files in Notion/Obsidian, a Codex-built tool for browsing YouTube outliers) consulted before generation begins.

Before

Generation starts from the prompt and the model's priors alone.

After

Generation is conditioned on an curated corpus of historically high-performing references retrieved at the ideation stage.

Consequence

Quality becomes a function of corpus curation and retrieval, so the maintenance burden shifts to keeping the reference library current rather than endlessly re-prompting.

Tradeoffs and failure modes

5

Voice-first capture vs. fast text prompting

Benefit

Speaking raw material produces scripts with the creator's natural tone, examples, and stories instead of generic marketing phrasing.

Cost or risk

Requires the human to actually talk at length before the agent can start; the pipeline is blocked on human time at the top, and the claimed anti-generic effect is asserted without measurement.

Source video ↗

Packaging-first optimization

Benefit

Treating title and thumbnail as half the performance outcome focuses effort on the highest-leverage step before any production work happens.

Cost or risk

An explicit 50% packaging weighting creates systematic pressure toward packaging over substance, and the figure is a single unverified attribution that could misallocate effort entirely if wrong.

Source video ↗

Autonomous multi-channel scheduling

Benefit

One agent schedules posts across channels with platform-specific captions, eliminating per-platform manual work.

Cost or risk

Depends on third-party API behavior and on captions being genuinely pre-approved; any gap between 'pre-approved' and 'auto-generated' leaks into public, unrecallable output.

Source video ↗

Two-pass constrained generation

Benefit

Annotation-only passes prevent downstream stages from inventing concepts the script never contained, preserving artifact integrity.

Cost or risk

Doubles the number of generation passes per script, adding latency and cost, and constrains the model from surfacing genuinely useful ideas discovered mid-annotation.

Source video ↗

Self-updating skills from performance review

Benefit

Monthly review prompts convert cross-platform performance data into revised skill definitions without retraining or redeploying.

Cost or risk

An automated loop that rewrites its own prompts from noisy, confounded engagement metrics can drift or overfit to a recent outlier, with no described eval gate before the new skill takes effect.
