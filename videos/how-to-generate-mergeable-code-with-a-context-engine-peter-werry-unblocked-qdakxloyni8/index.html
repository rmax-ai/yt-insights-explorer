Summary

Overview

  • Speaker: Peter Werry
  • Channel: AI Engineer
  • Main topic: Context engines for AI software engineering agents and the limitations of raw MCP access versus organizational context layers.
  • Purpose: To demonstrate how a context engine bridges the gap between AI agents and organizational knowledge, reducing token waste, hallucinations, and code review friction. Peter Werry, co-founder of Unblocked, explains why AI coding agents fail to produce production-grade mergeable code without an organizational context layer. He explores the AI maturity curve in engineering organizations, contrasts access to tools with actual understanding, demonstrates a live demo of the Unblocked context engine integrated with Claude Code and Slack/GitHub, and analyzes token usage and efficiency tradeoffs.

Topic Map

The Problem: Agents Lack Organizational Context

  • Explanation: AI agents treated as new employees reset their knowledge every time they start a new task, lacking tribal knowledge, past decisions, architecture rationale, and incident history.
  • Key claims:
    • AI-generated code should feel like it was written by someone who has been on your team for years, but it doesn't today.
    • For years, humans have been the context layer.
    • Now your agents have the same problem. Only the cost compounds.
  • Examples:
    • Searching across outdated docs, Notion, Slack discussions, Confluence, and GitHub pull requests to figure out how auth validation works.
  • Terminology:
    • context engine
    • organizational context
    • tribal knowledge
    • AI maturity curve
  • Why it matters: Without context, agents produce plausible output that compiles but fails human review and real-world expectations.

Levels of AI Maturity in Engineering Organizations

  • Explanation: A taxonomy of engineering organization maturity ranging from basic tab completion to fully autonomous software factories.
  • Key claims:
    • Levels 1-2: Tab complete, Agent IDE (You are the context layer).
    • Levels 3-4: Context engineering, Parallel agents (Curated context).
    • Levels 5-6: MCP + skills, Harness engineering (Context layer).
    • Levels 7-8: Cloud agents, Software factories.
  • Examples:
    • Moving from GitHub Copilot tab-complete up to automated software factories.
  • Terminology:
    • AI maturity curve
    • MCP
    • context layer
    • software factories
  • Why it matters: Most engineering organizations are currently stuck at levels 4 to 5 and treat context as the primary bottleneck.

Access Does Not Equal Understanding

  • Explanation: Connecting agents to Model Context Protocols (MCP) gives them access to code and docs, but suffers from 'satisfaction of search' similar to radiologists stopping at one X-ray indicator.
  • Key claims:
    • Access to information does not equal understanding.
    • Dumping an entire codebase and all docs into a context window causes agent distraction and wastes tokens.
    • Task-specific flow is required to prevent agents from getting distracted.
  • Examples:
    • Radiologist finding one cancer indicator and missing others; agents finding one piece of info and stopping prematurely.
  • Terminology:
    • satisfaction of search
    • context window
    • task-specific flow
  • Why it matters: Unstructured massive context dumps lead to wasted tokens, distracted agents, and operating on wrong assumptions.

Key Points

Agents as New Employees

  • Explanation: AI coding agents reset their knowledge on every new task, requiring rediscovery of codebases, test suites, and deployment patterns.
  • Evidence: Analogy comparing agents to expert software engineers who onboard for the first time on every task.
  • Practical implication: Engineering teams must provide persistent context layers to prevent repetitive onboarding overhead.

Access vs Understanding

  • Explanation: Giving agents raw access to repos via MCPs allows them to search, but they lack holistic understanding of architectural dependencies.
  • Evidence: Radiology analogy of 'satisfaction of search' where finding one indicator causes an agent to stop searching.
  • Practical implication: Context engines must curate and route precise information rather than dumping raw codebases into context windows.

Compounding Cost of Contextless Agents

  • Explanation: Without upfront context preparation, agents iterate on wrong assumptions, leading to compounding token costs and repeated human intervention.
  • Evidence: Cost comparison showing session usage with Unblocked (~$0.93, 1 min) versus without Unblocked (~$1.22, 2 mins).
  • Practical implication: Context layers save significant token costs and wall-clock time on complex multi-step coding tasks.

Core insights

6
[!]Failure Modehigh noveltymoderate evidence

Raw MCP access to repos and docs is architecturally insufficient: it provides retrieval ability without holistic understanding, and agents exhibit a 'satisfaction of search' failure mode — finding one plausible piece of evidence and terminating the search prematurely.

Why it matters

It reframes the tool-access layer as the wrong abstraction boundary: unbounded search over a corpus is not the same as an understanding layer that routes task-specific context. Teams building agent stacks on MCP servers alone are building the failure mode into the architecture.

Generalization

Any agent system whose knowledge interface is 'search the corpus' will systematically under-retrieve and stop at the first satisfying hit; the fix is a curated routing layer that enumerates what a task requires, not a bigger index or larger context window.

[E]Empirical Resultmedium noveltymoderate evidence

Context failures compound in cost rather than staying constant: agents iterate on wrong assumptions, driving repeated human intervention and multiplied token spend, so pre-task context curation is cheaper than post-hoc correction.

Why it matters

Gives a concrete economic argument for investing in a context layer upstream of the agent loop instead of paying for retries and human triage downstream — a cost model that changes where budget is spent in agent harness design.

Generalization

For multi-step agent tasks, per-iteration cost is dominated by the correctness of initial assumptions; investing in retrieval precision at step zero reduces total tokens and wall-clock superlinearly with iteration count.

[O]Mental Modelmedium noveltyweak evidence

An AI maturity taxonomy where the differentiator between stages is *who supplies context*: at levels 1-2 the human is the context layer, at 3-4 context is curated, at 5-6 a context layer plus harness engineering exists. The bottleneck is treated as context rather than model capability.

Why it matters

Provides an adoption diagnostic that locates teams on a capability axis defined by context supply, and claims most organizations stall at levels 4-5 — implying the binding constraint in industry practice is context infrastructure, not model quality.

Generalization

Agent-system maturity can be characterized by whether context is supplied by a human in the loop, curated ahead of time, or provisioned by an engineered layer — an axis usable for roadmapping any agent platform.

[M]Mechanismhigh noveltyweak evidence

Organizational intelligence for code review extends beyond source code into communication history: correlating GitHub PRs with Slack threads, and weighting comments by seniority/expertise signals from an engineering social graph, improves review relevance.

Why it matters

Suggests the retrieval corpus for engineering agents should include conversational and social-signal data, not just code and docs — a non-obvious expansion of what counts as context, and one that requires an identity/authority model layered over the retrieval index.

Generalization

Where decision rationale lives outside artifacts (chat, review comments, incident threads), any context engine needs both a correlation mechanism linking those channels to artifacts and an authority ranking, otherwise it retrieves opinion without weighting it.

Satisfaction of search in agentic retrieval: termination criteria as a harness constraint

Research question

Does requiring an explicit evidence checklist (a schema of what a task needs before the agent may act) measurably lower premature retrieval termination and raise merge rate on multi-step coding tasks, compared with free-form search over the same corpus?

Why

If the failure mode is premature commitment to the first satisfying hit, the fix is a harness-level constraint rather than a bigger index or a larger context window — which changes what a context layer must emit (coverage assertions, required-evidence sets) instead of merely returning ranked chunks.

Task-scoped context routing versus tuned retrieval: where the merge-rate gap actually closes

Research question

On the same multi-step coding tasks, how much of the improvement in merge rate and file-reference precision comes from task decomposition and sequencing alone versus from better retrieval over the same corpus (code, docs, PRs, Slack)?

Why

The distinction between 'access' and 'understanding' is the central claim of the talk but is never mechanized; an ablation separates routing/decomposition effects from retrieval-quality effects and tells builders which layer to invest in first.

MCP Gives Your Agent Access. It Does Not Give It Understanding.

Building an agent stack on raw MCP access bakes the 'satisfaction of search' failure mode into the architecture: unbounded search over a corpus systematically under-retrieves and terminates at the first plausible hit, so the missing layer is task-scoped routing and sequencing, not a larger index.

Angle

Architectural argument: contrast the tool-access boundary (MCP) with a selection/sequencing boundary, and show why bigger context windows and broader retrieval cannot fix premature termination.

Compile success and plausibility are proxy metrics that hide the dominant downstream cost of agent-written code; review acceptance and rework rate at the merge gate are the metrics that actually track whether a context layer paid for itself.

Project ideas

4

Evidence-Checklist Harness

gatehouse

Requiring an agent to satisfy an explicit, task-derived evidence checklist before it may edit code reduces premature retrieval termination and raises diff merge rate versus free-form MCP search on equivalent tasks.

Proof of concept

Build a middleware layer that decomposes an incoming task into a required-evidence schema, gates tool access until each item is satisfied with a cited source, and logs every termination point; run paired trials against a baseline free-search agent on the same multi-step coding tasks.

Measurement

Premature-termination rate (retrieval stops after one hit), required-evidence coverage at first edit, human merge rate, and total tokens per completed task, with per-run variance across repeated trials.

Source video ↗

Routing-vs-Retrieval Ablation Bench

beyond-evals

Task-specific routing and sequencing accounts for a larger share of merge-rate improvement than retrieval quality over the same corpus, meaning context-layer effort should be spent on decomposition before index tuning.

Proof of concept

Run three arms on one fixed task suite over a frozen corpus: raw MCP free search; tuned hybrid retrieval with no task routing; task-decomposed routing that emits a step-by-step sequencing plan with file references. Hold model and cache state constant.

Measurement

Merge/review-acceptance rate, file-reference precision, tool calls per task, token spend, and wall-clock per task per arm, reported with confidence intervals across repeated runs.

Source video ↗

Context-Layer Cost Trial Protocol

beyond-evals

The reported ~50% token reduction from a context layer persists across a fixed multi-task suite under controlled cache state and task equivalence, with effect size smaller than the single-demo figure but still directionally significant.

Proof of concept

Instrument a Claude Code workflow with an A/B harness that pins task equivalence, cache state, and complexity labels, then replays each task with and without the context layer for N repetitions, logging token usage, wall-clock, and a cost-equivalent figure.

Measurement

Mean and variance of tokens and wall-clock per task, cost per completed task, and the fraction of the reported reduction surviving controls for caching and task equivalence.

Source video ↗

Authority-Weighted Review Context

new

Boosting retrieved review comments by seniority and expertise signals improves review-comment precision and merge acceptance up to a threshold, beyond which confidently-wrong senior opinions degrade precision relative to unweighted retrieval.

Proof of concept

Build a retrieval ranker that correlates PR review threads with Slack discussion and applies an authority weight derived from a minimal engineering social graph; evaluate against a labeled set of review comments with known-correct outcomes and sweep the weight parameter.

Measurement

Comment retrieval precision/recall against ground-truth outcomes, merge acceptance of agent changes, and precision degradation as a function of authority-weight strength.

Architectural implications

4

Context provision is being extracted from the human-in-the-loop and from the model prompt into a dedicated engine sitting between agents and organizational knowledge stores.

Before

Engineer manually gathers context in the IDE; agent receives whatever is pasted or searched via MCP.

After

A context engine resolves task-specific flows and hands precise, sequenced context to the agent via MCP/Claude Code or Slack.

Consequence

A new service boundary with its own indexing, correlation (PR↔Slack), and ranking (seniority) responsibilities — and a new failure domain between agent and repo.

Source video ↗

The unit of retrieval shifts from documents/chunks to task-specific flows.

Before

Dump the codebase and docs into the context window, or let the agent search freely.

After

Curate and route only the information a specific task requires, with explicit sequencing.

Consequence

Retrieval must be task-aware; evaluation must be task-scoped, and index design must support dependency tracing rather than similarity search alone.

Source video ↗

Dependency tracing and sequencing plans become a first-class output of the context layer, not of the coding agent.

Before

The agent scans files to discover call paths and ordering.

After

The context engine returns a step-by-step sequencing plan with precise file references.

Consequence

Reduces exploratory tool calls and token burn, and makes plans auditable against a context source independent of the agent.

Source video ↗

Authority/expertise weighting is injected into the retrieval ranking function.

Before

All retrieved comments and docs treated as equal-signal text.

After

Seniority and expertise signals boost specific comments in review context.

Consequence

Requires an engineering social graph and identity data as a dependency of the context engine, plus governance over how authority is inferred.

Tradeoffs and failure modes

4

Context volume vs. agent focus

Benefit

Larger context dumps maximize coverage and require less curation infrastructure.

Cost or risk

Agent distraction, wasted tokens, and premature search termination; agents operate on wrong assumptions.

Source video ↗

Token/time savings from a context layer

Benefit

Reported ~50% fewer tokens and faster triage with Unblocked in Claude Code; ~$0.93/1 min vs ~$1.22/2 min on a demo task.

Cost or risk

Numbers come from a single vendor demo with the speaker as founder; correctness of the comparison (task equivalence, caching effects, one run) is unverified.

Source video ↗

Satisfaction of search

Benefit

Early termination keeps agents cheap and fast when the first hit is actually sufficient.

Cost or risk

The first hit may be outdated (docs, Notion, Confluence) or partial, so the agent confidently proceeds on stale rationale.

Source video ↗

Correlating conversation history into the review context

Benefit

Captures rationale and intent that never made it into code or docs.

Cost or risk

Adds noisy, opinion-laden, context-dependent signal and requires authority ranking; seniority boosting can entrench wrong-but-senior opinions.
