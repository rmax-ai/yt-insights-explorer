Summary

Overview

  • Speaker: Ryan Carson
  • Channel: AI Engineer
  • Main topic: Managing multiple AI coding agents and engineering teams using an agentic organizational hierarchy.
  • Purpose: To share practical architectures and workflows for running a large fleet of AI coding agents concurrently in a startup environment. Ryan Carson, founder and CEO of Untangle, explains how his company builds and scales an AI paralegal for family law by treating AI coding agents like human employees. He outlines an organizational structure where a human sets weekly priorities and interacts via audio chat with an 'engineering manager agent', which in turn oversees up to 20 concurrent builder agents backed by automated QA, video screen recording review, and a merge queue manager.

[A]Architecturehigh noveltystrong evidence

Untangle splits the agent stack into a non-coding manager agent that supervises up to 20 concurrent builder agents, so the human's only interface to the fleet is a delegation layer rather than individual code-producing sessions.

Why it matters

The supervisor/executor split decouples human attention from agent count: adding builders scales throughput without adding supervisory channels, and it puts the hard problem (context, prioritization, decomposition) in one place instead of in every worker.

Generalization

For any fleet of parallel workers, insert a manager-tier whose contract is 'never execute, only decompose, dispatch, and report' — human bandwidth then scales with managers, not with workers.

[M]Mechanismhigh noveltymoderate evidence

The unit of work is constrained to exactly one ticket mapped to exactly one PR on the board of record (Linear), which is what makes 20 concurrent agents' output composable and reviewable.

Why it matters

A 1:1 ticket-to-PR invariant makes agent work atomic and independently verifiable, turns the ticket board into the shared state that both agents and the merge layer can reason about, and prevents ambiguous multi-PR sessions that are hard to review or roll back.

Generalization

When parallelizing agents against a shared codebase, enforce a rigid work-item-to-change-set invariant; the artifact graph (ticket↔branch↔PR) becomes the coordination protocol instead of inter-agent chat.

[M]Mechanismhigh noveltymoderate evidence

A dedicated Merge Manager Agent schedules PR 'waves' (e.g., database migrations) to keep the merge queue from gridlocking when many agents finish simultaneously.

Why it matters

Concurrency control at the integration boundary is a distinct responsibility from code production; ordering-dependent changes (migrations) are exactly where naive parallel agents deadlock or corrupt state, so merge scheduling must be an agent/tier of its own.

Generalization

Parallel agent systems need an explicit serialization layer for operations that mutate global shared state, decoupled from the workers that generate those operations — analogous to a scheduler or two-phase-commit coordinator.

[P]Practicemedium noveltymoderate evidence

Verification shifts from reading diffs to watching agent-recorded video of the feature being exercised and tests passing; the human 'ship it' gate is a behavioral artifact, not a code artifact.

Why it matters

Code review is a poor fidelity signal for agent output; recorded execution is tamper-evident-ish behavioral evidence that compresses review into watching, at the cost of linear human minutes per feature.

Generalization

For agent-generated changes, design verification around replayable execution traces (video, tests, logs) rather than source-diff inspection — but budget it as a human-attention cost that scales with change volume.

[M]Mechanismmedium noveltymoderate evidence

Supervision is implemented as a polling loop — automation checks in with the manager agent every 15 minutes to read child sessions — rather than event-driven callbacks.

Why it matters

Polling is a cheap, robust orchestration primitive that avoids building streaming infrastructure and tolerates partially-failed children, but it bounds responsiveness to the poll interval and risks stale context when a builder's state changes mid-window.

Generalization

Early-stage multi-agent orchestration can be built on scheduled state reconciliation (pull) instead of push notifications; the poll interval becomes an explicit latency/freshness knob.

Deep dives

5

Supervisor-tier context saturation: how many builders can one manager agent actually hold?

Research question

At what fleet size does a manager agent's status reporting over child sessions lose recall/precision, and which summarization strategy (full transcripts vs. per-child state snapshots vs. ticket-delta digests) moves the degradation curve furthest right?

Why

The '20 concurrent builders per manager' ceiling is asserted, not measured. If the manager's context is the binding constraint on throughput, then all fleet scaling work reduces to supervisor memory engineering — and the whole delegation-layer argument inverts if accuracy collapses at N=8.

Source video ↗

Merge tier as explicit serialization layer for global-state mutations

Research question

Does wave-based PR scheduling measurably reduce merge-queue latency versus FIFO at fixed PR volume, and at what concurrency does a single merge manager become the fleet's throughput ceiling such that sharded or hierarchical merge managers are required?

Why

Code production parallelizes cheaply; integration does not. Ordering-dependent operations (schema migrations) are precisely where naive parallelism deadlocks, so the merge tier is a scheduler with global visibility — a different permission and state model from builders. Designing it as an afterthought is how fleets gridlock at exactly the moment they start working.

Source video ↗

Replayable-execution verification: escape rate and human attention cost of video gates

Research question

What fraction of injected UI regressions still produce a passing recorded video, and what is the per-feature reviewer watch time — i.e., does behavioral-artifact review actually beat diff review on defects-caught-per-human-minute?

Why

If recorded execution is the ship gate, review cost scales linearly with agent throughput and becomes the new bottleneck that the manager tier was supposed to remove. Without an escape-rate number, 'watch the video' is a ritual, not a control.

Source video ↗

Calibrating judge agents that gate other agents' outputs (hiring ranker as the canonical case)

Research question

What is the agreement between a ranking agent scoring recorded agent-operation artifacts and human reviewers, and do ranker-selected candidates outperform human-selected ones on a downstream paid project?

Why

The reported distrust-then-deference sequence is the exact failure pattern of unaudited LLM-as-judge gates: the human has no better signal, so the model wins by default. The same calibration problem recurs anywhere an agent's output admits the next agent's work — hiring, PR triage, QA pass/fail.

Source video ↗

Pull-based supervision: poll interval as an explicit latency/freshness tradeoff

Research question

What is the real detection latency for a stuck or looping builder under a 15-minute reconciliation poll, and does state-reconciliation polling beat event-driven callbacks on total orchestration complexity at fleet sizes of 10-20?

Why

Polling is the pragmatic choice that avoids streaming infrastructure, but it silently makes supervisor responsiveness a config value. Quantifying the cost of that choice (idle agent-minutes burned per stuck session) turns an implementation detail into an engineering decision.

Article ideas

4

Span of Control Is the Real Context Window

The constraint on AI agent fleets is not model capability but human and supervisor attention bandwidth; the correct architecture therefore inserts a non-executing manager tier whose job is decomposition and compression, and every scaling claim should be restated as a claim about how many managers a human can ingest.

Angle

Reframe 'how many agents can one person run' as a classical management span-of-control problem, using the manager-agent/builder-agent split and the audio-first supervisory channel as evidence that modality and summarization — not tokens — set the ceiling.

Source video ↗

Your Verification Artifact Is Now a Video, and That Is a Bottleneck, Not a Victory

Replacing diff review with recorded execution is a genuine fidelity upgrade for agent-generated code, but it converts verification from a parallelizable, skimmable activity into a serial human watch-time tax that scales 1:1 with agent throughput — so teams adopting it should budget reviewers before they budget builders.

Angle

Argue against treating video review as an unambiguous best practice; price it in human minutes per feature and contrast with automated regression checks plus spot-audit sampling.

Source video ↗

Parallelism Without a Serialization Layer Is Just Distributed Gridlock

Any system that generates changes in parallel against shared global state must own an explicit scheduler at the integration boundary; a merge-tier agent that batches PRs into waves and sequences migrations is the multi-agent analogue of a commit coordinator, and omitting it makes concurrency a liability past a handful of workers.

Angle

Draw the systems-engineering parallel between merge-queue wave scheduling and transactional serialization, then show why the merge tier needs a different permission model (global visibility) than the builders it serves.

Source video ↗

When the Judge Is Also an Agent: Calibration Debt in Automated Evaluation

Ranking and QA agents that gate other agents' output become unaudited gatekeepers the moment humans admit they have no better signal; the honest posture is to treat every judge agent as uncalibrated until measured against human judgment on the same artifacts, and to report agreement before it is trusted in the loop.

Angle

Use the reported trajectory from distrusting the candidate-ranking agent to trusting it as a cautionary pattern, generalizing to PR triage, QA gates, and any model-scored pipeline stage.

Project ideas

4

Manager-Fleet Degradation Harness

movement-lab

A manager agent's accuracy at reporting child-session state degrades measurably before 20 builders, and per-child state snapshots preserve accuracy at substantially higher N than raw transcript accumulation.

Proof of concept

Synthetic fleet of N builder sessions with scripted states (running, blocked, looping, done-with-wrong-result); a manager agent polls at a fixed interval and must enumerate status per child; sweep N from 2 to 40 and swap three summarization strategies.

Measurement

Precision/recall of stalled-child detection and false-completion rate vs. N, per summarization strategy; identify the N at which recall drops below 90%.

Source video ↗

Video Gate Escape Benchmark

gatehouse

A meaningful fraction of injected UI regressions still produce a passing recorded happy-path video, and human reviewers catch them at a rate far below what the ship gate assumes.

Proof of concept

App with seeded regressions (broken empty state, off-by-one pagination, silent auth fallback); agent builds the feature and records video of tests passing; reviewers watch under diff-review and video-review conditions, with and without agent narration.

Measurement

Escape rate (regressions shipped) and defects caught per human review-minute, video vs. diff; reviewer inter-rater agreement.

Source video ↗

Merge Wave Scheduler Simulator

new

Wave scheduling with migration-dependency ordering reduces merge-queue latency versus FIFO at the same PR volume, but a single merge manager saturates and loses that advantage past a concurrency threshold where sharded merge managers win.

Proof of concept

Discrete-event simulator of N concurrent PRs with declared schema dependencies against a queue; policy A=FIFO, B=wave batching, C=hierarchical/sharded merge managers; same PR arrival distribution across policies.

Measurement

Mean and p95 queue latency, gridlock incidence, and throughput ceiling per policy vs. N; the crossover point where B stops beating A.

Source video ↗

Operator-Telemetry Ranker Calibration

beyond-evals

A ranking agent scoring recorded agent-operation artifacts reaches high rank correlation with expert human reviewers only after calibration on a labeled subset, and uncalibrated deployment produces selection decisions that diverge from humans in the tails.

Proof of concept

Collect recorded 45-minute sessions of operators shipping a feature on an unfamiliar app; score with a ranker agent and with 3 human experts; calibrate the ranker on half the set and evaluate on the held-out half; test whether top-ranked operators do better on a downstream timed task.

Measurement

Spearman correlation with expert mean rank (before/after calibration), tail disagreement rate, and downstream task performance of ranker-selected vs. human-selected operators.

Architectural implications

4

The human no longer holds per-task agent sessions; they hold one manager agent that multiplexes many builders.

Before

Human ↔ single coding agent session, context and task state live in that session.

After

Human ↔ manager agent ↔ N builder agents, with the manager owning decomposition and status aggregation.

Consequence

The manager's context window and summarization quality become the binding constraint on fleet size, and it becomes the natural place to invest in memory/RAG over child sessions.

Source video ↗

The ticket board becomes the durable coordination substrate rather than chat history.

Before

Inter-agent coordination via shared conversation or human relay.

After

Linear tickets as system of record, one ticket per PR, readable by manager, QA, reviewer, and merge agents.

Consequence

Agent orchestration inherits ticket-system semantics (status transitions, assignment, ordering) and the tracker becomes an API surface needing idempotency and access control.

Source video ↗

A merge-tier agent owns ordering of integration events, separate from builders.

Before

Each worker merges when done; ordering is incidental and migration conflicts surface as queue stalls.

After

Merge Manager Agent batches PRs into waves and sequences migration-dependent work.

Consequence

Integration throughput becomes a schedulable resource; expect the merge tier to need global visibility (all open PRs, schema state) and therefore a different permission model than builders.

Source video ↗

Verification artifacts change type: from source diff to recorded runtime behavior.

Before

Reviewer reads code diffs to judge correctness.

After

Reviewer watches agent-recorded video of the feature passing tests before approving ship.

Consequence

Review pipelines need artifact storage, retention, and indexing of video; review cost grows linearly with feature count and is the most likely new human bottleneck.

Tradeoffs and failure modes

5

Video-based verification of agent output

Benefit

Behavioral evidence that a UI feature actually works, catching failures that diff review misses.

Cost or risk

Human watch time per feature scales linearly with agent throughput, so review — not code generation — becomes the throughput ceiling.

Source video ↗

Poll-based supervisor loop at 15-minute intervals

Benefit

Simple to implement, no streaming infrastructure, tolerant of flaky child sessions.

Cost or risk

Status is stale up to the poll interval; an idle or looping builder may burn 15 minutes before the manager notices.

Source video ↗

Centralized merge management

Benefit

Prevents merge-queue gridlock and orders database migrations correctly across parallel agents.

Cost or risk

Introduces a single serialization point that can itself throttle the whole fleet; the summary's own open question is how this holds up as concurrency scales.

Source video ↗

Replacing interviews with recorded agent-operation artifacts

Benefit

Tests the actual skill (operating an agent to ship a feature) instead of interview performance, and removes pre-screen/video-chat bias.

Cost or risk

The ranking agent becomes an unaudited gatekeeper; the speaker admits distrusting its output, and no ground-truth calibration for the ranker is described.

Source video ↗

Banning local coding in favor of cloud agents

Benefit

Keeps all work in the shared, observable agent environment so velocity and review are uniform.

Cost or risk

Hard dependency on cloud agent infrastructure and session continuity; small tasks now pay orchestration overhead.
