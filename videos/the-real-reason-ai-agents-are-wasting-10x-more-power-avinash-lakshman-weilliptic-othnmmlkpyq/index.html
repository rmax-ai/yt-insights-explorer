Summary

Overview

  • Speaker: Avinash Lakshman (Interviewed by Siddhartha Ahluwalia)
  • Channel: The Neon Show
  • Main topic: AI infrastructure, LLM commoditization, power inefficiencies in agentic AI, and enterprise AI startup playbook.
  • Purpose: To educate founders, developers, and investors on the realities of AI infrastructure, the economics of LLMs, and architectural considerations for building scalable agentic systems. Avinash Lakshman, founder and CEO of Weilliptic Inc. and veteran creator of Cassandra, Dynamo, and Hedwig, discusses the evolution of AI infrastructure, why LLMs are becoming a commodity similar to hard disks or SSDs, and the hidden power drain of running agentic workflows on Python. He highlights the infrastructural bottlenecks in enterprise AI, drawing parallels from cloud evolution, and shares lessons from building and exiting previous deep-tech companies.

Topic Map

LLM Commoditization

  • Explanation: LLMs are following the exact trajectory of hard disks, SSDs, and specialized servers, becoming commoditized layers where the intelligence shifts entirely to software.
  • Key claims:
    • LLMs will become commodity hard disk drives or SSDs.
    • Infrastructure costs for LLMs are super high, but pricing pressure will force costs super low.
    • Hardware vendors pounded their chests about 10x servers, but nobody cares about raw server specs anymore; intelligence moved to software.
  • Examples:
    • Hard disk drives and specialized servers in the late 90s and early 2000s selling at 10x prices before becoming pure commodity.
  • Terminology:
    • LLMs
    • Commoditization
    • Inference providers
  • Why it matters: Understanding commoditization helps founders and investors avoid over-investing in raw foundational model infrastructure expecting sustained high margins.

The Python Problem in Agentic AI

  • Explanation: As everyone builds agentic AI systems using Python, they are ignoring extreme power inefficiencies. Python is argued to be one of the most inefficient languages ever created for large-scale agent workloads.
  • Key claims:
    • Python is the most inefficient language ever made by mankind.
    • A non-trivial agent in Python uses ~15 watts, whereas an equivalent agent implemented in Rust consumes 0.7 watts.
    • At scale across millions of agents, the energy footprint difference between Python and Rust creates massive data center power crises.
  • Examples:
    • Comparing power utilization between Python-written agents and Rust-written agents at scale.
  • Terminology:
    • Agentic AI
    • Python
    • Rust
    • Power utilization effectiveness (PUE)
  • Why it matters: Highlights a critical engineering bottleneck that will plague enterprise AI deployments as agent usage scales exponentially.

Cloud Infrastructure vs AI Infrastructure Parallels

  • Explanation: Drawing parallels from how AWS, GCP, and Azure commoditized storage and compute, AI infrastructure is experiencing a similar cycle of centralized spend followed by optimization layers.
  • Key claims:
    • The cloud did not become commoditized right away; it was expensive until overlay services emerged.
    • AWS outages and regional outages prove that businesses need overlay solutions running on top of commodity cloud providers.
    • AI infra providers risk being wiped out by LLM providers unless they abstract data and compute sovereignty.
  • Examples:
    • AWS S3 running on pure commodity hardware while software layers handle intelligence and storage.
  • Terminology:
    • Cloud infrastructure
    • Data sovereignty
    • Compute sovereignty
  • Why it matters: Provides a historical playbook for anticipating how the AI infrastructure market will consolidate and where lasting enterprise value resides.

Key Points

Open weight models will win

  • Explanation: Open weight models democratize access and mirror open-source software disruption against proprietary infrastructure.
  • Evidence: Historical parallels with open-source software competing against proprietary enterprise software.
  • Practical implication: Enterprises should design architectures that remain agnostic to specific foundational models.

The Python efficiency bottleneck

  • Explanation: Interpreted languages like Python consume orders of magnitude more power per agent execution than compiled languages like Rust.
  • Evidence: Comparative power metrics cited (15 watts for Python agents vs 0.7 watts for Rust agents).
  • Practical implication: High-scale agentic applications will eventually require migration away from Python for core execution loops to survive data center power limits.

Data and compute sovereignty in enterprise AI

  • Explanation: Enterprises demand that their data and compute remain within specific geographic and jurisdictional boundaries.
  • Evidence: Enterprise clients in regions like Singapore requiring local data residency guarantees.
  • Practical implication: Infrastructure players must offer distributed, cryptographically secure compute platforms to satisfy enterprise compliance.

The Infrastructure Playbook

  • How it works: Build core infrastructure layers that abstract hardware complexity, solve data sovereignty, and deliver operational efficiency as a managed service.
  • Components:
    • Commoditized underlying hardware/cloud
    • Software abstraction layer
    • Cryptographically secure audit trails
    • Managed service delivery model
  • When to use: When building deep-tech infrastructure companies facing intense competition from hyperscalers.

Building Dynamo and Cassandra at scale during early distributed systems evolution.

Compressed Summary

  • LLMs are rapidly commoditizing like hard drives and SSDs.
  • Python is critically inefficient for agentic AI, consuming up to 20x more power than Rust.
  • Enterprise AI adoption requires strict data and compute sovereignty.
  • Small, frugal engineering teams outperform bloated organizations in infrastructure.

Agent Power Crucible

beyond-evals

For identical non-trivial agent workloads with mocked model calls, a Rust implementation uses at least 10x fewer CPU joules per completed task than Python, and the gap is dominated by interpreter overhead rather than I/O wait.

Proof of concept

Implement the same agent loop (tool calls, memory, retries) in Python and Rust; instrument CPU package energy (RAPL) while executing N tasks with model calls mocked to fixed latency.

Measurement

Joules per task, CPU time per task, context switches per task, and ratio Python/Rust; decomposition of energy in compute versus wait.

Source video ↗

Crossover Instrument

movement-lab

There is a measurable agent concurrency and duty cycle at which runtime power exceeds inference power, and this crossover can be predicted from per-agent-hour and per-token energy models.

Proof of concept

Build an instrumented two-runtime agent deployment with configurable concurrency; mock or proxy model calls to fixed energy per token; sweep fleet size and duty cycle.

Measurement

Crossover concurrency, runtime vs inference joules per hour, total facility power proxy, and PUE sensitivity.

Residency-Attested Agent Runtime

gatehouse

Per-action cryptographic attestation for data residency and compute location can be added to an agent runtime with less than 10% latency overhead while enforcing jurisdictional pinning.

Proof of concept

Prototype a regional execution broker that pins agent steps to a jurisdiction and emits signed attestations for data placement and inference location; benchmark against centralized baseline.

Measurement

Added p50/p99 latency, throughput delta, key-management overhead, and audit coverage completeness.

beyond-evals

Architectural implications

3

Agent execution substrate is a cost/power lever comparable to model choice.

Before

Python orchestrates and executes the full agent loop end-to-end.

After

Performance-critical agent execution loops move to a compiled runtime (e.g., Rust) with Python retained for orchestration, tooling, and glue.

Consequence

Requires measurable power/CPU-per-agent telemetry and a benchmark harness to justify and validate the migration; risks splitting the codebase across two languages.

Source video ↗

Value accrues to the abstraction layer above commoditized models and hardware.

Before

Application logic is written directly against a specific LLM provider's API and hosted on a single cloud region.

After

A software abstraction layer owns model routing, data placement, and audit trails over commodity models and cloud.

Consequence

Provider swaps and jurisdiction changes become configuration rather than rewrites, at the cost of an extra abstraction to maintain and debug.

Source video ↗

Enterprise requirements impose residency and compute-location constraints on agent infrastructure.

Before

All agent state, context, and inference run in a single default region.

After

Compute and data are distributed and pinned to jurisdictional boundaries with cryptographically secure audit trails.

Consequence

True data/compute sovereignty becomes the product boundary that LLM providers are least likely to cross, but adds latency, replication, and key-management complexity.
