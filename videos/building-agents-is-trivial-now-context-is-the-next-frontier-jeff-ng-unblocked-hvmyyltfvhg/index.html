Summary

Overview

  • Speaker: Jeffrey Ng
  • Channel: AI Engineer
  • Main topic: Context engineering for AI agents and why infrastructure and primitives are no longer the primary bottleneck in agent development.
  • Purpose: To demonstrate that context engineering is the next major frontier in AI agent development and to explain why humans currently act as context layers for agents. Building AI agents has become trivial due to mature cloud infrastructure and primitives like Flue, Vercel Eve, and Mastra. However, agents still fail reliably because they lack context. This talk explores the shift from infrastructure challenges to context engineering, introducing the concept of a Context Engine that provides relevant, reconciled, governed, and well-timed context across tools, docs, code, and conversations, contrasting it with the raw access provided by MCP (Model Context Protocol).

Topic Map

The Evolution of Agent Building

  • Explanation: Six months ago, building an agent required an extensive team effort and a quarter of work across session management, checkpointing, orchestration, retry logic, sandbox infrastructure, execution isolation, observability, multi-channel adapters, and replay/debugging. Today, modern primitives and cloud frameworks have abstracted this complexity away.
  • Key claims:
    • Building agents is trivial now.
    • Infrastructure components like sandbox isolation and state persistence are now solved by modern frameworks.
    • Agent runtimes like Flue on Cloudflare handle almost all infrastructure requirements out of the box.
  • Examples:
    • Flue, Vercel Eve, and Mastra as modern agent frameworks.
  • Terminology:
    • Session management
    • State persistence
    • Sandbox infrastructure
    • Observability
  • Why it matters: Developers can now focus on core agent logic and customer value rather than infrastructure.

Why Agents Fail: The Missing Context

  • Explanation: Even with easy agent setup, agents still get things confidently wrong because they lack organizational and situational context, such as past decisions, tribal knowledge, migration plans, and post-mortems.
  • Key claims:
    • Agents lack a full picture because they miss tribal knowledge and post-mortem discussions.
    • Without proper context, background agents make silent mistakes that misinform teams.
    • Humans currently act as the context layer by babysitting agents.
  • Examples:
    • An AI agent fixing a linear ticket recommended reenabling async dispatch because it lacked context that a support engineer had explicitly disabled it due to a past outage.
  • Terminology:
    • Silent failure
    • Tribal knowledge
    • Post-mortem
    • Context layer
  • Why it matters: Without context, agent-generated solutions can cause real production outages and propagate misinformation.

The Context Engine vs. MCP

  • Explanation: While MCP (Model Context Protocol) connects agents to various data sources and returns raw matches, a Context Engine synthesizes sources, ranks by task relevance, resolves contradictions, and enforces permissions.
  • Key claims:
    • MCP provides access, but access is not understanding.
    • MCP floods the agent with raw matches, increasing context window costs and forcing the agent to decide what to believe.
    • A Context Engine delivers a synthesized understanding that an agent can act on directly.
  • Examples:
    • Connecting Slack MCP, Linear MCP, and GitHub MCP versus using Unblocked's Context Engine.
  • Terminology:
    • Model Context Protocol (MCP)
    • Context engine
    • Targeted retrieval
    • Conflict resolution
  • Why it matters: Context engines solve the signal-to-noise problem and prevent token bloat while respecting organizational permissions.

Key Points

Agents lack contextual awareness

  • Explanation: Agents have instructions, tools, skills, and code, but they lack the underlying 'why' behind architectural decisions and tribal knowledge.
  • Evidence: An agent suggesting a fix for linear tickets without knowing why a previous engineer disabled async dispatch.
  • Practical implication: Engineers must provide synthesized contextual intelligence to agents rather than raw data dumps.

The definition of an agent is now minimal code

  • Explanation: With frameworks like Flue on Cloudflare, defining an agent requires only selecting a model, setting instructions, defining tools and skills, and choosing sandbox locations.
  • Evidence: Code snippet showing defineAgent using Anthropic Claude 3.5 Sonnet with simple configuration parameters.
  • Practical implication: Agent creation code is extremely compact, shifting developer focus entirely to workflow and data relevance.

Context Engine pillars

  • Explanation: A context engine operates on relevance, reconciliation, governance, and delivery.
  • Evidence: Comparison slide showing how Unblocked processes sources (code, docs, tickets, conversations) into structured context.
  • Practical implication: Ensures agents receive precise, permissioned, and timely information without polluting context windows.

Frameworks, Models & Processes

Context Engine Framework

  • How it works: Merges signals from all company data sources, resolves conflicts, enforces permissions, and delivers synthesized context tailored to the user or agent task.
  • Components:
    • Unified system context
    • Conflict resolution
    • Token optimization
    • Targeted retrieval
    • Personalized relevance
    • Permission enforcement
  • When to use: When deploying AI agents for code generation, code review, ticket triage, and incident management in enterprise environments.

Compressed Summary

  • Agent infrastructure and building blocks are now commoditized and trivial to set up.
  • Agents fail in production because they lack tribal knowledge, intent, and historical context.
  • MCP provides raw data access, whereas a Context Engine provides synthesized understanding and conflict resolution.
  • Context engines ensure relevance, reconciliation, governance, and timely delivery of enterprise knowledge.
  • Keywords: context engineering, ai agents, mcp, unblocked, llm architecture
  • Core insight: The primary barrier to effective AI agents is no longer model intelligence or infrastructure primitives, but the lack of a centralized context engine to deliver relevant organizational knowledge.

Core insights

6
[A]Architecturemedium noveltymoderate evidence

Context assembly should be a distinct architectural layer (a "Context Engine") sitting between the agent and data sources, responsible for merging signals across code, docs, tickets and conversations, ranking by task relevance, resolving contradictions, enforcing permissions, and delivering a synthesized result rather than raw matches.

Why it matters

It relocates responsibility for relevance, conflict resolution and ACL enforcement out of the agent's prompt and into a dedicated, testable service — changing where the hard engineering lives and making context quality independently measurable from model quality.

Generalization

Any agent operating over multiple heterogeneous organizational systems will eventually need a synthesis layer; relying on the model to adjudicate raw multi-source retrieval pushes an unbounded reasoning and token cost into every call.

[!]Failure Modemedium noveltymoderate evidence

MCP provides reach without understanding: connecting multiple MCP servers returns raw matches that inflate the context window and force the agent itself to decide which sources to believe, which is a distinct failure mode from missing access.

Why it matters

It reframes tool-connectivity work as necessary-but-insufficient, and predicts a specific degradation pattern (token bloat plus agent-side arbitration between conflicting sources) that appears precisely when teams scale from one MCP server to several.

Generalization

Adding integrations increases recall but decreases signal-to-noise; without a ranking/reconciliation step, more connected sources can make agent output worse and more expensive, not better.

[O]Mental Modelhigh noveltymoderate evidence

The highest-cost context gap is negative knowledge — the record that something was deliberately disabled or rejected and why (post-mortems, prior decisions, tribal knowledge). An agent without it doesn't abstain; it confidently proposes reverting the fix.

Why it matters

It implies context stores must capture decision rationale and prohibitions, not just documents and code, and that 'no relevant results' is a dangerous state rather than a neutral one for autonomous agents.

Generalization

Context systems optimized for retrieval of what exists systematically under-index what was intentionally removed or forbidden; agents then treat absence of evidence as permission.

[!]Failure Modemedium noveltyweak evidence

Background agents fail silently: without context they produce confident, wrong artifacts that misinform teams, and the current industry mitigation is a human acting as a manual context layer by babysitting the agent.

Why it matters

It identifies the human-in-the-loop as an unscalable workaround masking a context defect, and points to a specific observability gap — errors that never surface as exceptions because the agent never knew it was wrong.

Generalization

As agents move from synchronous chat to asynchronous background execution, the dominant risk shifts from visible wrong answers to plausible-but-unfounded artifacts propagating through team workflows; the fix is upstream context quality, not better prompting.

[>]Predictionmedium noveltymoderate evidence

Agent runtime infrastructure (session management, checkpointing, orchestration, retries, sandbox isolation, observability, multi-channel adapters, replay) has been absorbed by frameworks, collapsing an agent definition to model selection, instructions, tools/skills, and sandbox choice.

Why it matters

If the definition of an agent is now a few declarative parameters, engineering differentiation cannot come from the runtime; it must come from workflow design and data relevance, which reorders what teams should staff and measure.

Generalization

When a layer commoditizes, competitive effort migrates one level up the stack; teams still investing in bespoke runtime plumbing are paying for solved problems.

Source video ↗
[M]Mechanismmedium noveltyweak evidence

Context delivery is per-task and per-user, not a static index: the same source corpus must be re-ranked for relevance to the specific task, personalized to the requesting user, and filtered to that user's permissions at query time.

Why it matters

It means context engineering is a runtime ranking-and-authorization problem with its own latency budget and per-call cost, not a one-off ingestion/indexing job — and that permission enforcement must live in the delivery path, not in the agent's prompt.

Generalization

Retrieval quality is a function of the request, not of the corpus; any context system with a single global index will over- or under-serve most tasks and will leak data across permission boundaries.

Deep dives

5

Negative knowledge as a first-class context class

Research question

What record structure makes prohibitions and prior decisions machine-actionable enough that an agent actively suppresses a plausible but previously-rejected change?

Why

Retrieval indexes what exists and systematically under-indexes what was deliberately removed, so agents treat absence of evidence as permission and re-propose changes that previously caused outages.

Source video ↗

Scaling behavior of raw MCP access versus a synthesis layer

Research question

How do task accuracy and token cost change as connected MCP server count rises from 1 to 3 to 5, with and without a ranking/reconciliation stage?

Why

It tests the falsifiable core claim that more connectivity can make agents worse and more expensive, and locates the crossover point where a context layer becomes mandatory rather than optional.

Source video ↗

Evaluation of missing-context failures

Research question

Can an eval suite detect a missing-context defect before deployment when the agent produces a confident, non-exceptional, wrong artifact?

Why

Silent failures never surface as tool-call errors, so standard end-to-end correctness evals are blind to them; context coverage must become a separately measured property of the pipeline.

Source video ↗

Permission enforcement in the context delivery path

Research question

What does it cost to enforce per-user permissions as a retrieval-stage gate rather than as prompt-level trust, and how does that gate behave when sources disagree about authorization semantics?

Why

Centralizing ACL filtering makes security auditable across all agents, but it places a high-blast-radius component on the critical path of every agent action and requires modeling each source's authorization model.

Source video ↗

Freshness and invalidation of decision rationale

Research question

Which event signals (commits, ticket closures, incident post-mortems) should invalidate a stored decision record, and how much staleness-induced error does invalidation actually remove?

Why

A context engine that serves stale rationale is worse than none, because it supplies confident justification for an obsolete decision; without a decay/invalidation mechanism the layer silently accumulates wrong context.

Article ideas

4

Your Agent Doesn't Need a Bigger Model, It Needs a Record of What You Turned Off

The dominant agent failure is not reasoning quality but the absence of negative knowledge: agents confidently revert deliberate decisions because no system stores prohibitions and their rationale, and fixing this requires a new data class, not a better prompt.

Angle

Start from the async-dispatch ticket example, then generalize: what retrieval systems index versus what decisions they must index, and what a decision record needs to contain to suppress a bad recommendation.

Source video ↗

Adding Integrations Made My Agent Worse

MCP is necessary but insufficient: each additional connected source raises recall and lowers signal-to-noise, pushing source adjudication and token cost onto the model — so connectivity without a ranking-and-reconciliation layer is a quality regression disguised as progress.

Angle

Argue against the integration-count scoreboard; show the mechanism (raw matches, conflicting sources, agent-side arbitration) and where a synthesis stage belongs architecturally.

Source video ↗

Babysitting Is Your Context Debt Metric

Human review of agent output is an implicit, unscalable context layer; the hours spent supplying missing rationale are a measurable proxy for context defects, and treating review time as a KPI converts an invisible cost into an engineering backlog.

Angle

Reframe human-in-the-loop from a safety practice into an accounting entry, and propose instrumenting review time to attribute it to missing context rather than to model weakness.

Source video ↗

The Runtime Is Solved; Your Relevance Problem Is Not

As frameworks absorb session management, sandboxing, observability and replay, engineering differentiation migrates to data relevance and workflow design — teams still building bespoke runtime plumbing are paying for solved problems while leaving context unowned.

Project ideas

4

Decision Ledger

new

Storing prior decisions as structured records (what changed, why, who, when, reversal conditions) and retrieving the reversal condition at task time measurably reduces agent proposals that revert a deliberate change, compared with document-only retrieval.

Proof of concept

Ingest a repository's tickets and post-mortems into a decision record schema; intercept agent proposals on a held-out set of historical revert incidents and score whether the agent still recommends the reverted change.

Measurement

Revert-recommendation rate on a curated set of deliberately-disabled features, with and without reversal-condition retrieval; also measure false suppression of legitimate re-enablement proposals.

Source video ↗

Abstention Suite

beyond-evals

A task suite whose correct answer is to preserve a prior decision or abstain detects missing-context failures that end-to-end correctness evals score as passes.

Proof of concept

Build tasks mined from incident post-mortems where the plausible action is wrong; run them against agents wired directly to MCP servers and against a context-engine pipeline.

Measurement

Percentage of tasks where the agent abstains or preserves the prior decision; gap between this suite's score and a standard correctness eval on the same agents.

Source video ↗

Policy Gate Proxy

gatehouse

Enforcing per-user permissions as a delivery-path stage produces zero cross-boundary leakage with latency overhead small enough to keep on the critical path of every agent action.

Proof of concept

Insert a context-delivery proxy between agents and multiple source connectors that filters, ranks and synthesizes before the prompt is built; test multi-tenant queries with deliberately overlapping permissions.

Measurement

Leakage rate on adversarial per-user queries, added p50/p95 latency per agent action, and token reduction versus direct multi-source attachment.

Source video ↗

Source Scaling Bench

new

Task accuracy degrades and token cost rises monotonically as MCP server count increases, and a synthesis layer flattens or reverses the accuracy degradation while cutting tokens.

Proof of concept

Benchmark the same agent task against 1, 3 and 5 connected sources, once with raw matches attached and once behind a ranking/reconciliation stage.

Measurement

Accuracy, tokens per task and conflict-resolution errors at each source count for both pipeline variants.

Architectural implications

4

Where context synthesis lives determines how much reasoning the model does about sources rather than about the task.

Before

Agent is wired directly to Slack MCP, Linear MCP and GitHub MCP servers and must reconcile conflicting matches inside its own context window.

After

Agent issues one task-scoped context request; the engine merges sources, ranks by relevance, resolves conflicts and filters by permission before anything reaches the model.

Consequence

Smaller, cleaner prompts and lower token cost, but a new component whose latency, freshness and failure modes now sit on the critical path of every agent action.

Source video ↗

Permission enforcement moves from prompt-level trust to a centralized delivery-path gate.

Before

Each tool/data connection enforces its own ACLs, and the agent is trusted to not over-share what it retrieves.

After

The context engine enforces permissions as a first-class stage of context delivery.

Consequence

Security becomes centrally auditable and consistent across agents, but the engine must model every source's authorization semantics — making it a high-value and high-blast-radius dependency.

Source video ↗

Human babysitting is an implicit context layer that can be removed only when curation is explicit.

Before

A human reviews background agent output to supply the missing 'why', acting as the context layer.

After

Rationale, decisions and post-mortems are captured and delivered as structured context at agent runtime.

Consequence

Unattended background agents become viable, but only if institutional decision history is actually written down and kept current — otherwise the silent-failure risk simply becomes invisible.

Source video ↗

Context quality becomes a separable, benchmarkable concern from model and runtime choice.

Before

Agent quality is evaluated holistically as a single end-to-end outcome.

After

Context assembly is a distinct layer with its own inputs (sources, conflicts, permissions) and outputs (synthesized, ranked snippets) that can be evaluated in isolation.

Consequence

Enables context-specific evals — coverage, contradiction handling, staleness — and lets teams swap models or frameworks without re-validating their entire knowledge pipeline.

Tradeoffs and failure modes

4

Access vs. understanding (MCP breadth)

Benefit

MCP gives uniform connectivity to many data sources with minimal integration work.

Cost or risk

Raw multi-source matches increase context-window cost and offload source adjudication to the model, degrading output quality as integrations are added.

Source video ↗

Autonomy vs. silent error propagation

Benefit

Background agents can act continuously without human involvement.

Cost or risk

Errors are confident and non-exceptional, so they spread through tickets and reviews and misinform the team before anyone notices.

Source video ↗

Centralized governance vs. per-call latency

Benefit

A single engine delivers precise, permissioned, relevant context tailored to the task and user.

Cost or risk

Synthesizing, ranking and permission-filtering before every agent action adds a query hop and a freshness problem on the critical path.

Source video ↗

Infrastructure abstraction vs. control

Benefit

Frameworks like Flue, Vercel Eve and Mastra remove session management, sandbox isolation, observability and replay work.

Cost or risk

Teams lose direct control over runtime internals and debugging surfaces, and the real engineering burden silently relocates to data relevance where there is far less tooling.
