Summary

Overview

  • Speaker: Harish Gaggar
  • Channel: AI Engineer
  • Main topic: Building and governing enterprise AI agents for production deployment
  • Purpose: To provide engineers and enterprise architects with a comprehensive framework and architectural blueprint for deploying secure, auditable, and cost-efficient AI agents in production. Harish Gaggar, Senior Staff Software Engineer at Credit Karma, explains how to transition AI agents from experiments to secure, governed enterprise production environments. He covers architectural patterns, MCP (Model Context Protocol) servers and gateways, monitoring, tracking and evaluation, PII blocking, and context optimization.

Topic Map

Challenges in Enterprise AI Agents

  • Explanation: Enterprise AI agents often fail in production because foundational controls such as gateways, proper tool execution, tracking, memory management, and security are missing.
  • Key claims:
    • AI agents fail in production when foundational controls are missing
    • Many lack secure gateways for authentication and authorization
    • Missing tracking, memory management, and PII data blocking
  • Examples:
    • Secrets leaking into LLMs or tracking systems
    • Lack of audit trails for agent tool executions
  • Terminology:
    • foundational controls
    • gateway
    • MCP gateway
  • Why it matters: Without proper enterprise controls, AI agents pose severe security, privacy, and cost risks in production.

Design Framework for Enterprise Agents

  • Explanation: A layered framework encompassing agent frameworks, OAuth authentication, customized MCP servers, continuous audit, PII stripping, tracking and eval, memory management, and context optimization.
  • Key claims:
    • Each layer must be scoped, sanitized, audited, and measured by design
    • An agent needs an enterprise-grade framework around it, not just a standalone agent
  • Examples:
    • LangGraph for task-specific nodes, skills, and prompts
    • FastMCP wrapper for exposing typed tools
  • Terminology:
    • agent framework
    • FastMCP
    • HITL
    • context optimizer
  • Why it matters: Structured layering ensures safety, compliance, and predictable behavior at enterprise scale.

MCP Servers and Gateways

  • Explanation: Model Context Protocol (MCP) servers turn REST APIs into typed, permission-scoped tools, while MCP gateways provide centralized authentication, routing, and JWE access token un-wrapping.
  • Key claims:
    • MCP servers enforce request filters, limits, and blocked fields
    • MCP gateway ensures every request runs as a real identity through an audited gateway
    • MCP servers never face the client directly
  • Examples:
    • Artifactory MCP and GitHub MCP
    • Redis session state storage for OAuth requests
  • Terminology:
    • MCP server
    • MCP gateway
    • FastMCP
    • JWE access token
  • Why it matters: Decoupling clients from servers via a secure gateway prevents unauthorized direct access to enterprise data and internal tools.

Monitoring, Tracking, and Evaluation

  • Explanation: Comprehensive telemetry using OpenTelemetry collectors, Tempo for traces, Prometheus for metrics, and Grafana for dashboards, alongside BigQuery tables for agent job tracking and evaluation.
  • Key claims:
    • AI agents cannot be trusted without continuous monitoring, evaluation, and feedback
    • Separate agent-side LLM telemetry from gateway operational telemetry
  • Examples:
    • BigQuery tables: agent_job_tracking, agent_quality_eval, agent_tool_invocations
    • OpenTelemetry collector routing to Tempo and Prometheus
  • Terminology:
    • OpenTelemetry
    • Tempo
    • Prometheus
    • Grafana
    • OTLP
  • Why it matters: Enables root cause analysis, latency tracking, cost monitoring, and quality evaluation across hundreds of deployed agents.

Agent Memory, PII Blocking, and Context Optimization

  • Explanation: Persistent checkpointing for workflows across runs, real-time PII stripping before LLM ingestion, and a context optimizer to prune, rerank, and compress context to save token costs.
  • Key claims:
    • Agent persistence ensures durability and seamless recovery across runs using thread IDs and checkpoints
    • PII trimming blocks high-severity secrets from ever reaching LLMs
    • Context optimization saves 70% to 90% in token costs
  • Examples:
    • SQLite for local development, Cloud Spanner for production
    • Blocking private keys, AWS access keys, SSNs, credit cards with 95%+ severity rules
  • Terminology:
    • checkpointing
    • thread ID
    • PII trimmer
    • context optimizer
    • token savings
  • Why it matters: Protects sensitive enterprise data from leaking while drastically reducing LLM operational costs.

Key Points

Build an enterprise framework, not just an AI agent

  • Explanation: Production agents require surrounding infrastructure for registration, CI/CD pipelines, secret management, memory, and tracking.
  • Evidence: Dev portal creates repository with workload identity, memory DB, tracking tables, and secret management automatically.
  • Practical implication: Standardizes agent development and deployment across the entire engineering organization.

Gateway-first security is the foundation

  • Explanation: All tool calls must be authenticated and governed through an MCP gateway before reaching backend servers.
  • Evidence: Architecture diagrams show MCP servers never facing clients directly; all requests pass through the gateway with JWE tokens.
  • Practical implication: Eliminates shadow IT and unauthenticated LLM tool invocations.

MCP turns REST APIs into safe, agent-friendly tools

  • Explanation: Using FastMCP server wrappers, developers expose typed, permission-scoped tools with strict input filters and limits.
  • Evidence: Internal security teams review all tools before deployment to production.
  • Practical implication: Prevents LLMs from constructing arbitrary or dangerous API calls.

Keep humans in control of high-risk actions

  • Explanation: Write and sensitive operations must pass through Human-In-The-Loop (HITL) approval workflows.
  • Evidence: Agent framework flow includes approval diamond checking execute vs reject states.
  • Practical implication: Mitigates catastrophic errors or unintended modifications by autonomous agents.

Optimize context before it becomes cost

  • Explanation: Context optimizers select relevant payloads, rerank information, remove duplicates, and compress prompts before sending to LLMs.
  • Evidence: Demo showed token usage dropping from 24,000 tokens down to 2,400 tokens (90% savings) for the same query.
  • Practical implication: Enormous reduction in API costs for high-volume enterprise AI agents.

Frameworks, Models & Processes

Agent Design & Governance Framework

  • How it works: A multi-layered architecture handling requests from agent framework through OAuth, MCP gateway, customized servers, PII stripping, tracking, memory, and context optimization.
  • Components:
    • Agent Framework (LangGraph)
    • OAuth Authentication
    • Customized MCP Server
    • Continuous Audit
    • PII/Secrets Stripping
    • Tracking and Evaluation
    • Memory Management
    • Context Optimizer
  • When to use: When deploying multi-agent workflows into enterprise production environments.

Context Optimizer Framework

  • How it works: Selects payload based on token limit, reranks relevant information, clusters to remove duplicates, and compresses the final context before LLM invocation.
  • Components:
    • Select
    • Rerank
    • Cluster
    • Compress
  • When to use: When handling large codebases, documentation, or extensive tool outputs to avoid token bloat and high costs.

Actionable Takeaways

  • Immediate:
    • Implement gateway-first authentication for all agent tool calls
    • Adopt FastMCP for building typed, secure MCP servers
    • Deploy PII and secret trimming before data reaches LLMs
  • Strategic:
    • Build a centralized developer portal for registering and deploying governed agents
    • Establish rigorous tracking, evaluation, and telemetry using OpenTelemetry and BigQuery
    • Always include Human-In-The-Loop approval gates for write and sensitive operations
  • Questions to investigate:

The MCP gateway functions as a mandatory identity-bearing chokepoint: every agent tool call is authenticated as a real user identity and passes through an audited gateway with JWE access-token un-wrapping, and MCP servers are never exposed directly to clients.

Why it matters

Reframes MCP from a developer-convenience protocol into a security boundary; it eliminates shadow IT and unauthenticated LLM tool invocations, and makes the gateway — not the agent — the unit of access control and audit.

Generalization

For any tool-using agent system, insert a policy/identity enforcement layer between the agent runtime and backend APIs so authorization and audit live outside the LLM's control.

Architectural implications

4

Tool access is mediated by a gateway that carries real identity, with MCP servers hidden behind it.

Before

Agents or clients connect directly to backend APIs and MCP servers.

After

All requests route through an audited gateway that unwraps JWE tokens and enforces identity.

Consequence

Access control and audit centralize at the gateway; direct server exposure and shadow IT become detectable and blockable.

A dedicated context optimizer layer sits between context assembly and the LLM.

Before

After

Context is selected, reranked, deduplicated, and compressed before ingestion.

Consequence

Token cost becomes an engineered, measurable pipeline output rather than an emergent expense.

After

Consequence

Quality evaluation and infrastructure debugging get independent, queryable pipelines.

Before

After

Consequence

Tradeoffs and failure modes

4

Gateway as mandatory chokepoint

Benefit

Centralized identity, authentication, routing, and audit for every tool call.

Cost or risk

Introduces an extra hop and dependency in the critical path; its availability, latency, and JWE handling become systemic risks.

Source video ↗

Aggressive context optimization

Benefit

70% to 90% token-cost savings demonstrated on a real query.

Cost or risk

Pruning, deduplication, and compression can drop information the model needs, risking quality regressions that are not visible in the token-count metric.

Source video ↗

High-severity PII blocking

Benefit

Prevents secrets and sensitive data from reaching LLMs, traces, or eval stores.

Cost or risk

Severity-thresholded rules may over-block legitimate inputs or miss novel secret formats, creating either false positives or coverage gaps.

Source video ↗

Human-in-the-loop approval for write/sensitive actions

Benefit

Prevents catastrophic errors from autonomous agent actions.

Cost or risk

Adds human latency and operational burden, limiting throughput and autonomy for legitimate write operations.
