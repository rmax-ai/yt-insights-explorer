Overview

  • Speaker: Ang Li
  • Channel: AI Engineer
  • Main topic: Building full-stack infrastructure for computer use agents using a neuro-symbolic approach (Agent S, Simulang, and Saibox).
  • Purpose: To provide technical insight into computer use agents, introduce the Simular infrastructure stack for CUA development, and discuss the future of AI-driven computer automation. Ang Li, co-founder and CEO of Simular, discusses the evolution and engineering of computer use agents over the past two years. He explores the challenges of autonomy and computer operation, the shift from VLM-only agents to neuro-symbolic architectures (combining VLM perception with coding agents), and introduces the infrastructure stack built by Simular: Agent S, Simulang CLI, and Saibox virtual computer cloud.

Key Points

Neuro-symbolic integration is necessary for general AI

  • Explanation: Combining neural networks (VLMs for perception and handling novelty) with symbolic systems (code for deterministic execution) creates robust agents.
  • Evidence: Agent S architecture combining VLM agents with coding agents.
  • Practical implication: Developers should not rely solely on VLMs or hardcoded scripts; combining them yields higher reliability.

Perception requires multiple signals

  • Explanation: Relying on a single signal like screenshots is insufficient; agents need screenshots, accessibility trees, and DOM trees combined.
  • Evidence: OSWorld benchmark results comparing single-signal vs multi-signal perception.
  • Practical implication: Agent frameworks must incorporate OS-level accessibility APIs alongside visual understanding.

Reliability decays with repetition without clarification

  • Explanation: When running tasks repeatedly in perturbed environments, agent success rates drop unless instructed to ask clarification questions.
  • Evidence: Research paper 'On the Reliability of Computer Use Agents' showing drop from Pass@1 to Pass^3.
  • Practical implication: Prompt agents to seek clarification on ambiguous instructions to maintain high reliability.

Frameworks, Models & Processes

Neuro-Symbolic Agent Architecture

  • How it works: Pairs a VLM agent for open-ended perception and handling novelty with a coding agent for deterministic, repeatable step execution.
  • Components:
    • VLM agent (perception, general reasoning)
    • Coding agent (deterministic execution, code generation)
    • Memory management and harness layer
  • When to use: When building agents that need to operate arbitrary desktop applications and web browsers autonomously.

Record -> Replay -> Break -> Heal

  • How it works: Record task execution as a skill, replay it, deliberately break the environment, and let the agent heal by rewriting the skill in real-time.
  • Components:
    • Record (capture skill)
    • Replay (watch reasoning)
    • Break (perturb environment)
    • Heal (recover and rewrite code)
  • When to use: When building robust, self-improving automation scripts on desktops.

[O]Mental Modelmedium noveltymoderate evidence

Computer use agents should be split into two separable subsystems: Autonomy (reasoning, planning, recovery) and Computer (operating desktop, browser, apps, terminal). Autonomy itself is neuro-symbolic — a VLM agent handles novelty while a coding agent handles deterministic execution — and the 'Computer' half is a perception/grounding problem over multiple signals.

Why it matters

Gives an explicit decomposition boundary for building CUA systems: it separates the reasoning/orchestration layer from the perception-and-actuation layer, so each can be developed, evaluated, and swapped independently instead of being tangled in one end-to-end loop.

Generalization

Any agent that must act on an environment it does not fully control can be factored into a planner/recovery layer and a grounding/actuation layer, with the actuation layer treated as a perception problem over heterogeneous signals.

[A]Architecturehigh noveltymoderate evidence

Pairing two foundation models inside a single harness — a VLM agent for open-ended perception and novelty, plus a coding agent for deterministic, repeatable step execution — outperforms a single-model agent. The harness layer, not the model, is where the composition happens.

Why it matters

Suggests a concrete architectural pattern for reliability: keep the non-deterministic perception model out of the repeatable execution path, and let generated code carry the deterministic steps. It also implies the orchestration harness is a first-class engineering artifact worth investing in.

Generalization

Decomposing an agent into a 'novelty handler' and a 'deterministic executor' sharing one harness is a general pattern for systems where LLM output must be turned into repeatable actions.

[M]Mechanismmedium noveltymoderate evidence

Relying on a single perception signal is insufficient; agents need screenshots, accessibility trees, and DOM trees combined to ground actions.

Why it matters

It reframes grounding as a multi-modal fusion problem rather than a vision problem, which changes what an agent framework must expose: OS-level accessibility APIs have to be first-class inputs alongside pixels, and the mapping from those signals to actionable element IDs is the core technical work.

Generalization

Grounding in any UI environment (desktop, browser, mobile) benefits from combining structural/tree signals with pixel signals rather than either alone.

[E]Empirical Resulthigh noveltymoderate evidence

Reliability decays with repetition in perturbed environments unless the agent is explicitly prompted to ask clarification questions. The evidence is the drop in success rates from pass@1 to pass^k as repetition and environment perturbation increase.

Why it matters

It identifies clarification-seeking as a reliability mechanism, not a UX nicety, and it implies pass@1 is a misleading metric for agents that will run repeatedly in a changing environment. Teams should evaluate with repeated/pass^k runs before trusting an agent's success rate.

Generalization

For any agent operating in an environment that drifts between runs, single-shot success metrics overstate reliability; explicit ambiguity resolution is a cheap mitigation.

[P]Practicehigh noveltyweak evidence

The Record -> Replay -> Break -> Heal loop turns a captured execution into a durable skill: record the task as a skill, replay it, deliberately perturb the environment, and let the agent heal by rewriting the skill in real-time.

Why it matters

It makes the perturbation itself part of the development loop rather than an accident of production, and it converts a brittle script into a self-repairing artifact. This is a concrete method for building resilient desktop automation instead of hoping recorded scripts keep working.

Generalization

Deliberate environmental perturbation as a training/eval step is a general technique for hardening any agent-generated artifact (scripts, workflows, tool sequences) against change.

[A]Architecturemedium noveltymoderate evidence

Simulang brings a Playwright-like scripting model to the entire desktop across major operating systems, exposed as a Node.js/TypeScript CLI, while Saibox provides isolated virtual desktops for running hundreds of agents in parallel.

Why it matters

It separates the scripting/programmatic-actuation layer from the scalable-execution layer, giving a concrete infrastructure shape: a cross-OS scripting API (sapi) plus pooled virtual desktop isolation. This is the substrate needed to make CUA development testable and horizontally scalable.

Generalization

Agent platforms tend to converge on a declarative scripting API over the actuation surface, plus disposable isolated environments for parallel execution and reproduction.

[O]Mental Modelmedium noveltyweak evidence

The trajectory from GPT-4V plus PyAutoGUI in late 2023 (brittle, iterative, often failing on a basic click) to multi-signal neuro-symbolic architectures and inference-time scaling represents an architectural shift rather than a model-only improvement.

Why it matters

It suggests that raw VLM capability was not the bottleneck for computer use; the missing pieces were grounding signals, harness structure, and test-time compute. Engineers should budget effort accordingly instead of waiting for a stronger model.

When an agent capability fails, the limiting factor is frequently architecture/harness rather than model quality, and improvements arrive faster through structural change.

Deep dives

4

Multi-signal grounding fusion and conflict resolution

Research question

When screenshot pixels, the accessibility tree, and the DOM tree disagree about what element exists at an actionable location, how should a CUA fuse them — and which signal should dominate under which failure condition?

Why

Grounding is the actuation half of the Autonomy/Computer split, and if the fusion rule is undefined, every downstream element-ID scheme and action target is arbitrary. A concrete fusion policy turns 'use more signals' from a slogan into an implementable component with testable behavior.

Source video ↗

Mechanism of pass@1 to pass^k reliability decay under perturbation

Research question

How much of the pass@1 to pass^k drop is recovered by explicit clarification prompting versus scaling test-time compute, and is the decay driven by state leakage between runs, environment drift, or stochastic perception?

Why

If pass@1 overstates reliability, every published CUA number and every internal sign-off on a desktop agent is measured wrong. Isolating the two named mitigations determines whether reliability work should be spent on prompt policy, compute budget, or environment isolation.

Source video ↗

Harness attribution: how much CUA performance comes from composition versus the foundation models

Research question

Holding the VLM and coding model fixed, how much of a CUA's success rate is attributable to harness structure (dual-model composition, memory management, test-time compute budget) rather than to model capability?

Why

It decides where an engineering team should spend the next quarter: swapping to a stronger VLM, or restructuring the harness around a novelty handler plus a deterministic executor. The claim that two models in one harness beat one model is comparative and currently unattributed.

Source video ↗

Convergence and semantic drift of the Record -> Replay -> Break -> Heal loop

Research question

After repeated break/heal cycles on the same recorded skill, does the rewritten skill converge toward a stable fixpoint, or does it drift away from the original task semantics while still appearing to pass?

Why

Self-healing is only a reliability mechanism if it converges; if it drifts, it silently converts a captured deterministic script into an unverifiable artifact. This determines whether healed skills can be trusted as versioned, reviewable assets.

Article ideas

3

Your Agent's Success Rate Is a Lie: pass@1, pass^k, and the Repetition Tax

Single-shot success rates are the wrong unit of trust for computer use agents, because reliability decays with every repeat in a perturbed environment — and the cheapest known mitigation is making the agent ask a clarifying question rather than making the model smarter.

Angle

Take the pass@1 to pass^k gap as the headline metric, argue that clarification prompting is a reliability primitive rather than a UX nicety, and show what changes in an eval harness when you report repeated-run success instead of one-shot success.

Source video ↗

The Harness Is the Product

The durable engineering asset in a computer use agent is the harness layer that composes a VLM novelty handler with a coding executor — not the foundation model inside it — so reliability work belongs in composition, memory, and deterministic replay rather than in prompt tuning or waiting for the next model release.

Angle

Use the late-2023 GPT-4V plus PyAutoGUI failure as the starting evidence and the Autonomy/Computer split plus dual-model harness as the destination, then argue that raw VLM capability was never the binding constraint.

Source video ↗

Grounding Is a Fusion Problem, Not a Vision Problem

Treating GUI grounding as screenshot understanding caps agent reliability; the actionable step is to make OS-level accessibility APIs and DOM structure first-class inputs alongside pixels, and to define an explicit conflict policy when the signals disagree.

Angle

Reframe grounding as multi-modal fusion mirrored on the self-driving analogy (lidar/radar/camera to accessibility tree/DOM/screenshot), and spell out the framework requirements that follow: element-ID schemes, tree access, and disagreement handling as core infrastructure.

Project ideas

4

Harness Ablation Rig

beyond-evals

Holding the VLM and coding model fixed, a dual-model neuro-symbolic harness with explicit clarification and a scaled test-time compute budget beats a single-model harness by a measurable margin on repeated perturbed runs — and the gain is larger at pass^k than at pass@1.

Proof of concept

A containerized eval rig with three interchangeable harnesses — single VLM loop, VLM plus coding agent in one harness, and the same with clarification prompting and test-time compute scaling — run against the same model checkpoints on the same desktop task set with scripted environment perturbations between repeats.

Measurement

pass@1 and pass^k success rates per harness, plus per-harness token/compute cost, reported as the marginal reliability gained per unit of compute.

Source video ↗

Signal Conflict Grounding Bench

movement-lab

Grounding accuracy degrades predictably when visual and structural signals disagree, and a resolved multi-signal fusion rule (screenshot plus accessibility tree plus DOM tree) outperforms any single-signal baseline specifically on the disagreement subset rather than uniformly.

Proof of concept

A task suite that deliberately constructs disagreement cases — element visible in pixels but absent from the accessibility tree, or DOM node present but occluded — and measures element-identification accuracy for screenshot-only, tree-only, and fused grounding against a manual ground-truth action target.

Measurement

Element-identification and action-target accuracy on the conflict subset versus the agreeing subset, per signal combination, with a confusion matrix over which signal wins when they disagree.

Source video ↗

Desktop Pool Isolation and Cost Harness

gatehouse

Running hundreds of computer use agents in parallel on isolated virtual desktops is bounded by provisioning latency and per-run cost rather than by isolation failure, and per-run cost is dominated by environment provisioning rather than agent inference.

Proof of concept

A virtual desktop pool manager that provisions disposable isolated desktops driven by a cross-OS scripting API, runs N agents in parallel on perturbed task variants, and deliberately attempts cross-environment state leakage and resource exhaustion to probe isolation boundaries.

Measurement

Provisioning latency distribution, per-agent-run cost breakdown (provisioning versus inference), achieved parallelism at fixed hardware, and count of successful cross-environment leak attempts.

Source video ↗

Skill Heal Drift Tracker

new

Repeated break/heal cycles on a recorded skill converge in the first few iterations but drift semantically afterwards, so task correctness stays high while the rewritten skill's diff grows and its behavioral surface diverges from the original recording.

Proof of concept

A loop that records a desktop task as a skill, replays it, injects a controlled perturbation, lets the agent rewrite the skill, and versions each healed artifact — running until either the diff stabilizes or the original task semantics fail.

Measurement

Task correctness per cycle, diff size of the rewritten skill per cycle, and semantic divergence measured by re-running the healed skill unperturbed and comparing action sequences to the original recording.

Architectural implications

3

Autonomy is decomposed into a VLM agent (novelty/perception) and a coding agent (deterministic execution), sharing one harness.

Before

A single vision-language model drives the whole perceive-decide-act loop, regenerating every step.

After

Perception and novelty handling are separated from repeatable, code-driven execution inside a shared harness with its own memory management.

Consequence

The harness becomes a primary engineering surface; reliability work shifts from prompt tuning toward composition, memory, and deterministic replay of generated code.

Source video ↗

Grounding is treated as fusion of screenshots, accessibility trees, and DOM trees.

Before

Agents act on screenshot pixels alone.

After

Framework inputs include OS-level accessibility APIs and document structure alongside vision.

Consequence

Agent frameworks must integrate platform accessibility APIs, and element identification/ID schemes become core infrastructure rather than a downstream concern.

Source video ↗

Scalable agent execution is provided as isolated virtual desktops (Saibox) separate from the scripting layer (Simulang).

Before

Agents run on the developer's own machine, one at a time.

After

Hundreds of agents run in parallel against disposable, isolated virtual desktops driven by a Playwright-like cross-OS scripting API.

Consequence

Enables reproducible evaluation, parallel benchmarking, and safe perturbation testing; raises new concerns around environment provisioning, isolation, and cost per agent-run.

Tradeoffs and failure modes

5

Neuro-symbolic composition vs. single-model simplicity

Benefit

Combining a VLM agent and a coding agent in one harness outperforms single models and yields deterministic, repeatable execution.

Cost or risk

Two foundation models plus a harness layer increase system complexity, coordination overhead, and the surface area for failure.

Source video ↗

Repeated execution reliability

Benefit

Scaling test-time compute and prompting for clarification improve success rates.

Cost or risk

Success decays with each repeat in perturbed environments, so pass@1 results overstate real-world reliability.

Source video ↗

Vision-only perception

Benefit

A vision-only multi-layer architecture (Agent S2) avoids dependence on accessibility trees.

Cost or risk

Single-signal perception is insufficient for robust grounding compared with combining screenshots, accessibility trees, and DOM trees.

Source video ↗

Self-healing recorded skills

Benefit

Breaking the environment and letting the agent rewrite the skill in real-time produces robust automation.

Cost or risk

Deliberate perturbation plus agent rewriting introduces nondeterminism into what was a captured, replayable script.

Source video ↗

Relying on VLMs directly for GUI control

Benefit

VLM-only agents can handle open-ended, previously unseen interfaces without APIs.

Cost or risk

Early VLM-driven GUI control was brittle: simple icon clicks required iterative refinement and often failed, motivating hybrid architectures.
