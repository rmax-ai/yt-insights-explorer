Summary

Overview

  • Speaker: Pete Koomen, Garry Tan, Diana Hu, Harj Taggar, Jared Friedman
  • Channel: Y Combinator
  • Main topic: Building AI native companies and internal AI infrastructure at Y Combinator
  • Purpose: To share YC internal AI playbook publicly for the first time, detailing how AI agents, tool registries, and context layering transform organizational workflows. Y Combinator partners discuss how they have built internal AI infrastructure, agents, harnesses, and shared organisational context tools, transforming YC into an AI-native organization and offering insights into how startups and companies can adopt AI agents for exponential productivity.

Topic Map

YC's Internal AI Infrastructure & Agent Adoption

  • Explanation: Pete Koomen details how YC started building internal AI agent harnesses, tool registries, and database integrations for finance and partner workflows over the past year.
  • Key claims:
    • YC built internal agent infrastructure and harnesses to empower every team.
    • A single Postgres database containing all company, founder, and financial context powers YC agents.
    • Agent tool registries enable teams to add custom skills and tools easily.
  • Examples:
    • Giving finance agents access to financial workflows, journal entries, and priced rounds.
    • Allowing agents to query database tables and model files directly.
  • Terminology:
    • agent loop
    • tool registry
    • shared organizational context
    • model router
  • Why it matters: Demonstrates how centralized context and agent harnesses eliminate friction and back-and-forth between teams, supercharging organizational speed.

Horseless Carriages & AI Software Design

  • Explanation: Discussion on how early AI software mimics old paradigms by hiding prompts and AI features behind traditional deterministic UIs instead of letting users interact directly with agents.
  • Key claims:
    • Many AI apps are 'horseless carriages'—mimicking old software paradigms by locking prompt control behind traditional UI.
    • Shift control of software development and execution from the developer to the user through AI agents.
    • True AI-native software wraps deterministic software tools inside agent wrappers rather than wrapping AI inside deterministic code.
  • Examples:
    • Gmail AI assistant hiding prompt context instead of letting users customize or interact freely.
    • Trewittick's Steam Carriage design mimicking horse carriages.
  • Terminology:
    • horseless carriages
    • software-deterministic
    • agentic tools
  • Why it matters: Explains why many current AI integrations fail to deliver true leverage and outlines the architecture of future AI software.

Skillification, Denormalization, and Two-Sentence Pitches

  • Explanation: The partners discuss 'skillification'—converting human workflows and company context into reusable agent skills, such as two-sentence company descriptions.
  • Key claims:
    • De-normalizing data and putting all organizational context into a single database enables agents to answer complex arbitrary queries.
    • Two-sentence descriptions act as atomic foundational prompts that every partner and agent uses to understand companies.
    • Multi-player harnesses and team skill sharing represent the next frontier of organizational AI.
  • Examples:
    • Tom Blomfield writing custom prompts to condense company context into two sentences.
    • Using MCP (Model Context Protocol) and shared skill registries across open-source tools like OpenClaw and Claude Code.
  • Terminology:
    • skillify
    • de-normalization
    • two-sentence description
    • meta-skill
    • check-resolvable
  • Why it matters: Shows how standardizing and compressing organizational context into reusable agent skills drastically improves output quality and team onboarding.

Centralization vs. Decentralization in AI Organizations

  • Explanation: Examining whether AI leads to centralized control or decentralized employee empowerment, and why transparent default-public agent conversations foster trust.
  • Key claims:
    • Default-public agent conversations broadcasted to Slack create internal transparency and social control.
    • AI eliminates the fear of asking 'dumb questions', allowing junior employees to ramp up much faster.
    • True AI-native organizations require being egalitarian and trust-by-default, which runs counter to traditional corporate structures.
  • Examples:
    • Broadcasting all agent conversations internally to Slack channels for collaborative learning.
    • New employees using open-source agent instances to query historical context and codebases without bothering senior partners.
  • Terminology:
    • social control
    • trust by default
    • egalitarian infrastructure
  • Why it matters: Highlights the cultural and structural prerequisites needed for organizations to successfully adopt AI agents at scale.

Key Points

Single Database Context Layer

  • Explanation: Storing all company, founder, and financial records in one Postgres database allows agents to execute complex cross-domain queries instantly.
  • Evidence: YC's internal database houses company tables, founder tables, financial transactions, and CRM notes in one schema.
  • Practical implication: Eliminates departmental silos and data fragmentation, empowering any agent or employee to query comprehensive company context.

The Shift from Coder to User

  • Explanation: AI shifts the locus of software control from developers writing deterministic workflows to users prompting and shaping agent behavior directly.
  • Evidence: Building custom Rails apps in days versus using agentic tools like Claude Code and OpenClaw to iterate dynamically.
  • Practical implication: Reduces software development cycles from months to days, making custom internal tools virtually free to build.

Skillification of Organizational Knowledge

  • Explanation: Translating human best practices into reusable agent skills (like two-sentence company descriptions) creates a shared organizational brain.
  • Evidence: Partners practicing and refining two-sentence company descriptions until agents internalize the standard.
  • Practical implication: Scales expert-level partner knowledge across the entire organization instantaneously.

Frameworks, Models & Processes

The Agentic Harness Framework

  • How it works: Combine a single-source database schema, a tool/skill registry, and a model router into an agentic loop that executes domain-specific tasks.
  • Components:
    • Agent Loop
    • Tool Registry / Resolver
    • Single Postgres Database Schema
    • Skillification layer
  • When to use: When building internal AI infrastructure for an organization to manage workflows, CRM, and financial analysis.

Examples & Case Studies

Building a half-million line Rails app for YC's directory replaced by building a dynamic agentic framework using OpenClaw and Claude Code in days.

  • Illustrates: The speed and efficiency of AI-native software development compared to legacy monolithic stacks.
  • Lesson: Do not rebuild complex traditional software; wrap AI around modular open-source agent primitives.

Actionable Takeaways

  • Immediate:
    • De-normalize and centralize your company's core data into an easily queryable database for AI agents.
    • Start building internal tool registries and agent harnesses for simple workflows like journaling and CRM notes.
    • Practice condensing your product or company description into a precise two-sentence pitch.
  • Strategic:
    • Shift software architecture from deterministic code wrapping AI features to AI agents wrapping deterministic tools.
    • Adopt default-public agent conversation channels to foster internal transparency, learning, and social alignment.
    • Embrace egalitarian, trust-by-default organizational structures to unlock the full potential of AI leverage.
  • Questions to investigate:
    • How do we balance internal agent transparency with privacy and security for sensitive data?
    • What is the optimal path for legacy enterprises with siloed data to transition to an AI-native architecture?

[A]Architecturehigh noveltymoderate evidence

The architecture of AI-native software is inverted relative to most current integrations: instead of embedding AI as a feature inside deterministic application code, you wrap deterministic tools inside an agent wrapper, letting the user drive prompts and execution directly.

Why it matters

It relocates the primary abstraction boundary — the agent loop becomes the top-level runtime and deterministic code becomes a callable tool, which changes where state, permissions, and UX live.

Generalization

Applies to any product where a fixed UI currently mediates model behavior: the interface should expose the agent surface, not hide it behind hardcoded flows.

[A]Architecturemedium noveltymoderate evidence

Deliberately de-normalizing organizational data into a single Postgres schema (companies, founders, financials, CRM notes) is used as the context layer so agents can execute arbitrary cross-domain queries without pre-built joins or per-team APIs.

Why it matters

Query surface, not modality, is the bottleneck for agent usefulness; a denormalized schema turns every new question into a read rather than an integration project.

Generalization

For agent-facing data layers, denormalization trades storage and write-path purity for read-path generality — the opposite trade-off from classical OLTP design.

[P]Practicehigh noveltymoderate evidence

'Skillification' treats human workflow knowledge as a portable artifact: compress expert judgment (e.g., a two-sentence company description) into an atomic prompt/skill that every partner and every agent consumes identically.

Why it matters

It makes organizational knowledge versionable and distributable at the prompt layer, so quality improvements propagate to all agents rather than being re-derived per session.

Generalization

Any org can convert recurring human review heuristics into shared, named skills with a canonical compressed form, turning prompt engineering into a knowledge-management function.

Generalization

[M]Mechanismmedium noveltymoderate evidence

The harness is assembled from separable parts — agent loop, tool registry/resolver, single-source database schema, and a skillification layer with a model router — so teams add capabilities without touching core code.

Why it matters

Registry-based tool resolution decouples capability addition from harness releases, which is what lets non-engineering teams contribute skills.

Generalization

Same registry pattern as MCP-style tool servers: the harness defines the loop and routing, the registry defines the capability surface.

Agent-scoped least privilege over a denormalized organizational context database

Research question

Can agent-scoped views or query-rewriting layers preserve arbitrary cross-domain query generality over a single denormalized schema while enforcing least-privilege access?

Why

If denormalization is used to remove integration friction, the same consolidation creates a large blast radius; without agent-level authorization and auditing, the context layer contradicts basic security expectations for financial and personnel data.

Versioning, evaluation, and rollback for shared agent skills

Research question

How should shared skills such as two-sentence company descriptions be versioned, regression-tested, and rolled back once multiple agents and people depend on them?

Why

Skillification turns prompts into organizational knowledge artifacts; without version pinning and eval suites, a single prompt change can silently degrade every downstream agent, making quality unmanageable as adoption grows.

AI features that hide prompt control behind deterministic UI inherit the limits of the old interface; true AI-native software must expose the agent loop and treat deterministic tools as callable capabilities rather than wrapping AI inside application code.

Angle

Architectural critique contrasting horseless-carriage AI integrations with an agent-first runtime where the user drives prompts and execution.

Denormalize for Agents, Not for OLTP: The Context Layer Trade-Off Nobody Wants to Make

Agent usefulness is bottlenecked by query surface, so a single denormalized schema can unlock arbitrary cross-domain reads; the same consolidation, however, demands compensating authorization, auditing, and blast-radius controls that classical OLTP design would have handled through separation.

Data architecture argument that agent-facing context layers invert conventional normalization trade-offs and must be paired with agent-scoped security.

Skills Are Specs: Turning Expert Judgment into Versioned Organizational Prompts

Practice-oriented argument that prompt artifacts deserve the same release discipline as code because they encode and distribute expert judgment.

Tradeoffs and failure modes

4

Default-public agent conversations

Benefit

Internal transparency, peer learning, social control, and fast onboarding for junior staff.

Cost or risk

Every prompt, query, and result becomes a broadcast record, so sensitive financial, legal, or personnel context reaches a wide audience; the summary does not describe any redaction or retention controls.

Source video ↗

Single denormalized context database

Benefit

Agents answer complex arbitrary cross-domain queries without per-team integrations; departmental silos and data fragmentation are eliminated.

Cost or risk

One readable schema means one large blast radius — any agent or employee querying it sees comprehensive company context, implying a need for agent-scoped permissions the summary does not mention.

Source video ↗

Hiding prompts behind traditional deterministic UI

Benefit

Familiar interfaces and lower immediate UX risk for shipping AI features.

Cost or risk

Users cannot shape or inspect the model's behavior, so the integration delivers little of the leverage that direct agent interaction provides — the 'horseless carriage' failure mode.

Source video ↗

Wrapping agent primitives instead of rebuilding monoliths

Benefit

Order-of-magnitude faster delivery; internal tools become cheap enough to build per-need.

Cost or risk

Correctness, maintainability, and reliability of the previously deterministic Rails app are not addressed by a days-long agentic replacement; the comparison favors speed only.
