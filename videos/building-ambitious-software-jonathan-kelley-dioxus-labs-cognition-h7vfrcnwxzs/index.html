Overview

  • Speaker: Jonathan Kelley
  • Channel: AI Engineer
  • Main topic: Building ambitious software using Rust and AI coding agents
  • Purpose: To share lessons learned from building Dioxus and utilizing AI coding agents for large-scale, complex software engineering projects. Jonathan Kelley, creator of Dioxus and team member at Cognition, discusses the journey of building Dioxus — a Rust UI toolkit — over five years and how the rise of advanced AI coding agents in recent months transformed their software engineering process. He explores how strict languages like Rust pair exceptionally well with AI agents, shifting the developer burden and allowing small teams to maintain high-velocity release cycles, excellent documentation, and robust codebases.

Key Points

Strict languages empower AI agents

  • Explanation: Because Rust has a strict type system and compiler, AI agents can't easily write broken code without the compiler catching it.
  • Evidence: Greg Brockman quote: 'rust is a perfect language for agents, given that if it compiles it's ~correct.'
  • Practical implication: Using strict systems programming languages reduces the failure rate of AI-generated code.

Agents excel at mundane, tedious tasks

  • Explanation: Agents shine when dealing with vast documentation, deep API reverse engineering, and tedious release checklists.
  • Evidence: Implemented Kotlin and Swift plugins in 2-3 weeks with AI assistance.
  • Practical implication: Offload tedious boilerplate and integration work to agents to focus human energy on architecture.

Code is cheap, quality is not

  • Explanation: Writing code has become trivial with AI, but maintaining high standards of architecture, documentation, and testing is harder than ever.
  • Evidence: Dioxus team shipped more patch releases than ever before by leveraging AI for maintenance.
  • Practical implication: Engineers must focus on system architecture and rigorous review rather than typing speed.

Core insights

6
[M]Mechanismmedium noveltymoderate evidence

Strict static type systems function as an automated verification surface for AI-generated code: because a compiled artifact must satisfy the type checker and borrow checker, the set of silently-broken outputs an agent can produce is sharply reduced, shifting verification from human reading to machine compilation.

Why it matters

If compilation is a cheap, high-coverage filter, then the choice of language and type system becomes a first-class reliability parameter for agentic coding pipelines, comparable to test coverage or CI gates. It implies agent harnesses should be designed around compiler-enforced invariants rather than only prompt discipline or post-hoc review.

Generalization

Any agent that produces artifacts consumed by a deterministic checker (type systems, schema validators, verifiers, formal lint rules) acquires a built-in correctness oracle that bounds its failure modes, making the checker's strictness a design lever for agent trust.

[O]Mental Modelmedium noveltymoderate evidence

The quality ceiling of AI-generated code is bounded by the architecture of the substrate it lands in: the same agent output is valuable or harmful depending on the pre-existing architectural boundaries and invariants of the repo.

Why it matters

This reframes the human engineer's role from writing lines of code to maintaining the architectural substrate that makes agent contributions composable. Investment in module boundaries, interfaces, and invariants becomes multiplicative on agent throughput rather than a cost center.

Generalization

For any system where generative components are inserted, the host architecture acts as an amplifier or attenuator of generated quality; architecture is therefore a governance mechanism, not just a design artifact.

[E]Empirical Resultmedium noveltymoderate evidence

Agents' comparative advantage is patience-bound work: exhaustive documentation search, binary reverse engineering, and multi-language (Kotlin/Swift) plugin integration, achieved in weeks rather than the months human teams would tolerate.

Why it matters

This is an operational targeting rule: route agents toward tasks whose cost is dominated by tolerance for tedium and breadth of search rather than by novel judgment. It gives a concrete assignment policy for hybrid human/agent teams.

Generalization

Task allocation between humans and agents should be driven by the shape of the cost function — agents win where marginal cost of repetition and exhaustive search approaches zero — rather than by task 'difficulty' in the abstract.

[P]Practicemedium noveltymoderate evidence

Line-by-line human review remains necessary even with AI pre-review, because the binding constraint is not code volume but the contributor's ability to communicate intent — agents (and humans) frequently transmit intent poorly, so review is an intent-recovery process, not a typo-detection process.

Why it matters

It defines where human review budget should be spent: reconstructing intent and validating architectural fit, a task AI pre-review does not eliminate. Teams that treat review as redundant once code passes compilation and pre-review will accumulate uncurated output ('slop cannon').

Generalization

As generation cost approaches zero, review becomes the scarcity; review should be scoped to intent and architectural conformance, because mechanical verification is already automated.

[M]Mechanismhigh noveltymoderate evidence

Sub-100ms hot-patching of native compiled code (Subsecond), spanning major OSes and WebAssembly, is an iteration-latency mechanism that collapses the edit-compile-run loop for compiled languages — the same languages favored for agent correctness.

Why it matters

Compiled-language strictness and fast repair cycles are usually in tension; Subsecond claims to remove that tension, which matters for agent loops where each iteration includes a compile-and-test cycle. Iteration latency directly bounds how many agent attempts are economically viable per task.

Generalization

In agentic development, the cost model is dominated by loop latency x attempts; reducing per-iteration latency or verification cost is functionally equivalent to increasing agent capability.

Source video ↗
[A]Architecturehigh noveltymoderate evidence

Blitz decouples browser-grade HTML/CSS rendering from the browser by extracting the CSS engine from Firefox and running it on WGPU with sub-5MB bundles, i.e., the rendering stack becomes an embeddable, composable component rather than a fixed runtime.

Why it matters

It is an example of a broader pattern: pulling a monolithic runtime's capabilities into a modular library so that an application framework owns its own rendering and distribution footprint. That changes deployment, startup, and platform-strategy trade-offs for cross-platform apps.

Generalization

Extracting a capability out of a heavyweight runtime into a GPU-accelerated modular library is a recurring architectural move that grants portability and bundle-size control at the cost of owning more low-level machinery.

Project ideas

Compile-Pass Divergence Harness

beyond-evals

For agent-written Rust, compile success predicts requirement satisfaction above 80% for isolated pure functions but falls below 50% for stateful, cross-module, or platform-integration tasks.

Proof of concept

Build a suite of 60 tasks in a strict language spanning pure functions, async/stateful services, and FFI/platform glue; have agents solve them and grade against executable behavioral specs independent of the compiler.

Measurement

Divergence rate = P(compiles AND fails requirements) / P(compiles), stratified by task class; correlation between compile success and behavioral pass rate.

Source video ↗

Substrate Ladder

gatehouse

Holding model and prompt constant, repositories with explicit module boundaries and invariant checks show lower agent-contribution defect rates than poorly modularized repos of similar size.

Proof of concept

Create 3 versions of a small service repo: monolith/no boundaries, modular interfaces, and modular plus invariant assertions; run identical agent tasks and grade defects.

Measurement

Defect escape rate per merged agent contribution, review-rework time, and architectural conformance failures across repo variants.

Source video ↗

Hot-Patch Loop A/B

movement-lab

A sub-100ms hot-patch loop increases agent task completion rate and reduces cost per completed task relative to a conventional compile-test loop.

Proof of concept

Instrument an agent coding loop with two execution backends: cold compile-test and hot-patch-capable; run matched task sets and record attempts, wall-clock, tokens, and success.

Measurement

Mean attempts per completed task, wall-clock per completion, tokens per completion, and success rate delta.

Intent-Gated Review Gate

gatehouse

Requiring a machine-readable intent and interface spec before generation reduces defect escape rate enough to allow sampled review instead of line-by-line review for bounded task classes.

Proof of concept

Add a pre-generation spec step to an agent workflow; compare against baseline line-by-line review and no pre-review on matched tasks.

Tradeoffs and failure modes

4

AI generation velocity vs. uncurated output

Benefit

Small teams ship tens of thousands of lines of Rust and more patch releases than ever.

Cost or risk

Uncurated agent output produces a 'slop cannon' effect, degrading quality unless reviewed line-by-line.

Source video ↗

Compile-passes-as-correct heuristic

Benefit

A compiling artifact is a strong positive signal for agent output quality and reduces silent bugs.

Cost or risk

Type-check success is a proxy ('~correct'), not semantic correctness; logic, intent, and requirement fidelity remain unverified by the compiler.

Source video ↗

Code generation vs. code quality/architecture

Benefit

Writing code has become trivial with AI, enabling high-velocity maintenance and releases.

Cost or risk

Maintaining architecture, documentation, and testing standards is harder than ever, so the scarce human skill is architectural judgment.

AI pre-review as a substitute for human review

Benefit

AI pre-review reduces the mechanical burden on maintainers.

Cost or risk
