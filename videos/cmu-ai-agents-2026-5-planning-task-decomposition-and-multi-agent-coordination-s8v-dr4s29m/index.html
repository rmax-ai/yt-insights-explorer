Summary

Overview

  • Speaker: Daniel Fried
  • Channel: Graham Neubig
  • Main topic: Planning, Task Decomposition, and Multi-Agent Coordination in LLM Agents
  • Purpose: To educate students on how AI agents plan, decompose tasks into sub-goals, and coordinate in multi-agent workflows. The lecture covers planning, task decomposition, and multi-agent coordination for language model agents. It discusses how agents form representations of future work, the role of chain-of-thought, subtask decomposition, and modularity in agentic systems, comparing them with classical AI planning (STRIPS/PDDL) and highlighting trade-offs between planning upfront versus reactive execution.

Key Points

Planning is a moving target

  • Explanation: Agents must balance commitment to a course of action with flexibility to adapt to new environmental information.
  • Evidence: Agent tasks in dynamic environments like web browsing require continuous plan revision.
  • Practical implication: Agent design must incorporate mechanisms for error detection and re-planning.

Chain-of-Thought acts as a primitive plan

  • Explanation: Prompting models to think step-by-step or decompose tasks provides a scratchpad and extra compute before final execution.
  • Evidence: Studies like Least-to-Most Prompting show performance gains from subtask decomposition.
  • Practical implication: Use structured prompting or decomposition to handle multi-step reasoning tasks.

Classical vs. Neural Planning Trade-offs

  • Explanation: Classical planning is explicit and verifiable but brittle; LLM planning is implicit, flexible, but prone to hallucination and execution drift.
  • Evidence: Comparison of STRIPS/PDDL state representations against LLM generated natural language text.
  • Practical implication: Hybrid approaches combining programmatic structures with neural flexibility are often optimal.

Separating Planner from Executor

  • Explanation: Decomposing tasks into planning modules and execution modules allows the use of specialized models and better optimization.
  • Evidence: SayCan and related vision-only web agents separate high-level planning from low-level grounding.
  • Practical implication: Use strong reasoning models for planning and specialized models or APIs for execution.

An agent tasked with buying a GPU workstation iterates through multiple vendor sites, checks compatibility on a wiki, and handles supply chain lead time failures.

  • Lesson: Agents cannot rely solely on upfront linear plans and must adapt to real-world feedback.

Applying Cursor Plan Mode to a software engineering task to generate a markdown checklist before implementation.

  • Illustrates: Human-in-the-loop plan review and editing before execution.
  • Lesson: Planning mode helps agents gather context and allows human verification, reducing expensive mistakes.

Evaluating multi-agent versus single-agent performance on OSWorld and WebTailBench.

  • Illustrates: Stronger manager models significantly improve coordination and boost the success rate of weaker worker models.
  • Lesson: Modularity and delegation can lift overall system performance without excessive cost increases.

Actionable Takeaways

  • Immediate:
    • Incorporate task decomposition and step-by-step reasoning in agent prompts.
    • Use plan modes or structured checklists to allow human oversight before agent execution.
  • Strategic:
    • Balance upfront planning with reactive re-planning based on environmental feedback.
    • Adopt modular multi-agent architectures (manager-worker) to handle complex, long-horizon tasks.
  • Questions to investigate:
    • When is planning worth the additional token compute cost?
    • How can we prevent multi-agent handoffs from dropping critical context?

Article ideas

4

Your Agent's Plan Is an Interface, Not a Paragraph

Plan representation should be treated as a first-class architectural decision: natural-language plans are general but unverifiable, so any agent that needs safety, permissioning, or replay must move to code/formal plan representations with explicit permission gates, accepting the loss of open-ended generality.

Angle

Take the checkability/flexibility trade-off seriously and show which production mechanisms (static inspection, permission modes, deterministic replay) are impossible under free-text plans.

Source video ↗

Invest in the Manager, Not the Org Chart

Coordination quality, not role specialization, is the bottleneck in multi-agent systems: multiplying fixed worker roles before strengthening the orchestrator produces rigid communication and dropped context, while a stronger manager measurably lifts weaker workers.

Angle

Argue against the reflex to add specialized agents, and reframe multi-agent design as an orchestrator-capability problem first.

Source video ↗

Re-Planning Is a Control Loop, Not a Prompt Trick

Long-horizon agent success depends on an explicit commit-vs-replan subsystem with defined triggers and error detection, not on better initial plans; teams that treat re-planning as a prompt technique leave the dominant failure source uninstrumented.

Angle

Move re-planning from prompt craft into the runtime control layer, with the same rigor as retries or circuit breakers.

Source video ↗

The Planner/Executor Split and Its New Failure Surface

Separating planners from executors enables specialized model training and independent optimization, but the interface between the reasoning layer and the acting layer becomes the new dominant failure surface, so the boundary should follow capability gradients rather than convenience.

Angle

Frame modularity as buying specialization at the cost of an interface contract that must itself be planned, checked, and monitored.

Project ideas

4

RePlanBench

beyond-evals

An explicit trigger policy for re-planning (value/affordance thresholds plus execution-anomaly detection) yields higher long-horizon task success than plan-once execution, and outperforms always-replanning on cost-normalized success.

Proof of concept

Build a harness that runs the same long-horizon tasks under three policies — plan-once, always-replan, and a triggered replan loop with configurable signals — instrumenting every re-plan event and its cause.

Measurement

Task success rate, re-plans per task, tokens/compute per success, and the distribution of trigger causes correlated with eventual success or failure.

Source video ↗

Plan IR Linter

gatehouse

A static verifier over code-based plan representations detects a measurable fraction of pre-execution errors that natural-language plans structurally hide, without reducing task success on open-ended tasks.

Proof of concept

Emit agent plans as structured code/programs with declared preconditions, effects, and permission gates; run a static checker and permission-mode gate before execution, comparing against a free-text plan baseline on identical tasks.

Measurement

Pre-execution error detection rate, verification coverage (fraction of plan actions covered by checkable structures), downstream task success delta, and false-block rate.

Source video ↗

Orchestrator Capability Ladder

movement-lab

Team task success is more sensitive to manager model capability than to worker role specialization; fixed-role configurations lose to dynamic assignment as context length and handoff frequency increase.

Proof of concept

Build a manager → DAG of parallel sub-agents pipeline with swappable manager capability tiers and swappable role-assignment policies (fixed vs dynamic), then ablate manager strength against worker strength and handoff frequency on long-horizon tasks.

Measurement

Success rate as a function of manager tier and worker tier, context-loss measurements across handoffs, and the crossover point between fixed and dynamic role assignment.

Source video ↗

Overthinking Budgeter

movement-lab

Optimal plan-token budget scales with task execution horizon, and beyond a horizon-relative threshold additional plan tokens reduce action quality while increasing cost.

Proof of concept

Sweep plan-token budgets across task suites of varying execution horizons, holding model and tools fixed, and plot success/cost curves to locate inflection and degradation points per horizon bucket.

Measurement

Success rate and compute cost per plan-token budget per horizon bucket; identification of overthinking thresholds where added planning depth becomes net-negative.

Architectural implications

3

Plan storage and execution move from free-text to code-based workflows with explicit permission modes and API calls.

Before

Agent plans expressed as natural-language text or ad-hoc prompting.

After

Plans expressed as code/programs with developer-defined procedures, conditional execution, and permission gates (e.g., Cursor Plan Mode, Claude Code, CodeX).

Consequence

Enables static inspection, permissioning, and deterministic replay, but sacrifices the generality of free-text plans.

Source video ↗

Multi-agent decomposition is formalized as an explicit Manager → DAG → parallel CUA sub-agents → follow-up/replan → deliverables pipeline.

Before

Single monolithic agent or loosely chained role prompts.

After

Orchestrated DAG of parallel computer-use sub-agents under a manager with a re-plan loop and summarization stage.

Consequence

Parallelization and specialization become explicit graph structures, making dependencies, handoffs, and context loss points observable and debuggable.

Source video ↗

Re-planning and error detection become required runtime components rather than prompt tricks.

Before

Plan once, then execute blindly; failures surface only at task end.

After

Continuous plan revision triggered by environmental feedback and value/affordance estimates.

Consequence

Adds a control-loop layer to agent runtimes that must decide when to commit vs. re-plan.

Tradeoffs and failure modes

4

Fixed multi-agent roles

Benefit

Enables specialization, parallelization, and reuse of role-specific agents.

Cost or risk

Rigid communication patterns and dropped context between handoffs degrade long-horizon performance.

Source video ↗

Classical symbolic planning

Benefit

Explicit predicates, preconditions, and effects make plans verifiable and checkable.

Cost or risk

Brittle outside fully known environment dynamics; cannot flexibly absorb novelty.

Source video ↗

Extended planning / chain-of-thought depth

Benefit

Extra compute and a scratchpad improve multi-step reasoning and subtask decomposition.

Cost or risk

Overthinking relative to the task's execution horizon wastes compute or degrades action quality.

Source video ↗

Natural-language plan representation

Benefit

General and expressive across open-ended tasks.

Cost or risk

Not checkable before execution, so errors propagate into actions.
