Overview

  • Main topic: Optimizing RMSNorm in transformer models using algebra, weight folding, and custom CUDA streams
  • Purpose: Explain how algebraic rewrites of RMSNorm eliminate GPU inefficiencies, share lessons from implementing parallel CUDA streams, and introduce Superlinked Inference Engine (SIE) for deploying optimized transformer models. Filip Makraduli discusses a paper co-authored with Nils Graff on rewriting RMSNorm to make transformers cheaper and faster. The talk covers two lines of algebra (weight folding, deferred normalization, and cancellation of pre-normalization), how these eliminate unnecessary memory trips and waiting times on GPUs, a specific CUDA stream bug that caused a model to output repeated tokens backwards due to race conditions, and practical implementations via Superlinked Inference Engine (SIE).

The Three Algebraic Rewrites: Weight Folding, Deferred Normalization, Cancellation

Key Points

RMSNorm Bottleneck

  • Explanation: RMSNorm takes up nearly a quarter of inference wall-clock time despite performing minimal arithmetic operations.
  • Evidence: In Llama-3-8B, RMSNorm runs 33 times per decode step.
  • Practical implication: Optimizing RMSNorm yields significant latency and cost reductions in production inference.

Algebraic Rewriting over Retraining

  • Explanation: FlashNorm uses algebra to rewrite layers into linear forms, folding gains and deferring divisions without retraining the model.
  • Evidence: Yields ~12.77% speedup for weight folding and +33 to 35% for deferred normalization on Llama models.
  • Practical implication: Engineers can apply simple configuration or weight modifications to existing pre-trained models.

CUDA Stream Concurrency Pitfalls

  • Explanation: Running tensor core matrix multiplications and vector unit normalizations on separate CUDA streams requires explicit synchronization barriers.
  • Evidence: Implicit joins led to reading stale buffer values, causing token repetition and backward speech.
  • Practical implication: Low-level CUDA programming requires rigorous event recording and waiting (cudaStreamWaitEvent) to prevent race conditions.

[P]Practicehigh noveltymoderate evidence

Deferred normalization splits the scalar 1/RMS divide so the matrix multiplication and the normalization can run on separate CUDA streams (tensor cores vs. CUDA cores), but this requires explicit synchronization — cudaStreamWaitEvent — because implicit joins do not guarantee ordering.

Why it matters

Concurrency across different execution units (tensor cores vs. vector/CUDA cores) can overlap work, but correctness depends on explicit event-based barriers that are easy to omit.

Generalization

When parallelizing work across heterogeneous execution units on independent queues, every cross-queue data dependency must be expressed as an explicit barrier/event; do not rely on implicit ordering.

Your Tests Are Blind to Concurrency Bugs: The Case of the Model That Spoke Backwards

Unit tests and perplexity are structurally incapable of catching cross-stream ordering defects, so any team shipping concurrent GPU kernels is unknowingly shipping race conditions unless they add long-horizon generation regressions.

Angle

Post-mortem framing: walk through a defect that produced repeated and one-step-lagged tokens while all standard green signals stayed green, then derive the minimum test suite that would have caught it.

Source video ↗

Optimize by Invocation Count, Not FLOPs

The dominant cost of normalization in transformer inference comes from launch overhead, memory roundtrips, and matmul stalls multiplied by how often the op runs per decode step, not from its arithmetic, so the correct optimization unit is invocations × overhead rather than FLOPs.

Angle

Reframe a profiling metric: teach readers to rank operators by invocation count times per-invocation overhead, using normalization running many times per decode step as the worked example.

Source video ↗

Exact Rewrites Beat Approximation: Retraining-Free Model Acceleration

Algebraic rewrites that are exact and retraining-free are strictly preferable to approximation or fine-tuning-based speedups because they carry no quality risk and can be applied to already-deployed checkpoints, at the cost of architecture-dependent applicability.

Angle

Argue the cost/benefit ordering of acceleration strategies: offline weight transformation and deferred computation first, approximation and retraining only when exact rewrites are provably inapplicable.

Source video ↗

Every Cross-Queue Dependency Needs an Explicit Barrier

Overlapping work across heterogeneous execution units is only safe when every cross-queue data dependency is expressed as an explicit event; implicit joins do not guarantee ordering and will produce stale reads.

Angle

Engineering-principle piece grounded in the split divide across tensor cores and CUDA cores, with a checklist for making cross-stream dependencies explicit.

Project ideas

4

Race Sentinel

beyond-evals

A long-horizon generation regression suite combined with varied batch/sequence-size replay will deterministically surface cross-stream ordering defects that unit tests and perplexity checks pass, and will fail loudly when an explicit stream barrier is removed.

Proof of concept

Take a normalization path with a deliberately removed cudaStreamWaitEvent barrier, run the suite, confirm it flags token repetition and one-step lag; re-add the barrier and confirm the suite goes green while unit tests and perplexity remain unchanged in both states.

Measurement

Detection rate of injected barrier-removal defects versus unit tests/perplexity, plus false-positive rate on correct builds across batch and sequence configurations.

Source video ↗

Rewrite Invariant Linter

gatehouse

A static checker over model topology can decide, per model family, which algebraic normalization rewrites are valid, and blocking a rewrite whose invariants fail prevents both silent no-op optimizations and incorrect normalization removal.

Proof of concept

Encode adjacency and scale-invariance conditions as lint rules, run them against a topology with consecutive RMSNorms and one without, and verify the linter enables the cancellation rewrite only in the first case and refuses it in the second.

Measurement

Agreement between lint verdicts and observed correctness/speedup outcomes across a set of model topologies, plus count of unsafe rewrites blocked.

Source video ↗

Regime Sweeper for Normalization Rewrites

movement-lab

The speedup from weight folding and deferred normalization is regime-dependent, and there exists a measurable crossover in batch size and sequence length below/above which stream overlap costs more than it saves.

Proof of concept

Benchmark folded, deferred, and baseline normalization paths across a grid of batch sizes, sequence lengths, and GPU tiers, recording wall-clock time per decode step and kernel counts.

Measurement

Per-configuration speedup deltas and identification of the crossover points where each rewrite becomes neutral or negative, with variance across repeated runs.

Source video ↗

Explicit-Event Scheduler

new

A scheduling layer that requires declaring every cross-stream dependency as an explicit event can overlap repeated non-matmul operators on independent streams without regressing output correctness, and the mandatory declaration prevents accidental implicit-ordering assumptions.

Proof of concept

Prototype the layer for the split scalar divide across tensor-core and CUDA-core streams, then apply it to a second repeated operator; run adversarial timing and variable-batch stress to confirm no stale reads occur.

Measurement

Correctness under adversarial timing tests, number of undeclared-dependency errors caught at schedule-build time, and achieved overlap versus serial execution.

Architectural implications

3

Normalization gain multiplication can be folded into the next layer's weight matrix ahead of runtime.

Before

Gain applied every forward pass inside the normalization kernel.

After

Gain pre-multiplied into the downstream weight offline, producing a modified weight matrix.

Consequence

Fewer kernels and memory roundtrips per decode step; requires an offline transformation step and updated model weights.

Source video ↗

Normalization can be decomposed so its scalar divide runs on a separate stream from the matmul.

Before

Matmul and normalization execute serially with an implicit join.

After

Two concurrent streams with explicit event-based synchronization (cudaStreamWaitEvent).

Consequence

Overlap improves throughput but introduces a new correctness responsibility: every cross-stream dependency must be expressed as an explicit barrier.

Inference runtime configuration is moving from per-model flag tuning to pre-tuned, pre-packed model configurations.

Before

Engineers hunt for flags and tune each model individually.

After

Pre-tuned configurations and model packing shipped with the engine.

Consequence

Reduces operational configuration burden and errors when deploying many model variants.

Tradeoffs and failure modes

3

Parallel streams for deferred normalization

Benefit

Overlaps matmul on tensor cores with normalization on CUDA cores, yielding reported +33 to 35% speedup.

Cost or risk

Without explicit cudaStreamWaitEvent barriers, post-scale reads stale buffer data, causing race conditions, token repetition, and one-step-lagged/backwards output.

Source video ↗

Exact algebraic rewrite vs. approximation/retraining

Benefit

Zero approximation and zero retraining means existing pre-trained models can be sped up without quality loss or retraining cost.

Cost or risk

Applicability is architecture-dependent — cancellation of pre-normalization only holds for topologies with consecutive RMSNorms (e.g., Gemma 2, DeepSeek-V2) due to scale-invariance.

Validation of concurrent kernel changes

Benefit

Unit tests and perplexity checks are fast and cheap to run.

Cost or risk

They can pass while a stream-ordering bug persists, so defects only appear in long-generation behavior, making regressions hard to detect and diagnose.
