Key Points

Video has always been passive

  • Explanation: Traditional generative video models like Sora and Veo operate like slot machines: you prompt them, wait for a file, and watch a fixed recording.
  • Evidence: Generated video files finish rendering before you arrive and cannot be changed frame-by-frame.
  • Practical implication: Creators lack real-time control and instant feedback loops.

Real-time changes the medium

  • Explanation: Just as GPS turned paper maps into live navigation that enabled Uber, real-time video generation turns static media into programmable software.
  • Evidence: GPS made location live and trackable, giving birth to on-demand services.
  • Practical implication: Content becomes addressable, conditionable, and alterable via APIs.

Serving a world requires streaming infrastructure

  • Explanation: Real-time interactive video cannot rely on standard batch inference request-response queues.
  • Evidence: Sessions must be stateful, pinned to specific GPUs, and stream frames continuously with tight latency budgets under 100ms globally.
  • Practical implication: Developers need specialized infrastructure platforms like Reactor rather than managing raw GPUs.

[A]Architecturehigh noveltymoderate evidence

Serving a real-time interactive video model is architecturally 'serving a world', not 'serving a model': each live world is a stateful session pinned to a single GPU with persistent state and memory, rather than a stateless request-response invoked through a batch scheduler.

Why it matters

This inverts the standard inference abstraction. Affinity between session and hardware becomes a first-class scheduling constraint, which means autoscaling, load balancing, and failover must all be session-aware rather than job-aware. Any engineer building long-lived generative or agentic runtimes hits the same wall.

Generalization

Any workload with persistent generative state (world models, long-lived agent sessions, simulations, voice/avatar streams) requires session-GPU pinning and state migration semantics that stateless inference stacks do not provide.

[~]Tradeoffmedium noveltymoderate evidence

Latency budget is a hard architectural constraint, not a tuning knob: sub-100ms interactive response requires routing each user to the nearest regional GPU, which forces a geo-distributed deployment topology instead of a centralized model endpoint.

Why it matters

It makes placement a design decision made per user, and it fragments capacity and state across regions. Cost, utilization, and consistency all degrade in exchange for interactivity—a trade-off that generalizes to voice agents, real-time copilots, and any human-in-the-loop loop.

Generalization

When an interaction loop has a human in it, the latency SLO determines the deployment topology, and topology determines cost and state-management complexity.

Generalization

Any unbounded generative or agentic session needs an explicit state-retention policy; the failure mode of no policy is incoherence after the first context eviction.

Stateful session durability: checkpoint, migration and failover for GPU-pinned generative sessions

Research question

What is the minimum viable checkpoint/restore mechanism for a GPU-pinned generative session, and what recovery latency does it impose relative to an acceptable interaction interruption threshold?

Why

If a pinned GPU failure destroys unrecoverable in-memory state, then the session-affinity architecture is only viable once state migration semantics exist. Without them, every failure is a hard session termination, which makes capacity drain, rolling deploys and regional rebalancing impossible to operate safely.

Component-level attribution of the sub-100ms interactivity budget

Research question

How much of end-to-end time-to-first-frame and steady-state frame latency is attributable to model compute, frame transport, and regional routing respectively?

Why

The claim that regional GPU placement delivers sub-100ms interactivity is unverified and uncosted. Without attribution, engineering effort is misallocated: teams may over-provision regional GPUs when the dominant term is transport, or accept inflated cost when the dominant term is inference.

Context retention policy and coherence horizon in unbounded generative sessions

Research question

At what session horizon does a generative world lose self-consistency under adversarial revisits, and which retention/compaction policy extends that horizon at lowest memory cost?

Why

Continuity over an unbounded stream is a context-management problem in pixel space, structurally identical to agent memory compaction. The failure mode is silent: the world simply contradicts itself after the first eviction, with no error surfaced.

Project ideas

4

Session Snap

new

A periodic state snapshot plus restore path for GPU-pinned generative sessions can bound recovery of a failed session to under two seconds, making session-eviction and rolling-drain policies operationally viable instead of equivalent to session termination.

Proof of concept

Build a harness around a stateful streaming session runtime that snapshots session state at a configurable cadence to host memory or remote store, forcibly kills the pinned worker, and restores onto a new worker with the same session identity and prompt history; compare snapshot overhead against uninterrupted-session baseline.

Measurement

Snapshot write cost as a percentage of steady-state frame budget; p50/p99 time-to-resume after kill; number of observable coherence breaks in the restored stream versus the pre-kill stream.

Source video ↗

Latency Ledger

new

In a real-time interactive video pipeline, transport and regional routing account for a larger share of end-to-end time-to-first-frame than model compute, meaning sub-100ms targets are network-bound rather than inference-bound.

Proof of concept

Instrument an end-to-end streaming pipeline with timestamped spans at client capture, regional router ingress, session scheduler dispatch, model compute, frame encode, and client render; replay traffic from simulated client locations at varying distances from a single GPU region.

Measurement

Component-level share of p50/p99 time-to-first-frame and steady-state inter-frame latency across simulated client distances; regression of each component against distance to confirm or refute network dominance.

Source video ↗

Turnaround Test

beyond-evals

Generative session coherence collapses abruptly rather than degrading gradually, and the collapse point is predictable from the ratio of retained context length to session elapsed length, allowing a horizon-bound retention policy to be chosen before deployment.

Proof of concept

Construct an adversarial revisit suite: after N seconds of session, instruct the camera or agent to turn around, return to a previously visited location, or reference a character introduced early in the stream; sweep retention and compaction policies and record consistency verdicts per horizon bucket.

Measurement

Coherence-break rate per horizon bucket per retention policy; the horizon value at which break rate crosses a fixed threshold; memory cost per policy at that horizon.

Source video ↗

In-Stream Gate

gatehouse

Mid-stream content insertions can be gated and audited reliably enough for brand safety only if control events are evaluated against a policy check before affecting the stream, rather than inspecting rendered output after the fact.

Proof of concept

Interpose a policy-checking control-event broker between the client input channel and the generative session; route every mid-stream alteration request (including ad and logo insertion) through allow/deny/rewrite rules and log the decision with the stream segment it bound to.

Measurement

Percentage of disallowed insertions blocked pre-render; false-block rate on benign control events; added latency per control event versus the interactivity budget; completeness of the audit trail when reconstructing a stream post hoc.

Architectural implications

3

Session-to-hardware affinity replaces job-level batching as the core scheduling primitive.

Before

Stateless request/response endpoints behind a load balancer, with a batch GPU scheduler maximizing utilization.

After

Stateful sessions pinned to specific GPUs, with routing, scale-down, and failure recovery that respect session affinity and persistent memory.

Consequence

Autoscaling becomes coarse and slow (you cannot freely migrate a live world), so capacity planning and drain/eviction policies must be designed for long-lived sessions.

Source video ↗

Latency SLO dictates geographic placement.

Before

A centralized model endpoint; latency absorbed by queueing and client tolerance.

After

Regional GPU presence with user-to-nearest-region routing to hit sub-100ms.

Consequence

Per-region capacity fragmentation, higher idle cost, and cross-region state-consistency questions for session continuity.

Source video ↗

The integration surface moves from model weights to a streaming SDK.

Before

Developers host GPUs and manage the serving stack to run generative models.

After

A few lines of JavaScript/TypeScript SDK to init a model, set an initial image and prompt, and start a stream.

Consequence

The binding constraint shifts from infra competence to product design and session-level observability; the provider becomes a hard dependency in the critical path.

Tradeoffs and failure modes

4

Session pinning vs. utilization

Benefit

Persistent state and memory let a world stay coherent and interactive for an unbounded session.

Cost or risk

A pinned GPU is dedicated to one session; utilization drops, a GPU failure kills a live session with unrecoverable in-memory state, and the model cannot be trivially load-balanced.

Source video ↗

Global low latency vs. cost and complexity

Benefit

Sub-100ms interactivity anywhere in the world.

Cost or risk

Requires regional GPU footprints and routing logic, multiplying deployment surface and idle capacity; violating the budget degrades the experience to a batch one.

Source video ↗

Programmable live content vs. verifiability

Benefit

Content can be altered mid-stream based on user intent, e.g. inserting brand logos and ads in real time.

Cost or risk

Removes the pre-production review checkpoint; there is no finished artifact to inspect before it reaches the viewer, so safety and brand control must move into runtime guardrails.

Source video ↗

Infinite synthetic data vs. environment validity

Benefit

Simulation labs can generate unlimited training scenarios on demand.

Cost or risk

Generated environments are only as trustworthy as their dynamics; silent distribution errors can contaminate training without any artifact to audit post hoc.
