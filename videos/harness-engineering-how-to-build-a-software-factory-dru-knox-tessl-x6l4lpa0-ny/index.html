Summary

Overview

  • Speaker: Dru Knox
  • Channel: AI Engineer
  • Main topic: Harness engineering and the architecture of agentic software factories
  • Purpose: To introduce harness engineering as an essential discipline for developers transitioning to agentic software factories and explain its core loops, stack components, and practical implementation. Dru Knox, Head of Product & Design at Tessl, presents harness engineering as the new core discipline for agentic software developers. He explains how software factories shift human effort from building individual features to building and improving the loops, control planes, and agent IT layers that automate software development end-to-end. The talk covers the three loops of harness engineering (inner loop, outer loop, and meta loop), the key metrics of autonomy, automation, and quality, and how Tessl's platform facilitates building agentic software factories.

Harness Engineering and the Three Loops

  • Explanation: Explaining harness engineering as the direct creation, monitoring, and improvement of a project's loops, broken into inner, outer, and meta loops.
  • Key claims:
    • Harness engineering is the new core discipline of agentic development.
    • There are three core loops: inner loop (drives automation), outer loop (drives autonomy), and meta loop (drives quality).
  • Examples:
    • Inner loop: agent edits, runs, and checks code before a PR.
    • Outer loop: agent runs tests, linting, and architecture reviews after a PR is opened.
    • Meta loop: observability over output that feeds improvements back into inner and outer loops.
  • Terminology:
    • Harness engineering
    • Loop engineering
    • Inner loop
    • Outer loop
    • Meta loop
  • Why it matters: Provides a structural framework for how developers should engineer agent systems rather than hand-building individual features.

Key Points

The three key metrics of software factories

  • Explanation: Automation measures how much human correction agents need; Autonomy measures oversight needed; Quality measures end-product excellence.
  • Evidence: Presented as the core pillars to measure when building towards a software factory.
  • Practical implication: Teams must improve autonomy first, then automation, while keeping quality constant and ultimately raising it.

Why harness engineering is hard

  • Explanation: Involves knowledge gaps due to fast-moving best practices, unplanned work when agents fail, competition with shipping features, and poor legibility of local agent logs.
  • Evidence: Derived from the psychological and operational challenges faced by teams adopting agentic workflows.
  • Practical implication: Teams need upfront strategies to surface local agent workflows and knowledge onto public, accessible surfaces.

Tessl's platform and agentic SDLC

  • Explanation: Tessl offers an agentic platform to help set up control planes, skills registries, maintenance agents, and automated improvement loops.
  • Evidence: Demonstrated via Tessl Agent and terminal workflows running tessl commands.
  • Practical implication: Allows engineering teams to adopt agentic workflows incrementally rather than building an entire factory from scratch.

Frameworks, Models & Processes

The Three Loops of Harness Engineering

  • How it works: Two loops run on code while a third improves the loops themselves.
  • Components:
    • Inner loop (drives automation)
    • Outer loop (drives autonomy)
    • Meta loop (drives quality)
  • When to use: When designing the architecture of an agentic software development pipeline.

The Agentic Stack (Three Layers)

  • How it works: Three hierarchical layers required to make a software factory run successfully.
  • Components:
    • Layer 01: Control plane (issue tracker, PR review, skills/plugin registry)
    • Layer 02: Agent IT (company brain, internal services, production logs, execution environments)
    • Layer 03: Improvement loops (repo maintenance, development playbooks, task automation, output quality optimization)
  • When to use: When organizing infrastructure and tooling for agentic development.

Core insights

[A]Architecturehigh noveltymoderate evidence

Harness engineering is defined as a recursive architecture: two loops operate on code (inner loop drives automation before a PR; outer loop drives autonomy after a PR opens) while a third meta loop observes output and feeds improvements back into the other two loops. The harness itself is the artifact under continuous improvement, not just the code it produces.

Why it matters

It reframes the engineering target from hand-built features to self-modifying pipeline loops, which changes what you instrument, version, and own; the loops become first-class products with their own quality metric.

Generalization

Any agentic pipeline can be decomposed into code-transforming loops plus a separate loop that improves those loops, giving a concrete place to attach observability and feedback.

[~]Tradeoffhigh noveltymoderate evidence

The three factory metrics map to distinct loop layers (automation=inner, autonomy=outer, quality=meta), and the speaker prescribes a sequencing constraint: raise autonomy first, then automation, while holding quality constant and only later raising it.

Why it matters

It argues against naive parallel optimization of all three metrics and implies an ordering discipline — you cannot safely expand automation before the oversight/autonomy layer is trustworthy.

Generalization

For staged rollout of autonomous systems, expand the scope of machine action (automation) only after the oversight and containment layer (autonomy) is established, keeping a fixed quality floor.

[A]Architecturemedium noveltymoderate evidence

The agentic stack is layered so that control-plane concerns (issue tracker, PR review, skills/plugin registry) are separated from runtime/infrastructure concerns (company brain, internal services, production logs, execution environments), with improvement loops as a third layer above both.

Why it matters

It gives explicit placement for responsibilities — coordination and policy at the control plane, execution and context at the agent IT layer — which affects where you put integrations, secrets, and observability rather than lumping them into one agent.

Generalization

Separating a coordination/control plane from an execution/context layer is a reusable boundary for multi-agent systems, letting each layer scale and be replaced independently.

[!]Failure Modemedium noveltymoderate evidence

Adoption of harness engineering is blocked by legibility: local agent logs are poorly observable and knowledge stays on individual machines, so the recommended remedy is moving agent workflows from local machines to shared, legible execution environments and surfacing knowledge onto public accessible surfaces.

Why it matters

Without shared legible execution surfaces the meta loop has no reliable input, so the improvement loop silently fails; this makes observability infrastructure a precondition rather than an add-on.

Generalization

Self-improving agent systems require their execution telemetry to be centralized and shared, because per-developer local logs cannot feed collective improvement.

Separating autonomy and automation metrics

Research question

Can intervention-rate (manual takeovers, human PR comments) and self-initiation-rate (auto-initiated PRs) be measured independently enough to enforce autonomy-before-automation sequencing without confounding with quality?

Why

Without separable metrics, teams cannot validate the prescribed rollout order, and automation may expand before the oversight layer is trustworthy, creating unplanned work.

Source video ↗

Meta loop convergence and dampening

Research question

What stabilization, filtering, and rollback mechanisms prevent the meta loop from oscillating or overfitting to noisy quality signals?

Why

If the meta loop chases noise, loop changes may not persist and the improvement layer becomes a source of variance rather than compounding gains.

Source video ↗

Shared legible execution as precondition for meta loop

Research question

Does moving agent execution from local machines to shared, legible environments causally improve meta-loop improvement rates, and what minimal telemetry makes local knowledge observable?

Why

If local logs remain illegible, the meta loop has no reliable input, so the improvement layer silently fails regardless of how well inner and outer loops are built.

Minimum viable control plane

Research question

Which control-plane components (issue tracker, PR review, skills registry) are necessary for a small team to obtain meta-loop benefits without adopting the full agent IT layer?

Why

A minimal path lowers adoption cost and tests whether the control plane or the execution layer is the true bottleneck for loop improvement.

Playbook codification criteria for skills registries

Research question

Why

Autonomy-Automation Split Dashboard

beyond-evals

A dashboard built on manual takeover counts, human PR comments, and auto-initiated PRs can distinguish autonomy from automation and predict quality regressions before they occur.

Proof of concept

Instrument an agentic repository with event counters for manual takeovers, human PR comments, auto-initiated PRs, and quality signals; run a staged rollout raising autonomy first and then automation; display time-series metrics.

Measurement

Correlation between intervention-rate drop and auto-initiation increase; quality regressions (test failures, rework) before/after the prescribed sequencing.

Meta Loop Damper

movement-lab

Adding dampening, signal filtering, and a change budget to the meta loop reduces oscillation and overfitting compared with an unconstrained feedback loop.

Proof of concept

Build a small agentic pipeline or simulation with inner, outer, and meta loops; compare an unconstrained meta loop against a damped version that filters noisy quality signals and limits loop changes per cycle.

Measurement

Persistence of loop changes across iterations, oscillation count, quality variance, and net improvement over baseline.

Minimal Control Plane

gatehouse

A reduced control plane with only issue tracker and PR review integrations yields measurable legibility and improvement-loop benefits for a small team without adopting the full agent IT layer.

Proof of concept

Measurement

Time-to-legible agent logs, number of meta-loop-driven improvements, human correction rate, and manual takeovers.

Architectural implications

2

Agent coordination responsibilities (issue tracking, PR review, skills registry) are pulled out of the human IDE workflow into an explicit control plane.

Before

Developers drive issue tracking and PR review interactively inside their editor and local git workflow.

After

A control plane layer owns issue tracker and GitHub integrations, PR review, and a skills/plugin registry.

Consequence

Coordination logic becomes centralized and automatable, but the control plane becomes a critical integration surface whose availability and permissions gate all agentic work.

Source video ↗

Agent execution moves from individual local machines to shared execution environments.

Before

Agent runs and logs live on each developer's local machine, largely illegible to others.

After

Execution environments are managed as part of the agent IT layer and shared across the team.

Consequence

Enables the meta loop to observe real output and improves legibility, at the cost of building and operating shared execution infrastructure.

Tradeoffs and failure modes

3

Adopting harness engineering vs shipping features

Benefit

Building and improving loops compounds automation and reduces long-term toil.

Cost or risk

Competition with shipping features means investing in the factory competes directly for engineering time against product delivery.

Agent failure handling

Benefit

Agents can operate autonomously across loops.

Cost or risk

Local vs shared agent workflows

Benefit

Cost or risk
