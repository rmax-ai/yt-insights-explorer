Overview

  • Speaker: Harrison Chase
  • Channel: 20VC with Harry Stebbings
  • Main topic: AI agents, LangChain, vertical vs horizontal agent architecture, model routing, memory, and LLM market dynamics
  • Purpose: Provide deep technical and strategic insights into AI agent development, enterprise architectures, market positioning of LLM providers, and open-source vs proprietary model dynamics. Harrison Chase, co-founder and CEO of LangChain, discusses the complexities of building AI agents, why agent development is difficult due to non-deterministic black box models, and the structural layers of agents including context, harnesses, and models. He analyzes the debate between horizontal and vertical agents, the role of model routing, memory architectures, the evolution of post-training, and market dynamics among open-source and proprietary models.

Topic Map

Why Building Agents Is Hard

  • Explanation: Discusses the inherent challenges of building AI agents using non-deterministic LLM black boxes that take natural language input and produce natural language output.
  • Key claims:
    • Models are non-deterministic black boxes with infinite input and output dimensions.
    • Agents rely on series of model calls interacting with tools, creating cascading errors.
    • Getting systems to behave reliably is the hardest part of agent engineering.
  • Examples:
    • A user can type anything into a chatbot, making it hard to predict what they will type next.
  • Terminology:
    • non-deterministic
    • black boxes
    • cascading errors
    • tool calling
  • Why it matters: Explains why agent frameworks like LangChain are necessary to bridge the gap between raw LLMs and reliable software applications.

Agent Architecture: Context, Harness, and Model Layers

  • Explanation: Breaks down the architectural layers of an agent system into context, harness, and underlying models.
  • Key claims:
    • The harness takes the model and connects it to tools, data, and computation.
    • Context management includes prompt caching, prompt engineering, and memory.
    • Switching models is critical for offensive and defensive agility against pricing and performance changes.
  • Examples:
    • Moving from JSON-parsing tool calling to native API tool calling.
  • Terminology:
    • harness
    • context layer
    • model layer
    • post-training
    • routing
  • Why it matters: Helps developers and enterprises understand where value is created and how to architect flexible AI systems.

Horizontal vs Vertical Agents

  • Explanation: Analyzes the market dynamics between general horizontal agents (like generic chatbots) and domain-specific vertical agents (like legal or financial agents).
  • Key claims:
    • Vertical agents leveraging deep domain expertise in harnesses and workflows win in specific verticals.
    • Horizontal agents work for simple tasks like general chat or basic coding, but domain tasks require domain-specific harnesses.
    • Domain experts who understand verification and evals will capture the value in vertical applications.
  • Examples:
    • Spotify vs. Strava for music versus fitness interactions.
    • Legal, finance, and coding as vertical domains.
  • Terminology:
    • vertical agents
    • horizontal agents
    • domain expertise
    • verification
    • evals
  • Why it matters: Guides founders and investors on where defensibility lies in the AI application layer.

Model Routing and Infrastructure

  • Explanation: Discusses whether model routing is a commodity or increasing in value, and where routing logic should live.
  • Key claims:
    • Routing belongs at the harness layer when it requires task awareness and context awareness.
    • Simple routing can live at the gateway layer, but sophisticated routing requires harness awareness.
    • Routing value may diminish as frontier models improve across all tasks, but cost and latency drive routing demand.
  • Examples:
    • Using cheaper models for simple tasks like general chat and frontier models for complex reasoning.
  • Terminology:
    • model routing
    • gateway layer
    • harness layer
    • latency

  • Why it matters: Informs infrastructure decisions for scaling enterprise AI applications efficiently.

Memory in AI Agents

  • Explanation: Examines the current state of memory in agents, why it is unsolved, and how it differs across domains.
  • Key claims:
    • Memory is still massively unsolved and domain-specific.
    • The hardest part of memory is distilling observations from user interactions into actionable context.
    • Most companies store memory in simple flat files, while advanced systems require intelligent processing.

Key Points

Agents require both model and harness engineering

  • Explanation: While foundation models get smarter, connecting them to tools, data, and memory through robust harnesses is critical for reliable agent behavior.
  • Evidence: LangChain's focus on developer tools and LangSmith observability.
  • Practical implication: Do not rely solely on raw model intelligence; invest in context engineering and harness design.

Vertical agents capture significant domain value

  • Explanation: Horizontal generalists face fierce competition, whereas vertical agents embedded in specific workflows with domain-specific verification capture high enterprise value.
  • Evidence: Success stories in legal, finance, and specialized coding tools.
  • Practical implication: Founders should focus on deep domain workflows rather than generic horizontal wrappers.

Memory is the next major agent bottleneck

  • Explanation: Managing short-term and long-term memory across interactions remains a hard engineering problem requiring intelligent distillation, not just database storage.
  • Evidence: Companies struggling to move beyond flat-file memory storage.
  • Practical implication: Build sophisticated context and memory layers tailored to your specific user domain.

Frameworks, Models & Processes

Three-Layer Agent Architecture

  • How it works: Separates the agent stack into Context, Harness, and Model layers to ensure modularity and prevent vendor lock-in.
  • Components:
    • Context Layer (prompts, memory, data)
    • Harness Layer (tools, planning, routing, orchestration)
    • Model Layer (LLMs, inference providers)
  • When to use: When designing enterprise AI agent systems that need to swap underlying models without breaking application logic.

Three-Step Cost Control Framework for Coding Agents

  • How it works: A methodology used to manage and reduce token costs in heavy agent loops.
  • Components:
    • Visibility (tracking token usage and spend via LangSmith)
    • Basic Controls (setting budgets and alerts)
    • Harness Improvement (optimizing prompt caching and tool calling efficiency)
  • When to use: When scaling high-volume agent applications that risk high inference costs.

Examples & Case Studies

A team built a frontend coding agent plugin that took DOM snapshots and screenshots every single turn and sent them to an LLM.

  • Lesson: Design efficient agent loops and implement strict cost controls and observability early.

  • Illustrates: How short-term hacks get absorbed by frontier model APIs over time.
  • Lesson: Recognize the difference between short-term prompt hacks and long-term architectural frameworks.

Why it matters

Determines where routing logic belongs in the stack; building sophisticated routing into a generic gateway means it lacks the context needed to route well, while putting everything in the harness loses centralized cost control.

Deep dives

5

Routing policy placement: gateway vs harness, and the cost-governance gap it creates

Research question

If task- and context-aware routing must live in the harness, what telemetry and policy interface must the harness expose so that centralized cost governance is not lost when routing leaves the gateway?

Why

This is the concrete engineering consequence of moving routing upward: gateways commoditize and stop being the place where spend is controlled, so someone has to define the contract between harness-level routing decisions and org-level budget enforcement. Without that contract, teams either keep routing in a blind gateway or lose cost control entirely.

Source video ↗

Turn-level context volume as the true cost driver in agent loops

Research question

For a fixed agent task, how much of total spend is attributable to per-turn observation payload (screenshots, DOM snapshots, tool output) versus model tier selection, and which reduction lever yields the larger cost saving at equal task success?

Why

It reframes cost optimization from 'pick a cheaper model' to 'shrink what gets resent each iteration,' which changes what engineers instrument and what routers should condition on. It also makes model routing a second-order lever relative to observation compression, a claim that is directly testable.

Source video ↗

Memory distillation pipelines and the write path as the real memory problem

Research question

Does an explicit consolidation stage (summarize-then-store, entity extraction into structured context) improve downstream task accuracy per unit of context tokens versus flat-file append-only memory, and does the optimal abstraction differ by domain?

Why

It converts an abstract 'memory is unsolved' claim into a measurable design question about the write path, and it predicts that no single generic memory API will win because distillation granularity is domain-coupled. That has immediate consequences for anyone choosing between buying a memory product and building a pipeline.

Source video ↗

Isolating the vertical-agent advantage: harness and verification vs raw model capability

Research question

Holding the underlying model constant, how much of the accuracy delta on domain tasks comes from domain-specific verification and eval logic embedded in the harness, as opposed to workflow scaffolding or prompt/context design?

Why

The 'vertical agents win' claim is assertion-level in the source. Decomposing the advantage matters because it tells a team where to spend: building verification infrastructure that encodes expert judgment, or building better workflow scaffolding. Only the former is claimed to be defensible.

Source video ↗

Containment mechanisms against cascading error amplification in multi-call tool loops

Research question

Which containment mechanism — per-step output schema validation, intermediate evals, or constrained tool interfaces — most reduces error amplification rate per additional model call in a multi-step agent loop?

Why

If reliability failure is structural rather than a model-quality problem, then the mitigation must be architectural, and the relative effectiveness of each mechanism determines what belongs in the harness by default. Error amplification rate per added call is a directly measurable quantity that makes the claim falsifiable.

Article ideas

4

Your Token Bill Is Going Up While Token Prices Go Down

Declining per-token prices are a misleading cost signal for agentic systems, because iterative loops multiply context volume per step times step count; teams that budget on unit price will be surprised, while teams that instrument per-turn observation payload will control spend.

Angle

Take the falling-price narrative head-on and replace it with a cost model built on loop depth and per-turn payload, using the runaway observation-payload example as the anchor, then derive the instrumentation an engineering team should put in place before scaling agent loops.

Source video ↗

Routing Is Not a Gateway Feature

The router-as-commodity thesis is wrong for anything beyond stateless cost/latency routing: sophisticated routing needs task and context awareness, which only the harness owns, so routing is migrating upward into the harness and the gateway is being reduced to a dumb pipe — which means the interesting router problem is now a policy problem inside the agent, not a proxy problem.

Angle

Argue from architectural ownership rather than from model capability: whoever owns context gets to route. Then address the counter-argument that improving frontier models erode routing value, and show why cost and latency pressure keeps the harness router alive even if the quality gap narrows.

Source video ↗

Memory Is a Write-Path Problem, Not a Database Problem

Most agent memory implementations fail not because they chose the wrong store but because they have no consolidation stage; distillation of interaction observations into actionable context is the hard, domain-specific engineering work, and it is why no single generic memory product will win outright.

Angle

Reframe memory from storage/retrieval API to a summarization-and-abstraction pipeline, contrast flat-file storage with processed structures, and lay out the design decisions a consolidation stage must make: what to retain, at what granularity, and when to run.

Source video ↗

The Vertical Agent Moat Is Verification, Not the Model

Vertical agents beat horizontal ones in domain tasks not because they use a better model but because they encode domain verification and evals into the harness; consequently the winners in vertical AI will be organizations that can operationalize expert judgment as checkable assertions, not those with the best model access.

Angle

Argue that horizontal generality is a commodity input while verification is the scarce asset, then specify what 'encoding verification into the harness' actually looks like as an engineering artifact, and why that skill sits with domain experts rather than generic AI teams.

Project ideas

4

Turn-Level Spend Decomposer

gatehouse

For long-running agent tasks, per-turn observation payload reduction (compressing screenshots/DOM snapshots and pruning tool output) yields a larger total cost reduction at equal task success than downgrading the model tier for the same tasks.

Proof of concept

Instrument an agent loop to record token counts per turn split by system prompt, conversation history, tool output, and observation payload. Run a fixed task suite under three configurations: baseline, model-tier downgrade, and observation compression. Compare total spend and task success rate.

Measurement

Total tokens and dollars per completed task, success rate on a fixed eval suite, and per-turn token breakdown; report the cost delta per configuration at matched success rate.

Source video ↗

Harness Router vs Gateway Router Bake-Off

gatehouse

A router that conditions on task semantics and accumulated conversation/tool context achieves a strictly better cost-quality frontier than a gateway router that can only see request-level features such as prompt length and declared model tier.

Proof of concept

Build two routers over the same task suite: a gateway-style router using only request-level signals, and a harness-style router with access to tool history and task state. Sweep routing policies and plot cost vs quality curves rather than point accuracy.

Measurement

Cost-quality Pareto frontier for each router (dollars per task vs eval score), plus latency distribution; success criterion is dominance of the harness router's frontier.

Source video ↗

Distillation Ladder for Agent Memory

new

A consolidation stage that summarizes and abstracts interaction observations before storage improves downstream task accuracy per context token versus flat-file append-only memory, and the optimal abstraction level differs between two contrasting domains.

Proof of concept

Implement four memory write policies over the same interaction logs: flat append-only, rolling summary, entity/fact extraction into a structured store, and a two-stage summarize-then-extract pipeline. Evaluate on two domains with different correctness criteria.

Measurement

Task accuracy and tokens of context consumed at inference per memory policy, per domain; look for an interaction effect showing domain-dependent optima.

Source video ↗

Error Amplification Meter

beyond-evals

Error amplification per additional model call in a tool loop is materially reduced by per-step output schema validation and intermediate evals, and the reduction is larger than what is obtained by upgrading to a stronger model alone.

Proof of concept

Construct synthetic multi-step tool-calling tasks with known intermediate ground truth. Run four harness variants: unconstrained, schema-validated outputs, intermediate eval gates, and both. Measure how error rate grows with call depth in each.

Measurement

Error amplification factor per added model call, task completion rate at depths 1/3/5/10, and cost per completed task, comparing containment mechanisms against a model-upgrade baseline.

Architectural implications

Routing logic placement in the agent stack

Before

Routing treated as a generic gateway/proxy concern keyed on cost and latency.

After

Task- and context-aware routing moves into the harness that owns conversation state and tool history.

Consequence

Gateways commoditize; harnesses become the durable place for cost/quality policy, and cross-cutting cost governance must be reintroduced via telemetry from the harness.

Agent system decomposed into context, harness, and model layers

Before

Agent design centers on the model, with tool wiring as an afterthought.

After

Model treated as a swappable dependency; harness (tools, data, computation) and context (caching, prompting, memory) become the primary engineering artifacts.

Consequence

Investment shifts from prompt tweaks toward harness engineering, observability, and context lifecycle management.
