Summary

Overview

  • Speaker: Subbiah Sethuraman and Abhilash Asokan
  • Channel: AI Engineer
  • Main topic: Lessons from building multi-agent AI pipelines for pharma commercial teams and why they transitioned to a single agent with a knowledge graph.
  • Purpose: To share practical engineering lessons, architectural failures, and successful design patterns when building agentic workflows for commercial analytics in pharma. Subbiah Sethuraman and Abhilash Asokan from ZS Associates share their journey of building multi-agent AI pipelines for pharma commercial teams. They detail why their initial multi-agent system failed—specifically due to language models deciding signals, context loss at handoffs, and lack of shared business domain understanding. They explain how they replaced the multi-agent pipeline with a bare agent, a database, and a knowledge graph acting as a deterministic control surface running an iterative loop (traverse, query, reason, conclude).

Key Points

Statistics finds the signal, the agent explains it.

  • Explanation: Signal detection should be handled by deterministic statistical methods with guardrails and thresholds before any LLM agent is invoked.
  • Evidence: Running automated pipelines that scan KPI anomalies and queue signals for agents.
  • Practical implication: Eliminates LLM non-determinism in basic metric monitoring and anomaly detection.

The knowledge graph is the agent's control surface.

  • Explanation: Instead of free-form reasoning over raw database tables, agents navigate a structured knowledge graph that defines valid entity relationships and business rules.
  • Evidence: Graph contract defines valid entity transitions (entity -> has category -> driver category).
  • Practical implication: Reduces hallucinated relationships and bounds the agent's investigation space.

Architecture should be derived, not designed.

  • Explanation: Instead of pre-designing complex multi-agent orchestrations, start with a bare agent, bash, and a database, then derive the structure based on observed behavior and bottlenecks.
  • Evidence: Building up from bare cloud code and observing where context was lost.
  • Practical implication: Leads to simpler, more reliable systems tailored to actual runtime challenges.

Compressed Summary

  • Multi-agent pipelines failed due to LLM signal detection, context loss at handoffs, and lack of domain understanding.
  • Replaced multi-agent systems with a single agent powered by a knowledge graph and deterministic statistical guardrails.
  • The knowledge graph acts as a control surface ensuring agents only evaluate valid business hypotheses.
  • The agent runs a strict loop: traverse the graph, query real numbers, reason over evidence, and conclude.
  • Keywords: multi-agent, knowledge graph, control surface, pharma analytics, determinism
  • Core insight: Complex agentic systems fail when LLMs handle deterministic statistics and multi-agent handoffs lose context; separating deterministic checks from agent reasoning over a knowledge graph control plane solves this.

Core insights

[A]Architecturemedium noveltystrong evidence

Signal detection must be relegated to deterministic statistics with guardrails and thresholds; the LLM is invoked only to explain an already-detected anomaly. The LLM is treated as a reasoning engine, never as a statistics engine, drawing a hard architectural boundary between anomaly detection and explanation.

Why it matters

Places the non-determinism of the LLM downstream of the correctness-critical decision, so a false or noisy signal can never originate from model sampling. It defines where the deterministic/agentic seam belongs in a monitoring pipeline.

Generalization

Any agentic system that must react to numeric or time-series conditions should compute the triggering condition deterministically and let the agent operate only on confirmed events, not on raw metric streams.

Turns the graph from passive context into an active governor of the agent's search space, bounding investigation and filtering out relationships the business domain declares invalid. This is a concrete mechanism for constraining agent behavior rather than prompting for it.

Generalization

Structured domain schemas can act as runtime navigation controllers for agents — a general pattern for grounding and bounding agent reasoning in any enterprise domain with well-defined entity relations.

Knowledge graph as runtime control plane versus retrieval layer

Research question

Does constraining an agent's traversal to a declared graph contract measurably prevent invalid relationship inferences, or only reduce their frequency, and how does that change as graph coverage becomes incomplete?

Why

The control-plane framing is the highest-novelty claim in the talk and the whole architecture's correctness argument rests on it. If the effect is only partial, the 'graph contract' becomes a soft prior rather than a guarantee, which changes how much the agent loop still needs prompt-level and eval-level guardrails.

End-to-end coherence loss at agent handoffs

Research question

Can information loss per handoff be measured, and does it predict end-to-end incoherence where each agent's local output is correct but the composed recommendation is wrong?

Why

The Brand A case is a concrete failure signature that per-agent evaluation cannot catch. If handoff loss is measurable and predictive, pipeline-level coherence becomes a first-class eval target rather than a hope, and decomposition decisions get a quantitative test.

Deterministic/agentic seam for anomaly-triggered reasoning

Research question

On the same KPIs, can deterministic anomaly detection with fixed guardrails match or exceed LLM-based signal detection while eliminating sampling-induced false alarms?

Why

This is the falsifiable core of the 'reasoning engine, not a statistics engine' boundary. If thresholds under-detect relative to an LLM, the seam shifts the failure from false positives to false negatives, and the boundary must be justified with detection curves rather than principle.

Token and latency economics of the traverse-query-reason-conclude loop

Research question

How do iterations per resolved root cause, re-queried evidence calls, and token spend scale with graph depth, and which traversal-pruning strategies preserve diagnosis accuracy?

Why

The loop's grounding guarantee comes from re-querying at every step, which is also its cost center. Without iteration budgets and pruning results, the pattern is hard to justify for high-volume monitoring versus a one-shot explanation.

Article ideas

4

Your Multi-Agent Pipeline Didn't Fail at Reasoning — It Failed at the Handoff

Decomposed LLM pipelines fail not because each agent reasons poorly but because serialized handoffs destroy the shared context that makes local correctness composable, so per-agent evals give false confidence and only pipeline-level coherence testing catches the real defect.

Angle

Use the Brand A 18% prescription drop case — correct root cause in one agent, action agent recommending rep visits for what was an insurance tier change — as the canonical signature of the failure and argue for end-to-end eval over agent-level scorecards.

Source video ↗

Your Knowledge Graph Is a Control Plane, Not a Vector Store

Treating a knowledge graph as a retrieval layer wastes its real value: it is the runtime governor that bounds an agent's hypothesis space through a declared contract of valid entity transitions, and that is an engineering control, not a prompting technique.

Angle

Contrast lookup-layer graph usage with contract-driven traversal (entity -> has category -> driver category), show how the graph proposes next moves while the database supplies the numbers, and be explicit about the open question of whether this reduces or actually prevents invalid inferences.

Source video ↗

Stop Designing Agent Architectures, Start Measuring Where Context Dies

Agent topology should be earned from observed runtime failure rather than drawn up front; start from a bare agent, a shell, and a database, instrument the loop, and add structure only where context loss and bottlenecks actually appear.

Angle

Argue derive-don't-design as an engineering discipline with an explicit cost — delayed architectural commitment and required instrumentation — rather than as a slogan, and pair it with the counterexample of a pre-designed driver-attribution agent that produced incoherent output.

Source video ↗

A Language Model Is a Reasoning Engine, Not a Statistics Engine

Putting an LLM upstream of anomaly detection means sampling noise can originate the correctness-critical decision; signal detection belongs to deterministic statistics with thresholds, and the model should be invoked only to explain an event that has already been confirmed.

Angle

Frame it as seam placement: the deterministic/agentic boundary should sit downstream of the trigger, and evaluate the trade by asking whether fixed thresholds under-detect compared with LLM signal judgment.

Project ideas

4

Control-Plane Graph Contract Harness

beyond-evals

Bounding agent traversal to a declared graph contract measurably lowers the rate of invalid relationship inferences compared with free-form reasoning over the same data, but the reduction is partial rather than complete and degrades as graph coverage drops.

Proof of concept

Build two agent variants over the same dataset — one traversing a contract-limited knowledge graph, one reasoning free-form — and adversarially probe both with entity pairs the contract forbids, measuring residual invalid inferences at 100%, 70%, and 40% graph coverage.

Measurement

Rate of invalid relationship inferences per variant at each graph-coverage level, plus traversal paths audited against the contract.

Handoff Loss Probe for Multi-Agent Chains

beyond-evals

Information lost at each agent handoff is measurable and correlates with end-to-end incoherence, so chains with higher per-handoff loss produce correct local steps that compose into wrong final recommendations.

Proof of concept

Instrument a serialized agent chain with a fixed context payload per handoff, quantify retained versus dropped fields at each step, and score final recommendations against a ground-truth action derived from the true root cause; replicate the prescription-drop-to-rep-visit mismatch as a target case.

Measurement

Per-handoff context retention rate versus pipeline-level correctness, and count of cases where a correct diagnosis is paired with an action that ignores the cause.

Deterministic Trigger versus LLM Signal Detection Bake-Off

movement-lab

Deterministic anomaly detection with fixed guardrails and thresholds matches or exceeds LLM-based signal detection on KPI streams while eliminating sampling-induced false alarms.

Proof of concept

Run both detectors over the same historical KPI series with known labeled anomalies, then route only confirmed events to an explanation agent and compare downstream explanation quality and auditability.

Measurement

Precision, recall, and false-alarm variance across repeated runs for LLM detection versus single-run determinism for threshold detection.

Source video ↗

Traverse-Query-Reason Loop Budgeter

new

Loop iterations per resolved root cause can be cut substantially by traversal pruning without reducing diagnosis accuracy, because most traversals do not change the concluded cause.

Proof of concept

Instrument a graph-and-database agent loop to log every traversal step and whether it altered the final conclusion, then apply pruning rules that skip low-yield branches and compare accuracy and token spend against the unpruned loop.

Measurement

Iterations and tokens per correctly resolved root cause, accuracy delta versus unpruned baseline, and latency per resolution.

Architectural implications

3

Responsibility for deciding whether a metric change is a real signal is moved out of the LLM entirely.

Before

A language model decides which KPI movements are genuine signals versus noise.

After

Deterministic statistical pipelines with guardrails and thresholds scan for anomalies and queue signals for an agent that only explains them.

Consequence

Signal detection becomes reproducible and auditable; the LLM's stochasticity is confined to explanation and cannot trigger false alarms.

Source video ↗

The knowledge graph's role is elevated from retrieval substrate to runtime control plane.

Before

The graph is treated as a lookup layer supplying context to the agent.

After

The graph acts as a control plane that the agent navigates and uses to make its next decisions, constrained by a graph contract of valid transitions.

Consequence

The agent's hypothesis space is bounded by domain-valid relationships, reducing hallucinated relationships and making traversal paths auditable.

Source video ↗

Multi-agent decomposition is replaced by a single bare agent plus database plus knowledge graph.

Before

Reasoning is split across multiple communicating agents (e.g. a dedicated driver-attribution agent) that hand off context.

After

One agent runs an iterative traverse-query-reason-conclude loop against a graph and database, with no serialized handoffs.

Consequence

Eliminates the handoff context-loss failure mode at the cost of concentrating reasoning responsibility in one loop that must be bounded by the control surface.

Tradeoffs and failure modes

4

Multi-agent task decomposition

Benefit

Splits complex analytical reasoning into specialized agents with narrower responsibilities.

Cost or risk

Context is lost at every agent handoff, and no single agent sees the whole picture, so locally correct steps can compose into an incoherent end-to-end recommendation.

Knowledge graph as bounded control surface

Benefit

Reduces hallucinated relationships and bounds the agent's investigation space with domain-valid transitions.

Cost or risk

Requires constructing and maintaining the graph/contract across enterprise data sources; scaling that construction is an explicitly open problem.

Benefit
