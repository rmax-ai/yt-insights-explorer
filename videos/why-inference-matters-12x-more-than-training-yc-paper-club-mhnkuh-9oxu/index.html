Key Points

Inference is Memory-Bound During Decode

  • Explanation: Every decode step re-reads model weights and the growing KV cache from HBM, making memory bandwidth the primary performance limiter.
  • Evidence: Arithmetic intensity for LLMs is very poor compared to training or diffusion models.
  • Practical implication: Focus engineering efforts on KV cache optimization and quantization rather than raw compute.

KV Cache Retention and Prefill Reuse

  • Explanation: Caching and reusing prompt states (Prefill) drastically reduces time-to-first-token and overall compute costs.
  • Evidence: DeepSeek achieving 96% input cache hit rate through 72-hour KV cache retention.
  • Practical implication: Implement prefix caching, radix attention, and smart routing to maximize cache locality.

Quantization Must Prioritize Quality

  • Explanation: Moving from FP16 to FP8, INT8, or INT4 shrinks weights and KV cache memory footprint, but requires rigorous evaluation loops to prevent accuracy degradation.
  • Evidence: Minimax M3 NVFP4 quantization successfully matched original model benchmarks while serving first-party traffic.
  • Practical implication: Adopt quality-first quantization pipelines with extensive benchmarking and agentic evaluation loops.

Core insights

7
[M]Mechanismmedium noveltystrong evidence

The serving stack has two phases with opposite bottleneck profiles: prefill is compute-bound, decode is memory-bandwidth-bound because each step re-reads weights plus the growing KV cache from HBM. This means optimization effort allocated by FLOPs is misallocated for decode-dominated workloads (chat, agents).

Why it matters

It tells you which resource to buy and which code to write: for decode, reduce bytes moved (quantized weights, smaller KV cache, fused kernels) rather than raising FLOPS utilization. An engineer optimizing FLOPS/GPU utilization on a decode-bound agent will spend money on the wrong axis.

Generalization

Stepwise autoregressive generation has intrinsically low arithmetic intensity; any system whose cost is dominated by repeated state re-reads (not arithmetic) should be optimized for bytes-per-token, not ops-per-token.

[A]Architecturemedium noveltymoderate evidence

Prefill/decode disaggregation places the two phases on separate, specialized GPU pools instead of one homogeneous pool, because their hardware ceilings differ. This inserts an explicit scheduling and state-transfer boundary between prefill and decode in the serving architecture.

Why it matters

It moves prefill from being an internal step of a single worker to a distinct tier, which changes where you provision capacity, where latency spikes originate, and where KV cache must be moved or shared across the network.

Generalization

When two stages of a pipeline are bounded by different resources (compute vs memory bandwidth), separating them onto specialized pools beats co-locating them on general-purpose workers, at the price of an explicit handoff.

[E]Empirical Resulthigh noveltystrong evidence

Prefix/KV-cache reuse is a first-order cost lever, not a micro-optimization: DeepSeek reports a 96% input cache hit rate sustained by 72-hour KV cache retention, implying cache locality should constrain routing decisions.

Why it matters

If cache hit rate drives prefill cost and TTFT, then the router is a cache-locality component. Load balancing purely by GPU utilization can destroy hit rate and silently multiply prefill spend; routing must be prefix/session-affinity aware.

Generalization

In stateful inference systems, request placement is a caching decision: schedulers that ignore reusable prefix state trade cheap cache hits for expensive recomputation.

[~]Tradeoffmedium noveltymoderate evidence

Quantization is framed as a quality-gated compression pipeline rather than a one-time conversion: shrinking weights and KV cache from FP16 to FP8/INT8/INT4 relieves the memory-bandwidth ceiling, but only survives if backed by continuous evaluation loops. Minimax M3 at NVFP4 reportedly matched original benchmarks while serving first-party traffic.

Why it matters

It reframes quantization work as an evaluation-engineering problem: the deployment artifact is not the quantized checkpoint but the quantized checkpoint plus a regression harness that gates promotion.

Generalization

Any lossy compression applied to a model (precision, distillation, cache truncation) requires an evaluation loop attached to the serving pipeline, not a one-off benchmark.

[O]Mental Modelmedium noveltymoderate evidence

The economic model is inverted: over a weight file's lifetime, inference FLOPS are claimed to be roughly 12x more consequential than training FLOPS, derived from DeepSeek-V3's 2.79M H800-hours of training versus 43.5K H800-hours per day of serving.

Why it matters

It changes capital allocation: for a deployed product, serving-side engineering (batching, cache reuse, precision) dominates lifetime compute cost, and COGS margin (claimed up to ~80% with heavy optimization) is a serving-architecture outcome, not a training outcome.

Generalization

For any model whose lifetime token volume is large relative to its training run, the marginal engineering dollar belongs in the serving path; the ratio scales with usage, so high-traffic products feel it first.

[O]Mental Modelmedium noveltymoderate evidence

Inference optimizations decompose into three layers with distinct ownership: model innovations (MoE, SSM, MLA, quantization), kernel/runtime innovations (RadixAttention, FlashAttention, PagedAttention), and harness innovations (routing, speculative decoding, RLM). Each layer changes the same metrics through different mechanisms.

Why it matters

It gives a stack-audit taxonomy so a team can see which lever it actually controls (harness/runtime for most application teams; model architecture only if training or fine-tuning), preventing wasted effort attempting model-level fixes at the application layer.

Generalization

Performance work should be attributed to the layer that owns it; most application teams own harness and runtime choices, not architecture choices.

[P]Practicelow noveltyweak evidence

A request traverses six distinct stages — request & routing, tokenization, queue & batch, prefill, decode, stream out — each with its own optimization target, so instrumentation must be per-stage rather than per-request.

Why it matters

Aggregate end-to-end latency hides which stage dominates; queue/batch and prefill cost behave differently from decode TPOT. Per-stage metrics (TTFT, TPOT/ITL, goodput) are what make bottleneck diagnosis possible.

Generalization

Decompose serving latency by lifecycle stage and instrument boundary metrics; a single p99 number cannot distinguish queuing from memory-bandwidth limits.

Deep dives

5

Prefix-affinity routing vs. utilization load balancing

Research question

When a router must satisfy both prefix/KV-cache locality and queue-depth balance, what placement policy maximizes cache hit rate per unit of prefill cost without violating p99 TTFT?

Why

If cache hit rate drives prefill spend and TTFT, then routing is a caching decision. Utilization-only balancing silently destroys hit rate and multiplies prefill cost, so teams need a scored placement policy and a way to measure the tradeoff.

Source video ↗

KV cache retention policy under long multi-turn agent sessions

Research question

What tiered retention/eviction policy (hot HBM, warm host or remote store, TTL) maximizes input cache hit rate per byte of KV memory held, for sessions whose state grows monotonically with turn count?

Why

Long retention is presented as the reason hit rates reach 96%, but retained KV state evicts concurrent sessions. Without an eviction/offload policy, the win becomes memory pressure and OOM-driven cache churn under agentic workloads.

Source video ↗

Per-layer attribution of inference speedups (model vs kernel/runtime vs harness)

Research question

For a fixed model and traffic trace, what share of TTFT, TPOT, goodput, and cost-per-token improvement is attributable to each lever (attention kernel, paged KV, prefix cache, speculative decoding, precision), and can the ranking be predicted from workload features?

Why

The three-bucket taxonomy is offered as an audit framework but with no comparative attribution. Application teams need to know whether the harness/runtime layers they actually control can deliver most of the available gain, or whether they are capped.

Workload-parameterized lifetime compute ratio (inference vs training)

Research question

Does the ~12x inference-to-training FLOPs ratio survive when recomputed with cache hit rate, output length, and session reuse as explicit parameters, and for which workloads does it invert?

Why

The multiplier drives capital allocation toward serving engineering. If it is workload-dependent, then teams need to compute their own ratio rather than inherit a single vendor's number, otherwise they over- or under-invest in the serving path.

Quality-gated quantization as a release-path artifact

Research question

Can a continuous agentic evaluation loop attached to the serving pipeline detect accuracy regressions from FP8/INT8/INT4 quantization that static benchmarks miss, at low enough cost to gate every precision promotion?

Why

Quantization is only a win if it does not ship a cheaper but dumber model. Making the eval harness part of the serving artifact's release path converts quantization from a one-time conversion into a promotion gate.

Article ideas

4

Your Load Balancer Is Burning Your Prefill Budget

For repeated-prefix traffic, request placement is a caching decision: utilization-based load balancing trades cheap cache hits for expensive recomputation, and the reported ~96% hit rates are only reachable with prefix-affinity routing plus an explicit retention TTL.

Angle

Trace one repeated-prefix workload through a round-robin router versus a prefix-affinity router and show where the prefill spend and TTFT go, then argue that the scheduler must be evaluated on hit rate, not utilization.

Source video ↗

Stop Optimizing FLOPs on a Decode-Bound Workload

Decode has intrinsically low arithmetic intensity, so engineering effort measured in FLOPs utilization is spent on the wrong axis; the binding resource is bytes moved per token, which is why fused kernels, quantization, and cache reuse beat compute-utilization work for chat and agent traffic.

Angle

Contrast the prefill and decode bottleneck profiles, then map each of the six levers to the resource it actually moves, arguing for bytes-per-token as the primary optimization target.

Source video ↗

Quantization Is an Evaluation Problem, Not a Conversion Step

The deployable artifact is not the quantized checkpoint but the checkpoint plus a regression harness: precision changes behave like model changes because accuracy loss is silent in well-formed output, so promotion of FP8/INT8/INT4 should be gated by continuous evaluation rather than a static pre-launch benchmark.

Angle

Argue from the failure mode (plausible-looking degradation) to a release-path design where precision changes ride the same gate as model changes.

Source video ↗

Prefill and Decode Are Two Different Products

Co-locating compute-bound prefill and bandwidth-bound decode in one homogeneous pool forces capacity to be sized for a blended average; disaggregating them into specialized tiers is the right move, but only if you accept an explicit KV handoff boundary and account for the new latency and failure surface it creates.

Angle

Reframe serving topology as two independently provisioned tiers with a state-transfer contract, and enumerate what the scheduler gains and what it now owes.

Source video ↗

Project ideas

4

Affinity Router Bench

gatehouse

A router scoring replicas jointly on prefix affinity and queue depth will achieve a higher input cache hit rate and lower cost-per-token at equal or better p99 TTFT than utilization-only balancing, on traces with repeated prefixes.

Proof of concept

Replay a repeated-prefix and long-session traffic trace against two routers over the same serving stack: (a) utilization/round-robin baseline, (b) a combined prefix-affinity + queue-depth scorer with a configurable retention TTL. Instrument prefill tokens recomputed, hit rate, TTFT, and TPOT per request.

Measurement

Input cache hit rate (tokens and requests), prefill tokens recomputed per request, cost-per-token, and p99 TTFT/TPOT deltas between the two routers at matched throughput.

Source video ↗

KV Retention Budget Model

movement-lab

A tiered retention policy (hot HBM with short TTL plus a warm offload tier) sustains hit rates comparable to a long single-tier TTL while reducing HBM held per active session and eliminating OOM-driven eviction, for multi-turn agent sessions.

Proof of concept

Simulate or instrument a serving loop with growing per-session KV state over many turns; compare a single long-TTL HBM policy against a hot/warm tiered policy with an eviction rule. Track cache bytes per active session, hit rate, TTFT, and eviction/OOM events as turn count rises.

Measurement

KV bytes held per active session vs. turn count, input cache hit rate, TTFT, and frequency of forced evictions under increasing concurrent session load.

Source video ↗

Lever Attribution Ablation

movement-lab

For a decode-dominated chat/agent trace, harness and runtime levers (prefix cache, paged KV, speculative decoding, quantization) together capture the majority of achievable latency and cost gains, and their ranking is predictable from a small set of workload features (prefix reuse ratio, output length, batch size) rather than from model architecture.

Proof of concept

On one fixed open model and one fixed traffic trace, apply each lever independently and then in combination: attention kernel fusion, paged KV, prefix/radix cache, speculative decoding, and lower precision. Attribute measured deltas per lever to TTFT, TPOT, goodput, and cost-per-token; then fit a simple predictor of lever ranking from workload features.

Measurement

Per-lever delta in TTFT, TPOT/ITL, goodput, and cost-per-token; share of total achievable gain attributable to each layer; prediction accuracy of the feature-based ranking against the measured ablation.

Source video ↗

Quantization Promotion Gate

beyond-evals

A continuous agentic evaluation loop wired into the serving pipeline will flag accuracy regressions from aggressive precision reduction (e.g., INT4/NVFP4) that static benchmark suites miss, while still permitting precision promotion when no regression is detected.

Proof of concept

Take one model, produce FP16/FP8/INT4 artifacts, and serve them behind a promotion gate. Run a static benchmark suite plus a multi-turn agentic task suite against each artifact; record where the static suite reports parity but the agentic suite diverges. Gate promotion on the combined result.

Measurement

Regression detection rate per precision level (agentic vs static eval), divergence between static benchmark scores and agentic task success at each precision, and eval cost per promotion decision.

Architectural implications

4

Prefill and decode have opposite hardware ceilings, yet are typically co-located in one worker pool.

Before

A single homogeneous GPU pool runs prompt ingestion and token generation on the same workers, sized for a blended average load.

After

Separate prefill and decode pools, each sized to its own bottleneck (compute-heavy vs bandwidth-heavy), with an explicit handoff of KV state between tiers.

Consequence

The scheduler gains a new responsibility: placing prefill work to maximize cache reuse and managing KV transfer latency between pools; capacity planning splits into two independent models.

Source video ↗

Cache hit rate is the dominant cost variable for repeated-prefix traffic (96% reported).

Before

The router balances load by GPU utilization or round-robin across replicas and providers.

After

The router becomes stateful: it routes by prefix/session affinity to preserve KV cache locality, with retention policy (e.g., a long TTL) as an explicit configuration knob.

Consequence

Load balancing and cache locality become competing objectives; routing policy must be evaluated on cache hit rate and prefill cost, not just utilization balance.

Source video ↗

Quantized models can lose quality silently while still returning well-formed output.

Before

Quantization is a one-time conversion validated against a static benchmark before launch.

After

Quantization becomes a pipeline with attached, continuous evaluation (including agentic eval loops) that gates promotion of new precision artifacts.

Consequence

The eval harness becomes part of the serving artifact's release path; precision changes are treated like model changes, not config changes.

Source video ↗

Goodput, MFU, and MBU are defined alongside throughput and latency.

Before

Serving dashboards report raw throughput and average latency, rewarding batching that inflates token rate.

After

Dashboards report useful-output rate (goodput) plus model and memory bandwidth utilization, tying each metric to the resource that actually binds (compute vs memory).

Consequence

Optimization targets become falsifiable per layer: a kernel fusion should move MBU/throughput; a cache change should move TTFT and prefill cost.

Source video ↗

Tradeoffs and failure modes

4

Quantization depth vs accuracy retention

Benefit

FP8/INT8/INT4 precision shrinks weights and KV cache, directly relieving the memory-bandwidth ceiling that binds decode.

Cost or risk

Silent accuracy degradation requires rigorous evaluation loops; without them you ship a cheaper but dumber model and attribute the regression to the base model.

Source video ↗

Long KV cache retention vs memory capacity

Benefit

Long retention (reported 72 hours) sustains very high input cache hit rates and slashes prefill recomputation and TTFT.

Cost or risk

Retained KV state consumes HBM and evicts other concurrent sessions; the optimization is a retention-policy tuning problem, and the failure mode is memory pressure under long multi-turn sessions.

Source video ↗

Prefill/decode disaggregation vs handoff complexity

Benefit

Specialized pools let each phase be provisioned against its real bottleneck instead of a blended average.

Cost or risk

Introduces a cross-pool KV transfer step and a scheduling boundary, adding a new latency and failure surface between prefill and decode.

Source video ↗

Throughput-oriented batching vs per-token latency

Benefit

Larger queues and batching raise tokens per second and GPU utilization, which is what makes high COGS margins possible.

Cost or risk

The metric set separates throughput from goodput and TPOT/ITL for a reason: work that inflates throughput can degrade the per-token latency users experience, so throughput gains are not automatically user-visible gains.

Why unresolved

The summary presents high cache hit rates as a win but gives no eviction, compression, or offload policy for state that must persist across many turns; retention and capacity are in direct tension.

Research direction

Measure cache bytes per active session as a function of turn count, then prototype tiered retention (hot HBM, warm host/remote store) and compare hit rate against TTFT and OOM-driven eviction rate.

Why unresolved

The summary names routing as a harness innovation and a cache-locality lever but does not resolve the conflict: spreading load across providers destroys the 96%-style cache hit rates that make prefill cheap.

Research direction

Build a router that scores candidate replicas/providers jointly on prefix affinity and queue depth, then A/B it against utilization-only balancing on cost-per-token and p99 TTFT.
