Overview

  • Speaker: Marc Klingen
  • Channel: AI Engineer
  • Main topic: Building self-improving open-source AI agent stacks with continuous feedback loops
  • Purpose: To educate AI engineers on how to build self-improving agent stacks by combining online observation with offline dataset curation, evaluation, and automated fix proposals. Marc Klingen, co-founder of Langfuse, discusses the evolution of open-source AI agent stacks and how teams are moving toward self-improving agents. By combining online tracing and monitoring with offline evaluation, dataset generation, and prompt/agent fixes, developers can create continuous improvement loops that reduce manual overhead and improve agent performance.

Key Points

Shift from Write-Intensive to Read-Intensive Agent Workflows

  • Explanation: Early agent systems required heavy manual prompt writing and debugging. Modern stacks allow agents to read through vast production traces, user feedback, and evaluation results to propose improvements.
  • Evidence: Production tracing data combined with offline evaluation metrics.
  • Practical implication: Teams can scale agent performance without exponentially increasing human engineering hours.

The Danger of Overfitting in Autonomous Loops

  • Explanation: If agents completely automate the creation of evaluation datasets and fixes without human oversight, they risk overfitting to quirks and introducing jargon leakage.
  • Evidence: Customer support agents leaking internal pipeline jargon to end users.
  • Practical implication: Maintain human-in-the-loop review for dataset boundaries and evaluation criteria.

Frameworks, Models & Processes

The Continuous OSS Agent Improvement Loop

  • How it works: Production traces and user feedback are captured online, fed into offline evaluation datasets, tested against new candidate prompts or agent configurations, and redeployed after verification.
  • Components:
    • Roadmap / Meta loop
    • Goal loop
    • Agent turn / Token loop
    • Trace & Monitoring
    • Dataset curation
    • Offline Evaluation
  • When to use: When developing production-grade AI agents that need to adapt and improve based on real-world usage.

Core insights

[A]Architecturemedium noveltymoderate evidence

Self-improving agent stacks are structured as a hierarchy of loops with distinct scopes and cadences — a roadmap/meta loop, a goal loop, and an agent-turn/token loop — where improvement work happens at a different level than task execution.

Why it matters

It gives a concrete decomposition for where improvement logic lives: the inner token loop optimizes a single run, the goal loop defines what the run should achieve, and the meta loop changes the agent itself. Engineers must decide which artifacts (prompts, tools, eval criteria, datasets) each loop is permitted to mutate, because conflating them lets the agent rewrite its own success criteria.

Generalization

Any adaptive system needs separated control planes for 'execute', 'define success', and 'change the executor'; mixing them collapses into reward hacking or unguided drift.

[O]Mental Modelhigh noveltymoderate evidence

The agent workflow inverts from write-intensive (humans authoring and debugging prompts) to read-intensive (agents ingesting large volumes of production traces, user feedback, and eval results and proposing the changes).

Why it matters

This changes the primary engineering input from human authoring effort to data availability and trace quality. It implies the highest-leverage investment is making execution data machine-readable and complete, not writing better prompts by hand. It also shifts the cost model toward large-context reading of traces.

Generalization

When a system's improvement bottleneck shifts from human expression to machine observation, the winning infrastructure is the observability substrate, not the authoring surface.

[P]Practicemedium noveltymoderate evidence

The binding constraint in the improvement loop is not fix generation but manual maintenance of datasets and evaluation criteria; automated fix proposals are only as useful as the continuously curated eval substrate underneath them.

Why it matters

Teams that automate prompt/code fixes without automating or resourcing dataset curation get fast iteration against stale or wrong criteria. It reorders priorities: dataset lifecycle and criteria ownership are the real engineering surface, and any 'self-improving' stack must budget for the eval side of the loop.

Generalization

Automation applied to the fast part of a pipeline (generation) without automating the slow part (specification/verification) just moves the queue.

Source video ↗
[~]Tradeoffmedium noveltymoderate evidence

Human-in-the-loop placement should not be uniform: humans retain ownership of evaluation criteria and dataset boundaries, while agents are delegated fix proposal and criteria maintenance within those boundaries.

Why it matters

This is a specific allocation rule rather than generic 'keep a human in the loop'. Granting the agent write access to its own evaluators is the failure path; granting it write access to the code/prompt fix while the human owns the grader keeps the loop corrigible. It defines an enforceable interface for the meta loop.

Generalization

In self-modifying systems, the agent must never own the oracle. Delegate generation, retain specification and boundary-setting.

[!]Failure Modehigh noveltyweak evidence

Fully automated dataset/fix generation produces a concrete, observable failure mode: overfitting to trace quirks and leaking internal pipeline jargon into user-facing output.

Why it matters

This is a checkable symptom rather than an abstract risk — internal vocabulary appearing in customer-facing text is a detectable signal that the agent learned from traces including internal context rather than from task-relevant behavior. It implies trace data carries context contamination that must be filtered before becoming training/eval material.

Generalization

Any pipeline that converts production logs into improvement signal inherits the logs' incidental context; contamination becomes regressions in the output distribution, not just noise in metrics.

Source video ↗
[>]Predictionmedium noveltymoderate evidence

Agent targets are inherently incomplete and shift over time, which makes evaluation criteria themselves a live, versioned artifact rather than a fixed benchmark.

Why it matters

If specs are unstable, a static eval suite silently becomes misaligned with the current goal, so the loop optimizes toward yesterday's objective. Architecturally, eval criteria must live in the same versioned, reviewable change pipeline as the agent configuration they gate.

Generalization

For underspecified objectives, the measuring instrument needs its own update loop and change history, or it becomes the dominant hidden bug.

Source video ↗
[M]Mechanismmedium noveltymoderate evidence

Production tracing data and offline evaluation are the same continuous artifact pipeline: online traces plus user feedback become offline datasets, which gate candidate prompt/agent configurations before redeployment.

Why it matters

Observability stops being a debugging utility and becomes the eval supply chain. This dictates that trace capture, feedback attachment, and dataset derivation be designed as one system with quality guarantees, not bolted on after launch.

Generalization

In adaptive systems, telemetry is a production input to the model/tool improvement process, so its completeness and schema stability are correctness concerns.

Deep dives

5

Loop-level attribution: which control plane owns a production failure

Research question

Can production failures be automatically attributed to the token loop (execution), the goal loop (objective definition), or the meta loop (agent configuration) using trace features alone, and how much diagnostic accuracy is gained over end-to-end quality metrics?

Why

The meta/goal/token hierarchy is presented structurally, but if a quality regression originates in the goal loop, end-to-end telemetry will misroute the fix to prompt-tuning, and the loop will churn without converging. A failure-to-loop classifier is the precondition for automated fix proposal being safe.

Source video ↗

Constrained dataset curation: automating the slow part of the loop without letting the agent own the oracle

Research question

Can agents propose candidate eval examples while selection is filtered against held-out production trace distributions and human-approved boundary rules, and does this preserve distributional match between eval and production better than either fully manual or fully automated curation?

Why

Automating fix generation while leaving dataset curation manual just relocates the queue. But naive automated curation admits incidental trace context into the eval substrate, which surfaces as output regressions rather than metric noise. The design question is which part of curation is delegable.

Source video ↗

Jargon leakage as a detectable contamination signal from trace-derived eval data

Research question

Can internal-vocabulary leakage into user-facing output be detected automatically by tracking tokens that appear in internal-only trace fields but never in human-approved reference outputs, and does a leaked-vocabulary gate catch regressions that semantic eval scores miss?

Why

This converts an abstract 'overfitting risk' into a checkable symptom with a cheap detector. It also gives a direct empirical probe of whether trace contamination is entering the improvement signal, which is otherwise invisible in aggregate quality scores.

Source video ↗

Meta-loop cadence: staleness versus churn under shifting agent targets

Research question

How does the frequency of the self-improvement loop (per-merge, daily, weekly) trade off against eval-score regressions, eval-set staleness, and human review-queue load when agent targets shift continuously?

Why

If targets are inherently incomplete and shifting, a static eval suite silently optimizes toward yesterday's objective. Cadence is the cheapest lever on that mismatch, and the review gate makes throughput a human-capacity constraint, so the sweep has a real cost axis on both sides.

Source video ↗

Review capacity as the throughput ceiling of the self-improving loop

Research question

Does packaging agent-proposed changes with evidence (failing trace, eval delta, blast radius) reduce human review time per change enough to raise loop throughput without weakening acceptance quality, compared with raw diffs?

Why

Routing agent changes through review gates makes human review the bottleneck of an otherwise automated loop. If evidence packaging does not cut review time, the self-improving stack's ceiling is set by reviewer headcount, not model capability, and every other optimization is second order.

Article ideas

3

Your Self-Improving Agent Is Optimizing the Wrong Thing, and the Metrics Won't Tell You

The dominant failure of automated agent improvement is not bad fix generation but a misaligned eval substrate: because targets shift and curation is manual, the loop converges confidently on stale criteria, so the correct investment order is dataset lifecycle and criteria versioning before fix automation.

Angle

Argue against the intuitive build order (automate the fixer first) using the observation that generation automation without specification automation just moves the queue, and pair it with the concrete contamination symptom of internal jargon reaching end users.

Source video ↗

Stop Writing Prompts, Start Reading Traces: The Inversion of Agent Engineering Work

Agent engineering has flipped from write-intensive to read-intensive, which means the highest-leverage artifact in an agent stack is no longer the prompt file but the trace schema, sampling policy, and feedback attachment that make execution data machine-consumable.

Angle

Treat observability as the eval supply chain rather than a debugging utility, and show that telemetry completeness and schema stability are correctness concerns because they gate what the improvement loop can even see.

Source video ↗

Delegate the Generation, Never the Oracle: A Concrete Rule for Human-in-the-Loop Placement

Human-in-the-loop placement should be specified as an access-control rule rather than a vibe: agents get write access to prompts and code fixes, humans retain write access to evaluators and dataset boundaries, and this asymmetry is what keeps a self-modifying loop corrigible.

Angle

Replace generic 'keep a human in the loop' guidance with an enforceable interface for the meta loop, illustrated by agent-drafted changes flowing through review gates with evidence attached.

Project ideas

4

Leak Gate

gatehouse

A fully automated trace-to-dataset curation loop produces measurably more internal-vocabulary leakage in user-facing output than a human-gated loop, and a leaked-vocabulary detector computed over internal-only trace fields catches these regressions before semantic eval scores do.

Proof of concept

Instrument a customer-support agent's traces with a marker set of internal-only field values (pipeline names, tool identifiers, internal status strings). Derive eval datasets two ways (automated vs human-approved boundaries), run the same candidate fixes through both, and run the leak detector as a mandatory deployment gate. Report leakage rate and lead time between leak detection and score-based detection.

Measurement

Leakage rate per 1,000 user-facing outputs in automated vs gated arms; fraction of leaks flagged by the detector before any semantic eval delta appears; false-positive rate on clean outputs.

Source video ↗

Loop-Level Fault Router

beyond-evals

Production agent failures can be classified into token-loop, goal-loop, and meta-loop origin from trace features with materially better than chance accuracy, and routing fixes by predicted loop level reduces iteration count to resolution versus unconditional prompt-level fixing.

Proof of concept

Take a seeded set of injected defects at each loop level (bad tool call formatting; contradictory goal spec; agent-config regression) on a single agent, capture traces, label by loop level, and train a lightweight classifier. Then run two fix pipelines: always-attempt-prompt-fix vs route-by-classifier, and count iterations to green.

Measurement

Classifier accuracy and confusion between goal-loop and meta-loop defects; mean iterations to eval-set pass; rate of churn where a correct fix is applied at the wrong level and reverted.

Source video ↗

Cadence Sweep

movement-lab

Beyond some threshold, increasing meta-loop cadence stops improving eval scores and instead increases regression rate, because criteria updates lag target drift and the review queue saturates.

Proof of concept

Run the same trace corpus and fix-proposal agent on per-merge, daily, and weekly cadences against a deliberately drifting objective. Track eval score, out-of-distribution regression count, eval-set staleness (age of criteria vs. observed failure modes), and human review minutes per accepted change.

Measurement

Eval score versus cadence curve with saturation point; regressions per accepted change; review minutes per accepted change; correlation between criteria staleness and production failure modes.

Source video ↗

Evidence-Packaged Change Review

gatehouse

Agent-proposed changes bundled with the failing trace, the eval delta, and an estimated blast radius are accepted at equal quality but in significantly less reviewer time than raw prompt diffs, which raises the loop's effective throughput ceiling.

Proof of concept

Build a reviewer-facing diff format that auto-attaches the triggering trace, before/after eval results on the gated dataset, and the set of affected test cases. Run a within-subject comparison where engineers review the same batch of agent-proposed fixes in raw-diff and evidence-packaged form.

Measurement

Median review seconds per change; acceptance rate and post-merge revert rate as quality controls; variance in review time across reviewers as a proxy for review confidence.

Architectural implications

4

Traces become the raw material for evaluation datasets rather than a debugging afterthought.

Before

Tracing is a debugging/logging layer used reactively when something breaks.

After

Trace capture plus attached user feedback is the upstream supply of the offline eval corpus that gates deployment.

Consequence

Sampling policy, feedback attachment, and dataset derivation from traces become first-class architecture decisions; gaps in tracing directly degrade improvement capability.

Source video ↗

Evaluation criteria and dataset boundaries are held by humans while fixes are generated by agents.

Before

Engineers hand-write prompts, criteria, and test cases in one manual pass.

After

Agents propose prompt and code fixes; humans own and review the eval criteria and dataset scope those fixes must pass.

Consequence

Eval definitions must be stored as reviewable, version-controlled artifacts inside the agent stack, and the deployment gate must be the eval result, not the author's intent.

Source video ↗

Improvement is organized into a meta loop, goal loop, and token loop instead of one iteration cycle.

Before

A single undifferentiated dev cycle: change prompt, ship, observe, repeat.

After

Changes at the agent-configuration level, goal-definition level, and per-turn level are tracked and gated separately.

Consequence

Monitoring and ownership must be assigned per loop level; a regression in agent quality may originate in the goal loop, so diagnosis requires per-level telemetry, not just end-to-end metrics.

Source video ↗

Agent-produced changes are routed through review gates rather than applied directly.

Before

Automated output is committed directly or is entirely human-authored.

After

Agents draft changes and submit them for review, backed by explicit evaluation criteria.

Consequence

The loop's throughput ceiling becomes human review capacity, so reducing review load per change (better diffs, evidence packaging) becomes the optimization target.

Tradeoffs and failure modes

4

Fully automated dataset and fix generation

Benefit

Removes the manual labor that currently bottlenecks updating datasets, eval criteria, and proposed fixes.

Cost or risk

Overfitting to trace quirks and leaking internal pipeline jargon into user-facing output.

Source video ↗

Human oversight of eval criteria and datasets

Benefit

Prevents overfitting and sloppy agent behavior while still cutting tedious engineering overhead.

Cost or risk

Review of dataset boundaries and proposed fixes remains a human-time bottleneck that caps how fast the loop can actually turn.

Source video ↗

Read-intensive agent workflows over trace data

Benefit

Teams can scale agent performance without exponentially increasing human engineering hours.

Cost or risk

Effectiveness now depends on having vast, high-quality traces and feedback captured in the first place; thin or unfedback telemetry starves the loop.

Source video ↗

Review gates on agent-proposed changes

Benefit

Automates developer workflows while maintaining output quality.

Cost or risk

Quality depends on the robustness of the evaluation criteria behind the gate; weak criteria let bad changes pass review.
