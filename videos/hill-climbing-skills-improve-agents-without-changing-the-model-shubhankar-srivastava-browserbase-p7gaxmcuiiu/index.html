Summary

Overview

  • Speaker: Shubhankar Srivastava
  • Channel: AI Engineer
  • Main topic: Improving browser agents via hill-climbing self-improving loops without changing model weights
  • Purpose: To demonstrate how browser agents can self-improve and become more reliable through iterative loops and skill extraction without fine-tuning underlying LLMs. Shubhankar Srivastava, sales engineer at Browserbase, discusses how to improve browser agents in production without modifying model weights. He introduces the concept of hill-climbing through an auto-research loop inspired by Andrej Karpathy's auto-research concept, utilizing a doer-teacher agent architecture that generates production playbooks (skill.md files) containing workflow steps and heuristics learned across iterations.

The Auto-Research Loop (Doer & Teacher Architecture)

  • Explanation: Presents an automated loop inspired by Andrej Karpathy's autoresearch concept, combining a doer agent and a teacher agent to iteratively refine execution strategies.
  • Key claims:
    • The auto-research loop uses two agents: a doer that browses and a teacher that analyzes traces.
    • A strategy.md file serves as the persistent artifact across runs, accumulating learnings.
    • The output of the converged loop is a production playbook (skill.md) containing exact workflows and heuristics.
  • Examples:

  • Why it matters: Provides a scalable alternative to costly fine-tuning or manual prompt engineering for every new task.

Key Points

Browser agents suffer from lack of cumulative learning

  • Explanation: Every agent execution starts from scratch, repeating mistakes because there is no built-in mechanism to learn from production traces.
  • Evidence: Failures on Google Flights slider dragging and OpenTable anti-bot screens.
  • Practical implication: Developers must build harness infrastructure around models to capture and persist learnings.

The Doer-Teacher loop enables autonomous skill creation

  • Explanation: A doer agent executes tasks using browser tools while a teacher agent analyzes screenshots and logs to update a strategy file after every iteration.
  • Evidence: Live demo showing cost and latency decreasing across iterations while success rate increases.
  • Practical implication: Reduces engineering hours spent manually writing and updating scraping scripts.

Two conditions are required for domain hill-climbing

  • Explanation: To successfully run a self-improving loop, you need a replayable environment and a verifiable outcome.
  • Evidence: Comparison between coding agents with deterministic testing and open-ended research agents.
  • Practical implication: Without determinism and verification, agents cannot reliably evaluate whether a strategy iteration succeeded.

Frameworks, Models & Processes

Auto-Research Loop (Doer-Teacher)

  • How it works: A prompt goes into the loop; the doer executes the task using browser tools, and the teacher evaluates traces and screenshots to fix strategy.md. When a run passes, the skill graduates to skill.md.
  • Components:
    • Doer agent
    • Teacher agent
    • strategy.md artifact
    • skill.md output
  • When to use: When building browser agents or autonomous workflows that need to handle tricky, non-deterministic websites reliably.

Deep dives

5

Convergence control in doer-teacher hill-climbing loops

Research question

What early-stopping and iteration-budget heuristics maximize success-rate delta per iteration before a strategy.md graduates to skill.md, and at what iteration count does marginal gain collapse?

Why

The loop's economics hinge on how many doer/teacher cycles are needed before a playbook is production-ready; if convergence is uncontrolled, teacher calls and trace storage may cost more than the reliability gain, making the whole approach uneconomic for long-tail sites.

Source video ↗

Replay substrates for live, anti-bot web environments

Research question

Can recorded-trace replay, DOM snapshot fixtures, or request-level mocking reproduce a live site's failure surface (sliders, captchas, anti-bot walls) faithfully enough for the teacher agent to evaluate a strategy iteration offline?

Why

Replayability is one of the two stated preconditions for the loop, yet browser targets are the least deterministic environments available; without a replay substrate, hill-climbing must run against live sites at full cost and cannot isolate regressions from site-side drift.

Source video ↗

Proxy verifiers for non-deterministic agent domains

Research question

Do proxy verifiers (source-grounding checks, rubric grading, selector-level assertions) correlate strongly enough with true task success to serve as the reward signal for open-ended research agents?

Why

The replayable+verifiable criterion predicts self-improvement stalls in open-ended domains; if a cheap proxy verifier can be shown to track ground truth, the addressable surface for hill-climbing loops expands well beyond deterministic coding tasks.

Source video ↗

Skill decay detection and automatic re-entry into the loop

Research question

Can runtime success-rate monitoring reliably detect when a graduated skill.md has gone stale, and does auto-demotion plus re-entry into the doer-teacher loop recover reliability faster than a full re-derivation?

Why

Discovered heuristics are site-state-specific, so a catalog of graduated skills silently rots; without a drift trigger, skill reuse becomes a liability that degrades agents rather than improving them.

Source video ↗

Teacher update rule: diff vs rewrite vs append on strategy.md

Research question

Which update semantics (incremental diff, full rewrite, append-only log) on strategy.md produce stable convergence without context bloat or loss of earlier-learned heuristics?

Why

The artifact is injected into the system prompt, so its growth directly trades against context budget and token cost; the update rule is a concrete, testable engineering choice that determines whether skill.md stays small and portable.

Article ideas

3

Reliability Is a Harness Problem, Not a Model Capability Problem

Teams waiting on stronger foundation models are optimizing the wrong variable: because every browser agent run starts from zero with no persistence of execution traces, harness investment (trace capture, replay, and a train-skill loop) compounds run over run while model upgrades alone reset to the same baseline.

Angle

Reframe the reliability debate from a model-capability question to an infrastructure question, using the doer-teacher loop as the worked example and the cost/latency/success-rate curve as the argument for where the next engineering dollar goes.

Source video ↗

The Two Preconditions: Where Self-Improving Agents Work and Where They Stall

A self-improving loop is only as good as its environment, and the replayable-plus-verifiable test cleanly partitions the agent landscape: browser and coding agents with deterministic tests can hill-climb cheaply, while open-ended research agents cannot judge their own iterations and will silently optimize noise.

Angle

Turn an architectural observation into a decision checklist teams can apply before building any self-improvement loop, with the open-ended-research case as the falsification test.

Source video ↗

Skills Are a Package Registry: The Coming Supply Chain of Agent Reliability

Once per-site reliability knowledge is shareable as skill.md artifacts, the unit of engineering shifts from per-project scraping scripts to a versioned catalog, and the token-cost savings from suggested selectors will drive adoption faster than any correctness guarantee — importing third-party skills therefore propagates unknown, unvalidated heuristics into production agents.

Angle

Argue that the registry layer needs versioning, validation against current site state, and provenance metadata before adoption outpaces the ability to audit what a skill actually does.

Project ideas

4

ConvergenceBench

beyond-evals

Marginal success-rate gain per doer-teacher iteration collapses sharply after a small number of cycles, and an early-stopping rule keyed to strategy.md change-magnitude will reach a production-grade skill.md in far fewer iterations than a fixed-budget loop, at no loss of final success rate.

Proof of concept

Run the same task set (e.g., flight search, restaurant booking) through the loop with per-iteration instrumentation of success rate, token cost, latency, and a structural diff size on strategy.md; A/B a fixed 20-iteration budget against a diff-magnitude early-stopping rule.

Measurement

Iterations-to-graduation, final success rate, and total token cost per task; success criterion is equal-or-better success rate at a materially lower iteration count and lower cumulative cost.

Source video ↗

Replay Fixture Harness

movement-lab

DOM snapshot fixtures plus request-level mocking can reproduce the specific failure surfaces that make browser agents unreliable (slider drag, anti-bot page) faithfully enough that a teacher agent's strategy verdict on replay matches its verdict on the live site in the majority of cases.

Proof of concept

Capture traces and DOM snapshots from real failing runs on two sites, build a replay substrate, then run the teacher agent on both live and replayed traces and compare the resulting strategy.md edits and pass/fail verdicts.

Measurement

Agreement rate between live and replayed verdicts, replay fidelity per failure-mode class, and cost reduction per evaluated iteration versus live execution.

Source video ↗

Skill Drift Sentinel

gatehouse

Runtime success-rate monitoring on a graduated skill.md can detect staleness before agent reliability visibly degrades in production, and auto-demotion plus re-entry into the doer-teacher loop recovers reliability faster and cheaper than full re-derivation from scratch.

Proof of concept

Deploy graduated skills against a set of sites, inject controlled UI/DOM mutations, and compare three responses: no action, full re-derivation, and drift-triggered re-entry with the existing skill.md as the teacher's starting point.

Measurement

Detection latency (runs after drift before alert), recovery time and token cost per recovery path, and post-recovery success rate relative to pre-drift baseline.

Source video ↗

Skill Registry Auditor

new

Third-party skills can be statically decomposed into their selector and navigation heuristics, and skills whose selectors no longer resolve against current site state measurably inflate token cost and lower success rate when imported — so validation gates plus selector-cost scoring will predict skill quality without executing them.

Proof of concept

Import a sample of catalog skills into a fixed agent, measure token cost and success rate against a selector-free baseline, and correlate those outcomes with a static audit score (selector resolution, staleness, instruction length).

Measurement

Token reduction and success-rate delta per imported skill, plus rank correlation between the static audit score and measured performance; a strong correlation validates pre-execution quality screening.

Architectural implications

3

Learning state lives in a text artifact (strategy.md → skill.md) injected into the system prompt, not in model weights.

Before

Improvement required fine-tuning the model or hand-editing prompts per task/site.

After

The improvement loop writes and revises a versioned playbook that any agent can load at runtime.

Consequence

Decouples model choice from reliability tuning, enables skill sharing (browse.sh) and per-site versioning, but makes prompt-context budget and artifact staleness primary concerns.

Source video ↗

A dedicated teacher agent consumes traces and screenshots separately from the executing doer agent.

Before

A single agent both executed and self-corrected within a run, with no cross-run memory.

After

Execution and post-hoc analysis are split into distinct roles with the trace as the handoff interface.

Consequence

Introduces a clean observability boundary (traces/screenshots) and a natural place to add reward/eval logic, at the cost of extra agent calls and trace storage.

Source video ↗

Replayability and verifiability are treated as environment properties rather than agent capabilities.

Before

Reliability debugging happened ad hoc against live production sites.

After

Environments must be provisioned to be replayable with verifiable outcomes before the loop is viable.

Consequence

Shifts engineering effort upstream into environment/harness construction and implies that domains lacking determinism (open-ended research) cannot use the loop as-is.

Tradeoffs and failure modes

4

Self-improving loop vs precondition costs

Benefit

Cheap, compounding improvement without fine-tuning and reduced manual script-writing.

Cost or risk

Requires a replayable environment AND a verifiable outcome; domains missing either (open-ended research) cannot reliably evaluate iterations.

Source video ↗

Discovered heuristics vs generality

Benefit

Loop finds superior tactics like pre-filled URLs and JS injection.

Cost or risk

These are site-state-specific; browser fragility and anti-bot/captcha failure modes can invalidate a graduated skill when the target site changes.

Source video ↗

Skill sharing/token savings vs correctness risk

Benefit

400+ ready-made skills and suggested selectors cut token costs significantly.

Cost or risk

Importing third-party skills into any agent propagates whatever heuristics (and staleness) those skills encode, creating supply-chain-like trust concerns.

Source video ↗

Automated skill generation vs convergence

Benefit

Reduces engineering hours spent manually writing and updating scripts.

Cost or risk

Loop may require many iterations and it is unresolved how to optimize convergence, so iteration cost could dominate before a skill graduates.
