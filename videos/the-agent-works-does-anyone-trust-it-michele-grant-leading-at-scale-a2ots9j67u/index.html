Key Points

Value must be pre-measured

  • Explanation: You cannot prove an agent moved the needle if you cannot measure where you started.
  • Evidence: Every metric requires a pre-deployment baseline.
  • Practical implication: Do not deploy AI agents without establishing baseline operational metrics first.

Code is proof, text is explanation

  • Explanation: LLM-generated prose or summaries cannot be used as proof of correct business logic.
  • Evidence: Core math must run in deterministic, finance-approved code.
  • Practical implication: Enforce deterministic code for calculations and rely on telemetry logs for auditing.

Frameworks, Models & Processes

The Three Questions Framework

  • How it works: Evaluating AI agents by answering what value they create, who is accountable, and what evidence allows autonomy.
  • Components:
    • What value does it create?
    • Who is on the hook for it?
    • What evidence permits greater autonomy?
  • When to use: Whenever deploying an AI agent into core enterprise business workflows.

The Three Lines Accountability Model

  • How it works: Mapping agent oversight across management, risk/compliance, and internal audit with a designated daily operator.
  • Components:
    • Management (owns risk and controls)
    • Risk & Compliance (oversight and challenge)
    • Internal Audit (independent assurance)
    • Daily Operator (understand, interpret, override, kill switch)
  • When to use: To define clear operational ownership and fail-safes for autonomous AI agents.

The Human Work Standard

  • How it works: A one-page policy mapping every decision fork to human roles, required evidence, and escalation paths.
  • Components:
    • The Decision
    • Authorized Role
    • Evidence Required
    • Escalation Path
  • When to use: When documenting where human authority stops and agent autonomy begins.

Four Stages of Autonomy

  • How it works: Phased graduation of agent independence based on empirical performance and evidence.
  • Components:
    • Stage 1: Shadow Mode
    • Stage 2: Supervised Draft
    • Stage 3: Exception & Sample
    • Stage 4: Exception-Only
  • When to use: When scaling agent permissions from parallel tracking to fully autonomous execution.

Separate the computation layer from the language layer: agent business logic (e.g., synergy math, ledger reconciliation) must execute in deterministic, finance-approved code, while the LLM's prose output is treated as explanation rather than proof. The LLM is demoted from calculator to orchestrator/explainer.

Why it matters

This relocates the trust boundary: correctness becomes unit-testable and auditable in code, while the model's role narrows to interpretation and narration. Any agent that emits business-critical numbers from prompt prose has an unverifiable core.

Generalization

For any agent producing numeric or financially material outputs, the authoritative path should be a deterministic function with the model supplying inputs, intent, and explanation—never the arithmetic or the rule evaluation itself.

Deep dives

4

Autonomy tier promotion criteria and scorecard gating

Research question

What per-stage quantitative thresholds (exception rate, override frequency, sampled error rate, duration, sample size) justify promoting an agent from shadow to supervised draft to exception-only, and can promotion be gated automatically by an autonomy scorecard rather than by social trust?

Why

Without thresholds, the four-stage model is a narrative rather than an operational control; promotion decisions revert to the same informal trust the framework is meant to replace, and the downgrade path has no trigger condition either.

Source video ↗

Validating proxy metrics against primary outcomes

Research question

How often does improvement in an instrumented proxy (cycle time, analyst hours) decouple from the primary outcome (detection time), and what paired-measurement design detects that decoupling before an ROI claim is filed?

Why

A pre-deployment baseline alone does not establish that the proxy is a causal conduit to the business outcome; an agent can optimize the easiest-to-instrument metric and produce a value case that looks validated but is unfalsifiable.

Source video ↗

Out-of-schema routing when deterministic rules do not cover a case

Research question

When an agent input falls outside the finance-approved deterministic rule set, should the runtime force an exception path rather than permit model inference, and how frequently does that exception path fire on real workloads?

Why

The deterministic-core mandate creates a boundary condition the framework does not specify; left unhandled, the system either silently reopens prompt-prose computation or stalls the workflow, and novel-case semantics become undefined.

Source video ↗

Kill switch state machine: suspend, resume, and in-flight work conservation

Research question

What state must an agent preserve when a named operator invokes the kill switch mid-execution, how is partially completed work handed to a human queue, and what prevents duplicate transactions on resume?

Why

A kill switch listed as an operator responsibility but without defined post-shutdown state and resume semantics is a control that can itself create financial exposure through duplicated or partially applied transactions.

Project ideas

4

Autonomy Tier Gate

gatehouse

Agents promoted through a scorecard-gated tier model produce fewer severe incidents than agents deployed directly to autonomous operation at equal elapsed time, without reducing measured value delivered.

Proof of concept

A delegation and permission layer decoupled from agent code that reads an autonomy scorecard (exception rate, override frequency, sampled error rate) and blocks tier promotion unless thresholds are met, with a one-click downgrade path and in-flight work handling.

Measurement

Severe incidents per 1,000 decisions, override frequency, time-to-tier-promotion, and value delta versus baseline across staged and direct cohorts.

Source video ↗

Proxy Decoupling Detector

beyond-evals

In a meaningful share of agent deployments, improvement in an instrumented proxy decouples from the primary outcome, and paired baseline/outcome measurement surfaces the decoupling before an ROI claim is filed.

Proof of concept

An eval harness that captures pre-deployment baselines for both the proxy metric and the primary outcome per agent release, then reports the correlation between their post-deployment deltas.

Measurement

Rate of releases flagged as decoupled, correlation between cycle-time delta and detection-time delta, and count of ROI claims overturned by paired measurement.

Source video ↗

Decision-Fork Policy Compiler

movement-lab

Compiling a one-page decision-fork standard into runtime authorization checks reduces unauthorized agent actions and reviewer minutes per decision compared with prose SOPs.

Proof of concept

A schema for decision, authorized role, required evidence, and escalation path, with a compiler that emits authorization checks the agent harness consults and a reviewer interface that surfaces the required evidence per decision.

Measurement

Unauthorized action attempts blocked, reviewer minutes per decision, escalation-path correctness rate, and latency from policy diff to deployed change.

Reversible Agent Suspend

new

A suspend/resume state machine that conserves in-flight work produces fewer duplicate or partial transactions after a kill-switch event than a hard stop.

Proof of concept

A harness-level kill switch that snapshots in-flight agent state, routes partially completed work to a human queue, and supports idempotent resume with a defined post-shutdown state.

Measurement

Duplicate transaction rate, partial-work loss rate, resume latency, and operator minutes to reconcile after a suspend event.

Architectural implications

5

The LLM is confined to interpretation and narration while business rules live in deterministic code.

Before

Agent logic and business math encoded in prompt prose and model output, verified by reading transcripts.

After

Deterministic, finance-approved functions own computation; the model supplies inputs and explanations, and outputs are validated against code-level assertions.

Consequence

The verification surface becomes testable software with real unit tests and reproducible numbers; prompt engineering no longer carries correctness risk, but the deterministic core must be maintained and its interface designed.

Source video ↗

Autonomy is a graded runtime permission rather than a launch flag.

Before

An agent is switched from pilot to autonomous in one step, with trust established socially.

After

A tiered authority model (shadow, supervised draft, exception & sample, exception-only) where tier promotion requires recorded evidence and is reversible.

Consequence

The harness needs a permission/delegation layer decoupled from agent code, with a supported downgrade path and in-flight work handling.

Source video ↗

Logs are promoted from debugging artifacts to compliance evidence.

Before

Telemetry captures latency, errors, and token usage for engineering diagnosis.

After

An auditable decision log plus model inventory record plus autonomy scorecard constitute the trust substrate for each agent.

Consequence

Observability must be designed up front with immutability, schema, retention, and per-decision linkage; retrofitting these onto ad-hoc logs is expensive.

Source video ↗

Human authority is encoded as an explicit decision-fork map.

Before

Human-in-the-loop is implicit: some reviewer checks outputs somewhere.

After

A one-page standard mapping each decision to authorized role, required evidence, and escalation path, paired with a named daily operator holding override and kill switch.

Consequence

Consequence

Tradeoffs and failure modes

5

Deterministic core versus agent flexibility

Benefit

Provable, auditable correctness for financially material computation.

Cost or risk

Hard-coding rules limits the agent's ability to generalize beyond encoded cases, creates an engineering bottleneck, and pushes novel cases into exception handling with unclear semantics.

Source video ↗

Staged autonomy versus time-to-value

Benefit

Each promotion is backed by empirical evidence, reducing the blast radius of failures.

Cost or risk

Four stages mean sustained human review overhead before full autonomy, delaying the economic benefit that justified the agent and consuming the very capacity it was meant to free.

Source video ↗

Human oversight versus capacity savings

Benefit

A named daily operator can interpret, override, and kill the agent, providing a real fail-safe.

Cost or risk

Daily review consumes senior reviewer time and, if the reviewer cannot genuinely interpret outputs, produces the appearance of control without the substance.

Source video ↗

Evidence artifacts versus maintenance burden

Benefit

Decision logs, model inventory records, and scorecards make agent behavior auditable and comparable.

Cost or risk

Per-agent governance artifacts create recurring documentation, storage, and scorekeeping work that can bottleneck scaling across many agents.

Source video ↗

Proxy metrics versus outcome verification

Benefit

Cycle time, analyst hours, and detection time are easy to instrument and report.

Cost or risk

Agents optimize instrumented proxies while the true outcome stays flat, yielding a value case that looks validated but is unfalsifiable without direct outcome measurement.
