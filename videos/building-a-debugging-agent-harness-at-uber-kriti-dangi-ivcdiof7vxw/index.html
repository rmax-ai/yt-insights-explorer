Summary

Overview

  • Speaker: Kriti Dangi
  • Channel: Agentic AI Foundation
  • Main topic: Building an AI-powered debugging agent harness (DebugAssist) at Uber using 11 MCP servers
  • Purpose: To share Uber's architecture, challenges, and impact of deploying autonomous agents for app quality and production bug resolution at scale. Uber senior software engineer Kriti Dangi presents DebugAssist, an AI-powered debugging agent harness built at Uber to tackle production crash investigations and reduce mean time to resolve issues. The system automates end-to-end debugging across discovery, auto-triage, deep root cause analysis (RCA) using models like Claude, and resolution, utilizing LangGraph combined with Model Context Protocol (MCP) servers and deterministic-AI hybrid pipelines.

Under the Hood: Agent Pipeline & MCP Servers

Key Points

Deterministic-AI Hybrid Pipelines

  • Explanation: Combining LangGraph deterministic skeletons with LLM nodes avoids hallucination and keeps token costs and latency under control.
  • Evidence: Pipeline enforces exact steps (Context Collector -> ClassifyRCA -> Fix -> Bazel Test -> Create Diff).
  • Practical implication: Engineers can build reliable agents that do not wander into infinite rabbit holes.

Scale and Productionization

  • Explanation: Agents are packaged as Python PEX binaries stored in Artifactory and executed using Docker image registries.
  • Evidence: 8 agent types running across 5 monorepos handling 9,000 RCAs per month.
  • Practical implication: Allows seamless deployment and execution of AI workloads across massive enterprise infrastructure.

Human-in-the-Loop UX

  • Explanation: Providing tools like Diff fixer, Ask AI chat, and one-click machine deployment ensures developers stay in control while saving hours of manual work.
  • Evidence: PR merge rate increased from 5% to 48% as developers gained interactive feedback loops.
  • Practical implication: Developers are much more likely to adopt and trust AI-generated fixes when they can easily review and tweak them.

[A]Architecturehigh noveltystrong evidence

DebugAssist bypasses LLM planning entirely: a LangGraph DAG hard-codes the step sequence (Context Collector -> ClassifyRCA -> Fix -> Bazel Test -> Create Diff) and inserts LLM calls only as bounded nodes, deliberately trading agent autonomy for reduced hallucination and controlled token/latency cost.

Why it matters

This inverts the default agentic design assumption that the model should decide the control flow. It suggests production reliability at scale may come from constraining where reasoning is allowed, not from maximizing it.

Generalization

For high-volume, repetitive, verifiable workflows, encode control flow deterministically and reserve LLM inference for the steps that actually require judgment; this bounds failure surface and cost.

Deterministic control flow as a reliability mechanism for production agents

Research question

Does hard-coding the step sequence in a workflow graph (Context Collector -> ClassifyRCA -> Fix -> Bazel Test -> Create Diff) with LLM calls only as bounded nodes reduce hallucination and cost enough to justify the loss of adaptivity on novel bug classes?

Why

This inverts the default agentic assumption that the model should own control flow; if the tradeoff holds, production agent design shifts from 'maximize reasoning' to 'constrain where reasoning is allowed', which changes how harnesses are architected, tested, and cost-modeled.

Downstream action metrics vs. upstream answer accuracy as the agent value function

Research question

Project ideas

4

Skeleton-vs-Planner Benchmark

beyond-evals

A fixed-graph pipeline will match or beat a planning-based agent on known bug classes while degrading measurably on out-of-distribution incidents, and the crossover point is predictable from the predefined step sequence.

Proof of concept

Port the Context Collector -> ClassifyRCA -> Fix -> Bazel Test -> Create Diff sequence into a fixed graph, add a planner-driven variant, and run both against a replay set of resolved incidents split into in-distribution and novel/ambiguous crash types.

Measurement

Exact-match and 'right direction' RCA rate per bucket, hallucinated-step count, tokens, and wall-clock latency for both configurations.

Per-Node Cost and Turn-Budget Profiler

gatehouse

Per-node instrumentation will reveal that a small number of graph nodes consume the majority of tokens and latency, and that reallocating model tier and max-turn budget per node improves cost per merged fix without reducing merge rate.

Proof of concept

Wrap each LangGraph node with token, cost, latency, and turn-utilization counters, then sweep model tier and max-turn configurations per node on a fixed incident replay set.

Measurement

Cost per node, latency per node, turn utilization vs. max turns, and cost per merged PR across configurations.

Source video ↗

Merge-Rate Instrumentation Harness

beyond-evals

Downstream action metrics (merge rate, resolution time) will correlate weakly or not at all with upstream RCA exact-match accuracy, meaning accuracy alone is a poor adoption predictor.

Proof of concept

Join agent-run logs to PR outcomes and JIRA resolution timestamps, bucketing runs by RCA accuracy bucket, and test whether accuracy bucket predicts merge outcome.

Measurement

Correlation between accuracy bucket and PR merge rate; PR merge rate and resolution time by bucket; attribution of merge-rate movement to edit-tool usage.

Source video ↗

Context-Budgeted Tool Gate

new

Per-run gating of MCP plugin availability reduces assembled context size and improves reasoning quality or latency versus exposing the full tool surface, without materially reducing task success on known bug classes.

Proof of concept

Implement a runtime gate that loads only the MCP plugins relevant to the inferred incident class, and A/B it against unrestricted plugin loading on a replay set.

Measurement

Context size per run, tool-selection errors, RCA accuracy/Latency deltas, and time-to-onboard a new plugin under the gated policy.

Architectural implications

3

Control flow authority moved from the LLM planner to a fixed workflow graph.

Before

Agent decides which tools/steps to invoke, potentially exploring unboundedly.

After

Predefined LangGraph skeleton dictates the exact sequence; LLMs act as bounded node functions within it.

Consequence

Hallucination, token cost, and latency become bounded and testable, at the expense of flexibility for novel bug classes.

Source video ↗

Agent code distribution via PEX binaries + Artifactory + Docker.

Before

Agent logic deployed as a long-running service or notebook, hard to version.

After

Each harness version is an immutable artifact pushed to a registry and executed in a container runtime.

Consequence

Agent behavior becomes reproducible and rollback-able like standard software, enabling fleet-wide consistent rollouts across monorepos.

Source video ↗

Context assembly decomposed into parallel specialized collectors/sub-agents.

Before

One large prompt assembled from all relevant sources.

After

Independent parallel sub-agents each query a narrow source (breadcrumbs, crash correlation, git history).

Consequence

Reduces context bloat and isolates retrieval failures, but requires orchestration and aggregation logic.

Cost or risk
