Summary

Overview

  • Speaker: Brendan McManus, Michael Ran, Santi Weight
  • Channel: LangChain
  • Main topic: Building Pat, an internal AI pocket analyst tool at Bridgewater Associates
  • Purpose: To demonstrate how a 50-year-old systematic macro hedge fund approaches AI by building specialized multi-agent systems, treating coding agents as compilers, and combining human and artificial investment workflows. Bridgewater Associates built an AI analyst tool named Pat to automate hours of expert macroeconomic research, leveraging 50 years of company data, methods, and systematic expert systems. The speakers discuss Bridgewater's AI journey, the design of Pat, security and data access considerations, and technical architectural details involving LangGraph, specialized chat agents, and compiler-inspired coding agents.

Key Points

Isolate agents for specialization

  • Explanation: Avoid generic powerful agents; build narrow, specialized compound agents designed around actual user workflows.
  • Evidence: Separating chat UX from coding agents and sub-agents improves evaluation and task performance.
  • Practical implication: Build task-specific agents and compound them rather than relying on a single general-purpose agent.

Apply compiler theory to coding agents

  • Explanation: Treat analysis plans as type signatures and enforce deterministic semantics to make agent-generated code reliable and correct.
  • Evidence: 95% output determinism in test suites and 4x faster code generation compared to unconstrained LLMs.
  • Practical implication: Enforce correctness in agent architecture through strict planning, static analysis, and automated validation loops.

Multi-archetype teams are essential

  • Explanation: Building expert AI products requires investors, technologists, and scientists sitting at the same table.
  • Evidence: Investors bring domain context, technologists bring architecture, and scientists bring rigor.
  • Practical implication: Cross-functional collaboration ensures domain-specific tools actually solve expert user problems.

Project ideas

4

TypedPlan Compiler

movement-lab

Representing analysis plans as typed programs and compiling them into parallel Python tasks with static analysis, dependency analysis, caching, and a validation loop yields at least 90% output determinism on a test suite and at least 3x faster code generation versus an unconstrained LLM coding agent.

Proof of concept

Build a minimal orchestrator that converts a natural-language research prompt into an Analysis Plan with type signatures, a codegen agent that compiles it into parallel Python tasks, and an execution harness with static/dependency analysis, caching, and validator agents; run on a benchmark of 20 analytical tasks.

Measurement

Determinism = fraction of repeated runs producing identical outputs; speed = time-to-valid-code; compare against a single-shot LLM baseline.

Source video ↗

PrincipalScope Leak Tester

gatehouse

Agent runtimes that enforce per-principal context/tool scoping with dynamic context loading prevent cross-user data leakage under adversarial prompts, whereas post-hoc prompt filtering does not.

Proof of concept

Implement a multi-user agent harness with baseline and secure context/tool sets, per-user policies, and audit logs; generate adversarial prompts attempting to access other users' data; compare leak rates against a prompt-filter-only baseline.

Measurement

Number of successful data leaks per 100 adversarial prompts; false-positive rate of legitimate access denials.

Source video ↗

SemanticValidator Benchmark

beyond-evals

Validator/debugger agents that check semantic correctness of generated analyses reduce false-positive validation (accepting incorrect code) below 5% and false-negative validation (rejecting correct code) below 10% on a ground-truth analytical task suite.

Proof of concept

Collect ground-truth analyses; have codegen agents produce Python tasks from Analysis Plans; run static, dependency, and type checks alone versus with semantic validator agents; measure acceptance of incorrect vs. correct outputs.

Measurement

False-positive and false-negative validation rates; time added by validation.

Source video ↗

FlywheelMemory Governance Simulator

new

Adding memory isolation, human review gates, and rollback to a shared-memory flywheel reduces the propagation of incorrect or stale learnings across agent sessions without eliminating compounding gains.

Proof of concept

Simulate a multi-user research agent with shared memory; inject incorrect preferences/learnings from some users; measure spread over simulated days with and without governance mechanisms (isolation, review, rollback).

Measurement

Percentage of incorrect learnings propagated to other users' sessions; compounding accuracy gain on a held-out task set.

Architectural implications

4

The chat experience and the code-generation/execution engine are separated into different agents.

Before

One general-purpose agent handles both conversation and code generation/execution.

After

A non-technical chat agent delegates to a hyper-specialized coding agent with orchestrator, analysis plan, codegen, and validation harness.

Consequence

Cleaner user experience and better evaluation boundaries, but new coordination, state-transfer, and failure-isolation concerns.

Source video ↗

Analysis plans function as typed programs that are compiled into parallel Python tasks.

Before

LLM generates code in a single unconstrained pass from a user prompt.

After

Orchestrator converts prompt into an Analysis Plan, codegen agents compile it into parallel Python tasks, and a harness validates and caches execution.

Consequence

Higher determinism and speed, but correctness now depends on plan representation, static/dependency analysis, and validator/debugger agents.

Source video ↗

Security context is per-user rather than shared globally.

Before

Agent tools and context access are assumed common across users.

After

Each user gets a unique version of the analyst with baseline versus secure context/tools and dynamic context loading.

Consequence

Reduces data-leak risk but multiplies configuration, testing, and audit surface across users.

Source video ↗

Human feedback and agent learnings are written into shared memory.

Before

Agent sessions and research outputs are ephemeral.

After

A research flywheel stores learnings that both humans and agents continuously draw upon.

Consequence

Compounding institutional knowledge, but raises contamination, staleness, and access-control risks for shared memory.

Specialized compound agents versus general agents

Benefit

Narrow agents designed around actual workflows improve evaluation and task performance.

Cost or risk

Composing and evaluating multiple specialized agents and sub-agents increases architectural and evaluation complexity.

Per-user security harness

Benefit

Unique per-user contexts and tools prevent users from accessing data they are not permitted to see.

Cost or risk

Maintaining a unique version of the analyst for each user requires dynamic context loading, tool scoping, and per-user validation.

Chat and coding separation

Benefit

Keeps the chat UX non-technical and unpolluted while allowing coding specialization.

Cost or risk
