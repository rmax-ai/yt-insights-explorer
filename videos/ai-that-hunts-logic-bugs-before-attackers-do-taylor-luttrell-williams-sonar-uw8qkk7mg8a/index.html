[O]Mental Modelmedium noveltymoderate evidence

The bottleneck being addressed is not detection of malformed code but detection of correct-looking code with wrong intent: the failure class is 'syntactically and functionally correct but violates underlying business logic or intent,' which rule/pattern engines structurally cannot express because the rule must know authorization and tenant context, not token shapes.

Why it matters

It reframes static analysis as an intent-inference problem requiring whole-application context (component relationships, tenant model), which changes what must be fed to the analyzer and therefore its architecture and cost profile.

Generalization

For any verification agent, first classify the property being checked as form-matchable (deterministic linter suffices) vs intent-dependent (requires context assembly plus model reasoning); only the latter justifies agentic cost.

[M]Mechanismmedium noveltymoderate evidence

The pipeline treats adversarial validation and noise gates as a mandatory stage between candidate generation and surfacing findings, rather than trusting the generating agent's output — a generator/falsifier split that is credited with high precision.

Why it matters

Precision, not recall, is what determines whether an autonomous agent's findings get consumed by humans or ignored; building a separate falsification stage is a concrete, reusable way to buy precision without hand-tuning every prompt.

Generalization

Any agent that emits claims (alerts, bug reports, refactors) should have a distinct adversarial role whose only job is to attempt refutation before the claim reaches a downstream consumer or ticket queue.

[A]Architecturemedium noveltymoderate evidence

The system decomposes by vulnerability class: a global repository mapping pass runs first, then specialized agents per issue class inspect component relationships within that map.

Why it matters

Specialization by issue class (rather than by file or by directory) keeps each agent's playbook narrow and its context selection targeted, which is how a whole-repo scan stays tractable instead of stuffing the codebase into one context.

Generalization

For large-artifact reasoning, separate a cheap global indexing/mapping phase from per-hypothesis-class investigation agents that query the map, mirroring map-then-investigate rather than single-pass full-context prompting.

[~]Tradeoffmedium noveltystrong evidence

Agentic analysis is roughly an hour per scan (clone, map architecture, context-aware scans, dedup), which is orders of magnitude slower than pattern scanning and forces a tiered pipeline: cheap always-on SAST/SCA plus expensive intent-based hunting on-demand or scheduled.

Cost/latency, not capability, dictates where the deep agent sits in the SDLC — it cannot be a per-commit gate without a different design, so it must be batched and combined with fast layers that prefilter.

Deep reasoning agents should be positioned as second-echelon analysis triggered by schedule, risk signals, or fast-layer candidates, not as inline blocking checks.

Falsification gating as the precision mechanism for claim-emitting agents

Research question

Does inserting a dedicated adversarial-falsifier stage between candidate generation and surfacing produce a measurable precision gain that survives on vulnerability classes the falsifier has never seen?

Why

Precision, not discovery, is the binding constraint on whether autonomous security agents get triaged. If a separate falsification role buys precision cheaply, it generalizes to every agent that files tickets, alerts, or bug reports; if it only works on seen classes, the design has a hidden long-tail ceiling.

Precision/recall accounting for agentic detectors

Research question

What is the recall and the labeled ground truth behind a 90% precision figure, and how do both change at a fixed human triage budget?

Why

A precision number without a denominator or recall is not decision-grade evidence for deployment. Establishing a reporting standard — precision at a fixed triage budget, plus recall against injected logic-flaw corpora — makes agentic security claims comparable across vendors and tools.

Map-then-investigate decomposition for whole-repository reasoning

Research question

How much of a scan's fidelity is bounded by the quality and freshness of the global architecture map, versus the per-issue-class reasoning agents that query it?

Why

If map quality is a ceiling on all downstream findings, then map construction — not prompting — is the highest-leverage engineering surface, and map staleness against a moving codebase becomes a first-class operational failure mode rather than a caching detail.

Playbook stability under model swaps

Research question

Do finding sets remain stable across repeated runs of the same scan and across frontier-model version upgrades, when the domain procedure is encoded in a named playbook?

Why

If repeatability comes from the playbook rather than the model, model upgrades become routine; if not, every vendor or model change silently re-shuffles the finding set and auditability claims collapse. This is directly measurable as a diff between finding sets across versions.

Tiered placement of deep analysis in the SDLC

Research question

Given a roughly one-hour whole-repo scan, what trigger policy (schedule, risk signal, fast-layer candidate) maximizes confirmed findings per model-dollar relative to continuous deep scanning?

Why

Latency and cost, not capability, decide where the reasoning layer can sit. Treating deep analysis as second-echelon — triggered by cheap-layer candidates or risk signals — is a concrete architecture decision that must be justified against a cheaper alternative, not assumed.

Your Linter Cannot See Intent — And That Is an Architecture Problem, Not a Model Problem

The class of bugs that matters is code that is syntactically and functionally correct but violates business logic; because such flaws depend on authorization and tenant context rather than token shapes, the fix is whole-application context assembly, and the model is the least interesting part of the design.

Angle

Reframe static analysis from pattern-matching to intent inference, and derive the engineering consequences: what must be loaded into context, what a global repo map costs, and why dedup and finding identity become first-class problems.

Precision Is the Product: Why 90% Precision Is a Better Claim Than 200 Zero-Days

Discovery counts are marketing; precision at a fixed triage budget is the only metric that determines whether an autonomous detector gets consumed. Any agent that emits claims should be evaluated like a classifier, with a falsification stage as the mechanism that buys the precision.

Angle

Metric critique plus a proposed reporting standard for agentic detectors: precision at fixed triage budget, recall against injected logic-flaw corpora, and per-layer marginal contribution after deduplication.

Deep reasoning agents are structurally incompatible with per-commit gating; the correct architecture is a cheap always-on deterministic layer plus expensive intent-based hunting triggered by schedule, risk, or fast-layer candidates — and pretending otherwise produces a gate developers route around.

Project ideas

4

Falsifier Ablation Harness

beyond-evals

A dedicated refutation stage raises precision on held-out, unseen vulnerability classes by at least 20 percentage points over a generator-only baseline, without dropping recall more than 10 points.

Proof of concept

Build a two-role pipeline over a labeled corpus of injected logic and authorization flaws: a generator that proposes candidate findings, and a falsifier whose only instruction is to refute each candidate before publication. Run generator-only versus generator+falsifier, holding the model constant.

Measurement

Precision and recall at a fixed triage budget, reported per vulnerability class, with unseen classes held out from any prompt or heuristic tuning.

Source video ↗

Playbook Drift Diff

gatehouse

Encoding the detection procedure as a versioned playbook makes finding sets stable within a model version but not across model upgrades, so model-induced drift is quantifiable and bounded by playbook pinning.

Proof of concept

Author three named playbooks (broken access control, tenant isolation, business-logic abuse) with a version registry and eval harness; run each against the same repository and diff emitted finding sets across repeated runs and across two model versions.

Measurement

Jaccard overlap of finding sets across repeated runs (determinism rate) and across model versions, plus findings added/removed per playbook revision.

Source video ↗

Map-Quality Ceiling Probe

movement-lab

Downstream finding quality is bounded by the global architecture map rather than by per-class agent reasoning: degrading the map alone reproduces most of the false-negative increase seen when swapping to a weaker model.

Proof of concept

Build a map-then-investigate pipeline where a global component/tenant map feeds per-class investigation agents; create three variants — full map, degraded map (dropped relationships), and no map with file-local context — and scan the same corpus.

Measurement

Confirmed-findings count and false-negative rate per variant, plus the fraction of findings whose evidence citation depends on a relationship present only in the full map.

Source video ↗

Layer Attribution Ledger

new

After deduplication, the intent-based layer contributes the majority of confirmed high-severity findings while the deterministic SAST/SCA layer contributes the majority of confirmed low-severity findings at far lower cost per finding.

Proof of concept

Instrument a layered pipeline so every confirmed finding records which layer originated it and which layer(s) also raised it; run SAST/SCA alone, intent layer alone, and the union over one corpus with a shared finding-identity scheme.

Measurement

Originating-layer distribution of confirmed findings by severity, cost per confirmed finding per layer, and dedup collision rate between layers.

Source video ↗

Architectural implications

4

Agentic findings are emitted into the same issue list as classic SAST findings.

Before

AI security tooling as a separate dashboard/report, requiring humans to correlate two surfaces.

After

Agent output normalized into the existing issue schema (severity, impact, remediation) inside the platform developers already use.

Consequence

Agentic systems must conform to pre-existing artifact contracts and deduplicate against incumbent tooling; the integration schema, not the model, becomes the adoption gate.

Source video ↗

Verification responsibility is split across two layers: pattern-based SAST/SCA and intent-based hunting, with explicit deduplication.

Before

A single scanner class expected to be both comprehensive and precise.

After

Cheap deterministic layer for known patterns; reasoning layer for intent/context flaws; a dedup stage arbitrating overlaps.

Consequence

Deduplication and finding identity (stable IDs across layers and rescans) become first-class engineering problems, since the same defect can be surfaced by both layers.

Source video ↗

A dedicated adversarial validation stage sits between generation and surfacing.

Before

Generator agent's output is the finding.

After

Generator proposes hypotheses; a separate falsifier/noise-gate stage suppresses them before publication.

Consequence

Adds an extra model-call stage per candidate, raising cost and latency per scan, and introduces a new failure mode where the gate suppresses genuine novel findings.

Source video ↗

A global repository mapping pass precedes per-class investigation.

Before

Analyzer inspects files locally without a model of application architecture.

After

An explicit architecture map/context store is built first and queried by specialized agents.

Consequence

Introduces a cacheable intermediate artifact whose freshness vs the moving codebase becomes an operational concern, and makes map quality a ceiling on all downstream findings.

Tradeoffs and failure modes

4

Noise gates vs recall

Benefit

Adversarial validation and noise gates buy the 90%-precision regime that makes findings triageable.

Cost or risk

Any suppression heuristic tuned on known issue classes can silence unusual true positives — novel vulnerability classes are precisely the ones a falsifier lacks priors to defend.

Source video ↗

Depth vs latency

Benefit

Whole-repo mapping plus context-aware scans catches cross-component flaws.

Cost or risk

Approximately an hour per scan makes continuous per-commit gating impractical and costs model calls at repo scale.

Source video ↗

Frontier model dependency vs auditability

Benefit

Frontier reasoning models supply the depth needed to keep pace with attackers.

Cost or risk

Offloading core detection to a third-party frontier model creates a dependency and governance surface, addressed here only via a 'governed access' partnership framing rather than an in-product mechanism.

Source video ↗

Specialization vs long tail

Benefit

Per-issue-class agents with narrow playbooks make reasoning focused and deduplication tractable.

Cost or risk

Coverage is bounded by the enumerated issue classes; classes without a playbook may be structurally invisible to the system.
