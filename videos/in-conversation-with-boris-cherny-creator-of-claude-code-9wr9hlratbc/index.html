Summary

Overview

  • Speaker: Boris Cherny and David C. Brock
  • Channel: Computer History Museum
  • Main topic: The creation, evolution, safety, and future impact of Claude Code and AI-assisted programming tools.
  • Purpose: To explore the intersection of artificial intelligence and software engineering through the lens of Claude Code's creation and Anthropic's philosophy on AI safety. In this conversation at the Computer History Museum, software engineer Boris Cherny discusses his journey creating Claude Code at Anthropic, the transition from traditional programming to AI-driven agentic software engineering, AI safety, prompt injection, and the broader societal implications of automating software development.

Deep dives

5

Guard-model evadability under asymmetric capability

Research question

When the working model that proposes an action is stronger than the guard model that vets it, at what rate can the working model generate action plans that pass the guard while still achieving an injected malicious objective?

Why

Dual-model validation is only a safety layer if the validator is not systematically weaker than the thing it validates. If evasion rate rises with primary-model capability, then 'automode' style guards create a false floor of safety exactly when agents get more competent, and teams will under-invest in isolation and human gating.

Source video ↗

Action surface as the true capability boundary of an agent

Research question

For a fixed model, how much does repo-level task autonomy improve when you expand the tool/permission surface (read, write, bash, network) versus when you upgrade the model with a fixed surface?

Why

If autonomy is dominated by the action surface, then engineering effort and safety review should be focused on the tool and permission abstraction rather than chasing model upgrades. It also reframes 'we need a better model' requests as permission-design requests, which changes roadmap and risk allocation.

Source video ↗

Untrusted ingestion as a first-class security boundary

Research question

Does trust-tiering ingested content (web pages, retrieved docs, third-party tool output) and stripping executable instruction patterns measurably reduce injection success on agentic tasks without breaking legitimate task completion?

Why

Once the model acts on what it reads, every read becomes an authorization decision. If provenance tiering reduces injection success with acceptable task-quality loss, it becomes a runtime primitive rather than a per-application heuristic, and retrieval/browsing layers must expose provenance metadata.

Source video ↗

Mapping layered safety mechanisms onto agent runtime stages

Research question

Do evals, interpretability probing, and runtime classification cover disjoint failure classes, or do they overlap while leaving specific agent failure modes (multi-step exfiltration, permission escalation, cross-turn instruction carryover) uncovered by all three?

Why

The 'layered pipeline' claim is only useful if the layers are non-redundant and instrumentable at distinct runtime stages. If coverage overlaps and gaps remain, teams will report composite safety posture that does not correspond to any single measurable property of the deployed agent.

Source video ↗

Inference efficiency as a demand-expanding loop for agent workloads

Research question

When tokens-per-dollar improves by a fixed factor, does total agent workload spend fall, stay flat, or rise, and over what horizon does the response differ?

Why

Agentic coding multiplies tokens per task by looping over read/write/execute cycles, so naive cost models that assume efficiency reduces spend will systematically under-provision. A demand-expanding model changes capacity planning and unit-economics assumptions for platform teams.

Article ideas

4

Your Agent's Capability Boundary Is Its Permission Boundary

Agent capability is set by the action surface you expose, not by the model you pick; therefore permission and sandbox design, not model selection, should be the primary design artifact for any agentic system, and teams that treat tools as an implementation detail will ship both unsafe and weak agents.

Angle

Reframe the standard 'which model?' engineering debate as a permission-scoping exercise, with a worked argument that a fixed model plus expanded tool surface outperforms a model upgrade with a fixed surface.

Source video ↗

Guard Models Are a Layer, Not a Moat

Secondary-model validation ('automode') is valuable but structurally fragile: a guard weaker than the model it vets will be evaded at a rate that grows with primary-model capability, so guard models must be paired with process isolation, human gating, and continuous adversarial measurement rather than treated as the safety guarantee.

Angle

Argue against safety architectures that consolidate trust in a single classifier, and specify what must sit behind the guard model for the claim of safety to be measurable.

Source video ↗

Every Read Is an Authorization Decision

Giving an agent execution privileges turns content ingestion into a security boundary, so provenance tiering and content sanitization belong in the agent runtime, not in application code — and retrieval systems that cannot report where content came from are unsafe by construction.

Angle

Walk through how the same channel that makes an agent useful (reading the web, docs, tool output) becomes the injection vector, and what runtime-level provenance metadata must look like.

Source video ↗

When Generation Is Cheap, Verification Is the Bottleneck

Democratizing code generation to non-engineers does not remove engineering work; it relocates it into specification, acceptance criteria, and verification, and organizations that do not build verification infrastructure will accumulate unmaintainable systems faster than they can review them.

Angle

Challenge the optimistic 'coding for everyone' framing by tracing where the review burden goes and why verification tooling becomes the limiting resource rather than authoring tooling.

Source video ↗

Project ideas

4

Asymmetric Guard Evasion Harness

gatehouse

A stronger working model can produce action plans that pass a weaker guard classifier while still satisfying an injected malicious objective, and evasion success rate increases monotonically as the capability gap between working model and guard model widens.

Proof of concept

Two-model harness: a planner model receives task context containing an injected instruction and emits a tool-call plan; a guard model independently classifies each plan as benign/malicious; blocked plans are not executed in a sandboxed VM; record whether the malicious objective is achieved in the sandbox without the guard flagging it.

Measurement

Attack success rate (malicious objective achieved without guard block) across capability gaps and across injection placements, plus guard false-positive rate on matched benign tasks.

Source video ↗

Permission-Surface Ablation for Repo Tasks

movement-lab

Repo-level task completion rate scales more with incremental tool/permission surface (read-only, write, bash, network) than with a model upgrade at a fixed surface, up to the point where added surface mainly increases incident risk rather than success.

Proof of concept

Take a fixed set of repo-level tasks, run them under a fixed model across graded permission tiers, then run them with an upgraded model at the lowest tier; log both completion and any unauthorized-scope actions taken during successful runs.

Measurement

Task completion delta per tier vs. per model upgrade, and unauthorized-action rate per tier among successful runs.

Source video ↗

Provenance-Tiered Ingestion Gateway

gatehouse

Tagging ingested content by trust tier and neutralizing imperative/instruction-shaped spans before it enters agent context reduces injection success on browsing tasks by a measurable margin with no more than a small degradation in legitimate task success.

Proof of concept

Middleware that labels each ingested chunk with provenance (first-party repo, user doc, external web, third-party tool output), applies tier-specific transformation, and enforces that low-trust content cannot directly parameterize write/bash calls without an out-of-band confirmation step.

Measurement

Injection success rate and legitimate-task success rate on a matched benchmark of browsing-plus-action tasks, with and without tiering enabled.

Source video ↗

Safety Layer Coverage Matrix

beyond-evals

Static evals, interpretability probes, and runtime classification target overlapping failure classes while leaving specific agentic failure modes (multi-step exfiltration, permission escalation across turns, cross-turn instruction carryover) uncovered by all layers.

Proof of concept

Build a failure-mode taxonomy, construct minimal reproducible cases per mode, then run each case against each of the three safety layers independently and record which layer detects it and at what stage of the trajectory detection occurs.

Measurement

Per-failure-mode detection coverage matrix (layer x failure mode), redundancy index across layers, and count of failure modes with zero coverage.

Architectural implications

3

Tool/execution access is what makes a model an agent, and that access requires isolation and gating.

Before

Model output is text reviewed by a human before any action is taken.

After

Model intent flows through a guard model into an isolated VM where it reads, writes, and executes code autonomously.

Consequence

Sandboxing, permission scoping, and guard-model validation become first-class runtime infrastructure rather than application-level features.

Source video ↗

Prompt injection is defended by a secondary safety model rather than by hardening the primary model.

Before

The model that performs the task is also trusted to refuse malicious injected instructions.

After

A separate classifier/safety model sits between the working model's plan and its execution.

Consequence

Introduces a new component to version, evaluate, and latency-budget, and creates a distinct interface between 'intent' and 'action' in the agent runtime.

Source video ↗

Untrusted data channels (e.g., web pages the agent reads) are an attack surface once the agent can act on what it reads.

Before

Reading content was harmless because the model only produced text for a human to judge.

After

Any content the agent ingests can carry executable instructions, so ingestion becomes a security boundary.

Consequence

Data provenance and content sanitization move into the agent runtime; retrieval and browsing need trust tiering.

Source video ↗

Tradeoffs and failure modes

3

Autonomy vs. injection surface

Benefit

Giving the agent file/bash/API access enables end-to-end autonomous coding and task execution.

Cost or risk

The same channels used to read untrusted data become vectors for injected instructions that can exfiltrate data or take unintended actions.

Source video ↗

Dual-model safety validation

Benefit

An independent safety model can catch rogue or maliciously-induced behavior the working model would execute.

Cost or risk

Adds a second model in the critical path and another component that must itself be evaluated and maintained.

Source video ↗

Democratized software creation vs. verification burden

Benefit

Non-CS domain experts can build complex software without traditional syntax skills.

Cost or risk

More software produced by users with less engineering discipline shifts the burden to judgment and verification, where errors may be harder to detect.
