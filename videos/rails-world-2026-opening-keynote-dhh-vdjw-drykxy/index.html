Summary

Overview

  • Speaker: DHH
  • Channel: Ruby on Rails
  • Main topic: The impact of AI agents on software development, programming productivity, and the future of Ruby, Rails, and native application development.
  • Purpose: To address how AI coding agents are transforming software engineering, shifting the role of developers from writing code by hand to directing intelligent agents, and positioning Ruby on Rails as the ideal framework for the age of AI. DHH delivers the opening keynote at Rails World 2026, exploring the massive acceleration in software development driven by AI coding agents. Drawing parallels to historical technological shifts like the introduction of the camera and the Kodak Brownie, he argues that hand-written code is becoming an exceptional state, comparing the 10x and 1000x programmer paradigms. He reflects on his own work with Basecamp, transitioning from web apps to native applications built with the help of AI agents, and introduces Omarchy, his new agentic Linux operating system.

Key Points

Code generation by agents has transformed software economics

  • Explanation: The cost of generating code has dropped exponentially, making manual coding an exception rather than the rule.
  • Evidence: DHH wrote 321K lines of code with agents in 20 months compared to 647K lines over 21 years previously.
  • Practical implication: Developers must shift from writing syntax to framing problems and guiding AI agents.

English is the ultimate high-level programming language

  • Explanation: Natural language prompts replace verbose, complex syntax like Rust for human developers.
  • Evidence: DHH notes English is more expressive than Ruby and eliminates the pain of writing low-level code manually.
  • Practical implication: Communication and prompt design become core technical competencies.

Rails' conventions are an superpower for AI agents

  • Explanation: Structured layouts, naming conventions, and opinionated frameworks reduce the ambiguity that trips up AI models.
  • Evidence: Agent evals show high completion rates on Rails architecture compared to unstructured codebases.
  • Practical implication: Opinionated frameworks like Rails provide the ideal guardrails for autonomous coding agents.

[O]Mental Modelhigh noveltymoderate evidence

Language choice criteria invert when agents write the code: Rust is framed as hostile to human writers but its runtime efficiency is what matters once agents author it, and the claim is backed by a concrete rewrite result (HEY backend: 99% less CPU, 95% less memory, 110 hosts to 10). The human-ergonomics axis of language selection is demoted in favor of execution efficiency plus agent authorability.

Why it matters

Architects typically select languages on human readability, hiring pool, and iteration speed. If agents both write and can maintain the non-ergonomic language, the previous penalty on verbose or difficult languages largely evaporates, and the runtime/ops savings become capturable. This changes the default answer to 'what language should this service be in?' and shifts the bottleneck to whether agents can reliably maintain the resulting code.

Generalization

Separate the language used to express intent (natural language, high-level framework DSL) from the language used to execute (systems languages optimized for CPU/memory). Choose the execution language by machine-relevant metrics once human authorship stops being the constraint.

[A]Architecturehigh noveltymoderate evidence

Convention over configuration is reframed as an agent-context optimization: framework conventions exist to minimize token waste and context overhead for the agent, and the claim is paired with agent eval benchmarks where Rails-style frameworks outperform reference apps. This makes 'how many tokens does the agent need to understand and extend this codebase' a first-class framework/codebase design metric.

Why it matters

It converts a decades-old human-ergonomics doctrine into a measurable agent-harness property. If conventions reduce the context an agent must load to act correctly, then codebase conventions, directory layout, and defaults become part of the agent runtime's cost/latency/accuracy budget rather than mere style. It also suggests an evaluation method: benchmark frameworks by tokens-to-correct-change and success rate, not by human preference.

Generalization

Any codebase, API, or tool surface consumed by an agent should be evaluated on context cost and convention density, not only human readability. Reduce degrees of freedom so the agent needs fewer tokens and less retrieval to infer correct action.

Natural language (English) is positioned as the highest-level programming language precisely because it is 'more expressive and vague' than Ruby — vagueness, normally a defect in a specification language, is treated as an asset for intent expression, with the agent absorbing the disambiguation work.

This identifies the emerging abstraction boundary: humans own intent and direction, agents own disambiguation and low-level realization. Generalization

Move the human interface upward until it can be vague without being wrong. Precision that the agent can supply should not be demanded from the human; precision the human withholds becomes nondeterminism the agent must resolve, and that resolution is where failures originate.

Conventions Are an Agent Interface: Benchmark Frameworks by Tokens-per-Correct-Change, Not Human Preference

The doctrine of convention over configuration survives in the agent era for a new reason: it lowers the context budget an agent needs to act correctly. But the framework advantage cannot be claimed until convention density is separated from training-corpus representation, so teams should adopt tokens-per-correct-change as a first-class evaluation metric alongside human onboarding speed.

Angle

Reinterpret convention over configuration as an agent-harness cost property and propose a controlled benchmark that isolates corpus effects by testing a conventional but minimally-pretrained framework against Rails and a low-convention baseline.

The Ergonomics Penalty Is Now Paid by Agents: When to Choose Rust for Its Runtime, Not Its Syntax

The historical penalty on difficult systems languages assumed human authorship. When agents write and maintain the code, the runtime-efficiency axis becomes capturable, but the decision is only sound if agent competence in that language is measured longitudinally. Otherwise teams retain an artifact their humans cannot comfortably read while the maintenance burden silently transfers to a model dependency.

Angle

Argue that language selection should decouple from human readability only when paired with a maintenance-competence evaluation, using the HEY rewrite as the motivating datapoint rather than the conclusion.

English as a Programming Language Trades Expressiveness for Nondeterminism: Why Production Pipelines Need a Constraint Layer

Treating vagueness as an asset at the intent layer moves disambiguation into the agent, where it resolves nondeterministically and silently. Production agentic pipelines therefore need a constraint layer of acceptance criteria, invariants, and tests whose job is to bound divergence, not to replace the vague intent but to make it reproducible.

Angle

Examine the failure-attribution problem when the same vague prompt yields divergent artifacts, and propose measurable divergence bounds as a required artifact in the agentic development workflow.

As frontier capability arrives from multiple suppliers on a short cadence punctuated by regression intervals, any agentic stack hard-wired to one model inherits concentration risk and re-validation cost. Tokens-to-Correct-Change Benchmark for Agent-Facing Frameworks

beyond-evals

Holding task and agent constant, a codebase with higher convention density and fewer degrees of freedom reduces tokens-to-first-correct-change and increases agent success rate at N attempts, and this effect persists for a conventional but novel framework with little pretraining representation, indicating the advantage is not solely corpus-driven.

Proof of concept

Implement the same small CRUD plus background-job application in (a) Rails, (b) a deliberately conventional but novel framework with minimal corpus presence, and (c) a low-convention Node/Express baseline; run a fixed agent on identical change tasks with retrieval access; record token consumption, retrieval volume, and success rate.

Measurement

Tokens-to-first-correct-change, context tokens retrieved per task, success rate at 1, 5, and 10 attempts, and the delta between the novel-conventional and Rails conditions.

Source video ↗

Longitudinal Tracker for Agent-Authored Rust Services

new

The one-time runtime gains of an agent-authored Rust rewrite (99% less CPU, 95% less memory) are sustained over successive quarters, but only if human intervention frequency and rework rate stay flat; if they rise, the maintenance burden has transferred to a model dependency that is vulnerable to model swaps.

Proof of concept

Instrument a small agent-authored Rust service (or rewrite a module in Rust) with change lead time, defect density, rework rate, and human intervention tracking over at least two quarters; compare against an equivalent service in the prior language.

Measurement

Change lead time, rework rate, defect density, human intervention frequency, and CPU, memory, and host counts per quarter.

Source video ↗

Spec Constraint Layer for Bounded Agent Divergence

gatehouse

Attaching machine-checkable acceptance criteria and invariants to an otherwise vague natural-language specification reduces divergence across repeated agent runs without eliminating the expressiveness advantage of high-level intent.

Proof of concept

Build a spec wrapper that accepts a vague feature request, flags under-specified intent, and requires acceptance criteria, invariants, and tests; run N independent agent runs with and without the constraint layer on the same tasks; diff the resulting artifacts for semantic divergence.

Measurement

Divergence rate across repeated runs measured by semantic diff of produced artifacts, constraint-check pass rate, and human effort to author constraints versus effort saved in review.

Source video ↗

Model-Swap Regression Harness for Agentic Stacks

beyond-evals

An agentic stack with a model-abstraction seam and a per-model regression suite can swap frontier model suppliers with bounded re-validation cost, whereas a hard-wired stack exhibits silent behavioral regressions that are only detected after deployment.

Proof of concept

Build a thin model-provider interface with recorded agent trajectories as regression fixtures; run the same task set across at least three frontier models, including one from a non-US lab, on each release; measure pass/fail drift and re-validation effort.

Measurement

Regression-suite pass rate per model and per release, number of silent behavioral diffs detected pre-deploy, and engineer-hours to re-validate after a swap.

Architectural implications

4

The human/agent responsibility boundary moves from syntax authorship to problem framing and direction.

Before

Humans write the code and own disambiguation of intent; agents assist within a human-authored syntactic substrate.

After

Humans specify intent in natural language and direct agents; agents own syntax, low-level implementation, and disambiguation.

Consequence

Tooling investment shifts from editor/autocomplete ergonomics toward spec capture, task decomposition, review-of-agent-output, and context provisioning; reviews must be recalibrated for volume produced rather than lines authored.

Source video ↗

Framework and codebase conventions become an agent-facing interface with a measurable context budget.

Before

Convention over configuration is justified by human cognitive load and onboarding speed.

After

Conventions are justified by tokens-per-correct-agent-change and accuracy of agent output.

Consequence

Codebase design, directory structure, and framework defaults become part of the agent harness cost model; a codebase with more degrees of freedom is more expensive and less reliable to operate agentically.

Source video ↗

Language/platform selection decouples from human readability once agents author and maintain the code.

Before

Verbose or difficult systems languages are penalized because humans must write and read them.

After

Difficult-but-efficient languages become viable because the readability cost is borne by models, not people.

Consequence

Runtime and infrastructure savings that were previously unattainable (CPU, memory, host count) become reachable, but a new dependency appears: agent competence in maintaining that language.

Scope of what a small team builds expands from web application to full stack including operating system and native desktop apps.

After

A small team directs agents across OS, native apps, and services.

Consequence
