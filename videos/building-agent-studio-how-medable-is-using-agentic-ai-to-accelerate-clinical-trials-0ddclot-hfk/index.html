Overview

  • Speaker: Teresa Torres with guests Luke Bates, Jen, Piera Matthews, and Matt Schoolfield
  • Channel: Product Talk
  • Main topic: Building agentic AI systems and agent platforms at Medable to accelerate clinical trials
  • Purpose: To share how Medable built Agent Studio and utilized agentic AI to tackle complex clinical trial operations, reduce drug development timelines, and handle massive data volumes while maintaining regulatory compliance. Teresa Torres hosts a panel discussion with Medable team members Luke Bates, Jen, Piera Matthews, and Matt Schoolfield about Agent Studio, their platform for building agentic AI products. They discuss the massive administrative, regulatory, and data challenges in clinical trials, how they transitioned from legacy systems to agent-driven workflows, the importance of human-in-the-loop design, data ontologies, and evaluation frameworks for AI agents.

Key Points

Solving Cognitive Load Limits

  • Explanation: Human workers in clinical trials face massive cognitive loads, reading 200+ page protocols and navigating 13 disparate systems.
  • Evidence: Clinical trials involve thousands of documents per month per study and strict regulatory oversight.
  • Practical implication: Agentic AI acts as a connective tissue, absorbing the heavy data-processing burden and providing actionable recommendations.

Platform Approach to Agent Building

  • Explanation: Medable provides both a platform and an experience, enabling internal teams and customers to build custom agents on top of core capabilities.
  • Evidence: A customer built a full Microsoft Teams agent ecosystem in a 70-minute session using Medable connectors.
  • Practical implication: Platform flexibility accelerates product delivery cycles and empowers non-technical users to configure domain-specific agents.

The Necessity of Data Ontologies

  • Explanation: Without a unified ontology, agents struggle to query fragmented data sources effectively.
  • Evidence: Different clinical systems use different terminology for the same concepts (e.g., participant vs. patient).
  • Practical implication: Investing in an AI data layer that maps data to a common ontology drastically improves agent accuracy.

Frameworks, Models & Processes

Agent Studio Platform Model

  • How it works: Provides foundational agent primitives (models, MCP connectors, workflow, triggers) that power both custom applications and customer-built agents.
  • Components:
    • Agnostic model support
    • MCP connectors for data systems
    • Workflow functionality
    • Agent skills
    • Multiple trigger types (chat, webhook, integrations)
  • When to use: When scaling AI agent development across multiple enterprise workflows and custom customer use cases.

Human-in-the-Loop Evaluation Framework

  • How it works: Combines automated agent outputs with human review loops to measure deltas, evaluate correctness, and continuously improve agent accuracy.
  • Components:
    • Ground truth comparison
    • Automated benchmarking against configurations
    • Human review and correction logging
    • Iterative prompt and model tuning
  • When to use: In highly regulated environments like clinical trials where error rates must be strictly monitored and minimized.

Human-in-the-loop as a regulatory control, not a UX nicety

Research question

What minimum set of human-in-the-loop checkpoints and captured artifacts makes an agentic output defensible to an FDA auditor, and how does adding those checkpoints change agent throughput?

Why

If the value proposition is compressing a 10-year trial timeline, every HITL gate either preserves auditability or erodes the speed claim. Quantifying that trade is the difference between a demo and a deployable regulated product.

Ontology-grounded metadata classification at document scale

Research question

For an ontology-constrained classification agent processing tens of thousands of trial documents per customer per year, what accuracy ceiling and human-escalation rate can be achieved, and how much of the 'hours of metadata classification' is actually recoverable?

Why

Metadata classification is a concrete, measurable, high-volume bottleneck. If the escalation rate stays high, the agent only shifts labor rather than removing it, which invalidates the timeline-compression premise.

Agent reconciliation across fragmented legacy systems

Research question

When an agent must monitor patient-safety signals spanning 13+ legacy source systems with conflicting schemas and update latencies, how should it resolve contradictions and what is the cost of being wrong?

Why

Fragmentation across 13+ systems is the real engineering problem; the model is the easy part. Conflict-resolution policy is where agentic monitoring either earns trust or produces silent safety failures.

Model-agnostic configuration surface for non-engineer agent builders

Research question

Can a common-user-facing configuration surface ('agnostic model selection') produce agents as reliable as hand-built ones, and what guardrails are needed so model swaps do not silently regress regulated behavior?

Why

The platform bet is that non-engineers can configure agents safely. That is falsifiable: compare configured-agent vs. engineered-agent performance and regression behavior across model swaps.

Evaluation frameworks for regulated agentic workflows

Research question

Why

Evaluation is named as a first-class pillar of the platform alongside ontology and HITL. If evaluation cannot be expressed in regulatory terms, it cannot gate releases in a compliant environment.

Your Agent Platform Is the Product, Not the Agents

The durable asset in enterprise agentic AI is a configuration platform that lets domain users build agents under shared ontology, evaluation, and deployment constraints; individual agents are disposable artifacts of that platform.

Angle

Argue against the 'ship one great agent' pattern using the Agent Studio platform-vs-product distinction, and show what must be centralized (ontology, evals, connectors, deployment modes) versus what can be decentralized to internal teams and customers.

Source video ↗

Ontology First, Prompts Second: Where Agent Reliability Actually Comes From

In regulated domains, the ontology—not prompt engineering or model choice—is the primary reliability artifact, because it converts an open generation problem into a constrained classification and retrieval problem.

Angle

Trace the path from an unconstrained document-upload workflow to ontology-constrained metadata assignment, and argue that teams that skip ontology work hit an accuracy ceiling they cannot prompt their way out of.

Source video ↗

The 10-Year-to-1-Year Claim Is a Toil-Removal Claim, Not a Model-Quality Claim

Compressing clinical trial timelines is mainly an automation-of-administrative-toil problem (document classification, cross-system monitoring), so the right success metrics are hours removed and escalation rates, not benchmark scores.

Angle

Decompose the timeline into administrative versus scientific time, then show why agentic gains concentrate on the administrative side and what that implies for where to invest engineering effort.

Source video ↗

Human-in-the-Loop Is a Compliance Architecture, Not an Apology

HITL checkpoints should be designed as auditable control points that produce evidence, not as fallbacks for weak models; the design question is which decisions may never be automated and how that is proven to a regulator.

Angle

Reframe HITL from a product compromise to a compliance mechanism, with the FDA-auditor lookup scenario as the concrete test of whether a workflow is auditable end to end.

Project ideas

4

Ontology-Constrained Doc Classification Harness

beyond-evals

Grounding an extraction/classification agent in a versioned domain ontology raises top-1 metadata accuracy by at least 15 points over an unconstrained prompt baseline at the same human-escalation budget.

Proof of concept

Build a small ETMF-like corpus with a versioned ontology, run (a) unconstrained prompt classification and (b) ontology-constrained classification with schema validation and escalation thresholds, then compare top-1 accuracy and escalation rate at matched throughput targets.

Measurement

Top-1 metadata accuracy, escalation rate, and documents-per-hour at a fixed escalation budget; falsified if the ontology variant does not beat baseline by 15 points or does not reduce escalation.

Source video ↗

Multi-Source Reconciliation Agent with Conflict Ledger

movement-lab

An agent that maintains an explicit conflict ledger over N heterogeneous source systems surfaces patient-safety-relevant contradictions with higher recall, and fewer silent overwrites, than an agent that merges sources implicitly.

Proof of concept

Simulate 5-13 mocked legacy sources (EDC-like, site data, spreadsheets) with injected schema drift, stale timestamps, and contradictory values; run a merge-implicit agent versus a conflict-ledger agent; score contradiction detection and false-merge incidents.

Measurement

Contradiction recall, false-merge (silent overwrite) count, and time-to-surface per conflicting record; falsified if the ledger agent shows no recall gain or introduces more false positives than it removes.

Source video ↗

Model-Swap Regression Gate for Configured Agents

gatehouse

Agents configured by non-engineers through an agnostic model-selection surface regress on regulated-task acceptance criteria when the underlying model is swapped, and a task-level regression suite can catch that regression before deployment.

Proof of concept

Author three configured agents on a fixed ontology and evaluation suite, snapshot behavior on model A, swap to model B with no config change, and diff outputs against acceptance criteria to measure silent behavioral drift.

Measurement

Number of acceptance criteria that flip after a model swap with zero config change, and detection rate of a pre-deployment regression gate; falsified if swaps produce no measurable criteria flips.

Source video ↗

HITL Checkpoint Throughput Trade Study

new

There is an identifiable HITL checkpoint configuration that preserves near-full auditability while still removing a majority of manual document-handling hours, and beyond a small number of gates the added audit value per gate drops sharply.

Proof of concept

Instrument a document-intake workflow with 0/1/3/5 HITL gates, capture the audit artifacts each produces, and measure both throughput (hours removed) and reconstructability of a decision chain from artifacts alone.

Measurement

Marginal audit-value per added gate versus marginal throughput loss; falsified if throughput loss scales linearly with gate count with no diminishing audit return.
