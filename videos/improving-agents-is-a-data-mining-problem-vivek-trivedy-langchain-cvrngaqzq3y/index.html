Summary

Overview

  • Speaker: Vivek Trivedy
  • Channel: AI Engineer
  • Main topic: Continual learning and agent improvement through data mining and tracing
  • Purpose: To explain how data mining over agent traces, observability, and continual learning drive agent improvement and cost efficiency. Vivek Trivedy from LangChain discusses how improving AI agents over time is fundamentally a data mining problem. He outlines a recipe for building, running, and improving agents by collecting traces, data mining, and running experiments. He explores the challenges of reading traces at scale, leveraging open-source models for cost-efficient trace judging, and drawing parallels between machine learning and agent harness engineering.

Topic Map

Key Points

Observability and Continual Learning are tightly coupled

  • Explanation: You cannot have continual learning without traces, and tracing provides the raw data needed for agent adaptation.
  • Evidence: Agents produce trace data during environment execution, which feeds human or automated learning loops.
  • Practical implication: Teams must prioritize robust tracing and logging infrastructure from day one of agent deployment.

Harness Engineering vs. Fine-Tuning

  • Explanation: Harness engineering provides fast feedback loops, while fine-tuning helps scale intelligence once harness limits are reached.
  • Evidence: Harness engineering gives feedback in minutes; fine-tuning optimizes base models for specific vertical tasks.
  • Practical implication: Use a sandwich approach: start with harness engineering, fine-tune to break ceilings, and continue harness engineering.

Core insights

[A]Architecturemedium noveltystrong evidence

Agent runs are now large enough that trace data structurally cannot be reviewed inside a model context window — modern long-horizon runs can reach millions of tokens — so trace analysis must be done as an out-of-context data-mining pipeline over external storage plus a smaller judging model, not by prompting a frontier model with the trace.

Why it matters

Determines where trace analysis belongs: it is a data-processing/batch-mining workload with its own retrieval, filtering, and sampling stages, not an inference call. Anyone planning to 'just ask GPT to read the logs' will hit a hard scaling wall.

Generalization

Any observability workload over high-volume execution logs will outgrow the context window; the analysis layer must be decoupled from the model that produced the data.

Article ideas

4

Your Agent's Trace Log Is Your Training Set, Not Your Debugger Output

Continual learning for agents is indistinguishable from observability work: teams that treat tracing as an ops add-on added after the agent works have foreclosed their own improvement loop, because the trace stream is the raw input to every later adaptation. Instrumentation and retention-schema decisions are day-one architectural commitments, not monitoring polish.

Angle

Reframe tracing from post-hoc debugging to the data substrate of the improvement loop, and enumerate the day-one design decisions (schema, retention, sampling) that become load-bearing later.

Source video ↗

Stop Pasting Traces Into a Frontier Model

Trace review is a batch data-mining workload, not an inference call. Long-horizon runs reach millions of tokens and cannot fit in a context window, so any workflow that streams a full run into a frontier model silently degrades into ad-hoc sampling while paying frontier prices; the analysis layer must be decoupled from the model that produced the data and given its own filtering, sampling, and judging stages.

Angle

Concrete cost and scaling argument showing where naive in-context review breaks, plus the pipeline stages that replace it.

Source video ↗

Harness First, Fine-Tune to Break the Ceiling

Fine-tuning should be a ceiling-breaking move, not a starting point. Because harness changes return feedback in minutes while fine-tuning optimizes a base model for a vertical, the correct ordering is fast-iteration harness engineering until it saturates, then a fine-tuning cycle, then back to the harness. Teams that invert this pay base-model customization cost while giving up their fastest feedback signal.

Angle

Ordering heuristic for where to spend engineering effort, framed against the default reflex to fine-tune or prompt-hack first.

Source video ↗

Binary Benchmarks Cannot Tell You Why Your Agent Failed

Pass/fail task suites are cheap and unambiguous the way a coin flip is: they carry almost no information about the failure. Traces are the dense label source that turns a binary outcome into actionable supervision, which means evaluation infrastructure should be measured by the density of the feedback it produces, not the number of tasks it scores.

Angle

Reframe benchmarking as a feedback-density problem and argue for outcome-plus-trace evaluation loops over scoreboard-style leaderboards.

Source video ↗

Project ideas

4

Dense-Label Trace Miner

beyond-evals

A segmented trace-mining pipeline that emits per-step critiques from sampled trace segments will produce supervision that improves downstream agent task success more than whole-trace review or binary-outcome-only training, at a lower judging cost.

Proof of concept

Take a set of long-horizon agent runs with binary outcomes, split each trace into segments under a fixed token budget, judge segments with a small model against the outcome label, aggregate into per-step critiques, then compare fine-tuning or harness revisions driven by dense labels versus binary labels only.

Measurement

Delta in held-out task success rate between dense-label and binary-label improvement loops, plus judging cost per run and agreement between segment critiques and the ground-truth outcome.

Source video ↗

Trace-Judge Cost Crossover Bench

beyond-evals

There exists a measurable monthly judging volume above which a fine-tuned open judge on dedicated compute is cheaper than frontier-model token billing for equivalent judgment quality, inclusive of fine-tuning and serving overhead.

Proof of concept

Build one judge task with a fixed rubric, run it through a frontier API judge and a fine-tuned open judge over increasing volumes, and chart total cost of ownership (fine-tuning hours, cluster/hosting, ops) against per-token API spend at matched quality.

Measurement

Crossover volume in judgments per month, quality parity margin between judges on the same rubric, and total cost curves including non-token overhead.

Source video ↗

Harness Saturation Meter

movement-lab

Marginal task-success improvement per harness iteration decays predictably before a fine-tuning cycle is warranted, so the decay curve can be used as a switch signal between harness engineering and fine-tuning.

Proof of concept

Instrument an agent improvement loop to record every harness change with its evaluation delta and wall-clock feedback latency, then test whether a flattening marginal-gain curve precedes the point where a fine-tuning cycle produces the next significant gain.

Measurement

Correlation between measured marginal gain per iteration and the observed benefit of the subsequent fine-tuning cycle across several task suites.

Source video ↗

Trace Retention Contract

gatehouse

Teams that commit to a durable trace schema and retention policy at first deployment can later run adaptation loops that teams adding logging post-hoc cannot, and the difference is visible in how quickly they can reconstruct dense labels from historical runs.

Proof of concept

Instrument two agents — one with day-one full-fidelity trace capture plus schema, one with logging added after it works — then attempt the same trace-derived label-mining task against each history and compare how much usable supervision can be reconstructed.

Measurement

Fraction of historical runs convertible into usable supervision, time to first mined improvement loop, and storage cost per retained run.

Tradeoffs and failure modes

5

Reading traces at scale

Benefit

Full-fidelity trace review gives the richest understanding of agent behavior.

Cost or risk

Cost and context limits make exhaustive reading infeasible for long-horizon runs; naive review silently degrades to sampling.

Source video ↗

Harness engineering vs. fine-tuning

Benefit

Harness engineering yields feedback in minutes; fine-tuning scales intelligence for a vertical once the harness saturates.

Cost or risk

Over-investing in the harness hits a ceiling, while jumping to fine-tuning early sacrifices fast iteration and adds base-model customization cost.

Source video ↗

Open models as trace judges

Benefit

Fine-tuned open models can reportedly match or exceed frontier performance on specific judging tasks at a fraction of the cost.

Cost or risk

Open models have hidden inflection points in intelligence, so capability may be mis-estimated; also implies fine-tuning effort and hardware/ops ownership.

Source video ↗

Sparse benchmark signals

Benefit

Binary pass/fail tasks like terminal-bench are cheap to score and unambiguous.

Cost or risk

They carry almost no information about why a run failed, requiring trace densification to produce actionable feedback.

Source video ↗

Autonomy vs. determinism

Benefit

Autonomous agents handle open-ended tasks without full specification.

Cost or risk

Behavior is unpredictable before execution, so correctness cannot be established by inspection and must be inferred from mined traces.
