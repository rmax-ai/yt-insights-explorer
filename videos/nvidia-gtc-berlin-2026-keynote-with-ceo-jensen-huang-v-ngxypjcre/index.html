Agent safety is being pushed out of prompt-level guardrails and into a hardware-isolated runtime: OpenShell splits the agent into gateway, supervisor, and policy-prover modules that mediate system calls, file access, and network requests, while NVIDIA Sentry observes the agent from a hardware-isolated trust domain (BlueField-4) and quarantines it in milliseconds.

Why it matters

This relocates the enforcement boundary for autonomous agents from application code and prompt instructions to an out-of-band, hardware-rooted supervisor. Generalization

Treat any agent runtime as untrusted code inside a sandbox whose egress (syscalls, file, network) is enumerated, policy-checked, and revocable by a separate trust domain; the 'permissions ceiling' becomes a deployment-time contract rather than a prompt convention.

Deep dives

5

Enforceable agent permission ceilings

Research question

What policy language and capability-enumeration scheme is expressive enough to enforce agent tool access at intercept time, while still permitting legitimate dynamic tool discovery and composition?

Why

If safety moves into an out-of-band supervisor (gateway/supervisor/policy prover), then the enforceable surface is exactly the set of side effects the agent routes through it. Any tool that bypasses the gateway becomes ungovernable in practice, so the harness's capability model — not the prompt — becomes the real security boundary. Getting the expressiveness/denial trade-off wrong either blocks useful agent behavior or leaves holes.

Source video ↗

Quarantine recovery semantics for long-running agents

Research question

When a supervisor quarantines a compromised agent in milliseconds, what in-flight side effects are rolled back, what is orphaned, and how much task work is lost per event?

Why

Millisecond containment is a detection claim, not a recovery claim. Agents that hold partial writes, open transactions, or shared state with other agents turn containment into a consistency problem. Without checkpointing at tool boundaries, the safety mechanism's cost is invisible until it fires in production.

Source video ↗

Joint power-and-latency inference scheduling

Research question

Can a scheduler that treats power as a per-workload allocation variable (rather than a static rack budget) preserve p99 latency for interactive agent traffic while reducing joules per token for the shared facility?

Why

The claim that dynamic power steering cuts power 30% 'for the same output' says nothing about latency distributions under contention. Agent workloads mix long reasoning traces with short interactive turns; if power steering reallocates away from latency-critical requests, the efficiency gain is paid for in tail latency. Efficiency must be reported as tokens per joule at a fixed SLO, not as a scalar multiplier.

Source video ↗

Stage-attributable retrieval pipelines

Research question

Does decomposing enterprise knowledge access into parse / embed / rerank specialists plus a separate structured-SQL path actually improve end-to-end answer accuracy, or does it just relocate error mass between stages that then go unmeasured?

Why

A pipeline of independently replaceable components only pays off if each stage has its own eval and rollback path. Otherwise the decomposition adds latency and operational surface while the agent's wrong answers remain attributable only to 'the model'. The structured-data bypass is the interesting part: it asserts that predictive modeling over SQL beats retrieval over text for tabular questions, which is testable.

Source video ↗

Pre-integrated pods versus bespoke builds under workload churn

Research question

When the workload mix changes every few months, does a standardized pre-integrated pod reduce or increase time-to-capacity and cost-per-token compared with a bespoke build?

Why

Pre-integration shifts integration and burn-in upstream and collapses on-site time from months to days, but it also standardizes the configuration. The trade-off is only decidable if you measure reconfigure time and per-unit defect blast radius (a defect replicates across every shipped pod rather than staying site-local), which the keynote does not address.

Article ideas

4

Your Permission Model Is Your Harness

Agent safety has silently migrated from prompt-level guardrails to an out-of-band, hardware-rooted supervisor, and that migration makes tool-harness design — not prompt engineering — the binding constraint on what an agent is allowed to be. Any capability that does not route through an interceptable gateway is, in practice, forbidden; the 'permissions ceiling' is a deployment-time contract, not an instruction.

Angle

Read OpenShell's gateway/supervisor/policy-prover split as a systems-design constraint on agent frameworks: enumerate the side effects, show which common agent patterns (shell execution, browser automation, unenumerated MCP tools) cannot be governed under it, and argue that harness authors should design tool surfaces as explicit capability manifests.

Source video ↗

30x Is Not a Number: Reading AI Infrastructure Claims With Denominators

The generative efficiency numbers that drive AI capacity planning — 30x token throughput, 30% power reduction — merge throughput and efficiency into single multipliers with unstated baselines, power envelopes, and workload shapes. Planning capacity on the multiplier while ignoring the denominator is how organizations over-provision; the only comparable figure is tokens per joule at a fixed latency SLO.

Angle

Set out a checklist for normalizing vendor efficiency claims: per-watt or per-rack, fixed power envelope or fixed workload, tail latency included or not, cooling and facility costs in or out. Apply it to the specific claims in the keynote and show which ones survive normalization and which do not.

Source video ↗

The Datacenter as a Shipped Artifact

When AI capacity arrives as a factory-built, pre-tested container instead of a site-integrated cluster, integration and burn-in testing move from the field into manufacturing and the on-site failure surface narrows to power and water. The consequence most teams miss is that defects become non-local: a bad pod configuration is replicated across every unit shipped, which makes the digital-twin validation step the real integration test harness.

Angle

Frame pre-integration as a general deployment pattern for any infrastructure whose on-site assembly time dominates delivery latency, then stress-test it against the case it handles worst: rapidly changing, heterogeneous workloads that a standardized pod cannot be reconfigured around.

Source video ↗

Stop Asking One Model to Do Retrieval

The knowledge layer is decomposing into narrow, individually benchmarked specialists — parse, embed, rerank — with a separate predictive path for structured SQL, and the operational win is attribution rather than accuracy: when a stage fails you can name it, evaluate it, swap it, and roll it back. A single general model over everything is not more capable, it is unauditable.

Angle

Argue for staged retrieval pipelines with per-stage evals and per-stage rollback, and make the falsifiable sub-claim that parse quality, not embedding drift, dominates downstream answer error in document-heavy enterprises.

Project ideas

4

Ceiling-Enumerated Tool Gateway

gatehouse

A declarative capability manifest (tool → syscall/file/network effects) checked at a single intercept point can govern agent tool use with under 5% false denials of legitimate dynamic tool discovery, and under 5 ms added median latency per intercepted action.

Proof of concept

Implement a gateway that every agent tool call must traverse, backed by a static policy file mapping tools to enumerated effects (read path, write path, host:port, exec binary). Route an existing agent's shell, file, and HTTP tools through it; add a policy prover that rejects any tool whose effects are not declared. Test against a workload that dynamically discovers new MCP-style tools mid-task.

Measurement

Legitimate-tool denial rate, malicious-or-out-of-policy tool block rate, added p50/p99 latency per intercepted call, and count of side effects that bypassed the gateway entirely (should be zero by construction).

Source video ↗

Quarantine Cost Accounting

gatehouse

Agents checkpointed at tool-call boundaries lose less than 10% of completed subtask work per quarantine event, whereas agents checkpointed only at task boundaries lose more than 50%, and the difference is measurable without any change to detection latency.

Proof of concept

Build a supervisor that can kill a running agent mid-task on an injected policy violation, at two checkpoint granularities. Run multi-step tasks that include partial file writes and an open database transaction. Instrument what is rolled back, what is orphaned, and what must be re-executed on a replacement agent.

Measurement

Work lost per quarantine event (steps and tokens recomputed), orphaned side effects per event, time from kill to a replacement agent resuming, and consistency violations found in shared state after restart.

Source video ↗

Per-Stage Retrieval Attribution Bench

beyond-evals

In document-heavy enterprise QA, replacing the parser with a stronger specialist changes end-to-end answer accuracy more than swapping the embedding model, i.e. parse-stage error dominates downstream error mass.

Proof of concept

Stand up a fixed corpus and question set, then run a factorial swap across parse / embed / rerank stages with each stage's model replaced independently. Keep the LLM reader fixed so any change in accuracy is attributable to the retrieval pipeline. Include a parallel structured-SQL path for tabular questions and compare predictive modeling against retrieval-then-generate on the same rows.

Measurement

End-to-end answer accuracy per stage-swap configuration, per-stage held-out metrics (parse fidelity, recall@k before and after rerank), and attribution rate: fraction of wrong answers traced to a single named stage.

Source video ↗

Power-Envelope Co-Scheduler Simulator

new

A scheduler that co-allocates power with batching decisions holds p99 latency within 10% of a latency-only scheduler while reducing joules per token by at least 20% on a mixed interactive/batch agent workload, under a fixed total power budget.

Proof of concept

Simulate a facility with a fixed power ceiling and two workload classes (short interactive agent turns, long batch reasoning traces). Compare three policies: static per-rack power headroom, latency-only scheduling, and joint power-plus-latency scheduling that can steer power toward latency-critical requests.

Measurement

Joules per token, p50/p99 latency per workload class, throughput at the fixed power ceiling, and the frequency and duration of latency-SLO violations caused by power reallocation.

Architectural implications

4

Agent permission enforcement is placed outside the agent, in a separate supervisor and hardware-isolated trust domain.

Before

Guardrails implemented as system prompts, output filters, or in-process checks inside the agent application.

After

A separate runtime layer (gateway/supervisor/policy prover) intercepts syscalls, file, and network access, with an external monitor able to quarantine the agent.

Consequence

Agent implementations must expose all side effects through enumerable, interceptable interfaces; capabilities that bypass the gateway become ungovernable and effectively forbidden.

AI capacity is delivered as a pre-tested modular pod instead of a site-integrated cluster.

Before

Racks, networking, power, and cooling assembled and debugged on site over months.

After

Compute, network, storage, software, power, and dry-cooler cooling arrive as an integrated container validated in a digital twin before shipping.

Consequence

Power is allocated dynamically per workload rather than provisioned statically per rack.

Before

Fixed power budgets per rack with headroom sized to peak draw.

After

Power steering follows workload demand, cutting consumption for equivalent output.

Consequence

Tradeoffs and failure modes

5

Hardware-isolated agent supervision

Benefit

Compromised agents can be quarantined in milliseconds with granular permission enforcement on system calls, file access, and network requests.

Cost or risk

Requires dedicated isolation hardware and a mediation layer all agent actions must traverse; agents whose tools bypass the gateway or need unenumerated access become impractical to run under the model.

Source video ↗

100% liquid cooling

Benefit

Enables very high-density compute nodes and racks.

Cost or risk

Adds facility-level dependency and plumbing complexity per node; the cooling loop becomes part of the node's operational envelope and a new failure domain.

Source video ↗

Modular pre-integrated pods

Benefit

Deployment time drops from months to days, with factory validation instead of field debugging.

Cost or risk

Standardized pod configurations constrain heterogeneous or non-standard workloads, and any defect is replicated across every shipped unit rather than isolated to one site.

Source video ↗

Generational efficiency claims

Benefit

30x token throughput and efficiency improvement in two years makes aggressive capacity planning plausible.

Cost or risk

Headline multipliers conflate throughput and efficiency and depend on power envelope, cooling, and workload shape; planning on the multiplier without the denominators risks over-provisioning assumptions.

Source video ↗

Full-stack vertical integration

Benefit

Compute, interconnect, DPU, networking, runtime, and safety framework are co-designed and pre-validated together.

Cost or risk

Creates tight coupling to one vendor's abstractions (OpenShell, BlueField trust domains, DSX pods), raising migration cost if the safety or orchestration model must change.
