[E]Empirical Resultmedium noveltymoderate evidence

Anthropic's reported unit economics — $2.08 of revenue per dollar of compute, up from $0.40 eighteen months earlier, with revenue growth outpacing compute cost growth by ~30x — implies that inference serving efficiency is a first-class product lever, not just an ops cost center.

Why it matters

If a frontier lab can roughly 5x its revenue-per-compute-dollar in 18 months, the same curve is available (smaller) to anyone operating inference: serving optimization, caching, batching, and model selection compound into gross margin rather than being a one-off savings.

Generalization

Track revenue (or task value) per unit of compute as a headline engineering metric; treat serving efficiency as a capability roadmap with its own benchmarks, not a cost-reduction project.

The Open/Closed Gap Is Not the Number You Think It Is

Composite intelligence indices are the wrong unit for model-substitution decisions: a 3-5 point headline gap can coexist with large per-task reliability gaps on agentic and tool-use work, so the only defensible substitute signal is your own per-task pass rate and cost per successful task.

Angle

Take the reported 12→3 convergence at face value, then argue it is decision-useless without task-class breakdowns, and show what a routing decision actually needs.

Source video ↗

Your Agents Ship at the Speed of Your Reviewers

The 80/20 human-agent split is a ratio about generation, not delivery; unless review capacity is instrumented and changes arrive as evidence bundles, autonomy converts into review backlog rather than throughput.

Angle

Reframe autonomous development as a queueing problem where the constrained resource is reviewer minutes per merged change.

Compute Has a Counterparty: Architecture Lessons From Debt-Financed GPU Supply

Neocloud fragility means compute should be designed for like multi-region failover — portable artifacts, quota across providers, explicit migration runbooks — because supplier credit risk is a runtime reliability property, not a procurement detail.

Project ideas

4

Compute-Unit-Economics Ablation Harness

movement-lab

In a representative serving stack, a small set of levers (prefix caching, continuous batching, routing to a cheaper tier for low-risk tasks) accounts for the majority of achievable improvement in task value per GPU-hour, and can be ranked by measured contribution.

Proof of concept

Instrument a serving stack to log task value per GPU-hour; then run sequential ablations on caching, batching, quantization, prompt-size reduction, and model-mix routing, reporting marginal delta and cost per successful task for each.

Measurement

Cost per successful task and task value per GPU-hour before/after each lever, with variance across task classes; rank levers by marginal contribution.

Source video ↗

Per-Task Routing Gate

beyond-evals

Routing between a frontier model and a cheaper near-frontier model using internal per-task pass rates (rather than composite index scores) preserves task success within a stated tolerance while materially lowering cost per successful task.

Proof of concept

Build a capability-indexed router with per-task eval gates over tool-selection, error-recovery, and long-horizon tasks; shadow-route live traffic and compare against a single-vendor baseline.

Measurement

Per-task pass rate delta, cost per successful task, and rate of silent regressions caught by eval gates versus composite-index routing.

Source video ↗

Review-Capacity Instrumented Agent Pipeline

gatehouse

Above some autonomy ratio, marginal generated change stops producing marginal merged change unless change sets are batched into reviewable units with attached evidence; reviewer minutes per merged change is the governing metric.

Proof of concept

Instrument an agentic pipeline to log reviewer minutes, change-set size, evidence completeness (tests run, diff scope, rationale), and defect escape rate while sweeping the autonomy ratio on a bounded refactoring workload.

Measurement

Reviewer minutes per merged change, merged-change throughput, and defect escape rate as a function of autonomy ratio and evidence completeness.

Source video ↗

Provider Failover Drill for Model Serving

new

A serving stack with portable artifacts and quotas across two supply sources can restore service after provider loss within a bounded time, and that time is dominated by artifact migration and egress rather than model re-tuning.

Proof of concept

Deploy the same model serving stack on two providers, define migration runbooks, then drill a simulated provider loss and measure restore time and cost delta under both spot and contracted pricing.

Measurement

Time-to-restore, egress and migration cost, and rework required due to provider-specific kernel assumptions; sensitivity to a rental-price drop scenario.

Architectural implications

4

Frontier capability is converging across vendors at divergent token costs, so model choice becomes a runtime decision rather than an integration commitment.

Before

Application logic pinned to one frontier vendor's SDK and prompting conventions; capability assumed to come from the vendor.

After

Provider-agnostic invocation layer with capability tiers, per-task eval gates, and cost/latency-aware routing; vendors differ mainly in price and failure profile.

Consequence

Investment shifts to internal eval harnesses and prompt/tool-schema portability; regressions from model swaps must be caught automatically or routing becomes a reliability hazard.

Source video ↗

Repo-scale ingestion cited as the enabler for autonomous refactoring, delivered as a pre-IDE tool.

Before

Agent context assembled per-request from the editor: open files, retrieved chunks, recent edits.

After

A persistent repo-level index/graph built by a bulk ingestion pass that the agent queries; the editing loop consumes a precomputed model of the codebase.

Consequence

New operational surface: index freshness, incremental re-indexing cost, per-user access control on indexed code, and staleness bugs that look like model errors.

Source video ↗

Agent does the generation, human does validation and architecture, at a claimed fixed 80/20 ratio.

Before

Human writes code, agent assists inline at keystroke latency.

After

Agent produces change sets; human reviews evidence bundles and makes architecture calls; pipeline throughput governed by review queues.

Consequence

Systems need change-set provenance (what the agent read, which tests ran) to make review tractable; without it, autonomy increases output volume but not shipped volume.

Source video ↗

Compute supply is debt-financed and price-volatile, with consolidation predicted for suppliers lacking independent revenue.

Before

Capacity treated as an always-available, monotonically cheap input; single-provider assumptions baked into deployment topology.

After

Compute procurement treated like multi-region failover: portable container/model artifacts, quota across providers, and explicit migration runbooks.

Consequence

Engineering must own supply-diversity: storage egress, model weight portability, and provider-specific kernel assumptions become design constraints.
