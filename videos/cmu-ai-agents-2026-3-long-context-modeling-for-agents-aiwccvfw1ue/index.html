Summary

Overview

  • Speaker: Graham Neubig
  • Channel: Graham Neubig
  • Main topic: Context Management for Long-Context Agents
  • Purpose: To educate students and researchers on the computational, architectural, and data management challenges of maintaining and scaling long context in AI agents. Graham Neubig discusses context management for long-context AI agents at Carnegie Mellon University. The lecture covers how agent context grows quadratically due to linear history growth, long-context architectural challenges like capacity and efficiency, LLM inference serving stacks (prefill vs. decode, KV caching, serving metrics like TTFT and TPOT), hybrid and long-context architectures (sliding-window attention, linear attention, DeltaNet, Gated DeltaNet, Kimi Delta attention, sparse attention, KV compression), training strategies (short-to-long training, positional encodings, RoPE, position interpolation, YaRN), data mixtures for long context, context parallelism, prompt design for cache reuse, and context compaction policies.

Topic Map

Agent Context Growth and Quadratic Input Scaling

  • Explanation: Explains how agent histories grow linearly with conversation/tool calls, resulting in quadratic input token processing when incorporating fixed prefixes and cumulative histories.
  • Key claims:
    • Agent input token usage scales quadratically based on linear history growth.
    • A coding agent session can easily accumulate nearly 80,000 tokens on average across multiple tool calls and tool results.
  • Examples:
    • OpenHands coding agent sessions averaging 77,922 tokens per session across 1,500 sessions.
  • Terminology:
    • quadratic input
    • system prompt
    • tool calls
    • tool results
  • Why it matters: Demonstrates why naive context retention quickly leads to massive computational bottlenecks and high token costs.

LLM Inference Serving Stack and Metrics

  • Explanation: Details the inference serving pipeline, breaking down prefill and decode phases, KV cache usage, serving metrics like TTFT (Time to First Token) and TPOT (Time Per Output Token), and throughput/cost tradeoffs.
  • Key claims:
    • Prefill phase processes all prompt positions and writes to the KV cache, while decode generates one new token per step.
    • Longer input prompts significantly increase TTFT (Time to First Token).
  • Examples:
    • OpenRouter pricing and latency benchmarks across various LLM providers (Mistral, DeepSeek, Reka, etc.).
  • Terminology:
    • prefill
    • decode
    • KV cache
    • TTFT
    • TPOT
    • throughput
  • Why it matters: Understanding serving infrastructure is crucial for deploying cost-effective, low-latency agents at scale.

Long-Context Architectures: Attention variants and Hybrid Models

  • Explanation: Covers architectural modifications to standard O(n^2) global attention, including sliding-window attention, linear attention, DeltaNet, Gated DeltaNet, sparse attention, and KV compression (MQA, GQA, MLA).
  • Key claims:
    • Standard attention computes pairwise comparisons across the entire sequence, leading to O(n^2) complexity.
    • Linear attention replaces softmax to allow recurrent state updates in constant time O(1) per step.
    • Gated DeltaNet and Kimi Delta attention introduce per-channel forgetting and targeted memory corrections.
  • Examples:
    • Qwen3.8-Flash-Next, GLM-5.3-Flash, Kimi K3, and Nemotron Ultra architectures.
  • Terminology:
    • sliding-window attention
    • linear attention
    • DeltaNet
    • Gated DeltaNet
    • sparse attention
    • KV compression
    • MLA
  • Why it matters: Architectural innovations allow models to handle hundreds of thousands or millions of tokens without running out of memory or compute.

Training Long-Context Models and Positional Encodings

  • Explanation: Explores short-to-long pretraining curricula, positional encoding strategies (RoPE, NoPE), position interpolation, and YaRN for extending context lengths.
  • Key claims:
    • Training directly on 128k+ tokens is limited by available natural data, requiring short-to-long curricula.
    • Rotary Position Embeddings (RoPE) encode relative position via rotation and can be extended using position interpolation or YaRN.
  • Examples:
    • Pretraining on 4K-8K tokens, continuing training on 32K-128K packed documents, and long adaptation with synthetic curricula.
  • Terminology:
    • RoPE
    • NoPE
    • position interpolation
    • YaRN
    • packed sequences
  • Why it matters: Enables pre-trained models to effectively generalize to much longer context windows without full retraining from scratch.

Prompt Design for Cache Reuse and KV Caching Mechanics

  • Explanation: Explains how prompt caching works in serving engines, the massive cost and speed advantages of cached KV prefixes, and prompt engineering best practices to preserve cache hits.
  • Key claims:
    • Cached tokens cost roughly 1/10th the price of uncached input tokens on major API providers.
    • Any change to the system prefix or prompt structure invalidates the cache, destroying cost savings.
  • Examples:
    • PagedAttention (vLLM, SGLang) and RadixAttention for prefix sharing and block-table KV allocation.
  • Terminology:
    • KV cache
    • prefix caching
    • PagedAttention
    • RadixAttention
    • cache hit rate
  • Why it matters: Proper prompt design and caching infrastructure can reduce agent operational costs by up to 90%.

Context Compaction and State Estimation

  • Explanation: Examines methods for compressing long agent history into working states (anchors, checkpoints, recent tails) to prevent context window overflow.
  • Key claims:
    • Compacting history into a working state preserves task success while reducing token overhead.
    • Repeated compaction can lead to drift or forgetting critical early instructions if not managed carefully.
  • Examples:
    • Compacting CI failure logs and tool observations into structured summaries with preserved goals and evidence.
  • Terminology:
    • context compaction
    • anchors
    • checkpoint
    • recent tail
    • evidence store
  • Why it matters: Prevents long-running agents from hitting hardware limits or suffering from attention dilution in extremely long sessions.

Key Points

Agent input token complexity is quadratic

  • Explanation: As agent loops accumulate instructions, actions, tool calls, and observations, each step reprocesses previous history plus new inputs, leading to quadratic scaling in token processing.
  • Evidence: OpenHands session data showing average token usage reaching ~78k tokens per session.
  • Practical implication: Agents require efficient context management strategies like caching, compaction, or sparse attention to remain economically viable.

KV caching provides massive cost and latency savings

  • Explanation: Serving stacks cache the Key-Value states of prompt prefixes, allowing subsequent calls with the same prefix to skip the prefill computation phase.
  • Evidence: API pricing data showing cached input tokens priced at $0.007-$0.014 per million tokens compared to $0.22-$1.44 for regular inputs.
  • Practical implication: Developers must stabilize their system prompts and instructions to maximize cache hit rates.

Positional encodings break down at extreme lengths without adaptation

  • Explanation: Standard absolute or rotary positional embeddings struggle when evaluated on sequence lengths far exceeding their training distribution.
  • Evidence: Needle-in-a-haystack evaluations showing accuracy drops at the bottom of long documents for unadapted models.
  • Practical implication: Techniques like position interpolation, YaRN, or partial RoPE are necessary to safely extend context windows.

Frameworks, Models & Processes

The Long-Context System Stack

  • How it works: Manages agent context across five layers: Growth (agent loops ingesting history), Inference (prefill, decode, attention bottlenecks), Architecture (local, recurrent, sparse, and compressed mechanisms), Caching (stable prefixes avoiding redundant prefill), and Compaction (preserving intent and work state).
  • Components:
    • Growth
    • Inference
    • Architecture
    • Caching

  • When to use: When designing or deploying production-grade LLM agents operating over extended multi-turn sessions.

Context Compaction Policy

  • How it works: Triggers compaction upon token threshold overflow or provider limits, selects regions to protect (beginning and recent tail) while compacting older regions into structured summaries, and replaces the raw history while retaining recovery links.
  • Components:
    • Trigger
    • Select
    • Replace
    • Recover
  • When to use: When agent execution spans hundreds of turns and exceeds model context limits.

Core insights

6
[E]Empirical Resultmedium noveltystrong evidence

Agent loops produce quadratic input-token growth: because each step reprocesses the accumulated history plus new instructions/observations, token processing scales with the square of history length rather than linearly. The effect is large in practice — OpenHands coding sessions averaged 77,922 tokens across 1,500 sessions.

Why it matters

Context management is not a polish step but a first-order driver of agent cost and latency; without caching, compaction, or sparse attention, long-running agents become economically unviable at realistic session lengths.

Generalization

Any iterative system that resends a growing state to a fixed-cost-per-token processor inherits quadratic work; the mitigation must live in the runtime (cache/compaction), not in the prompt text.

[P]Practicehigh noveltystrong evidence

Prompt layout is a cache-layout constraint: KV prefix caching makes repeated prefixes skip prefill, with cached tokens priced roughly 1/10th of uncached input, but any mutation of the system prefix or prompt structure invalidates the cache entirely. Cost optimization therefore becomes a prompt-structure invariant (stable immutable prefix, volatile content appended last).

Why it matters

A one-token change near the front of a prompt can silently destroy the majority of an agent's cost savings, so prompt construction must be governed by cache topology rather than by authoring convenience.

Generalization

Wherever content-addressed or prefix-keyed caches sit in front of expensive compute, upstream content ordering becomes a correctness-adjacent performance contract enforced by the platform, not just a style choice.

[!]Failure Modemedium noveltymoderate evidence

Context compaction is effectively state estimation: long history is compressed into a working state (anchors, checkpoints, recent tail, evidence store) rather than truncated. It preserves task success while cutting token overhead, but repeated compaction introduces drift and loss of early instructions — a silent correctness failure rather than a capacity failure.

Why it matters

Compaction trades a visible resource limit for an invisible behavioral regression; without drift measurement, an agent can look healthy on token budgets while quietly violating instructions set in its first turns.

Generalization

Any lossy summarization of agent state needs an explicitly preserved, non-compressible subset (goals, evidence) plus a drift metric, otherwise reliability degrades monotonically with session length.

Source video ↗
[M]Mechanismmedium noveltymoderate evidence

Frontier long-context architectures are converging on hybrid and gated-recurrent designs rather than pure global attention: sliding-window, linear attention, sparse attention, KV compression (MQA/GQA/MLA), and DeltaNet-family models. The distinguishing mechanism in gated variants is per-channel forgetting plus targeted memory corrections inside the recurrent state.

Why it matters

Attention variant choice constrains what a model can recall at long range and how much state it must carry; gated per-channel forgetting means the state is actively edited, not merely accumulated, which changes recall characteristics for retrieval-heavy agent workloads.

Generalization

Constant-time recurrent state with learned erase/write gates is a general pattern for bounded-memory sequence processing, applicable beyond LLMs to any streaming state store.

Source video ↗
[P]Practicelow noveltymoderate evidence

Long-context capability is a training-curriculum problem, not only an architecture problem: natural 128k+ documents are scarce, so practice is short-to-long pretraining (4K-8K), continued training on 32K-128K packed documents, then synthetic long adaptation. RoPE-based models are extended via position interpolation or YaRN rather than retrained from scratch.

Why it matters

It explains why supported context lengths are a data-availability artifact, and why position-extension techniques are the cheap path to longer windows — useful when selecting or self-hosting models.

Generalization

Capability limits are frequently data-distribution limits; curriculum plus positional rescaling is a cheaper lever than architectural change when extending any positional/indexed model.

Source video ↗
[O]Mental Modelmedium noveltystrong evidence

Serving-phase asymmetry: prefill processes all prompt positions and writes the KV cache, while decode emits one token per step. Consequently prompt length drives TTFT, while decode drives TPOT — meaning agent latency for long contexts is dominated by prefill, which is exactly the phase caching and compaction eliminate.

Why it matters

It localizes the optimization target: for interactive agents, reducing uncached prompt length improves perceived responsiveness directly, and compaction versus caching can be reasoned about as two ways to shrink the same prefill term.

Generalization

Separating a bulk parallel setup phase from a serial incremental phase yields a reusable performance model (setup cost scales with input size, incremental cost with output size) for any inference or batch service.

Architectural implications

2

Prefix caching makes the head of the prompt a shared, immutable resource across calls; PagedAttention and RadixAttention exist specifically to share and block-allocate KV state across prefixes.

Before

Prompt construction is treated as free-form text authoring where dynamic content (timestamps, retrieved docs, tool results) can be interleaved anywhere.

After

Prompts are structured as a stable immutable prefix followed by append-only, volatile content, and the layout is treated as a versioned contract with the serving engine.

Consequence

Teams need prompt-layout review, cache-hit-rate observability, and regression tests that detect accidental prefix mutation, since such a mutation is a silent cost/latency regression.

Source video ↗

Context cost reduction is split across two layers: engine-level KV prefix caching and application-level history compaction.

Before

A single 'context window management' concern owned by prompt code, typically implemented as truncating the oldest turns.

After

Two distinct responsibilities — a cache-aware serving/runtime layer and an application-level compaction-and-evidence layer with its own policy and failure modes.

Consequence

Compaction policy becomes a pluggable runtime component (anchors, checkpoints, recent tail, evidence store) rather than ad hoc string trimming, enabling evaluation of policies against task success.

Tradeoffs and failure modes

3

Context compaction policy

Benefit

Compacting history into a working state preserves task success while reducing token overhead, and prevents agents from hitting hardware limits or suffering attention dilution.

Cost or risk

Repeated compaction can cause drift or forgetting of critical early instructions, degrading behavior without any visible token-budget signal.

Source video ↗

Prompt prefix caching

Benefit

Cached tokens cost roughly 1/10th the price of uncached input, and proper prompt design plus caching can cut agent operational costs by up to 90%.

Cost or risk

Any change to the system prefix or prompt structure invalidates the cache, so routine prompt edits or injected dynamic content near the front silently destroy the savings.

Naive full-history retention

Benefit

Keeping the complete history maximizes information available to the agent and requires no summarization policy.

Cost or risk

Input token usage scales quadratically with linear history growth, so cost and prefill latency grow superlinearly as sessions lengthen.
