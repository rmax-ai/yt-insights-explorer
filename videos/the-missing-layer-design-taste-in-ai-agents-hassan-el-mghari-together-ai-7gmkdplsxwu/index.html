Overview

  • Speaker: Hassan El Mghari
  • Channel: AI Engineer
  • Main topic: How to make AI agent UIs look good and avoid AI slop
  • Purpose: To educate AI engineers and developers on how to improve the design and user interface of AI-generated applications by avoiding common AI design clichés and implementing structured design constraints. Hassan El Mghari, lead of the developer experience team at Together AI, discusses the problem of AI-generated applications shipping with ugly, homogeneous user interfaces known as AI slop. He shares his experience building 40+ AI apps reaching millions of users and outlines practical strategies for improving UI/UX design taste in AI-generated apps, introducing frameworks like Hallmark and recommending practices such as using references, longer prompts, and smaller, faster open-source models for iterative development.

Key Points

AI slop is a major differentiator

  • Explanation: Most AI-generated apps share identical design patterns that instantly signal low effort and generic generation.
  • Evidence: Purple gradients, italicized header words, pills with all caps and dots, and random icons appear across most AI-built landing pages.
  • Practical implication: Investing 10-20% extra effort into design polish provides a massive competitive advantage.

Hallmark eliminates slop patterns

  • Explanation: Codifying design rules and anti-patterns into an AI skill file prevents models from using tired tropes.
  • Evidence: Hallmark explicitly refuses gradient headers, three-card rows, fake testimonials, purple glows, and italicized title words.
  • Practical implication: Embedding design constraints into your agent environment raises baseline aesthetics instantly.

Use references and screenshots instead of imagination

  • Explanation: AI models perform significantly better when given concrete visual examples rather than abstract stylistic instructions.
  • Evidence: Hassan's personal inspiration collection of high-quality app screenshots produces vastly superior results when fed to models.
  • Practical implication: Always feed your agent multiple reference screenshots of apps whose aesthetic you admire.

Write longer, highly specific prompts

  • Explanation: Short, vague prompts lead to generic output; multi-paragraph prompts or voice notes provide necessary UX context.
  • Evidence: Hassan records 2-3 minute voice notes detailing target user personas, UI components, and micro-interactions.
  • Practical implication: Treat agent prompting like writing detailed product specifications.

Break iteration into step-by-step queues

  • Explanation: Instead of demanding an entire app in one massive prompt, build the foundation and queue smaller incremental messages.
  • Evidence: Queuing multiple incremental feature requests yields cleaner, more robust code and design than one monolithic prompt.
  • Practical implication: Deconstruct app building into iterative prompt queues rather than single shot attempts.

Frameworks, Models & Processes

Hallmark

  • How it works: A design skill framework that defines strict anti-patterns (slop gates) and provides a curated library of professional themes as context to AI models.
  • Components:
    • Anti-slop gates (no purple gradients, no italicized headers, no fake testimonials)
    • Curated theme library (Bubble, Distill, Cold Snap, Cinder, etc.)
    • Single-prompt context injection
  • When to use: When prompting LLMs or coding agents to generate landing pages or web UIs.

Core insights

[M]Mechanismhigh noveltymoderate evidence

Taste is best encoded as explicit negative constraints (anti-pattern 'slop gates') rather than positive stylistic adjectives. Hallmark enumerates forbidden outputs — gradient headers, three-card rows, fake testimonials, purple glows, italicized title words — which structurally removes the model's default repertoire instead of asking it to 'look good'.

Why it matters

Blacklists of specific, recognizable anti-patterns are checkable, diffable, and enforceable at generation time, whereas 'make it beautiful' is unverifiable. This is a general recipe for constraining any generative artifact where the model has a dominant low-quality prior.

Generalization

Any generative agent task with a strong default mode (UI, docs, API schemas, error messages, code structure) can be improved by enumerating the specific bad outputs to refuse rather than describing the desired good output.

[A]Architecturemedium noveltymoderate evidence

Design taste is packaged as a portable context artifact — a skill file combining anti-pattern gates with a curated theme library (Bubble, Distill, Cold Snap, Cinder), injected in a single prompt. Aesthetic capability is thus relocated from the model into versioned configuration.

Why it matters

If quality lives in a config artifact rather than in model weights or ad-hoc prompting, it can be reviewed, versioned, shared across a team, and A/B tested per model — and it makes model swaps cheaper because the quality contract travels with the repo.

Generalization

Wherever output quality is a product of taste rather than correctness, the durable abstraction is a declarative style/constraint pack loaded into agent context, not per-request prompt wording.

[!]Failure Modemedium noveltymoderate evidence

Model output homogenization is a named, observable failure mode: AI-generated apps converge on identical visual tells, so output similarity itself becomes a detectable signal of low-effort generation (and, inversely, of default model behavior).

Why it matters

Homogenization is measurable — an engineer can score a corpus of generations for shared tells. That turns 'AI slop' from a complaint into a metric: an anti-pattern detector that gates output or triggers regeneration, analogous to a linter for a deployed agent.

Generalization

Default-mode collapse applies to any high-frequency generative surface: if all outputs from an agent look alike, that sameness is both a UX liability and a cheap, automatable quality signal.

AI slop as a measurable, gateable property

Research question

Can the enumerated visual tells of AI-generated UI (purple gradients, italicized header words, all-caps pill buttons, scroll-to-explore badges, gradient logos, emoji-as-icon) be scored reliably enough to act as an automated generation gate rather than a post-hoc complaint?

Why

If homogenization is detectable, taste becomes a lintable property with thresholds and regressions, which is the precondition for treating design constraints like any other CI check. Without a detector, 'slop gates' remain a prompt-level wish.

Ablating the three taste levers: gates, references, and spec length

Research question

Of anti-pattern gates, reference screenshots, and long voice-note-derived specs, which lever carries the observed quality gain, and do they compose additively or redundantly?

Why

The workflow bundles three interventions and reports a single qualitative improvement. Teams cannot budget or tool the right lever without an ablation; the answer determines whether the durable artifact is a constraint file, an asset store, or an upstream spec capture step.

Portability of negative-constraint packs across domains and model families

Research question

Does an enumerated-anti-pattern pack retain its quality effect when moved from web aesthetics to a non-visual artifact (API schemas, error message voice, code structure), and when moved across model families?

Why

The mechanism claim is general but the evidence is scoped to landing pages on models named in a single talk. If constraint packs are model-idiosyncratic, the 'quality contract travels with the repo' argument collapses into per-model tuning debt.

Cost-per-accepted-change as the routing criterion for agent iteration loops

Research question

On held-out UI tasks with blind human acceptance judgments, what is the win rate and cost ratio between a small open-source model and a frontier closed model, and does parity survive complex stateful UI beyond landing pages?

Why

Iteration is the high-frequency phase, so per-turn cost and latency dominate the loop's economics. A routing decision needs an acceptance-adjusted metric, not a token price or a single head-to-head on one task class, otherwise a weaker tier silently compounds mediocre decisions across turns.

Incremental milestone queues versus monolithic generation: coherence drift

Research question

Does a foundation-first queue of small incremental requests reduce defect rates and improve design ratings versus single-shot generation when total token spend is held constant, and how much cross-step contradiction accumulates as the queue lengthens?

Why

Decomposition is claimed to produce cleaner code but introduces state re-reading, drift, and later steps contradicting earlier ones. The real engineering question is where the checkpoint and rollback boundary sits, not whether small steps are fashionable.

Article ideas

4

Stop Describing Good Taste. Enumerate Bad Output.

Style adjectives are unverifiable prompt noise; enumerated forbidden outputs are checkable, diffable, and enforceable at generation time. The durable abstraction for generative quality is a blacklist of recognizable anti-patterns, not an adjectival request to 'make it beautiful' — and this transfers to docs, API schemas, and error messages, not just UI.

Angle

Frame anti-pattern gates as the aesthetic analogue of guardrails and refusals: the same enforcement pattern applied to quality rather than safety, with the same escape-hatch and over-constraint risks.

Source video ↗

The Aesthetic Regression Test: Putting Design in the Diff

When quality lives in a versioned constraint-and-theme artifact injected into agent context rather than in scattered prompt wording, aesthetic regressions become attributable to a config change and model swaps become cheap because the quality contract travels with the repo. Teams that keep taste in chat history keep re-buying it every session.

Angle

Configuration-as-capability argument: relocate the quality contract from model weights and prompt craft into a reviewable repo artifact, and show what breaks (maintenance, de-duplication with prompt text, per-model transfer).

Source video ↗

Homogenization Is a Signal, Not Just a Complaint

When all outputs from a generative surface look alike, that sameness is a free, automatable quality signal — and, inversely, a fingerprint of default model behavior. Output similarity should be measured distributionally, because gating may only shift the mode rather than increase variance, producing a different shared style instead of genuine diversity.

Angle

Measurement-first argument: distinguish 'constraints shift the mode' from 'constraints restore diversity' and show why the distinction decides whether design work is real or cosmetic.

Source video ↗

Cost-Per-Accepted-Change: The Only Benchmark Your Design Loop Needs

Aggregate model benchmarks mislead for iterative work because iteration is many-turn and exploratory. Route per phase — cheap fast models for the refine loop, frontier models only where a measured acceptance gap justifies them — and report quality-per-dollar-per-accepted-edit, since a weaker tier inside the loop compounds mediocre decisions across turns.

Angle

Contrarian benchmark critique grounded in loop economics; includes the caveat that single-task parity does not generalize to stateful UI.

Project ideas

4

Slop Gate

gatehouse

A detector trained on the enumerated visual tells (purple gradient headers, italicized title words, three-card rows, fake testimonials, all-caps pill buttons, scroll-to-explore badges) can reject generated UI at a precision that reduces human-rated slop without suppressing legitimate uses of the same primitives.

Proof of concept

Assemble a labeled corpus of AI-generated and human-designed pages annotated for each tell; build a rubric-prompted scorer plus a lightweight classifier; wire it as a post-generation gate that either blocks, regenerates, or flags. Report residual banned-trope rate in constrained vs unconstrained generations across two model families.

Measurement

Residual rate of banned tells per 100 generations; precision/recall of the detector against human labels; human aesthetic rating delta; false-positive rate on legitimately gradient/pill-based designs; agreement between detector score and blind human preference.

Source video ↗

Lever Ablation Bench

beyond-evals

Anti-pattern gates account for a larger share of blind-rated quality improvement than reference screenshots or long specs, and the three levers are partly redundant rather than additive, so removing the weakest lever preserves quality at lower context cost.

Proof of concept

Factorial design over identical build tasks: constraints only, references only, long voice-note-equivalent spec only, all combined, none. Freeze task prompts and model versions, gather blind pairwise human ratings, and hold total token budget constant across arms.

Measurement

Blind human win rate per arm against the null arm; marginal quality gain per added 1k tokens of context; variance of ratings across arms; cost per quality-adjusted generation.

Source video ↗

Reference Vault

movement-lab

Treating admired screenshots as a retrievable, curated context asset — rather than ad-hoc pastes — produces measurable quality gains that persist when the reference and target differ substantially in layout, with diminishing returns beyond a small number of exemplars.

Proof of concept

Build a licensed, attributed screenshot store with tags and a retrieval step that injects N exemplars into generation; sweep N from 0 to 8 against layout-similar and layout-dissimilar reference sets; log which exemplar was active per generation for attribution.

Measurement

Blind-rated quality versus N (diminishing-returns curve); quality delta when reference layout similarity is low; attribution accuracy of which exemplar drove improvement; context-token overhead per gain.

Source video ↗

Milestone Queue Harness

movement-lab

A foundation-first queue of small incremental requests with per-step checkpoints reduces regression and cross-step contradiction rates versus single-shot generation at equal total token spend, and the benefit decays predictably as queue length grows.

Proof of concept

Implement an orchestration layer that owns an ordered milestone queue, re-reads accumulated state per step, verifies each step, and can roll back. Benchmark against a monolithic prompt on the same target apps with matched token budgets; log contradictions introduced per step.

Measurement

Defect and regression count per build; cross-step contradiction rate versus queue length; rollback frequency; blind design rating; tokens spent per accepted milestone.

Tradeoffs and failure modes

5

Anti-pattern gating vs. over-constraint

Benefit

Blocking known clichés removes the model's dominant low-quality prior and raises the baseline in one prompt.

Cost or risk

Inference: a hard blacklist can suppress legitimate uses (gradients and pills are not inherently bad) and may push output into a different, equally narrow band; the gates need review and escape hatches.

Source video ↗

Small-model iteration vs. generalization of the parity claim

Benefit

Cheap, fast open-source models make many-turn design iteration economically viable.

Cost or risk

The parity claim rests on a single landing-page comparison; it may not hold for complex stateful UI, and silently using a weaker tier in the loop risks compounding mediocre decisions across turns.

Source video ↗

Long, voice-note-derived prompts vs. context cost and maintainability

Benefit

Multi-paragraph, persona-and-micro-interaction-level context eliminates generic output.

Cost or risk

Higher token cost and latency per turn, plus the specification lives in an unstructured note that drifts out of sync with the codebase unless externalized to a durable spec.

Source video ↗

Incremental prompt queues vs. cross-step coherence

Benefit

Smaller steps produce cleaner, more robust code and a recoverable build process.

Cost or risk

More turns and accumulated drift: later steps can contradict earlier ones, and the agent must re-read growing state each turn; consistency requires explicit per-step verification.

Source video ↗

Treating design as the differentiator vs. attributing success causally

Benefit

Framing design/UX as the primary growth driver justifies spending 10-20% extra effort on polish.

Cost or risk

Distribution effects (viral one-page apps like LogoCreator, MakeComics) are confounded with design quality; over-indexing on aesthetics could misallocate effort versus core functionality.
