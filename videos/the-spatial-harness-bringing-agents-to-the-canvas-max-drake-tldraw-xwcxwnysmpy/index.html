Overview

  • Speaker: Max Drake
  • Channel: AI Engineer
  • Main topic: Agents on the Canvas and Spatial User Interfaces for AI
  • Purpose: To demonstrate how tldraw's infinite canvas and SDKs serve as a spatial harness for AI agents, enabling multi-agent collaboration, spatial task management, and multimodal UI interactions. Max Drake, product engineer at tldraw, explores the intersection of AI agents and infinite canvas applications. He discusses why agents struggle in 2D space, the development of tldraw's infinite canvas SDKs as an agent engine, teaching LLMs about canvas geometry and interaction via 'teach' and agent starter kits, and multi-agent human collaboration through experimental 'fairies' systems.

Key Points

Agents Are Bad at 2D Space

  • Explanation: Because LLMs are trained on text-in/text-out, they lack native intuition for 2D spatial positioning, resizing, and UI alignment.
  • Evidence: Developers encounter repeated failure modes when asking agents to build canvas apps without spatial harnesses.
  • Practical implication: Engineers must build custom spatial wrappers and tools so agents can perceive and manipulate canvas geometry.

The Canvas as a Spatial Harness

  • Explanation: Treating the infinite canvas as an agent runtime environment provides a shared workspace for humans and multiple AI agents.
  • Evidence: tldraw's SDK supports multiplayer live sync, cursors, and viewports out of the box.
  • Practical implication: Canvas apps become powerful interfaces for orchestrating multi-agent systems visually.

State Over Chat Logs

  • Explanation: In multi-agent spatial setups, users can inspect agent states directly on the canvas rather than digging through lengthy chat interfaces.
  • Evidence: Fairy agents show planning status, assigned tasks, and progress directly next to their visual avatars.
  • Practical implication: Improves observability and transparency in complex multi-agent workflows.

Dependency-graph-as-orchestration: failure, retry and blocking semantics

Research question

When every node of a planning DAG is bound to an autonomous coding agent, what retry, rollback, and dependency-blocking policies are needed before partial completion stops requiring human intervention?

Why

Collapsing planning and execution into one graph makes graph correctness equal execution correctness. The summary presents the tech tree as a hackathon-era idea with no described error handling, which is exactly where DAG-as-orchestration either becomes practical or deadlocks.

The Harness Is the Product: Why 'Agents Are Bad at 2D' Is an Engineering Problem, Not a Model Problem

Persistent agent failures on spatial and other non-text state spaces are representation mismatches, so the durable engineering value accrues to the harness layer — perception adapters, tool surfaces, and control loops — while the foundation model stays a swappable component.

Angle

Reframe the 'better model / better prompt' reflex as a harness-design discipline: the model's modality never matches the task's state space, so an explicit bridge abstraction is mandatory, and whoever owns that bridge owns the product.

Source video ↗

Pixels, JSON, and Prompts: The Three-Channel Observation Layer for Agents on Rich State

Agents operating on rich visual or structured state should fuse a lossy perceptual channel (screenshots) with a lossless structured channel (JSON) and an intent channel (spatial prompts); picking any single representation caps accuracy, and the interesting engineering question is the mix and cadence, not the choice.

Angle

Argue against the screenshot-only 'computer use' framing and the structured-API-only framing simultaneously, using canvas geometry as the concrete case where each channel alone fails.

Source video ↗

Your Dependency Graph Is Already an Agent Orchestrator — You Just Haven't Enforced Its Semantics

Any DAG already used for planning can be reinterpreted as an agent orchestration topology, but the reuse is only safe once blocking, retry, and partial-completion semantics are enforced by the orchestration layer, because graph correctness becomes execution correctness.

Angle

Take dependency-graph planning artifacts as the control flow and show what breaks when nodes become autonomous agents rather than human-assigned tasks.

Source video ↗

Stop Debugging Agents in a Chat Log: Spatial State as the Primary Observability Interface

Multi-agent observability improves when internal state is bound to a spatial or structural object the user can look at directly, but the gain is paid for by giving up the linear, searchable audit trail — so the right answer is state-first inspection with logs demoted to a secondary forensic layer.

Spatial Observation Ablation Bench

beyond-evals

On canvas manipulation tasks (alignment, spatial search, shape relocation), a hybrid observation channel of screenshot + JSON state + spatial prompt outperforms the best single channel on task success rate, and JSON-only degrades most on perceptually-grounded alignment tasks while screenshot-only degrades most on precision placement.

Proof of concept

Build a fixed task suite of canvas layout tasks in a tldraw-style canvas, run the same LLM through three observation configurations (screenshot-only, JSON-only, hybrid) with an identical tool surface and control loop, and log per-step token cost, latency, retries, and success.

Measurement

Task success rate per configuration, tokens and latency per successful task, and retry counts; report the accuracy-per-token frontier rather than raw accuracy.

Source video ↗

DAG Harness with Explicit Blocking and Failure Semantics

movement-lab

Binding each node of a launch dependency graph to an autonomous agent with explicit blocking, retry-with-context, and rollback policies reduces human interventions per graph by a measurable margin versus an equivalent flat task list, without increasing duplicate or conflicting work.

Proof of concept

Implement a minimal orchestration layer over a real dependency graph where each node dispatches an agent, dependencies gate execution, failed nodes retry with prior-attempt context, and partial completions mark downstream nodes as blocked rather than failed; stress-test on a realistic multi-stage plan.

Measurement

Human interventions per graph, duplicate-action rate, deadlock/blocked-node count, and wall-clock time from graph submission to completion.

Source video ↗

State-vs-Transcript Diagnosis Study

gatehouse

Operators diagnosing injected faults in a multi-agent run reach a correct root cause faster and more accurately when agent planning status, assigned tasks, and progress are rendered as positionable state objects next to each agent than when the same information is presented as a chronological chat transcript.

Proof of concept

Instrument a small orchestrator-plus-worker multi-agent setup to emit both a structured spatial state model and a text transcript, inject a fixed catalog of coordination faults (duplicated assignment, stalled dependency, wrong-target edit), and run a within-subject diagnosis task under both interfaces.

Measurement

Time-to-diagnose and diagnosis accuracy per fault type, plus reported confidence and time spent searching history.

Source video ↗

Coordination-Overhead Tracer for Spatial Multi-Agent Systems

new

Quantifying orchestrator routing, task assignment, and redundant actions in a configurable-persona multi-agent canvas system reveals that coordination overhead (messages and duplicate work per completed task) grows non-linearly with agent count, and that a single designated orchestrator is not sufficient to bound it beyond a small team size.

Proof of concept

Extend a persona-based multi-agent canvas setup (configurable agent attributes plus one orchestrator) with tracing of every assignment, claim, and action, then sweep agent count on a fixed task set and attribute wasted actions to coordination rather than task difficulty.

Measurement

Messages and duplicate actions per completed task as a function of agent count, plus task completion rate and orchestrator queue depth.

Tradeoffs and failure modes

3

Spatial grounding of LLMs

Benefit

General text-trained LLMs can be made canvas-capable via a harness without retraining.

Cost or risk

Requires building and maintaining a custom spatial wrapper (screenshots, JSON, prompts, tools), which is significant engineering work not provided by the model.

Canvas as shared multi-agent workspace

Benefit

Multiplayer live sync, cursors, and viewports come out of the box, giving humans and many agents a common plane.

Cost or risk

Agent state and identity must be expressed as canvas objects, coupling agent internals to the canvas data model.

Spatial state over chat logs

Benefit

Cost or risk
