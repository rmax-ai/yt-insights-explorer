Summary

Overview

  • Speaker: Sydney Runkle, Allie Laabs, Hunter Lovell
  • Channel: LangChain
  • Main topic: Building an agent harness using Jev and LangChain with TypeSafe
  • Purpose: To educate developers on building agent harnesses and leveraging Jev models for efficient agent engineering. Sydney Runkle, Allie Laabs, and Hunter Lovell discuss building agent harnesses using Jev, a System One model from TypeSafe AI. They explore how Jev differs from traditional LLMs by providing fast, typed-safe, non-text-generating decision-making capabilities (Choice, Score, Noul) that make agent development faster and cheaper. Hunter Lovell demonstrates practical integration using LangChain, LangGraph, and LangSmith middleware for tool validation and model routing.

Core insights

6
[A]Architecturehigh noveltystrong evidence

A distinct class of 'System One' decision models can replace text generation for machine-to-machine decisions: Jev returns typed answers (Choice, Score, Noul) rather than tokens, removing the text-generation step from agent control flow.

Why it matters

If decision points in an agent loop no longer need to round-trip through token generation, then routing, classification, and gating can be handled by a cheaper, faster, type-safe layer while a generative model is reserved for actual text work.

Generalization

Separate 'what should I decide' from 'what should I say' into different models behind different interfaces; decision layers want types and latency, generation layers want expressiveness.

[M]Mechanismmedium noveltystrong evidence

Tool-call safety is enforced in harness middleware that intercepts calls before execution and blocks them against defined criteria, rather than relying on instructions embedded in prompts or in the tool itself.

Why it matters

Moves safety from a probabilistic, prompt-level suggestion to an explicit pre-execution gate in the runtime, which is a materially different reliability posture for destructive actions.

Generalization

Put authorization and risk checks in the call path between the model and the side effect, not in the model's context; any agent runtime can adopt an interception point for irreversible tools.

[P]Practicemedium noveltystrong evidence

Model routing is itself expressed as a structured decision made by the fast typed model, selecting between fast and deep models based on prompt complexity.

Why it matters

Cost and latency become a runtime optimization controlled by the harness rather than a static configuration chosen at development time.

Generalization

Any heterogeneous model fleet (cheap/expensive, small/large, local/remote) needs an explicit, auditable routing decision; the router should be the cheapest component in the stack.

Threshold calibration for probabilistic tool-call gating (Noul)

Research question

For a given domain, how does the choice of Noul threshold trade off false-blocking of legitimate tool calls against false-negatives that let destructive calls through, and can a stable per-domain calibration heuristic be derived from a labeled evaluation set?

Why

The harness owner now owns the correctness of the pre-execution gate; without a calibration method, threshold selection is a guess that either blocks legitimate irreversible-adjacent work or fails its only job.

Source video ↗

Decision-model context limits vs. generative baselines at scale

Research question

At what state size does a typed decision model's Choice/Score/Noul accuracy degrade relative to a prompted LLM baseline, and does the typed model degrade earlier or later than the generative one?

Why

If typed decisions degrade faster with state size, the harness must route large-state decisions back to a generative model, which changes the whole cost model behind the 'decision layer is cheap' premise.

End-to-end economics of a typed router in the call path

Research question

On a mixed prompt workload, does inserting a typed routing decision before every call produce net latency and cost savings versus a single deep model once router overhead and misroute cost are included?

Why

The router adds a hop and a failure surface to every request; the claimed savings are only real if misroutes and middleware overhead do not consume them, and no measurement is reported.

Bypass and trace-completeness of pre-execution gates

Research question

Can a blocked tool call be re-attempted or routed around by the agent after a middleware block, and are the probability and confidence values of each block actually persisted and queryable in traces?

Why

A gate is only as strong as its unbypassability, and aggregate auditing requires stored decision metadata rather than a per-run visual trace.

Article ideas

4

Your Agent's Control Flow Should Not Speak English

Using text generation as the bridge between machine execution and human interfaces couples backend agent logic to a human-readable format it never needed, and the fix is to make every internal decision boundary carry typed data, reserving prose for the boundaries where a human actually reads the output.

Angle

Trace a single tool-call round trip and separate the bytes that exist for the machine from the bytes that exist for a human reader; show what disappears when the machine-facing layer returns typed decisions instead of prose.

Source video ↗

The Harness Owns the Gate, Not the Prompt

Tool-call safety expressed as system-prompt instructions is a probabilistic suggestion, while a pre-execution interception layer is a deterministic choke point; moving authorization into the call path changes who is accountable for irreversible actions and makes false-block behavior an explicit engineering concern rather than an emergent one.

Angle

Argue that any irreversible tool warrants an interception point between model intent and side effect, then enumerate the new obligations the harness owner inherits once that gate exists.

Source video ↗

The Cheapest Model in the Stack Should Be the Router

Model routing is itself a decision, so the component that arbitrates between cheap and expensive models should be the cheapest and most auditable part of the runtime; a router that costs as much as the thing it routes is a net negative and should be replaced by static configuration.

Angle

Treat routing as a heterogeneous-fleet problem: every mixed cheap/expensive fleet needs an explicit, logged routing decision, and the router's misroute rate is the metric that determines whether the fleet is worth having.

Source video ↗

What Would Falsify a 200x Speed and 40x Cost Claim?

Comparative performance claims about decision models are only actionable when stated with a task set, a baseline, and a volume assumption; until then they should be treated as a hypothesis to test rather than a budget line, because the cost profile at production volumes can invert the ranking.

Angle

Take the headline multipliers seriously as a claim and list the measurement conditions that would need to hold for them to survive contact with a production workload.

Project ideas

4

Gatehouse Noul Gate

gatehouse

A pre-execution interception gate that blocks irreversible tool calls when a typed boolean-probability decision exceeds a calibrated threshold can drive destructive tool executions to zero on a labeled adversarial suite while keeping false-blocks on legitimate calls below an agreed rate.

Proof of concept

Instrument a harness middleware that evaluates every irreversible tool call (account deletion, payment, config mutation) with a boolean-probability decision and blocks above threshold; run a labeled suite of authorized and unauthorized calls, then sweep the threshold to trace the false-block / false-negative curve.

Measurement

False-negative rate on unauthorized calls and false-block rate on authorized calls across at least five thresholds; report the threshold where the tradeoff curve bends.

Source video ↗

Router Economics Instrumentation

movement-lab

Adding a typed routing decision in front of a two-tier model fleet reduces net cost and p95 latency on mixed workloads only when the misroute rate stays below a workload-specific break-even point.

Proof of concept

Build a duplicate-instrumented harness that runs a mixed prompt workload twice, once through a typed router selecting fast vs. deep models and once against a single deep model, logging per-request route decision, latency, and cost.

Measurement

Net cost per request, p50/p95 latency, and misroute rate (requests where the fast model produced an output the deep model would have changed); compute the break-even misroute rate.

Source video ↗

Threshold Calibration Bench

beyond-evals

Per-domain evaluation sets yield stable confidence-threshold heuristics for probabilistic decisions that transfer across decision points within the same domain but not across domains.

Proof of concept

Assemble labeled decision sets for two or three domains, sweep the continuous 0-to-1 decision threshold for each, and test whether a threshold calibrated on one domain's evaluation set holds on a held-out set from a different domain.

Measurement

Precision and recall of the gating decision per threshold per domain, plus cross-domain threshold transfer error.

Source video ↗

State-Size Degradation Sweep

new

Typed decision accuracy degrades measurably beyond a context-size knee point, and that knee arrives at a smaller state size than the equivalent prompted-LLM baseline's degradation point.

Proof of concept

Take a single decision task (classification with Choice and ordinal scoring with Score) and vary the state payload size across a sweep; run the same tasks through a typed decision model and a prompted LLM baseline on identical inputs.

Measurement

Decision accuracy versus state token count for both systems; identify each system's knee point and the size at which the typed model falls below the baseline.

Architectural implications

3

Decision-making is factored out of the generative model into a separate, typed-answer service callable from middleware.

Before

A single LLM prompt handles classification, routing, and tool selection alongside text generation, with all outputs parsed from prose.

After

A fast typed model returns Choice/Score/Noul answers at the decision points, while a generative model is invoked only when text is actually required.

Consequence

Harness code becomes the orchestrator of heterogeneous models; interface definitions and thresholds, not prompts, become the primary artifacts to maintain.

Source video ↗

Safety checks move into a pre-execution interception layer between agent intent and side effect.

Before

Guardrails are expressed as system-prompt instructions and hope the model complies before calling a destructive tool.

After

Middleware evaluates risk with a typed decision and can block the call outright before the tool runs.

Consequence

Irreversible operations gain a deterministic choke point, but the harness owner now owns that gate's correctness and false-block behavior.

Source video ↗

Routing between cheap and expensive models becomes a runtime function of the prompt rather than a static choice.

Before

A single model (or hand-tuned per-feature selection) serves all traffic, so simple and complex tasks pay the same cost and latency.

After

A router decision assigns each request to a fast or deep model based on task requirements.

Consequence

Cost and latency profile becomes tunable at runtime, with new failure modes around misrouting and router overhead.

Source video ↗

Tradeoffs and failure modes

3

Routed model selection

Benefit

Simple tasks use fast models, so cost and latency drop for the common case.

Cost or risk

Complex tasks sent to a non-reasoning model may silently underperform; the routing decision itself can be wrong and is only as reliable as the classifier behind it.

Source video ↗

Probabilistic gating of tool calls

Benefit

Destructive actions can be blocked by evaluating risk probability before tool execution.

Cost or risk

A probability output (Noul on a 0-to-1 continuum) requires a threshold choice; the summary states best practices for setting confidence thresholds are an open question, so mis-set thresholds can block legitimate calls or let unsafe ones through.

Source video ↗

Typed decision models and state size

Benefit

Decisions are fast, type-safe, and free of text-generation overhead.

Cost or risk

Complex state evaluation may be constrained by context length limits, which the summary lists as unresolved.
