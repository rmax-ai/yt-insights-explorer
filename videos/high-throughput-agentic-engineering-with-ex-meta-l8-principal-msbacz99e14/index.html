Summary

Overview

  • Speaker: Kun Chen
  • Channel: Kun Chen
  • Main topic: High-throughput multitasking agentic engineering workflows using multiple AI agents and orchestration tools
  • Purpose: To share an advanced workflow for high-throughput multitasking with a large number of AI coding agents. Kun Chen, an ex-Meta L8 Principal Engineer, demonstrates an advanced agentic engineering workflow focused on high-throughput multitasking using multiple AI agents. He walks through herdr (a multiplexer tmux alternative), firstmate (an open-source orchestrator tool where you talk to one agent who orchestrates other agents), backpass, and quota management tools, demonstrating how he manages 36+ projects simultaneously without cognitive overload.

Topic Map

Introduction and Firstmate Workflow

  • Explanation: Kun introduces himself and Firstmate, an open-source orchestrator that allows a developer to talk to a single agent (firstmate), which then orchestrates other agents (crewmates) across multiple repos.
  • Key claims:
    • Firstmate acts as the primary contact agent that orchestrates all other agent crewmates.
    • Voice input is used by default for natural language prompting and faster throughput.
  • Examples:
    • Listing all managed projects using firstmate via voice command.
  • Terminology:
    • firstmate
    • crewmates
    • herdr
    • pi
  • Why it matters: Eliminates context switching and session juggling by delegating orchestration to a primary agent.

Crew Dispatch and Model Selection

  • Explanation: Explaining crew-dispatch.json configuration rules, which map specific task types, harnesses, models, and effort levels to different crewmates.
  • Key claims:
    • Different models excel at different tasks (e.g., Fable for UI, Codex for image generation, Kimi/Astra for complex planning, Opus/Grok for bug fixes).
    • Automated model selection based on task type prevents wasting expensive tokens.
  • Examples:
    • Assigning Claude with Fable harness for iOS app UI development, Codex for image generation, and pi for complex planning.
  • Terminology:
    • crew-dispatch.json
    • harness
    • effort
    • grok-4.5
    • opus
    • fable
  • Why it matters: Optimizes token usage, speed, and output quality by matching tasks with the best-suited LLM and harness.

Quota Management with Quota-Axi

  • Explanation: Using quota-axi to monitor API subscriptions across Claude, Codex, Cursor, and Grok, automatically routing tasks to models with available quota.
  • Key claims:
    • Firstmate calls quota-axi to select the model with the most quota available, preventing hitting rate limits unexpectedly.
    • Automating quota checks saves time compared to manual monitoring.
  • Examples:
    • Checking quota status panel for Claude, Codex, Cursor, and Grok subscriptions.
  • Terminology:
    • quota-axi
    • quota
    • subscription
  • Why it matters: Ensures uninterrupted agent development by intelligently distributing workloads across available API quotas.

Backpass and Agent Memory

  • Explanation: Backpass analyzes past agent sessions using gradient descent principles to improve agent.md and cloud.md instructions for future runs.
  • Key claims:
    • Backpass closes the loop by having a human review past agent failures to improve agent instructions.
    • Automated collection of agent session transcripts across remote machines.
  • Examples:
    • Running backpass to collect transcripts across remote machines and dispatching a crewmate to work on it.
  • Terminology:
    • backpass
    • agent memory
    • gradient descent
    • transcripts
  • Why it matters: Continuously refines agent behavior and memory over time, reducing recurring mistakes.

Lavish Editor and Review Artifacts

  • Explanation: Lavish is an interactive HTML editor used by crewmates to present reports, design mockups, and decision points for captain review.
  • Key claims:
    • Interactive HTML artifacts allow the captain (human) to make decisions quickly without reading raw terminal logs.
    • Feedback given in Lavish is routed back to the appropriate agent crewmate.
  • Examples:
    • Reviewing bird variants and snow-capped mountain prototypes in Lavish editor.
  • Terminology:
    • Lavish
    • artifact
    • captain's call
    • decision
  • Why it matters: Simplifies human review and decision-making for complex multi-agent tasks using rich visual interfaces.

Scaling Up with Secondmates

  • Explanation: Scaling up management by spinning up secondmates to own different domains or projects, offloading orchestration from firstmate.
  • Key claims:
    • When firstmate gets too busy orchestrating tasks, secondmates are created to own specific app domains (e.g., Ship app, Edies Wallet app).
    • Secondmates act as firstmates for their respective sub-projects.
  • Examples:
    • Spinning up secondmates on Mac mini for separate app codebases.
  • Terminology:
    • secondmates
    • scaling up
    • Mac mini
    • headless
  • Why it matters: Enables massive horizontal scaling of agentic workflows across dozens of projects without hitting cognitive or computational bottlenecks.

Key Points

Talk to one agent, ship with a crew

  • Explanation: The developer only interacts with firstmate, which delegates and orchestrates all other agent crewmates in the background.
  • Evidence: Firstmate CLI commands and fleet registry listing 36 active projects.
  • Practical implication: Drastically reduces human cognitive load and context switching.

Calm Mode for Signal vs Noise

  • Explanation: Using the /calm command to hide verbose tool calls and terminal noise, showing only a floating boat indicator when agents are working.
  • Evidence: Toggling /calm mode in the terminal CLI.
  • Practical implication: Allows developers to focus on higher-level thinking and planning rather than watching terminal scrolling.

Policy-Driven PR Management (Yolo vs No-Mistakes)

  • Explanation: Each project has defined policies in projects.md specifying whether PRs require strict adversarial review (no-mistakes) or can be auto-merged (yolo).
  • Evidence: projects.md configuration showing policies like direct-PR+yolo or no-mistakes+yolo.
  • Practical implication: Automates routine merges for low-risk toys while applying rigorous validation for high-stakes code.

Human Attention is the Ultimate Bottleneck

  • Explanation: Trying to micro-manage every optimization leads to burnout. Focus human attention strictly on high-value architectural decisions.
  • Evidence: Discussion on context window limits (e.g., 500k auto-compact threshold) and avoiding manual micro-optimization.
  • Practical implication: Accept imperfect micro-optimizations and let automated pipelines handle routine tasks.

Frameworks, Models & Processes

Firstmate Agentic Workflow

  • How it works: Human talks to firstmate -> Firstmate reads intent and crew-dispatch rules -> Dispatches crewmates with specific harnesses and models -> Crewmates execute tasks, generate Lavish artifacts -> Human reviews artifacts and makes decisions -> Crewmates merge PRs.
  • Components:
    • Firstmate (primary orchestrator)
    • Crewmates (implementer agents)
    • Herdr (multiplexer)
    • Lavish (interactive UI review)
    • Backpass (memory improvement)
  • When to use: When managing multiple software projects and tasks simultaneously with AI coding agents.

Actionable Takeaways

  • Immediate:
    • Set up a multiplexer like herdr to manage multiple agent sessions.
    • Use voice input for prompting agents to increase coding throughput.
    • Configure dispatch rules to route tasks to the most appropriate AI model.
  • Strategic:
    • Treat human attention and time as the ultimate bottleneck in agentic engineering.
    • Scale horizontally by delegating sub-projects to secondmate agents.
    • Build feedback loops (like backpass) to continuously improve agent memory.

Project ideas

4

Quota-Aware Capability-Constrained Router

new

A task router that optimizes placement under capability constraints and live quota signals reduces rate-limit-induced stalls by at least 30% versus capability-only routing, without more than a 5% relative quality regression on task-type benchmarks.

Proof of concept

Wrap a set of coding tasks with simulated provider quota APIs; route each task via capability-only, round-robin, highest-quota, and capability-constrained quota-aware policies.

Measurement

Stall/rate-limit rate, task success quality, token cost, end-to-end latency across routing policies.

Source video ↗

Backpass Loop Harness

beyond-evals

One offline optimization pass that edits agent instruction files from historical transcripts reduces recurring failure rate on a held-out task set, with diminishing returns and measurable overfitting risk on repeated passes.

Proof of concept

Collect session transcripts, define a failure taxonomy, generate instruction-file edits, and rerun held-out tasks before/after each iteration.

Measurement

Held-out failure rate per iteration, instruction diff size, train-vs-held-out gap, human-review acceptance rate.

Attention-Budget Review A/B

movement-lab

Artifact-based review reduces human decision latency and error rate versus raw terminal logs, and latency gains diminish as artifact complexity increases.

Proof of concept

Present the same set of agent decisions to reviewers as structured HTML artifacts versus raw logs, randomizing order.

Measurement

Tradeoffs and failure modes

5

Per-project merge autonomy (yolo vs no-mistakes)

Benefit

Auto-merging low-risk changes raises throughput and avoids spending review budget on trivial work.

Cost or risk

Auto-merge policy can let defects into a repo; mis-classifying a high-stakes project as low-risk bypasses adversarial review entirely.

Source video ↗

Calm mode signal suppression

Benefit

Hides verbose tool calls and terminal noise so the human can focus on planning.

Cost or risk

Suppressing tool-call output reduces observability; silent agent misbehavior becomes harder to detect.

Source video ↗

Autonomous memory/instruction optimization via backpass

Benefit

Continuously refines agent instructions from real transcripts, reducing recurring failures.

Cost or risk

Depends on human review of past failures and cross-machine transcript collection; instruction drift or overfitting to past sessions is a risk.

Source video ↗

Ignoring micro-optimizations

Benefit

Preserves scarce human attention for architectural decisions and avoids burnout.

Cost or risk

Accepting imperfect micro-optimizations leaves systematic inefficiency (cost/latency) unaddressed indefinitely.

Source video ↗

Quota-based routing

Benefit

Avoids hitting rate limits by sending work to models with the most remaining quota.

Cost or risk

Routing to the highest-quota model can override capability fit, potentially trading quality for availability; quota signal accuracy is assumed.
