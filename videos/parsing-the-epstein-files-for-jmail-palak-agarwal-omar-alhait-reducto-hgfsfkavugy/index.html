Core insights

[A]Architecturemedium noveltymoderate evidence

Reducto treats document ingestion as a visual understanding problem — documents are viewed like a human would (rasterized), rather than relying strictly on the underlying text layer or embeddings. This reframes parsing as image/layout reasoning rather than text extraction.

Why it matters

It moves the hardest part of document ingestion (rotated pages, charts, handwriting, degraded scans) into a visual model boundary instead of a brittle text-extraction boundary, which is where most naive pipelines fail.

Generalization

For layout-heavy or handwritten inputs, grounding extraction in rendered visual representations can outperform pipelines that depend on the document's own text layer.

[M]Mechanismmedium noveltymoderate evidence

The OCR layer is agentic: instead of a single pass that commits to an answer, the model flags uncertainty, self-corrects, and proceeds step-by-step within the ingestion engine.

Why it matters

Uncertainty-flagging plus iterative self-correction is a concrete mechanism for reducing hallucinations and structural errors, and it implies OCR should be a stateful loop, not a stateless transcription call.

Generalization

Extraction stages in agentic pipelines can be made more reliable by explicitly surfacing uncertainty and allowing a correction pass rather than emitting a final answer in one shot.

[A]Architecturemedium noveltymoderate evidence

Document processing is decomposed into five orthogonal primitives — Parse, Split, Extract, Edit, Classify — exposed as a composable toolset rather than a single monolithic parser.

Why it matters

Separating layout parsing from splitting, extraction, editing, and classification lets developers compose document workflows and swap stages independently, instead of writing custom brittle parsers per use case.

Generalization

Complex ingestion problems are easier to reason about when split into discrete, composable stages with clear responsibilities.

[O]Mental Modelmedium noveltymoderate evidence

Ingestion is positioned as a dedicated pre-model layer (layout analysis, OCR correction, schema mapping) that runs before data reaches the LLM, rather than being folded into the LLM prompt.

Why it matters

It assigns responsibility for document cleanup to a separate preprocessing layer, keeping the LLM downstream of cleaned, structured data instead of asking it to compensate for messy inputs.

Generalization

Reliability of downstream reasoning improves when messy-format normalization is handled by a purpose-built layer with its own correctness concerns, not by the generative model.

[P]Practicemedium noveltymoderate evidence

Schema generation can be tailored to the actual parsed document contents (enhanced) rather than fixed up front (standard), making the extraction schema a configurable artifact applied after parsing.

Why it matters

Choosing between a quick generic schema and a content-tailored one is a design lever that affects nuance capture versus setup speed; treating the schema as a post-parse artifact decouples parsing from the target data shape.

Generalization

Extraction quality can be improved by generating or adapting the output schema after inspecting the source content rather than committing to a static schema before parsing.

Your PDF Text Layer Is Lying to You: Move Document Ingestion Into the Visual Model

For messy enterprise inputs, rasterizing pages and reasoning over rendered layout beats trusting the embedded text layer, so the ingestion layer — not the LLM prompt — should own rotation, handwriting, and charts.

Angle

Before/after pipeline walkthrough showing where text-layer extraction silently loses information and where a visual render preserves it.

OCR Should Be a Loop, Not a Call

Treating OCR as a stateless transcription call bakes errors into downstream data; a stateful loop that flags uncertainty and re-reads suspect spans spends compute at the cheapest point in the pipeline rather than paying for LLM repair later.

Angle

Contrast single-pass transcription with an uncertainty-flagged correction loop, and argue about where the extra latency budget is best spent.

Source video ↗

Generate the Schema After You Read the Document

Pre-committing an extraction schema trades nuance for speed; deriving or enhancing the schema from parsed content — with a validation step against gold fields — is the higher-fidelity default for heterogeneous corpora.

Angle

Design-lever argument: when standard schema speed is worth it versus when enhanced schema nuance pays off, plus how to grade a generated schema.

The Pre-Model Layer: Keep Messy Formats Out of the Prompt

Asking an LLM to compensate for scanned, rotated, or handwritten inputs wastes tokens and reliability; a normalization layer with its own correctness metrics keeps the model downstream of clean structured data.

Angle

Raster-vs-Text A/B Harness

beyond-evals

On rotated, handwritten, and scanned pages, a rasterized visual parsing pipeline yields higher field-level extraction F1 than a text-layer extraction pipeline at equal or lower cost per corrected field.

Proof of concept

Take a public corpus of scanned forms or FOIA PDFs, hand-label ground-truth fields, then run both a render-then-parse pipeline and a text-layer extraction pipeline over the same pages and score them with identical field definitions.

Measurement

Field-level exact match and F1 per document class, cost per corrected field, p95 latency per page, and the document classes where the accuracy gap flips direction.

Source video ↗

Agentic OCR Correction Loop

movement-lab

Adding an explicit confidence signal and one bounded correction pass over low-confidence spans reduces structural and field errors on handwritten pages versus single-pass OCR, at a bounded latency increase.

Proof of concept

Wrap a vision-OCR stage with a self-reported confidence field, re-read only spans below a threshold once, then compare outputs against the same pages processed single-pass.

Measurement

Structural error rate (malformed output / field misalignment), field F1 delta, and added latency per page; sweep the confidence threshold to find the cost/benefit knee.

Source video ↗

Post-Parse Schema Generator with a Schema Critic

new

Generating the extraction schema after parsing improves field F1 on heterogeneous corpora versus a fixed standard schema, and a schema critic can score proposed fields against gold with measurable precision.

Proof of concept

Parse a mixed sample corpus, auto-propose a schema, extract with it, and compare against a fixed-schema baseline; add a critic that matches proposed field names and types to a gold schema.

Measurement

Field F1 delta versus fixed schema, schema precision/recall against gold fields, and setup time per corpus.

Source video ↗

Thousand-Page Ingestion Scaling Probe

beyond-evals

Per-page cost and peak memory in a rasterize-plus-visual-parse pipeline scale sublinearly only when documents are chunked with cross-page state; below some page threshold, cross-page context loss degrades extraction accuracy.

Proof of concept

Generate synthetic documents with known ground truth at 10, 100, 1,000, and 5,000 pages, run the same visual parsing pipeline with and without overlap/cross-page state, and record where accuracy and memory break.

Measurement

Accuracy versus page count, peak memory, cost per page, and latency per page; the page count at which context-loss errors appear.

3

Document understanding shifts from text-layer extraction to visual rasterization.

Before

Parse the PDF text layer and feed strings to the model.

After

Render documents visually and reason over layout, handwriting, and charts like a human reader.

Consequence

Pipeline stages must handle image rendering and visual model inference, and accuracy on complex layouts is claimed to improve.

Extraction schema is a post-parse configuration artifact, not a pre-committed contract.

Before

Define a fixed schema before seeing document contents.

After

Generate or enhance the schema based on parsed document contents before extraction.

Consequence

Developers must plan for a schema-generation step in the workflow rather than hardcoding target shapes.

Ingestion becomes a composable primitive set (Parse/Split/Extract/Edit/Classify) rather than one parser.

Before

Write a monolithic custom parser per document type.

After

Compose discrete document primitives into per-product pipelines.

Consequence

Teams can build downstream products (resume parsing, flight-history extraction) by recombining stages instead of rebuilding parsers.
