Summary

Overview

  • Speaker: Sam Witteveen
  • Channel: Sam Witteveen
  • Main topic: TypeSafe AI's Jev model, a System One model designed for structured outputs, classification, and function calling without chat interfaces.
  • Purpose: To analyze and demonstrate Jev by TypeSafe AI, explore its underlying mechanics (RLCD, parallel sampler), compare it to existing LLMs, and walk through practical applications and pricing. Frontier AI labs have focused heavily on reasoning, long chains of thought, and thinking budgets (System 2 thinking), which make models slow, expensive, and opaque for software integration. Software typically needs fast, structured decisions like classification (pick from a list, scoring, yes/no probabilities). TypeSafe AI, founded by former OpenAI researcher Diogo Almeida (lead author of InstructGPT), spent two years in stealth building Jev, a System One model that outputs typed choices, scores, and probabilities without chat interfaces, token-by-token generation, or hallucination of schema, offering high speed and very low cost.

Software Needs System 1 Classification

  • Explanation: Most decisions made inside software every second are not complex System 2 problems; they are simple classification problems (pick-from-a-list, urgency checks, rule violations) that should not take 30 seconds or minutes.
  • Key claims:
    • Most decisions in software are classification problems.
    • Asking reasoning models to return one-word answers wrapped in JSON incurs massive latency and token costs.
  • Examples:

Introducing Jev by TypeSafe AI

  • Explanation: TypeSafe AI, founded by Diogo Almeida (co-author of the InstructGPT paper), came out of stealth with Jev, a model designed for software automation rather than chat.
  • Key claims:
    • Jev has no chat box and does not write left-to-right token by token.
    • Output tokens are free on OpenRouter, while input tokens cost $0.042 per million tokens.
    • Jev is a System One model acting like a typed function call.
  • Examples:
    • Passing unstructured text state and typed questions into jev(state, questions).
  • Terminology:
    • TypeSafe AI
    • Jev
    • Diogo Almeida
    • InstructGPT

  • Why it matters: Introduces a radically different paradigm for integrating AI into software pipelines.

The Three Building Blocks: Choice, Score, and Noul

  • Explanation: Jev operates on three types of questions: Choice (picks one option from a list plus probabilities), Score (rates on a user-defined scale), and Noul (yes/no probability via a sigmoid function).
  • Key claims:
    • There are only three kinds of questions: Choice, Score, and Noul.
    • Outputs contain no text to parse, returning structured probabilities and confidence scores.
    • Jev eliminates faked JSON outputs from order-regressive LLMs.
  • Examples:
    • Classifying support ticket language as French, English, German, or Thai.
    • Scoring customer review sentiment from 0 to 2.
    • Determining whether text is asking a question (Noul).
  • Terminology:
    • Choice
    • Score
    • Noul
    • Sigmoid function
    • Confidence score
  • Why it matters: Provides developers with deterministic, structured primitives instead of parsing fragile text.

How Does It Work? RLCD and Parallel Sampler

  • Explanation: TypeSafe AI utilizes a new model architecture, a parallel sampler for maximum efficiency, and a training method called Reinforcement Learning for Calibrated Decisions (RLCD).
  • Key claims:
    • RLCD stands for Reinforcement Learning for Calibrated Decisions.
    • Unlike RLHF (Human Preference) and RLVR (Verifiable Rewards), RLCD optimizes for calibrated decisions with epistemically honest probabilities.
    • End-to-end response time is 700ms-500ms (40x-200x faster than frontier models).
  • Examples:
    • Comparing existing LLMs (RLHF, RLVR) with System One + Jev (RLCD).
  • Terminology:
    • RLCD
    • Parallel sampler
    • RLHF
    • RLVR
    • Calibrated decisions
    • Epistemically honest probabilities
  • Why it matters: Explains the technical breakthrough enabling fast, non-autoregressive, calibrated structured outputs.

Key Points

Chat is the wrong interface for software

  • Explanation: Software applications do not want paragraphs of text; they want structured values they can use immediately without parsing latency.
  • Evidence: Traditional LLMs require parsing markdown JSON out of conversational text streams, introducing latency and failure points.
  • Practical implication: Developers should use function-call-like interfaces that return typed values directly.

Jev eliminates token-by-token generation for classification

  • Explanation: Jev does not write text left-to-right; it evaluates the whole answer at once using parallel sampling.
  • Evidence: Output tokens are priced at $0/M on OpenRouter because generation is non-autoregressive for the output values.
  • Practical implication: Massive reduction in latency (700-500ms) and cost.

Reinforcement Learning for Calibrated Decisions (RLCD)

  • Explanation: A new training methodology optimized for calibrated, epistemically honest probability scores rather than human conversational preferences.
  • Evidence: Outputs include accurate confidence scores and probability distributions across all available options.
  • Practical implication: Eliminates hallucinations in structured outputs and tool selection.

[M]Mechanismhigh noveltystrong evidence

Jev produces its output values non-autoregressively via a parallel sampler, so output generation is not billed per output token the way autoregressive decoding is.

Why it matters

Output-token cost is the dominant cost driver for high-volume classification/agent loops; if the values are evaluated at once rather than generated left-to-right, marginal cost per decision collapses, reshaping what workloads are economically viable (10 queries/sec Doom control, 20-step action chains).

Generalization

Any system where the 'answer space' is a bounded typed set (labels, scores, probabilities) can in principle be evaluated in parallel instead of decoded sequentially, decoupling output cost from answer-space size.

[O]Mental Modelhigh noveltymoderate evidence

RLCD (Reinforcement Learning for Calibrated Decisions) is positioned as a third training paradigm distinct from RLHF (human preference) and RLVR (verifiable rewards), optimizing for epistemically honest, calibrated probabilities rather than rewarding plausible or verifiably-correct answers.

Why it matters

Calibration is the property agent runtimes actually need for thresholds and routing decisions — a 97% confidence label is only useful if it is honest. If preference/reward-verification objectives systematically distort confidence, then a separate objective is required for decision-critical classifiers.

Generalization

Training objectives determine the trustworthiness of downstream decision signals; systems that act on model output probabilities need an objective explicitly shaped around calibration, not preference ranking or binary correctness.

Architectural implications

3

Structured output is currently faked by autoregressive models writing JSON inside prose, then parsed by the caller.

Before

Caller prompts a chat model to emit JSON, then parses markdown/text to recover values, with fallback and retry logic for malformed output.

After

Caller invokes a typed function (jev(state, questions)) that returns the decision values and probabilities directly.

Consequence

The parsing/validation layer moves from the developer's harness into the model interface, removing a class of production failure modes and reducing response latency.

Source video ↗

Output cost is currently proportional to generated tokens, so bounded answers still cost per token.

Before

Cost scales with output length; a one-word classification still pays for tokens and generation time.

After

Non-autoregressive evaluation of a bounded answer space decouples output cost from token count (output priced at $0/M).

Consequence

High-frequency, per-decision model calls become economically feasible, enabling model-in-the-loop control and dense agent action selection.

Source video ↗

Decision-critical classifiers must expose trustworthy confidence for thresholding and routing.

Before

Confidences come from softmax over generated tokens or self-reported confidence, often poorly calibrated.

After

A training objective (RLCD) explicitly optimizes calibrated, epistemically honest probabilities.

Consequence

Teams can build deterministic control flow on confidence thresholds (routing, human escalation) with a principled expectation that stated confidence means what it says.
