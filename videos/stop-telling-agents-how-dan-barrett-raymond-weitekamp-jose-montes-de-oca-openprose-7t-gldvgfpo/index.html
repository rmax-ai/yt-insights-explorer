Summary

Overview

  • Speaker: Dan Barrett, Raymond Weitekamp, Jose Montes de Oca
  • Channel: AI Engineer
  • Main topic: Event-Based Multi-Agent Financial Workflows with Only Markdown
  • Purpose: To demonstrate how OpenProse enables event-driven multi-agent workflows using pure markdown contracts and declarations. This workshop introduces OpenProse, a framework and language for agent-based multi-agent workflows written entirely in markdown. The speakers explain how declaring intent, contracts, and outcomes in plain markdown—rather than writing imperative Python or complex orchestration code—allows intelligent agents to figure out the 'how', dramatically simplifying multi-agent composition and integration with existing enterprise stacks.

Core insights

6
[A]Architecturehigh noveltymoderate evidence

The runtime/compiler for an agent workflow is itself an LLM prompt: markdown contracts are interpreted directly by a model acting as compiler and runtime, with no parser, binary, or SDK in the loop. This collapses the traditional interpreter boundary (grammar → AST → executor) into a single model call that both validates and executes the declaration.

Why it matters

It removes an entire layer of infrastructure (parser, orchestration backend, deployment) and relocates correctness responsibility to the model's instruction-following. That changes what you must test: instead of parser unit tests you need prompt-runtime conformance and hallucination bounds.

Generalization

Any DSL whose semantics are simple enough can be executed by an LLM instead of a bespoke interpreter, trading determinism and static checking for zero infrastructure cost and natural-language editability.

[M]Mechanismmedium noveltymoderate evidence

Declarative contracts — declaring the end state and success criteria rather than a step sequence — let the harness and the model select the execution path. The contract doubles as the evaluation target: agent output is benchmarked against the declared ideal state, which the speakers claim reduces hallucination loops.

Why it matters

It merges specification and evaluation into one artifact, so the same text that generates the run also gates it. This is a cheap evaluator-optimizer loop that doesn't require a separate rubric-maintenance pipeline.

Generalization

Write specs as machine-checkable acceptance criteria co-located with intent, so generation and verification share a single source of truth.

[A]Architecturemedium noveltymoderate evidence

The trigger layer is event-driven (webhooks, GitHub issue opens, cron), not conversational. Workflows fire from external system events and produce automated job output, deliberately avoiding chat interfaces.

Why it matters

Chat-first agent designs couple the agent to a human-in-the-loop session and to session-scoped context. Event-triggered execution makes agents CI/CD citizens — deterministic entrypoints, no interactive state — and is what lets them slot into existing enterprise infrastructure without new procurement.

Generalization

Design agents as event consumers with declared input/output contracts, not as always-on conversational services; the integration surface becomes the event bus rather than a UI.

Why it matters

Defines a concrete composition unit (the markdown file with declared I/O) that can be reviewed, versioned, and reused, which is the missing primitive in most prompt-reuse schemes.

Generalization

Pick a text-native module boundary with explicit declared inputs/outputs so agents can be composed and reviewed by the same process as code, without a runtime linking step.

Deep dives

5

Behavioral conformance testing for an LLM-as-compiler runtime

Research question

If the runtime and compiler of a markdown agent workflow are themselves prompts, what test suite replaces parser unit tests, and how much cross-run and cross-model variance does a fixed contract exhibit?

Why

Removing the parser moves correctness responsibility onto instruction-following, so the failure surface shifts from syntax errors to silent interpretation drift. Without a conformance harness you cannot tell whether a contract edit or a model version bump changed behavior, which makes the whole architecture unauditable in practice.

Source video ↗

Self-grading contracts: circularity between generation target and evaluation rubric

Research question

When the contract supplies both the generation objective and the scoring rubric, does the contract-grader reproduce the generator's misinterpretations, and does a second independent evaluator agent catch what the first certifies as correct?

Why

The claim that contracts benchmark output against declared ideal states to reduce hallucination loops is asserted without error rates. If the same wording drives generation and grading, an ambiguous contract yields confidently wrong passes, which is worse than a loud failure because it produces no signal to act on.

Source video ↗

Event-triggered agent jobs need idempotency, retry, and duplicate-event semantics that chat never required

Research question

What minimal job semantics (idempotency keys, retry policy, duplicate-event suppression, dead-letter handling) must a markdown-declared event-driven agent carry before it can safely run unattended against enterprise event sources?

Why

Moving the entrypoint from a human conversation to a webhook or cron job converts each run into a stateless automated job. Chat scoped state hid exactly the problems that now become production incidents: replayed events, partial writes, and unbounded retry loops, none of which a prose trigger declaration expresses by default.

Source video ↗

Governance of executable prose: provenance, diff review, and rollback for programs that are documents

Research question

How do version control, review, and rollback work when the program, the runtime contract, and the compiler instruction are all natural-language documents editable by non-engineers under an existing compliance perimeter?

Why

The compliance argument rests on the logic being text that flows through already-approved gateways rather than a new deployable artifact. That only holds if change control moves with it: document versioning, reviewer identity, golden-run regression per revision, and pinned model versions. Otherwise the governance path was relabeled, not shortened.

Source video ↗

File-level module boundaries for composed sub-agents and interface validation without a linker

Research question

What file granularity and declared input/output schema minimize interface mismatch and review effort when workflows are composed from many sub-agent markdown files, given that nothing statically checks the interfaces?

Why

The file is proposed as the composition unit, but with no runtime assembly step there is no linker to catch a mismatch between one file's declared output and another's declared input. Boundary conventions and a lightweight interface check are what make prompt reuse safe rather than aspirational.

Collapsing specification and evaluation into one artifact is efficient but creates a circular reasoning risk, because the wording that makes an ambiguous contract under-specified is the same wording used to certify the resulting output as correct.

Project ideas

4

Contract Conformance Bench

beyond-evals

A fixed set of markdown contracts executed N times across M model versions will show run-to-run output variance concentrated in contracts with implicit success criteria, and explicit acceptance criteria co-located in the contract will measurably reduce that variance.

Proof of concept

Build 12 contracts (half with explicit machine-checkable acceptance criteria, half with prose-only intent), run each 20 times across two model versions through the same gateway, and diff normalized outputs plus declared-criteria pass rates.

Measurement

Per-contract output divergence rate across runs, pass rate against declared criteria, retry count, and token cost per successful run; compare explicit-criteria versus prose-only cohorts.

Source video ↗

Ambiguity Divergence Probe

beyond-evals

Deliberately ambiguous contracts will be silently resolved to a single interpretation that the contract-based grader then certifies as correct, and an independently authored second evaluator will flag a detectable share of those self-certified passes.

Proof of concept

Author 10 contracts with one planted ambiguity each, run generation plus contract-as-grader, then run an independent evaluator with no access to the generator's reasoning; manually adjudicate disagreements.

Measurement

Percentage of ambiguous contracts where grader passes output judged wrong by human adjudication, and the recall of the independent evaluator on that subset.

Source video ↗

Idempotent Event-Trigger Runner

gatehouse

An event-triggered markdown-declared agent job without idempotency keys and duplicate-event suppression will produce duplicate side effects on replayed webhooks at a rate above zero, and adding a declared job-identity layer will drive that to zero without changing the contract prose.

Proof of concept

Wrap a contract-declared workflow in a thin event adapter that replays the same webhook and cron events with injected duplicates and partial failures, first naive, then with idempotency keys and a dead-letter path.

Measurement

Duplicate side effects per 100 replayed events, retry loop depth, recovery time after injected mid-run failure, and contract-diff size required to gain the guarantee.

Source video ↗

Executable SOP Drift Detector

movement-lab

Where a written procedure is the authoritative source, executing the procedure document and regenerating the documentation from the run will surface latent discrepancies between the prose and actual execution that a human re-documentation pass misses.

Proof of concept

Take two internal SOPs and one methodology-style document, run each as an executable prose program, auto-regenerate the document from the run trace, and diff against the human-authored version.

Measurement

Number and severity of semantic discrepancies found per document, reviewer acceptance score of the regenerated document, and edit volume required before sign-off.

Architectural implications

4

The compiler/runtime is a prompt rather than a program

Before

A DSL requires a parser, an AST, and an executor service; semantics are enforced statically and failures are deterministic

After

A model reads the declaration, decides the execution steps, and self-checks against the contract; semantics are enforced probabilistically

Consequence

You lose static guarantees and gain zero-infrastructure iteration; testing effort shifts from parser conformance to behavioral conformance and hallucination measurement

Source video ↗

Workflow entrypoint moves from chat to events

Before

Agent invoked by a human in a conversation; context and state scoped to the session

After

Agent invoked by webhook/cron/issue event; each run is a stateless job with declared inputs and outputs

Consequence

Agents become auditable job runners that fit CI/CD and enterprise automation, but require idempotency, retry, and duplicate-event handling that chat never needed

Source video ↗

Agent logic is delivered as a document instead of a deployment

Before

New automation means new code, new deploy, and security/procurement review of a new artifact

After

New automation means a markdown file reviewed as text and run through the already-approved gateway

Consequence

Shipping cost drops to documentation review cost; governance must instead track document versions and who may edit executable text

Source video ↗

Specification and evaluation become the same artifact

Before

Spec lives in a design doc; evaluation lives in a separate harness with its own rubric that drifts

After

The contract declares the ideal end state and the run is benchmarked against it in the same loop

Consequence

Fewer desynchronized artifacts, but the contract's wording now directly determines both generation and grading, so a bad contract silently produces confidently wrong scores

Tradeoffs and failure modes

4

LLM-as-compiler vs. conventional parser

Benefit

No parser, binary, or SDK to build, version, or deploy; workflows ship as text and run through existing gateways

Cost or risk

No static validation of the declaration; malformed or ambiguous prose fails at runtime and failures are non-deterministic and model-version-dependent

Source video ↗

Declarative intent vs. control over execution path

Benefit

The harness and model choose steps, so contract authors don't hand-build orchestration graphs

Cost or risk

Execution path is chosen by the model, so cost, latency, and step count become emergent and hard to budget or bound ahead of time

Source video ↗

Human-readable contracts vs. machine-checkable guarantees

Benefit

Anyone who can read logical English can read and edit the contract, collapsing the business-to-engineering handoff

Cost or risk

Prose admits ambiguity; correctness depends on shared interpretation between author and model, and edits by non-engineers can change runtime behavior without tests

Source video ↗

Text-only delivery vs. depth of control

Benefit

Slots into approved enterprise stacks without touching security controls or procurement

Cost or risk

Constraints on token budget, tool permissions, and rate limits must be expressed in prose and enforced downstream, not by the runtime
