Summary

Overview

  • Speaker: Jo Kristian Bergum
  • Channel: AI Engineer
  • Main topic: The resurgence and effectiveness of BM25 lexical scoring for agentic information retrieval loops
  • Purpose: To explain why lexical search (BM25) combined with simple tools like grep outperforms complex vector/embedding retrieval setups in agentic search workflows. Jo Kristian Bergum, CEO of Hornet.dev, explains why a 30-year-old lexical scoring function like BM25 is experiencing a strong comeback in the era of LLMs and agentic search. He defines agentic search as search running inside an agent loop consisting of an LLM model, a harness, and a retrieval engine. Modern LLM users are more powerful, issuing complex queries, using syntactic operators, and rewriting queries dynamically. BM25 provides exact matching, low cost, and interpretability, making it an ideal foundational primitive when paired with simple tools like grep.

Key Points

BM25 as an interpretable primitive

  • Explanation: BM25 scores based on exact term matches, making it fully explainable and easy for LLMs to reason about.
  • Evidence: Outperforms complex embedding models when paired with sophisticated agent query generation.
  • Practical implication: Engineering teams should use BM25 as a robust baseline before adopting heavy embedding or neural retrieval models.

Context window vs corpus size

  • Explanation: Even large LLM context windows are tiny fractions of real-world enterprise corpora (billions of documents).
  • Evidence: Corpora like BrowseComp-Plus have 736M tokens while model context windows hold ~370k tokens.
  • Practical implication: Retrieval infrastructure remains indispensable regardless of how large LLM context windows grow.

Evaluating agent + retriever as a system

  • Explanation: Traditional IR evaluation metrics based on static single queries are obsolete for agents.
  • Evidence: Agents generate query trajectories, rewriting queries dynamically over multiple turns.
  • Practical implication: Evaluation must measure end-to-end task success, latency, and tool call efficiency rather than static NDCG@10.

Frameworks, Models & Processes

Agentic Search Loop

  • How it works: An LLM agent determines when to search and formulates queries, interacts with a retrieval engine to get snippets, and refines results in a loop until it finds enough evidence for a final answer.
  • Components:
    • Capable model (LLM)
    • Harness
    • Retrieval engine
  • When to use: When building complex QA, coding assistants, or deep research agents over large corpora.

BM25 + Grep Workspace Architecture

  • How it works: Retrieves candidate documents using BM25, places them in a virtual file system workspace, and uses Unix-like tools (grep, cat) for progressive disclosure and inspection.
  • Components:
    • BM25 retriever
    • Virtual file system (vfs)
    • Grep / read tools
  • When to use: For scaling direct corpus interaction in developer tools and enterprise RAG systems.

Retrieval quality, not model reasoning, is the dominant bottleneck in agentic search: when the exact evidence document is placed in context upfront, GPT-4 reaches 93% accuracy on BrowseComp-Plus, implying most end-to-end task failure comes from the retriever rather than the LLM.

Why it matters

Shifts engineering investment from prompt/reasoning tuning toward retrieval pipeline quality and evidence placement, and gives a concrete upper bound (the oracle ceiling) to measure how much accuracy a retrieval system is leaving on the table.

Generalization

For any agentic QA or research system, benchmark the 'oracle evidence' ceiling first; the gap between oracle and retriever-mediated accuracy is the retrievable ROI, and it is usually larger than any reasoning-side improvement.

Tradeoffs and failure modes

3

BM25 effectiveness depends on the quality of agent-generated queries

Benefit

Interpretable, cheap, exact-term scoring that LLMs can reason about and exploit with operators and entity filters.

Cost or risk

The reported superiority over embedding models is conditional on sophisticated query generation; with weak query formulation the lexical baseline degrades rather than being inherently superior.

Progressive disclosure via workspace tools

Benefit

Inspectable reasoning and evidence verification inside the agent loop.

Cost or risk

Requires additional tool calls and multi-turn traversal, adding latency and token overhead relative to a single retrieval call.

Long context windows as a retrieval substitute

Benefit
